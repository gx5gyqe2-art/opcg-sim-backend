# 理論とうちの CPU の差分——どの層が壊れているか

2026-09-13 作成（`game_theory.md` の再構成で、**実装・CPU・計器の話をこちらへ分離**した）。

> **本書の位置**: [`game_theory.md`](game_theory.md) が「このゲームでは何が最適か」を書く。
> 本書は **「うちの CPU はそれに対して何をしているか」**——診断・計器・手当ての候補。
> 測り方の理論は [`measurement.md`](measurement.md)、配置と運用は `rust_engine_plan.md`／`n_loop_ops.md`。

## 1. 層ごとの判定（2026-09-13 時点）

| 層 | 状態 | 根拠 |
|---|---|---|
| **候補生成（列挙）** | 律速ではない | 枝予算は候補を 1 つも落としていない（40 局 2,606 判断点で被覆 1.000） |
| **探索（世界数）** | 効果の証拠なし・分解能不足 | 腕 4 で +12.6 Elo・腕 8 で +3.0（用量反応は逆・±41〜45 Elo） |
| **探索（PIMC の構造）** | 壊れるのは接戦帯だけ | 世界の最善が 44% 割れ・融合 2.0%（決着帯は 0.2%） |
| **価値（符号）** | **正しい** | 手札 1 枚の傾きは 3 ネット × 両席で実測と符号一致 |
| **価値（水準）** | **零和が破れている** | `V_p1+V_p2 = −0.058`〜−0.170・偏りは**手番でない席だけ** |
| **価値（交換レート）** | **ライフを高く見すぎ** | 内部の `λ/μ` 3.60〜4.69 対 実測 2.47〜2.67 |
| **方策（順序）** | **壊れている（一次対象）** | 接戦帯の `order_acc(p,q)` **0.5016＝コイン**・失う Q が後悔の全量 |
| **打ち回し（価格）** | 使われていない | `θ` 平ら・安い攻撃を 47.9% 受ける・無駄な守り 23%・払い過ぎ +0.406 枚 |
| **打ち回し（攻め）** | ドンを使い切れない | `don_idle` 2.32／6.38・77.1% のターン・**相手ライフ 1 でいちばん余らせる（4.79）** |
| **読まれやすさ** | 公開情報からは読めない | 予測器の `lift` 0.000〜0.005 |

**一次対象は方策の順序**（`order_acc` がコイン水準で、その損が後悔の全量）。
価格はその下の層で、**順序を直す教師として価格が使える**という関係になる
——`c(x) − Θ` は「どちらの手が良いか」の**符号を与える量**なので、順序の教師そのものになりうる。

## 2. 探索の実装（PIMC）とその構造的誤り

エンジンの探索は **PIMC（Perfect Information Monte Carlo）**: 情報集合から世界を `K` 本引き、
各世界を**完全情報ゲームとして**解いて根の統計を束ねる。近似であって、**2 つの誤りが原理的に残る**
（Frank & Basin 以来の古典的指摘）:

- **strategy fusion**: 世界ごとに別の手を選べる前提で価値を作る。実際には
  **区別できない状態では同じ手しか打てない**＝「A の世界なら守る・B なら受ける」で得た価値は達成不能。
- **non-locality**: 完全情報の解は「その世界の最善」を返すが、相手の戦略は情報集合全体に
  対して決まるので、ある世界での最善が全体の最適と一致しない。

**カウンター窓がまさにこれ**——相手の手札が見えている世界では「止められるか」が確定するので、
`K` 本の世界がそれぞれ違う結論を出し、束ねた訪問分布は「どの世界でも最善でない手」を選びうる。

**実測（`pimc_diag.py`・K=8・606 判断点）**:

| 帯（`|v0|`） | 世界の最善が割れる | **どの世界の最善でもない手を打った** | 選んだ手の Q の世界間の幅 |
|---|---|---|---|
| close（≤0.2） | **0.440** | **0.020** | **0.361** |
| decided（>0.6） | 0.231 | 0.002 | 0.133 |
| 全体 | 0.271 | 0.007 | 0.182 |

**K=4 でも壊れる場所は同じ**（接戦帯 0.400／4.0%／0.212）。
**K をまたいだ数字の比較はできない**（世界が多いほど `disagree`・`q_spread` は上振れし、
世界の最善の集合が大きくなるので `merged_novel` は下振れする＝機械的な偏り）。

**読み**: `merged_novel` が全体 0.7%＝**PIMC はほぼ自分の良い領域に居る**
（＝`game_theory.md` §5 の leaf correlation が高い）。ただし**2% の融合は今の弱さを説明できる量ではない**。

**世界数の設定**: `SeatSpec.opts` は `{net, sims}` だけで、Rust の `DecideOptions::default()` は
`worlds: 1`。`worlds 4` は `record_gen --worlds 4`（波 29 以降）だけ。
＝**出荷エンジンは、教材を作った生成器より隠れ情報のサンプリングが粗い**。
理論（`game_theory.md` §5）は `K` を上げろと言うが、**2 腕の実測は効果を示さなかった**
（腕 4 で +12.6 Elo・腕 8 で +3.0・CI は 0 をまたぐ・**用量反応が逆向き**）。
**未解決の不一致**で、説明の候補は 2 つ: (a) `p` が小さい線は K=8 でも拾えない・
(b) 拾っても評価が正しく値を付けない。分解能不足（±41〜45 Elo）も残る。

**窓の畳み込みはミニマックス**（`game_theory.md` §2-3）＝訪問数の平均で畳むと
「相手が下手を打つ確率」を勝手に置くことになる。実装はミニマックスで畳んでいる。

## 3. 価値（V）の診断

### 3.1 零和の反対称が破れている

同じ盤面を両席から評価した `V_p1 + V_p2` は 0 であるべき（`game_theory.md` §2-2）。実測:

| ネット | `sum_mean` | 対局クラスタ 95% CI | 手番側の較正 | **手番でない側** |
|---|---|---|---|---|
| r3（出荷既定） | −0.058 | [−0.119, −0.003] | **+0.006** | **−0.035** |
| r5（生成役） | −0.008 | [−0.089, +0.050] | +0.018 | −0.025 |
| r10（時間軸ヘッド） | −0.170 | [−0.247, −0.081] | −0.025 | −0.060 |

**偏りは「手番でない席の評価」だけに乗っている**＝訓練の行が**決定点の席からしか作られない**
ことの帰結（`is_my_turn=0` の行は「攻撃を受けている窓」に偏る）。
**r5 では破れておらず、r10 が最も悪い**＝世代で単調ではない（補助ヘッドを足した r10 で悪化・監視対象）。
**帯で点推定が 2 倍動く**（同じ r3 が別の seed 帯で −0.138）。

**実害**: 探索は窓のミニマックスで「そのとき手番でない側」の価値を使う
＝**歪んでいるのはまさに畳み込みに入る値**。

**直し方（ユーザ決定が要る・訓練の変更）**: (1) **反対称の正則化**（同じ盤面の両席を評価して
`V_me + V_opp` を 0 へ罰する・教師は要らない）／(2) **非手番側の行を訓練に入れる**（`z` は反転だけ）。

### 3.2 手札の価値の符号は正しい（交絡は否定された）

`V_guard − V_take`（守った方が勝ちやすい +0.141）は「V が**手札が減った＝勝者の相貌**を
学んでいる」だけで説明できてしまう恐れがあった（v5 までの符号化で実測された逆相関）。
**3 ネット × 両席すべてで実測と符号が一致**（`slope_true` +0.0433 対 `slope_V` +0.041〜0.045）
＝**NRel では起きていない**＝守りの読みの土台は無事。

### 3.3 内部の交換レートが高すぎる

| | 実測 | ネットの応答 |
|---|---|---|
| `λ`（ライフ） | +0.1158 | +0.1189（**合っている**） |
| `μ`（手札） | +0.0433 | +0.0331（**24% 過小**・相手ターンは 48% 過小） |
| `λ/μ` | **2.674** | **3.60**（相手ターン 4.69） |

**ライフを正しく恐れ、手札を軽く見ている**。歪みの向きは**守りすぎ**を生むが、
実プレイは**守らなすぎ**——**価値の歪みと行動の誤りが逆を向いている**＝
**行動の誤りは価値から来ていない**（§4 の結論を別角度から支持）。

## 4. 方策（π）の診断——一次対象

`order_acc(p,q)` ＝ 方策の事前分布と探索の Q が兄弟手を同じ順に並べる割合（波 32・410,290 行）:

| 帯 | `order_acc(p,q)` | `q_cost`（方策だけで打った時の Q の損） |
|---|---|---|
| **close**（\|v0\|≤0.2） | **0.5016** | **0.0701** |
| mid | 0.5014 | 0.0608 |
| decided | 0.5279 | 0.0211 |

**接戦帯はコイン**＝事前分布は「どちらの手が良いか」をまったく並べられていない。
`q_cost` 0.070 は**独立に測った後悔 0.033〜0.084 と桁も範囲も一致**＝
**後悔のほぼ全部が順序の誤りで説明できる**。方策のエントロピーは 1.89〜2.11 bit（候補 10〜13 本）
＝平ら＝**情報が無いのではなく、持っている情報が順序と無関係**。

**限界**: 探索の Q を正としているので、測れているのは
「方策が探索に追いついていない」ことだけ（「方策が真に誤っている」は反事実が要る）。

## 5. 打ち回しの診断——価格が使われていない

### 5.1 守り（13.7 万窓）

| 量 | 実測 | 理論（`game_theory.md`） |
|---|---|---|
| 領域 1（受けても死なない）での守り率 | **0.382** | §8: **純粋な無駄** |
| `p≤0`（ライフが減らない攻撃）の窓 | 全体の **23%**・守り率 0.524・0.95 枚 | 同上 |
| `c(x) < Θ` を**受けた** | **47.9%** | §9: **2000 までは守る**べき |
| `c(x) > Θ` を守った | 30.3% | §9: 3000 以上は受けるべき |
| `L − θ` 対 守り率 | −4〜+4 で **0.33〜0.39（平ら）** | §11: しきい値を割ってから守り始めるはず |
| 払い過ぎ（`greedy_gap`） | 平均 **+0.406 枚**・守った窓の 52.3% | 止める最小で足りる |

**予算モデルの入力は正しい**（実プレイの最小枚数曲線がデッキ側の `c(x)` と一致）**が、
出力が使われていない**。守り率が帯ごとに下がるのは合理の証拠ではない——
同じ帯で「止められない確率」も 0.12→0.84 と上がるので、**下がり方の大半は能力の限界**。

### 5.2 「できない」と「しない」の分離

t≤2 で受けた行のうち **89.4% は守る手段を持ち・64.7% は止めるだけ足りていた**
（攻撃 1 回ごと・DON 補正後）。DON 補正で落ちたのは 5.3 ポイントだけ＝
**「守れたのに受けた」は事実として残る**。

**ただし §14 の `k̄_use` が未測定**なので、**予算の側からは「守るべきだった」と言えていない**
——手札を攻めに使う価値が支配的なら、受けるのが正しい打ち回しになる（未解決の最重要項目）。

### 5.3 攻め（9.3 万ターン）

| 量 | 実測 | 理論 |
|---|---|---|
| 手持ちのドン | 6.38 | — |
| 付与した | 1.16 | §10: **段を跨ぐ時に付ける** |
| **何にも使わず余らせた** | **2.32**（1 個以上余るターン **77.1%**） | §13: 平均的には残すのは損 |
| 相手ライフ別の `don_idle` | 5 で 1.31・**1 で 4.79** | **逆**（リーサル圏でいちばん残している） |
| 打った攻撃の超過パワー | **38.5% が x≤0**・`x≥3k` は 24.5% | §10: 段に跨げていない |
| 一度も殴らなかったターン | 0.295 | — |
| 相手ターン中の自分のアクティブなドン | **0.55〜0.68** | §13: 薄いライフの帯でだけ残す |

**理論が触る 3 か所すべてで逆を向いている**。

### 5.4 攻撃順序（反事実・48 局 147 点）

同じ盤面で入口（最初の攻撃）だけ替えて残りをエンジンに打たせると:

```
opt_gap_honest = 0.0420        対局クラスタ 95% CI [0.0218, 0.0663]
腕の差 0.112 対 続きの雑音 0.0141（= 7.9 倍）      勝者の呪いの上振れは 0.004 だけ
最良の入口を選ぶ 55.1%（腕 2.64 本＝無作為 37.9%）  無作為な入口より 0.8 ポイント良いだけ
```

大きさは後悔の実測と同じ桁＝**§4 の「兄弟手を並べられない」を勝率の側から見たもの**の可能性が高い
（母集団が違うので足し合わせない）。**副産物**: 攻撃の入口が 2 つ以上あるのに
**49.0% は攻撃を打っていない**（判定から外した）＝**攻めの取り逃がしの全体はこれより大きい**。

## 6. 候補 F——価格を打ち回しに入れる（着手はユーザ指示により最後）

### 6.1 旧案が誤っていた点

旧 F は「**方針の価値で探索の事前分布をバイアスする**（決着 2 ターン以内の守りに限定）」。
3 点で誤っていた:

1. **層を間違えている**（と当時は考えた）——事前分布をいじるのは方策の手当てだが、
   観測された欠陥は価格の誤り＝評価の問題で、零和では評価が正しければ探索が拾う。
   → **2026-09-13 にこの前提が崩れた**（§4・後述）。
2. **しきい値で切っている**——「決着 2 ターン以内」も「ライフ 3」も、価格が状態とデッキの
   関数である以上（`game_theory.md` §11）**定数で切った時点で誤り**。これは**今も有効な指摘**。
3. **根拠が未確定**——`V_guard − V_take` は交絡で説明できる余地があった。
   → **2026-09-13 に解消**（§3.2 で符号検査を通した）。

### 6.2 2026-09-13 の測定で変わったこと

- **前提 1 は誤りだった**: 「評価が正しければ探索が拾う」は**事前分布が順序の情報を
  持っているときだけ**成り立つ。実測の `order_acc` は接戦帯で**コイン**で、
  PUCT は事前分布で枝を選ぶ＝**順序情報の無い事前分布は探索の入口を塞ぐ**。
  **したがって「方策に触るのは層の間違い」は成立しない**——価格は**方策の教師にも**入れる。
- **前提 3 は解消**（交絡は否定された）。
- **前提 2 はそのまま残る**（定数で切らない）。

### 6.3 渡す量は 3 つに確定している

| 渡すもの | 何か | どこから来るか |
|---|---|---|
| **`c(x)`** | 自デッキの費用曲線（x=1000…5000） | **対局前に**デッキから計算（`deck_profile.py` の算術） |
| **`Θ`** | 盤面の無差別点 | `λ/μ − 1 − τ_value`／`L`・`T`・`A`・`B` から |
| **`Δpressure(x)`** | 相手の費用曲線の**段** | 相手の未見プールから（公平性の規約の範囲内） |

**`Θ` だけでは足りない**——`Θ` は窓の判断にしか効かず、**自分のターンの「札の用途」を
決められない**（`game_theory.md` §14）。`Δpressure` が入って初めて
「7000 に積む」と「ドンを残す」が同じ台帳で比較できる。

**実装の段**（append-only・v13→v14 と同じ手続き）:
- **F-1**: `n_rel_feat` の列を**末尾へ追加**（v15）。Rust の `encode/scalars.rs` と Python を
  **同時に**直す（片方だけだと訓練と推論の入力がずれる）。
- **F-2**: 既存ネットを **warm-start**（0 埋めで読めるので退行しないところから始まる）。
- **F-3**: 判定は**高分解能アリーナ 2,800 ペア以上**＋3 波の holdout 行列。

**やらないこと**: ライフのしきい値・「決着 N ターン以内」の場合分け（定数で切る形）。

### 6.4 反証可能な予測（F が誤りなら何が起きるか）

1. **領域 2 の順序の誤り（47.9%）が減らない** → 価格は既に暗黙に学べていた＝列は情報を増やしていない。
2. 順序の誤りは減るのに**アリーナが動かない**（2,800 ペアで CI が 0 を含む）→
   価格の誤りは強さに効いていない＝残る差は探索側。
3. **`order_acc` が上がらない** → 価格は方策の順序の教師として機能しない＝設計の見直し。

## 8. 実装側の宿題

1. **`k̄_use` の符号**（`order_option.py` の腕を「札を攻めに使う／残す」に替える）＝
   **F の前に測るべき唯一の項目**。これで §5.2 の評価が決まる。
2. **`G*`（読まれたときの取り分）**＝相手席の `Q` を自分の各候補手で条件付けて引く
   （`pimc_diag` と同じ型・対局は要らない）。`lift ≈ 0` を予測器に依らず閉じられる。
3. **ドンの 3 つの検査**: (P1) 相手ターン中のアクティブなドンを**自ライフ別**に／
   (P2) 付与は段を跨ぐ時だけか（`Δpressure = 0` の過剰盛りの割合）／
   (P3) `don_idle` 2.32 と相手ターンのアクティブ 0.55〜0.68 の**1.7 個のずれ**は
   【起動メイン】のドンで説明できるか（できなければどちらかの計器が誤り）。
4. **順序の誤りの因果**——`order_acc` は探索の Q を正としているので、
   「方策が真に誤っている」かは反事実（順序だけ差し替えて打ち切る）でしか出ない。
5. **零和の残り**: 補助ヘッド無しの r7 を同じ seed 帯で測る（r10 悪化の切り分け・安い）／
   帯ごとの較正（盤面に依る偏りか）。
6. **接戦帯の分解**: option value の CI を半分にするには 150 局規模。
   融合 2% の損の大きさも同じ型の反事実で測れる。
7. **leaf correlation / disambiguation factor の数としての推定**（今は代理のみ）。
8. **`τ_value` の直接測定**（トリガーが出た／出なかったの反事実）。
