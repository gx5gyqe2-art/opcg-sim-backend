# 何を測っているのか（推定量の定式化）

2026-09-13 作成。ユーザ指摘「懸念を言語化して数式化して定量化できないか」への回答のうち、
**ゲームの中身ではなく測り方に関する部分**。ゲーム側の定式化は `docs/life_budget.md`。
過去にユーザから受けた指摘を、**それぞれ 1 つの量**として書く。量にすると
「どの測定なら結論を出せるか」「今の物差しで見える差はどこまでか」が先に分かる。

## 1. 「〜しないではなく〜できない」（2026-09-13）

観測される差を分解する。方針 p（守る）と q（受ける）について

```
Δ_obs = E[z | p が打たれた] − E[z | q が打たれた]
      = Δ_causal + Δ_selection
Δ_selection = E[z(q) | p が打たれた局面] − E[z(q) | q が打たれた局面]
```

`Δ_selection` は**局面の違い**（打ち手の違いではない）。**合法手で絞ると、選択の原因のうち
「できなかった」ぶんだけが消える**——残りは消えない。だから

- **帯・合法手で絞る**＝粗いマッチング＝`Δ_selection` の一部を落とす
- **共変量を増やしたときの `Δ_obs` の動き**が `Δ_selection` の大きさの推定になる
  （絞るほど縮むなら選択の寄与が大きい・動かないなら因果の寄与が大きい）
- **`Δ_selection = 0` を保証できるのは強制選択の A/B だけ**（同じ局面から両方を打たせる）

実測の例（`2026-09-13_can_or_wont.md`）: t≤2 の守りは 0.153 → 0.147（手段あり）→ 0.141（足りた）で
**ほぼ動かない**＝この共変量で説明できる選択の寄与は小さい。ただし `docs/life_budget.md` の予算を
共変量に入れると更に動きうる（**未測定**）。

## 2. 「どの方針が勝ちやすいかを教える」（2026-09-12）

「ブレると負ける」ではなく「この方針が勝ちやすい」を教えたい、という指摘は**目的関数の差し替え**。
測る量は**方針の後悔（regret）**:

```
A(s, p) = V(s, p) − max_q V(s, q)   ≤ 0
R = E_s[ −A(s, p_played) ] = E_s[ max_q V(s,q) − V(s, p_played) ]
```

`R` は**勝率の単位**で「打ち手の方針選択が損している量」。方針ヘッド（`plan_head`）の
`gap` がそのまま `R̂`。実測（`plan_head_r8`）: 全体 **0.033〜0.042**・
**両方リーサルの圏で 0.061〜0.084**。較正が ±0.05 以内なので、
**「方針の選び方で、効く局面では勝率 6〜8 点を落としている」**と読める。
`R` は反事実ではないが（V̂ の推定誤差と選択交絡が乗る）、**上限の目安**として使える。

## 3. 「離散・連続は時系列に対しての話」（2026-09-12）

V は盤面 1 つに勝率 1 個を返す＝**決着の時刻を潰している**。潰さない形は

```
P(win | s) = Σ_t P(T = t | s) · P(win | s, T = t)
```

`T` は決着までの自席ターン数。V はこの和を 1 つのスカラにしたもので、**分布 `P(T|s)` を持たない**。
時間軸ヘッドが持つのは平均 `E[T|s]` だけ（1 点）。

- 実測の分解能: 残差 **0.73 ターン**（定数予測は 1.79 ターン）＝**時刻のばらつきの 59% を説明**
- その 0.73 ターンが判断に効く量: 守りの利得は t≤2 で +0.153・t5+ で +0.001＝
  **1 ターンのずれで勝率 0.15 前後動く帯がある** → **時刻の誤差 0.73 ターンは勝率 0.1 級の不確かさ**
- ゆえに「時間を連続に扱う」の次の段は**ハザード `h(t|s) = P(T = t | 生存, s)` を出すこと**
  （平均ではなく分布・`pol_v0` を将来の行から引くブートストラップ版もこの形に入る）

**2026-09-13 実測（波 32・92,800 行・`tests/scripts/hazard_curve.py`）＝形は実在する**:
帯（自ライフ × 相手ライフ）ごとの `h(t)` の振れ幅は **0.26〜0.63**（全体 0.254・事前基準 0.3 を満たす）。
例（自ライフ 3・相手 4）: `p(T=t)` 0.008/0.183/0.337/0.269/0.131/0.073 に対し
`h(t)` 0.008/0.184/0.416/0.569/0.641/1.000。さらに**同じ帯の中で `P(win|T=t)` が大きく動く**
（自ライフ 4・相手 5 で T=2 の 0.121 → T≥6 の 0.527）＝上の分解は**実際に働いている**
＝**時間軸ヘッドが学ぶべきは平均 1 個ではなく `h(t)`**。`2026-09-13_readout_w32.md` §5。
（`all` は作りから一様なので読まない。）

## 4. 判定の分解能（192 ペアで世代交代を判断していた問題）

勝率 `w` と Elo の関係は `w = 1/(1 + 10^(−Elo/400))`。`w = 0.5` 近傍の傾きは
`dw/dElo = ln10 / 1600 ≈ 0.00144`。95% の分解能を `Δ` Elo にするのに要る**局数**は

```
1.96 · 0.5 / √N = 0.00144 · Δ      ⇒      N ≈ (680 / Δ)²   [局]
```

| 測定 | 局数 | 分解能 |
|---|---|---|
| 現行の昇格ゲート（8 帯 × 24 ペア） | 384 | **±35 Elo** |
| 高分解能アリーナ（2,800 ペア） | 5,600 | ±9 Elo |
| 世代差 5 Elo を見る | **18,500**（9,250 ペア） | ±5 Elo |

実測された世代差は **r5 vs r3 +3.5 Elo・r7 vs r5 −4.5 Elo**（どちらも 2,800 ペア）。
つまり**今作っている差は 5 Elo 級**で、**現行ゲートの分解能 ±35 Elo では原理的に見えない**
（必要な局数の比は `(35/5)² ≈ 48` 倍）。192 ペアの「+25.4」「+81」は
**この式から予想される大きさのノイズ**だった。

**結論（運用に直結）**: 昇格の可否を 192 ペアで決めるのは、**測れない差を測ったことにしている**。
取れる道は 3 つで、どれも定量的に言える:

1. **局数を増やす**（9,250 ペア＝約 33 セッション × 2 時間）
2. **効果量を大きくする**（5 Elo の改善を積むのをやめ、20 Elo 級の変更だけを測る＝N は 1,156 局）
3. **分散を減らす**（同一局面からの強制選択 A/B・共通乱数。同じ局面を使うので局面の分散が落ちる）

## 5. デッキ別のしきい値（2026-09-12）

「しきい値はリーダー＝デッキの中身で変わる。平均に強制するのは誤った学習」は、
**定数ではなく状態の関数**として書ける（導出は `docs/life_budget.md` §4）:

```
θ(deck, state) = A · T − B
```

`A`（相手の攻撃回数）・`T`（自分が決めるまでのターン数＝デッキの速さ）・`B`（ブロッカー）。
**群ごとに 1 つの数を当てる（平均でも個別でも）のが誤りで、行ごとに計算するのが正しい**。
「個別化すべきか」を統計で決める必要も無くなる（`Var_between(θ)` を測る話ではなくなる）。

## 6. 行動空間の被覆（「候補にすら無い」・ユーザ指摘 2026-08-12）

`cpu_v54_don_margin_20260812.md` の診断は**評価の誤りではなく候補生成の穴**だった:

```
coverage = P(強い打ち手の指す手 ∈ 候補集合)
```

実測（当時・Python エンジン・人間のリプレイ）: **ATTACH_DON で 36%**（58 手のうち候補に残るのは 21）。
**被覆が c なら、どれだけ評価と探索を良くしても上限は c で止まる**——ネットの世代も sims も無関係。
したがって不一致の診断は必ず 3 つに分解する:

| 区分 | 意味 | 手当て |
|---|---|---|
| (a) 候補に無い | 行動空間の穴 | 候補生成（枝刈りの規則） |
| (b) 候補にあるが事前分布が低い | 方策の学習 | 教材・訓練 |
| (c) 事前分布は高いが探索が上書き | 探索・価値 | sims・価値の較正 |

**(a) は他の 2 つで代替できない**（`cpu_v48_human_baseline_20260810.md` で (b)(c) と誤診した実例あり）。
**Rust エンジンの枝刈り（`prune_don_moves`／`prune_futile_attacks`）で被覆を測り直していない**＝未測定。

## 7. 「過去バージョンでは今の問題は検出できない」（ユーザ指摘 2026-08-15）

`gen16_negative_20260815.md`。1 局あたりの露出率 `p` の欠陥を `n` 局で見つける確率は

```
P(detect) = 1 − (1 − p)^n        ⇒   95% で見つけるには n ≈ 3 / p
```

| 検査 | 局数 | 見つけられる露出率 |
|---|---|---|
| golden replay | 200 | `p ≳ 1.5%` |
| `audit-cross`（交差対面） | 数百 | 同程度だが**通る経路が違う** |

**要点は n ではなく p**: ミラー対面では `p = 0` の経路がある（同じデッキ同士では起こらない状況）。
**`p = 0` の欠陥は局数をいくら増やしても検出確率 0**——これが「ミラー監査では一度も通らない経路に
しか出ない欠陥が 3 件実在した」（2026-08-16）の理由。基準が人間・過去世代・レフェリーである限り
**系統が揃って見落とす欠陥**には光が当たらない（処方＝オラクル不要の不変量監査）。

## 8. 較正は「決定に効く帯」で測る（ユーザ指摘 2026-08-13）

`holdout_ns2_20260813.md`。全体の較正誤差は**易しい局面に支配される**ので、決定に効く帯で測る:

```
ECE_band = E[ |V̂ − z| : |lethal_margin| ≤ 1, 両者ライフ ≥ 1, turn ≥ 5 ]
```

さらに**打ち手が使うのは V の絶対値ではなく兄弟手の順序**なので、本来の量は

```
order_acc = P( sign(V̂(a) − V̂(b)) = sign(V(a) − V(b)) )   （同じ局面の兄弟手 a, b）
```

**較正が完璧でも順序が壊れていれば打ち手は壊れる**（逆も真）。

**2026-09-13 実測（波 32・410,290 行・3,107,445 ペア・`tests/scripts/order_acc.py`）**:
方策の事前分布 `p` と探索の `Q` の順序一致は **接戦帯（|v0|≤0.2）で 0.5016＝コイン**
（mid 0.5014・decided 0.5279・全体 0.5158）＝**事前分布は「どちらの手が良いか」を
まったく並べられていない**。方策だけで打ったときに失う Q（`q_cost`）は接戦帯で **0.070** で、
独立に測った後悔（§2 の `R` = 0.033〜0.084）と**桁も範囲も一致**＝**後悔のほぼ全部が順序の誤り**。
方策のエントロピーは 1.89〜2.11 bit（候補 10〜13 本）＝平ら＝**情報が無いのではなく、
持っている情報が順序と無関係**。`order_acc(p,n)`（訪問との一致）は 0.74〜0.77 だが、
**訪問は事前分布から作られるので指標として弱い**（使わない）。

**この量の限界**: 探索の `Q` を正としている＝測っているのは「方策が探索に追いついていない」ことで、
「方策が真に誤っている」ことではない（後者は反事実が要る）。
`docs/reports/2026-09-13_readout_w32.md` §1。

## 9. 隠れ情報のサンプリング（serve は `worlds = 1`・生成は 4）

§7 の式は探索の中にもそのまま出る。PIMC は相手の手札を `worlds` 個引いて平均する。
「勝てる世界の割合 `p`」の線が 1 度でも当たる確率は

```
1 − (1 − p)^worlds       worlds=4 で  p=0.10 → 34%・p=0.25 → 68%・p=0.50 → 94%
```

**`worlds = 4` は「2 割の世界でしか勝てない線」を半分以上見落とす**。負け濃厚の局面で
必要なのはまさにその線（ユーザの「どちらにしろ負け濃厚なら最初から無茶をする」）なので、
**無茶ができない原因は評価ではなく世界の数**と読める。`worlds` を上げる費用は線形なので、
`worlds = 8／16` の効果は「その帯の勝率」で直接測れる（未測定）。

**ただし 4 は生成の設定であって、出荷エンジンの設定ではない**（2026-09-13 に確認）。
`SeatSpec.opts` は `{net, sims}` だけを積み、Rust の `DecideOptions::default()` は `worlds: 1`
＝**serve・アリーナは世界 1 本**。`worlds 4` は `record_gen --worlds 4`（波 29 以降）だけに付いている。

```
serve/アリーナ:  1 − (1−p)^1 = p        p=0.2 → 20%（8 割見落とす）
生成:            1 − (1−p)^4            p=0.2 → 59%
```

つまり**出荷エンジンは、教材を作った生成器より隠れ情報のサンプリングが粗い**。
この非対称は測定にも効く——アリーナで「世界を増やす」腕を測るときの基準席は 1 本であり、
2026-09-09 の R2（worlds 4 を `q_min_n`＋`root_prior_temp` と束で測った 191 ペア・0.5314）は
**世界数の効果を分離していない**。分離した 2 腕（4／8）の測定は台帳 §6 の帯 1031000〜1038000。

## 10. 昇格ゲートの副条件には検出力が無い（§4 の帰結・未提起）

規約の副条件は「固定ミラーで**退行なし**＝勝率の 95% CI 下限 ≥ 0.45」（ユーザ決定 2026-09-08）。
192 ペア＝384 局では 1 局あたりの標準誤差が `0.5/√384 = 0.0255`・CI の半幅が約 `0.050` なので、
**この条件は「観測勝率 ≥ 0.50」と同義**。真の勝率が 0.47（≈ −21 Elo の退行）でも

```
P(観測 ≥ 0.50 | 真 = 0.47) = P(Z ≥ (0.50−0.47)/0.0255) = P(Z ≥ 1.18) ≈ 12%
→ 退行を見逃す確率 88%
```

**副条件は −21 Elo の退行を 9 割近く通す**。主条件（wr ≥ 0.55 かつ CI 下限 > 0.50）も同じ分解能
（±35 Elo）なので、**ゲートの 2 条件はどちらも「今作っている 5 Elo 級の差」に対して無力**。

## 11. ならば何で選別するか（構造の提案・規約変更なのでユーザ決定）

同じ holdout 行での 3 波の行列（`n_rel_band --policy`）は**対応のある比較**で、
1 波 19,000〜32,000 行 → top1 の差の標準誤差は約 `0.0035`＝**0.005〜0.01 の差を判別できる**。
アリーナは 384 局で ±35 Elo。**つまり今のループは「安い方が分解能が高い」状態にある。**

これまでに**高分解能（2,800 ペア）で真の値が分かった点**は 2 つあり、行列の勝ち波数と並べると:

| 候補 | 行列（3 波のうち勝った数） | 高分解能アリーナ |
|---|---|---|
| r5 vs r3 | 2/3 | **+3.5 Elo** |
| r7 vs r5 | 0/3（事前基準では未達） | **−4.5 Elo** |
| r3 vs a1 | 3/3 | +81 Elo（**192 ペア＝当てにならない**） |

点が 2 つしか無いので関係式は引けないが、**向きは一致**している。提案する構造は:

1. **選別は 3 波の行列で行う**（安い・分解能が高い・同じ行で対応がある）
2. **アリーナは「行列で大きく勝った候補」だけに回し、そのときは 2,800 ペア以上**
3. **192 ペアの数字は判定に使わない**（記録には残すが、Elo として語らない）

これは規約（`CLAUDE.md` の「条件を 2 本以上測る」）の変更にあたるので**ユーザ決定が必要**。
放置した場合の費用は「5 Elo 級の改善／退行がどちらも見えないまま世代を重ねること」。

## 12. V が「手札を使った＝勝者の相貌」を学ぶ向きの偏り（ユーザ指摘 2026-07-30・コード注釈から発見）

`opcg_sim/learned/encoder.py` の v6（自手札の資源集約）の注釈:

> v5 までスカラーに載る手札情報は**枚数だけ**で、質（カウンター値・ブロッカー・イベント）は
> card_idx の埋め込み経由でしか見えなかった。その結果 value は**「手札が減った＝勝者の相貌」という
> 逆向きの相関**を学んでいた（遮蔽帰属: 手札枚数 +0.084・手札ID +0.165 が誤着を押し上げ）

**これは今の読み出しに直接効く交絡**。守るのは札を使う行為・受けるのは札が増える行為なので、
V が「札が減った＝勝ち」を（部分的にでも）学んでいるなら **V_guard − V_take は上振れする**。
今日の地図（`2026-09-13_time_plan_map.md`）と方針ヘッドの読み（`plan_head_r8`）は
**この偏りの検査をしていない**。

検査できる量（未測定）:

```
slope_V   = ∂V̂ / ∂(手札枚数)        （同じ盤面帯の中で・holdout）
slope_true = ∂P(win) / ∂(手札枚数)  （同じ帯の実測勝率の傾き）
```

`slope_V` と `slope_true` の**符号が違えば V は手札の価値を逆に学んでいる**。
NRel の入力は手札の質を持つ（トークンの `counter_value`・EXTRA の `guard_per_card`
`opp_pool_counter_total`）ので v5 当時より条件は良い。
勝敗（z）だけで訓練すると「勝つ側は札を使い切る」という相関は必ず入りうるため、
**方針の価値（V_guard − V_take）を打ち回しに使う前に必ず測るべき量**とした。

**2026-09-13 実測（波 32 の holdout・r3／r5／r10 の 3 本・`tests/scripts/hand_value_slope.py`）
＝交絡は否定された**。単位は勝率/枚:

| ネット | 席 | `slope_true` | `slope_V` | `dv_count`（モデル応答） | `dv_slot` |
|---|---|---|---|---|---|
| r3 | 自席 | +0.0433 | +0.0453 | +0.0331 | +0.0407 |
| r5 | 自席 | +0.0433 | +0.0412 | +0.0290 | +0.0310 |
| r10 | 自席 | +0.0433 | +0.0415 | +0.0278 | +0.0261 |
| r3 | 相手ターン | +0.0551 | +0.0483 | +0.0288 | +0.0303 |

**3 ネット × 両席すべてで符号が一致**（`sign_agrees.all = True`）＝v5 で実測された逆向きの相関は
**NRel では起きていない**＝**`V_guard − V_take`（+0.141）はこの偏りでは説明できない**＝
`2026-09-13_time_plan_map.md`／`can_or_wont.md` の結論と手当ての向きは**そのまま残る**。

**残るのは較正**（符号ではなく大きさ）: モデルの応答 0.026〜0.033 は実測の傾き 0.043 より
**25〜35% 小さい**＝1 枚の価値を過小に見ている。`dv_slot` は r3 0.041 → r5 0.031 → r10 0.026 と
**世代で鈍っている**（監視対象）。`2026-09-13_readout_w32.md` §2。

## 13. 搾取可能性の推定量（2026-09-13・理論は `game_theory.md` §3-4）

§9 までは「アリーナで測れる量」を扱ってきたが、**搾取可能性はアリーナでは測れない**
（両席が同じ固定方策＝適応する相手が居ない・§15）。推定量として書くと

```
e(σ) = max_τ u(τ, σ) − V*                 （定義・測れない）
G(f) = u_opp(br(f の予測)) − u_opp(br(事前分布))          （下限・予測器 f を積んだ相手を走らせる）
G*   = E_s[ max_a Q_opp(s, a | 私の手を知った) − Q_opp(s, br(知らない)) ]   （上限）
0 ≤ G(f) ≤ G* ≤ e(σ)
```

- **`G*` が本命**。「**完全に読まれても取れる量**」＝応手の感度で、**予測器に依らない**。
  私の各候補手で条件付けた相手席の `Q` の幅なので、**`pimc_diag` と同じ型の計器で読める**
  （エンジンの探索を 2 通り引くだけ・対局は要らない）。**`G*` が小さければ搾取は原理的に小さい**。
- **`G(f)` は「適応する相手」を作る測定**＝アリーナの構造を変える（相手席に予測器を積む）。
  2026-09-13 の `lift ≈ 0`（`policy_entropy`）は **`f` が弱いことしか言っていない**ので、
  「読まれない」を閉じるには `G*` を測る方が筋が良い。
- **`lift` と `G*` の積で読む**（診断のための分解・不等式ではない）:
  `G ≈ (読める量) × (応手が変わる量)`。第 1 因子が 0 なら結論は出るが、
  **より強い予測器の余地は第 1 因子の側に残る**。

> **理論の橋（検査可能）**: `G*` が小さいことと **PIMC が効く条件**（leaf correlation が高い＝
> 私の手が変わっても勝つ側が変わらない）は**同じ性質**。実測で `merged_novel` は決着帯 0.2%
> ＝相関は高い。**`G*` が大きいのに `lift ≈ 0` なら、この橋は誤り**。

## 14. 交絡のカタログ（読むとき必ず添える・旧 `game_theory.md` §19 から集約）

1. **V が手札を負に学ぶ向き**（v5 までの符号化で実測された）。守るのは札を使う行為なので
   `V_guard − V_take` は上振れしうる。→ **2026-09-13 に符号検査を通して否定**（§12）。
2. **決定に汚染された軸**: 「決着までのターン数の真値」で守りを割ると、受けた結果が軸に入る
   ＝**決める前の軸（予測）で割る**。
3. **ターン単位と攻撃単位**: 旧 take/guard ラベルは相手ターン 1 つの単位＝
   「2 回殴られて 1 回守り 1 回受けた」が潰れる。予算の式は**攻撃 1 回ごと**。
4. **上限として読むべき量**: 「守れた 92.6%／足りた 71.0%」はドンを見ていない上限
   （攻撃 1 回ごと・DON 補正後は 89.4%／64.7%）。
5. **浮動小数の丸め**: 符号化を戻すと 2000 が 2000.0002 になり、**ちょうど 1000 の倍数の閾値が
   1 段上がる**＝枚数が系統的に +1 される（計器は `PWR_EPS = 10` で吸収）。
   **2026-09-14 までに 4 回踏んでいる**（f16 の上振れ・f32 の下振れ 0.7×1e4 = 6999.999 など）。
   **`1e4` を掛けて戻す量は必ず 10 の単位に丸める**（`_round10`）——**毎回別の器で踏むので、
   新しい器でパワーを復元したら最初に丸めを書く**。
6. **勝者の呪い**（2026-09-13 追加）: 複数の腕の最大と「打った腕」を比べると、
   **腕が全部同じ強さでも max は上に出る**。反事実の計器では
   **A で選び B で測る**（選択と評価を別の標本で行う）＋**雑音の下限を併記**する。
7. **対局でクラスタしていない SE**（同 2026-09-13）: 1 局から複数の点を採る測定で
   点の数で割ると SE を数倍過小に見る（零和・option value の両方で踏んだ）。
8. **母数を結論で条件付ける**（2026-09-13 に踏んだ・**符号が反転した**）: 「理論と探索が
   食い違った行だけ」で理論の損を測り、比較する無作為の基準を条件付けないと、
   **理論の損は定義上正になる**（−0.51 → +0.32 と符号が変わった）。
   **判定可能な全行を主の母数にし、条件付けた方は「偏っている」と明記して副次に置く**。
9. **印字パワーと現在パワーは別物**（2026-09-14）: `scalars` の場の集約は**印字パワー**なので
   **付与ドンと強化が見えない**。超過パワーの話をするなら**トークンの `power_now`**（列 0）を見る。
   ——「パワーの軸が通貨に無い」ことに気付くのが 1 日遅れた原因。
10. **「体を持つか」はパワーでは判別できない**（2026-09-14・**符号が反転した**）:
    ステージとイベントは**パワー 0** なので最弱帯に混ざり、体を持たないのに
    `(Δ自場 − 1)·ν` を引かれて利得の符号を変えた（−0.0016 → +0.0125）。
    **カードの種類は種類の欄で分ける**（`Cards.info` の `stage`／`event`）。
11. **テストがバグを守っていることがある**（2026-09-14・**今週 3 本**）:
    直した器の**期待値をテストが固定していた**ので、直すとテストが落ちる＝
    「テストが赤いから元に戻す」と**バグへ戻る**。実例:
    (a) `don_idle == 6 − 1 − 4`（付与が抜ける再構成を固定）、
    (b) `entry_gain` の要る額 0.0290（ステージを外す前の値）、
    (c) `saturation_x(0.8) == 1000` と `saturation_x(10.0) == 5000`（`x=0` を候補にせず端で頭打ち）。
    **共通点は「計算の結果を写しただけ」のテスト**である。
    **定義そのものをラチェットする**と防げる——`saturation_x` なら
    「返した `x` で足り、1000 手前では足りない」を書く（値を書かない）。
12. **器を直したのに定数が古いまま**（2026-09-14 に 2 回踏んだ）: ステージを外して
    「要る額」が 0.0290 → 0.0318 に動いたのに既定を直さず**充足率を高く出していた**（0.43 対 0.39）。
    もう 1 件は**「記録に無い」という思い込み**——`don_k` は最初から `pol_k` に在ったのに
    「無い」と報告し、既定 1 を入れて**k=0 の攻撃 58% に幻のパワーを足していた**。
    **「無い」と書く前に列を数える**。
13. **黙って空を返す器**（2026-09-14）: 必要な列を渡さずに呼び、`except Exception` が
    `KeyError` を飲んで**0 件の結果を正常に見せた**。**前提が欠けたら例外を上げる**
    （`except` は上げたい型だけに絞る）。
14. **巨視手は中の原始手を隠す**（2026-09-14・**この engine では 3 度踏んだ**）:
    `DON_BOX` は「k 個ドンを乗せてから T を殴る」を束ねた 1 手なので、
    **`ATTACK` も `ATTACH_DON` も「選ばれた手」として記録に現れない**
    （300 局 約 1.9 万手で 0 件）。踏んだ 3 件:
    (a) 攻撃を `ATTACH` の式で値付けしていた＝候補の 44% が誤った価格（1b の数字が無効）。
    (b) `don_k` は `pol_k` に在ったのに「記録に無い」と報告し、既定 1 で**幻のパワー**を足した。
    (c) `don_idle = don − ATTACH_DON の行数 − PLAY のコスト` が**付与を丸ごと落とし**、
    余りを 4 倍（2.07 対 真値 0.51）に見せた——**「ドンを余らせている」という診断が消えた**。
    **対策は 1 つ**: **状態が答えを持っているものを、行動の再構成で出さない**
    （余ったドンは「最後の main 行のアクティブなドン」を読めばよい）。
    再構成が避けられないときは**恒等式で閉じるか確かめる**
    （`don = 付与 + コスト + 余り` の残差を必ず出す）。
15. **比の統計量には必ず CI を付ける**（2026-09-14・**差を読み違えた**）:
    `q_recovered = 1 − 損/無作為の損` のような**2 つの小さな平均の比**は、分母・分子の
    両方に雑音が乗るので**驚くほど動く**。実測で**同じ設定・同じ帯**が局の部分集合で
    **0.17／0.20／0.31** と出た——**設定の差（0.27 対 0.31）より標本の振れ幅の方が大きい**。
    それを「`board` は接戦帯で悪化する」と読んで報告し、後から撤回した。
    **気付き方**: **変えた行が 2% しかないのに指標が 13% 動いたら、まず雑音を疑う**
    （母数の入れ替わりでないことも確かめる）。
    **対策**: 比は**局を復元抽出して作り直す**（`_recovered_ci`）。
    なお**比のブートストラップ分布は歪む**ので、点推定が自分の CI の外に出ることがある
    ——そのときは**CI の側を読む**。
16. **自由度が足りない「勘定」は検定ではない**（2026-09-14・**方法についての発見**）:
    制約が 3 本しかないのに動かせる量が 3 つ以上あると、**足す項を選べば必ず勘定は閉じる**。
    実際、正当な項を 1 つ足しただけで 2 帯が要る額を**超えた**（1.39 倍・2.05 倍）。
    **「閉じた」を成果として読む前に、閉じない構成が在り得るかを数える**
    （在り得なければその測定は反証力を持たない）。

## 15. 自己対戦アリーナが原理的に測れないもの（旧 `game_theory.md` §21）

両席が**同じ固定方策**なので、次は測れない:

1. **読まれやすさ（搾取可能性）**——適応する相手が居ない（§13 の `G(f)`／`G*` で代替する）。
2. **混合の価値**——決定論同士では混合の利得が出ない。
3. **人間の打ち筋に対する頑健さ**——人間は分布の外側を打つ。

**含意**: 「アリーナで差が出ない」は「強さが同じ」ではなく「**この物差しでは同じ**」。
人間相手の実用性は別の測定（読まれやすさ・実デッキでの挙動）で押さえる必要がある。
