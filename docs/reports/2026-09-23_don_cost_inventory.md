# T150a: ドン費用を払っている型と払っていない型の棚卸し（2026-09-23）

T147a（`2026-09-23_attach_delta.md`）は、付与の借りた攻撃価格に `k·DELTA`（定額）を引くと悪化すると
分かった。原因は「比較相手（攻撃候補自身・出す手・効果）が同じ費用を払っていない」ことだった。
本 T はコードを読むだけで、型ごとにドンの機会費用を払っているかを表にする。式は書かない・測らない
（ユーザ指示「両方とも追いましょうか」の束 1・1 番目）。

---

## 0. 結論（先に書く）

**払っている型と払っていない型がはっきり分かれ、かつ払っている型（`PLAY`）は既に定額の `δ` ではなく
盤面依存の機会費用を使っている。** T147a の「定額 `δ` を引く」という直し方は、既存の機構と比べても
粗すぎた。

| 型 | ドンを使うか | 機会費用を払うか | 使う関数 |
|---|---|---|---|
| `ATTACK`／`DON_BOX`（対象あり・k 枚付けて殴る） | 使う（k 枚） | **払わない** | `attack_value(sp+1000k, tp)`（`score_candidate`） |
| `DON_BOX`／`ATTACH_DON`（対象なし・純付与） | 使う（k 枚） | **払わない** | `attach_value(sp, olp, k)`（増分のみ） |
| `PLAY`（キャラ・イベント） | 使う（`cost` 枚） | **払う**（盤面依存） | `play_cost_term` → `don_opportunity` → `_attach_total`（既定 `PLAY_COST_MODE=state`） |
| `ACTIVATE_MAIN` | 使わない（この規則では起動コストにドンを要らない） | （対象外） | `_effect_value(cid, "activate", ...)` |
| `nu_of` の体の潜在価値（Θ・PLAY の `ν` の内部） | 予定として最適化 | **払う**（`max_k` の中で） | `attack_value_don`（`nu_of` の内部だけ） |

## 1. `PLAY` が既に持っている、正しい形の機会費用

`play_cost_term(ctx, cost, mu, theta)`（既定 `PLAY_COST_MODE="state"`）は、**定額の `δ` ではなく**
`don_opportunity(attackers_x, don_active, cost)` を呼ぶ——「このコストを払わなければ、余ったドンを
自分の攻撃手に**貪欲に配ったときの攻撃価値の増分**」（`_attach_total`）を、**実際の盤面**
（今の攻撃手の一覧・今のアクティブなドンの枚数）から計算する。定額の `DELTA`（T57・0.0277）は
**この関数を通らない別の場所**（`nu_of` の中の `attack_value_don`）でだけ使われている。

**T147a の誤りが具体的になった**——付与の借りた価格に `k·DELTA`（定額）を引いたのは、`PLAY` が
既に持っている「盤面依存の機会費用」という正しい形を無視して、`nu_of` 用の定額の近似を持ち込んだ
ことだった。**攻撃・付与にドンの機会費用を入れるなら、`don_opportunity`／`_attach_total` を
再利用するのが筋が通っている**（新しい定数ゼロ・既存の関数の再利用）。

## 2. `ATTACK`／`DON_BOX`（対象あり）が機会費用を払わない具体的な場所

`score_candidate`（`theory_order.py` 1289〜1294 行）:

```python
if at == "ATTACK" or (at == "DON_BOX" and has_target):
    if at == "DON_BOX":
        sp += 1000.0 * k                 # パワーは上がるが、k 枚の機会費用は引かれない
    ...
    return attack_value(sp, ctx["opp_leader_power"], True, theta, mu, blockers=blockers)
```

**`attack_value_don`（`max_k[attack_value(+1000k) − k·δ]`）は呼ばれていない**——`attack_value_don`
の呼び出しは `theory_order.py` に 4 箇所あり、全て `nu_of` の内部（T147a で確認済み）。

## 3. 純付与（対象なし）の欠落

`attach_value(power, target_power, k, theta, mu)` は `c(x+1000k) − c(x)` の**増分**だけを返し、
k 枚の機会費用は最初から式に無い（T141 以来の単位ミスマッチの根）。`don_opportunity` を通していない
点は `ATTACK`／`DON_BOX` と同じ。

## 4. 二重計上の懸念（帳簿側・T58/T85/T109〜T114 との切り分け）

T85（`2026-09-18_attach_once.md`）・T109〜T114 は**帳簿**（`ΔG`・実際に記録された `+1000k` の
出現回数）が付与と攻撃で同じ増分を 2 回数えていないかを扱った——これは**記録された増分の集計**の
問題で、**本 T が見ている `score_candidate` 内の 1 候補の価格**とは別の層である。T58 の分離
（「決める価格 `s` は増分のまま・帳簿 `ΔG` は `exercise` の規約」）に従えば、**本 T の変更（`s` の
価格に機会費用を入れる）は帳簿の集計を変えない**——ただし T150b で実際に触るときに、`s` にだけ
効かせるか帳簿にも及ぼすかは選択肢として残し、ユーザ判断に出す（T150e）。

## 5. 【ドン!!×N】との切り分け

T73/T74 の「N・δ/R」（条件付けの価格・`search_ctx` を渡す計画価値の内部）は、**まだ条件が満たされて
いない将来の可能性**を割引く別の機構で、**本 T が見ている「今この候補が使う k 枚」の機会費用とは
別物**（探す能力の計画価格の内部で使われる・`score_candidate` の `ATTACK`／`DON_BOX` 分岐とは別の
経路）。混同しないよう名前を分けて扱う。

## 6. T150b への申し送り

* **`don_opportunity`／`_attach_total` を再利用する**（新しい定数ゼロ）——定額 `DELTA` の代わりに、
  盤面の実際の攻撃手一覧（`ctx["attackers"]`）と今のアクティブなドン（`ctx["don_active"]`）から
  機会費用を計算する。
* **対象は `ATTACK`／`DON_BOX`（対象あり・k>0）と純付与の両方**——どちらも今は機会費用ゼロ。
* **k=0 の攻撃は変わらない**（機会費用も 0）——予告の 1 つになる。
* **`s`（決める価格）にだけ効かせ、帳簿（`ΔG`）には及ぼさない**ことを既定案とする（T58 の分離を
  保つ）——ただし選択肢として持ち、ユーザ判断（T150e）に残す。

## 7. 上手くいったこと／いかなかったこと

**上手くいった**:
* **T147a が見つけた欠落の正しい直し方が、コードを読むだけで既に見つかっていた**（`don_opportunity`
  ／`_attach_total`）——新しい仕組みを考える必要が無かった。
* **帳簿側（T85/T109〜114）との層の違いをはっきりさせ、混同を避けた。**

**いかなかった**:
* **`ACTIVATE_MAIN` がドンを使わないという前提は、規則を熟読して確かめてはいない**（本 T の対象外の
  カード個別の効果でドンを要求するものが無いかは、T150b の実測で異常が出れば疑う）。
