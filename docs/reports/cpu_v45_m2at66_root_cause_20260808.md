# v45 m2@66 の原因特定 — 「打ち切り」ではなく「リーダーで最初に殴るか」だった（2026-08-08）

m2@66 は gen9〜gen13 のどの世代でも 0.62〜0.69 から動かなかった唯一の常時未達点。
本文書はその原因を計器で特定した記録（この時点のスナップショット・追記改変しない）。
計器は `tests/scripts/turn_exhaust_probe.py`（v45 新設）。

## 0. 結論

**value でも policy でもない。ply0 でリーダー攻撃を選ぶかどうかの一点に還元される。**

| 最初の攻撃 | 4/4 達成 | 未達 |
|---|---|---|
| **OP11-041（自リーダー）** | **11回** | 0回 |
| EB03-055（ナミ） | 0回 | **5回** |

16seed で**例外ゼロの完全分離**（Fisher 正確検定 p ≈ 0.00023）。
0.62〜0.69 という数字は「実力の6〜7割」ではなく、**ply0 でリーダー攻撃を選ぶ確率**そのものだった。

## 1. まず否定されたこと

着手前の仮説は「ネットが攻撃後の盤面を悪く見て早めにターンを畳む」（value）または
「policy が TURN_END に厚い prior を置く」（prior）だった。**どちらも外れ**。

```
消化率 11/16 = 0.69（コーチゲートの turn_all_rate と一致）
未消化5件の内訳: 選べたのに選ばなかった 0件 ／ 枝刈りで除外 5件 ／ ルール上打てない 0件
```

**16seed すべてで TURN_END は唯一の合法手**（prior=1.0・visit%=100・合法手1件）。CPU は一度も
「まだやれるのに畳む」判断をしていない。**やれることを全部やってから終えている**。
未消化の中身は常に `('ATTACK','OP11-041')`＝リーダー攻撃だけだった。

計器の設計上の要点はここにある——prior と Q を見る前に**その時点の合法手集合**を残すこと。
それが無ければ「TURN_END の Q が最高だった」だけを見て value の問題と誤診していた
（TURN_END の平均 Q は −0.41 で、確かに一番高い。だが他に候補が無いのだから当然である）。

## 2. 何が起きているか（リーダー攻撃力の推移・失敗した seed3）

```
開始 7000
  自 ACTIVATE_MAIN(Mr.3 OP16-056) → 7000
  自 ATTACK EB03-055              → 7000
  相 （防御時の効果解決）           → 6000    ← シャンクスの −1000
  相 SELECT_COUNTER OP10-018      → 6000
  相 （その後の効果解決）           → 4000    ← カマクラ十草紙の −2000
  相 PASS                         → 4000
  自 ATTACK EB03-053              → 4000
  → TURN_END（リーダー攻撃は枝刈りで消滅・3/4）
```

打ち切り時点の盤面: 自リーダー攻撃力 **4000**／攻撃可能な標的は相手リーダー 7000・
**レスト状態の** 6000 と 9000 のみ（2000 と 10000 はアクティブで攻撃対象外）。
どれにも届かず、攻撃してもリーダーをレストにするだけ＝`_prune_futile_attacks` が正しく落とす。

成功した seed0 は**最初の攻撃がリーダー自身**で、7000 のうちに殴り切っている。

## 3. 原因カード（テキスト確認済み）

- **OP09-001 シャンクス（相手リーダー）**: 【ターン1回】相手がアタックした時、発動できる。
  相手のリーダーかキャラ1枚までを、**このターン中**、パワー−1000。
- **OP10-018 カマクラ十草紙（カウンターイベント）**: 【カウンター】自分のリーダーかキャラ1枚までを、
  このバトル中、パワー+3000。その後、相手のリーダーかキャラ1枚までを、**このターン中**、パワー−2000。

**どちらも対象を相手が選ぶ効果で、相手は両方ともこちらのリーダーに集中させている。**
合計 −3000 が**ターン終了まで残る**（「このバトル中」ではない）。エンジンも枝刈りも正しく、
相手の防御が的確なだけである。

## 4. 裁定との食い違い（要ユーザ判断）

現行の裁定（2026-08-05）は次の理由づけで「初手はどれでも良い・合格は4件の消化で測る」としている。

> 盤面の機構（相手リーダー シャンクスの【ターン1回】相手アタック時 −1000）が「どの攻撃を
> 不発にするか」の択一を相手に迫るため**攻撃の順序はほぼ等価**

**この理由づけは事実と食い違う**。裁定時に勘定されていないものが3つある。

1. カウンターイベント OP10-018 による**2つ目の −2000**（シャンクスの −1000 だけを見ている）
2. どちらも **「このターン中」で永続**すること（1回の攻撃を不発にして終わりではない）
3. 相手が両方とも**リーダーに集中**させ、リーダーの攻撃手段を恒久的に奪うこと

結果として**順序はリーダー攻撃の可否そのものを決めており、等価ではない**。正しい戦術ルールは
**「リーダーで最初に殴る」**。

ただし裁定の**結論**（4件すべて消化）が達成不能なわけではない——11/16 で達成できている。
変わるのは「何を教えるべきか」であり、それは ply0 の1手に還元される。

## 5. 注意: 直しても勝率に効くとは限らない

同じ裁定コメントに、レフェリー32世界（def_temp0.7）で**攻撃同士の z 差は全てノイズ幅
（2σ≈0.35）内**だったと記録されている（ロビン→ヤソップ −0.125 〜 ナミ→ヤソップ −0.562）。
つまり「4件消化するか3件で終わるか」の**勝率差は測定限界以下**の可能性がある。

ゲートの点は 0.69→1.00 に動かせても、アリーナでは何も動かない——v44 でプラン読み出しについて
確認したのと同じ構図。**着手前に「この1点を取ると勝率がいくら動くか」をレフェリーで測る**のが、
v44 の教訓の正しい適用である。

   （`verified_inject_gen.py`）の枠組みにそのまま乗る。`exit_head_probe` でも判定可能になる。

   注入教師は作れず（単一 root 手で採点できない）、教える対象は結局 ply0 の1手。

いずれにせよ §5 の勝率測定を先に行う。
