# 分岐点シナリオの分析 #3: 「イベントを打たない」の正体は合法手の穴だった（2026-09-08・r3／a1・計画 §8.26・§20）

分析 #2（`2026-09-08_scenario_analysis_02.md`）の「次にやること 1」＝**イベント PLAY の訪問割合を測って
方策の事前分布か価値かを切り分ける**、の結果。測ろうとして**測る対象が無い**ことが分かり、エンジンの
不具合として直し、9 シナリオを回し直した。判定はユーザ、分析は Claude。

## 結論（先に）

1. **Rust 化後の CPU は【メイン】イベントを一度も打てなかった**。`rules/legal.rs` が全イベントを合法手
   （PLAY）から外していたため（P2 移植時の読み違い・Python 版は「【メイン】効果を持たないイベントだけ
   除外」）。探索の候補は同じ列挙を使うので、**除去・ドロー・パンプのイベントは探索の対象にすら
   なっていなかった**。人間はフロントから `PLAY` を直接送るので打てる＝気付かない経路。訓練データ
   （波 23〜28）は Python 時代の生成なので無傷。分析 #2 の「探索が触っていない」という読みは
   **原因の取り違え**（合法手に無かった）。修正: `legal.rs` を `play_card_action` と同じ判定に 1 本化
   （`tests/test_main_event_legal.py`・`make test` 449 passed・`make audit-cross` void 0／240 局・
   wr 0.5125）。計画 §8.26。
2. **修正後、イベントは普通に探索され、打たれる**。9 シナリオ × r3／a1 × 2 seed の seat 側 MAIN 決定
   （r3 122・a1 124 件）で、イベント PLAY が合法な決定は 8 割、そのうち訪問 0 の手は 13〜14%
   だけ（キャラ PLAY は 45%）。決定ごとの訪問割合の平均はイベント 15〜17%（キャラ 19〜21%・
   攻撃／ドン!! 61〜62%）。**事前分布 P はイベントもキャラも同水準**（平均 0.07）。
3. **ただし除去イベントの事前分布は低い**。ガンマナイフ P 0.015（a1）／0.031（r3）・ゴムゴムの雷
   0.013／0.029 に対し、放電 0.10／0.08・雷龍 0.16／0.20・神の裁き 0.08・万雷 0.08。**ネットは
   「ドロー・パンプのイベント」を好み「除去イベント」を嫌う**。修正後の 36 本でも、ガンマナイフ・
   ゴムゴムの雷・万雷（メイン）は 1 度も打たれなかった（放電 5 回・雷龍 1 回・神の裁き 4 回）。
   これが分析 #2 で「除去を打たない」と見えたものの、**エンジン修正後に残る本物の傾向**。
4. 生成データ（Python 時代・波 28 w01・569 局・a1・sims 128・Dirichlet 0.25）でも同じ傾向:
   MAIN 決定 47,828 件のうちイベント PLAY が合法 30.7%・その決定でのイベント訪問割合 6.6%・選ばれた
   のは 5.5%（キャラ PLAY は 17.0%・18.4%）。ターン別では T1〜2 で 35〜39%（安いドロー）、T5 以降は
   3〜10%。イベント別上位はドロー／サーチ系で、除去系は下位。**訓練データの π 自体が除去イベントに薄い**
   ＝自己強化されている。
5. 副産物で見つかった別の欠陥（未修正・§8.27）: **効果の対象選択が「対象なし」で解決される**ことがある。
   万雷を【カウンター】で使うと +1000 の対象が空（`BUFF targets []`）＝カウンター値 0 で捨てただけ、
   神の裁きの KO 対象が空（1c ルフィが選べたのに）。既定解決 `default_interaction_payload` の
   ゾーン意味論（自分側の候補は「コスト系」として min 件＝0 件を選ぶ・Python 由来）が、自分への
   パンプに当たると「何も選ばない」になる。探索の窓／コミット経路（枝の中の対話は既定解決）で起きる。
   修正候補は「BUFF 等の利益系は max 件」だが、効果の種別を既定解決に渡す設計が要る。

## 4. 分岐点シナリオという道具について

- **今回の発見は道具の目的（定性の目視）から出た**。数値の物差し（アリーナ・評価帯・人間一致率）は
  全部この穴の上で回っていて、何も言わなかった。両者が同じ制約で打つ比較（r3 vs a1）には現れない
  種類の欠陥＝**人間の手と比べる道具にしか見えない**。
- 再生 golden（200 局）は `--decks singleton`（イベント 0 枚の 50 種構築）で作られているため、
  イベント PLAY の合法性を一度も通っていない（手札にイベントが来た歩 0／20,169）。修正後も
  golden は不変で通った＝**golden はイベントを守っていない**。作り直しを synth デッキで行うかは
  ユーザ判断（§16.3-10 のとおり差分レビュー込み）。
- 道具への要望（分析 #1・#2 の分は据え置き）: 追加で「効果の対象選択で**対象なしで解決した**手に印」
  （§8.27 の検出用）。

## 5. 次にやること（提案・優先順）

1. **§8.27（対象なし解決）を直す**。カウンター万雷・神の裁きが機能していない＝実プレイの CPU の
   防御力・除去がそのぶん落ちている。既定解決に「効果の種別（利益／コスト）」を渡すか、探索の枝で
   対話を既定解決せず 1 段だけ分岐する。
2. **除去イベントの事前分布が低い理由**を評価帯で切る: 波 28 で「除去イベントが合法で打たれなかった
   決定」の Q（打った枝 vs 打たない枝）を比べ、価値が除去後の盤面を低く見ているのか、π の自己強化かを
   分ける。前者なら符号化（相手キャラの将来価値）、後者なら生成側の探索ノイズ（除去イベントに
   Dirichlet を厚く）か人間ログの π 教師。
3. era7（r3 生成）の波 29 は**この修正の後に**回す（修正前に回すとイベントを打たない教材になる）。
4. r3 vs a1 のアリーナはこの修正で数字が変わりうる（両者ともイベントを打つようになる）。採用は維持
   するが、次の世代交代（r4）の比較はこのコードで測る。
