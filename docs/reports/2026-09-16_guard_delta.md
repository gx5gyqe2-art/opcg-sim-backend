# T62——守りの窓の `g` を「攻め手の価格 − 払った額」に（同じ移転を 1 回だけ数える）。橋は実 0.678 → 0.728・合成 0.672 → 0.663、守り側は両記録で上がるが反対向きのまま＝残りは「受ける費用がライフ水準で変わる」

本報告は特定時点のスナップショット。器は `theory_bridge.py`（`GUARD_G_MODE`・`grd_by_life`）。`SURV_MODE=geo`・`CBAR_MODE=strict`・`ΔG` は `exercise`。

## 結論を 5 行で

1. **定義**: 零和なので、攻撃という移転は攻め手の行で 1 回だけ数える（`g = 価格 = min(c(x)·μ, Θ·μ)`）。受け手の行には**見積もりとの差分**
   `価格 − 払った額` だけを載せる（最安の応答なら 0・高い方を選べば負・払えずに受けた行も差分）。旧形 `−払った額` は同じ移転を
   両席で二重に数え、**払える席ほど損に見えていた**。
2. **橋（`ΔG`）**: 実 **0.678 → 0.728**・合成 0.672 → 0.663。守り側だけ見ると **0.243 → 0.279／0.359 → 0.401**＝両記録で上がるが
   **まだ 0.5 を割る**（「守りの窓で見積もりより多く払う席ほど勝つ」のまま）。攻め側・`ΔS` は定義上不変。
3. **残りの正体は受ける費用の水準**: 自ライフごとに見ると、理論は**ライフ 1〜3 で 87〜99% 「受けろ」**と言うが実際は 58〜80% しか受けず
   （低ライフでは受けられない）、**ライフ 4〜5 では理論 46〜72% に対し実際 51〜58% が受ける**（高ライフでは受けるのが安い）。
   受ける費用 `Θ·μ` は定数（λ の平均）で、**T19 が測った「λ はライフが減るほど高い（λ(2) 0.218 対 λ(4) 0.078）」を使っていない**。
4. 勝つ席（ライフが多い側）は安い攻撃を受けて札を温存する。定数 Θ はそれを「守るべきだった」と数えるので、勝つ席ほど `g` が負になる。
   これが守り側の反対向きの残りで、`g` の定義ではなく**受ける費用のライフ依存**の問題。
5. **`delta` を既定にする**（理論の側で決められる定義の訂正・実デッキで +0.05）。次は受ける費用を `λ(L) − h·μ`（T19 の実測）にすること。

## 3. 読み方

- **定義の訂正は正しい向きに効いた**（守り側は両記録で改善・実デッキの `ΔG` は 0.05 上がる）。合成の全体が 0.01 下がるのは、`paid` の
  二重計上が合成では偶然「席の資源」を写していた分が消えたため（`delta` の守り側 0.401 の方が定義として筋）。
- **残る反対向きはライフ依存**。`Θ` は「受ける費用の平均」で、ライフが少ないほど高く多いほど安い（T19）。定数のままだと、
  低ライフで守る席を「払い過ぎ」・高ライフで受ける席を「守るべきだった」と数え、後者が勝つ席なので `g` と勝敗が逆に結びつく。
- 記録の拡張（P8・窓に来た攻撃の一覧）の前に、**受ける費用のライフ依存**を式に入れる方が先（理論の側で決められる）。
