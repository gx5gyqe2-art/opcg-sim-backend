# 身代わり率は攻撃側の誤りで水増しされていないか——**逆だった。CPU はキャラを殴らなさすぎる**

2026-09-14 実施・判定（ユーザ指摘「身代わりが有効な攻撃を吸っているケースでも、攻撃する側が
相手の低パワーキャラクターの価値を誤っていた場合は、身代わりに攻撃する必要がないはずなのに
攻撃してしまっている場合もあると思います」）。同じ 300 局・攻撃 6,426 本。
本報告は特定時点のスナップショット（追記・改変しない）。

## 結論を 3 行で

1. **指摘は妥当**——身代わり率は**自己対戦の攻撃判断から出ている**ので、
   攻撃側が誤って弱いキャラを殴れば、その誤りが「身代わりの価値」に化ける。
   **`shield_rate.py` の妥当性そのものへの指摘**である。
2. **測ったら逆だった**。キャラ狙いのうち誤りは **7.1%** だが、
   **リーダー狙いのうち 57.5% は「キャラを殴るべきだった」**＝
   **CPU はキャラを殴りすぎではなく、殴らなさすぎ**。身代わり項は**過大ではなく過小**。
3. **ただし判定は `Θ` に強く依る**（1.15 で 3.13 倍・5.00 で 1.22 倍）。
   **向きだけが全ての `Θ` で揃う**ので、**主張できるのは向きだけ**である。

## 1. 何を測ったか

攻撃 1 本ごとに、**同じ体で**「リーダーを殴る」と「盤面のキャラを殴る」を値付けして比べた:

```
リーダー狙い  vL = min( c(x_lead)·μ , Θ·μ )          x_lead = 実効パワー − 守る側のリーダー
キャラ狙い    vC = min( c(x_char)·μ , ν(対象の帯) )    ν は **実測値**
```

**`ν` は実測（帯別 0.0690／0.1503／0.2112）を使う**——式の `ν` はこの帯で 0 なので、
式で判定すると「キャラ狙いは常に誤り」という自明な答えしか出ない。

- **キャラを殴ったのに `vL > vC`** → 殴る必要が無かった＝**身代わり率の水増し**（ユーザ指摘の形）
- **リーダーを殴ったのに `max_T vC > vL`** → 殴るべきキャラが居た＝**率は過小**

## 2. 実測——**水増しではなく取り逃がし**

| `Θ` | キャラ狙いの誤り | リーダー狙いの誤り | **最適な吸収 / 観測** |
|---|---|---|---|
| **1.15**（出荷既定） | **0.071** | **0.575** | **3.13** |
| 1.62 | 0.397 | 0.209 | 1.40 |
| 2.64（実測のライフ 0） | 0.410 | 0.196 | 1.34 |
| 5.00 | 0.432 | 0.170 | 1.22 |

**どの `Θ` でも「最適な吸収 / 観測」が 1 を超える**＝
**理論どおりに対象を選べば、キャラへの攻撃は今より 1.2〜3.1 倍起きる**。

> **ユーザ指摘の向き（水増し）は、どの設定でも支持されなかった。**
> 身代わり項 0.0597 は**過大ではなく、むしろ過小**の側にある。

**誤り 1 本あたりの大きさ**は両方向とも小さい（キャラ狙いの誤り 0.0173 の損・
リーダー狙いの誤り 0.0162 の逸失＝どちらも `Θ·μ` = 0.063 の 4 分の 1 程度）。

## 3. **この検定の限界が主結果より重い**

### 3.1 定数 `Θ` が壊れている証拠がそのまま出た

既定の `Θ = 1.15` で**守る側のライフ別**に割ると:

| 守る側ライフ | リーダー狙いの誤り | 本数 |
|---|---|---|
| **0** | **0.779** | 488 |
| 1 | 0.694 | 760 |
| 2 | 0.651 | 1,014 |
| 3 | 0.597 | 1,347 |
| 4 | 0.470 | 1,695 |
| 5 | 0.414 | 1,069 |

**ライフ 0 で「リーダー狙いの 77.9% が誤り」は明らかにおかしい**——
**次の一撃で倒せる場面でリーダーを殴るのが誤りのはずがない**。
これは CPU の誤りではなく **`Θ` を定数にしていることの誤り**である
（実測の `Θ` はライフ 4 で 0.31・ライフ 0 で **2.64**＝**8 倍**動く・`2026-09-14_theta_price.md`）。

**＝この器は、CPU の対象選びを測るつもりで `Θ` の誤りを測っている部分がある。**
`Θ` を 1.15 から上げると誤りの向きが急に釣り合う（キャラ狙いの誤りが 7% → 40%）のも同じ理由。

### 3.2 循環が完全には切れていない

判定に使う `ν` の実測も**同じ自己対戦（r3）から出ている**。
「r3 の打ち方の下での体の価値」で「r3 の対象選び」を採点しているので、
**独立な基準ではない**。切るには外部の基準（反事実・強い相手）が要る。

### 3.3 盤面の他の要素を見ていない

ブロッカーの応手・カウンターでの反撃・除去の誘発・リーサル計算は入っていない。
**「誤り」の絶対水準は読めない。読めるのは向きと感度だけ。**

## 4. 判定

| 問い | 答え |
|---|---|
| 身代わり率は攻撃側の誤りで水増しされているか | **いいえ**——キャラ狙いの誤りは 7〜43%、リーダー狙いの誤りの方が常に効く |
| 身代わり項 0.0597 は過大か | **過大ではない**。どの `Θ` でも**過小**の側 |
| どれだけ過小か | **判定できない**（1.2〜3.1 倍と `Θ` で 2.6 倍振れる） |
| この器で CPU の対象選びを採点できるか | **まだできない**——`Θ` を状態の関数にするまでは `Θ` の誤りを測ってしまう |

## 5. 副産物——**`Θ` を状態の関数にする動機が 1 本増えた**

`Θ` の `max`（`2026-09-14_theta_max.md`）は**式としては確定したが判定できず保留**になっていた。
本報告は**別の経路から同じ場所を指している**——**定数 `Θ` は、対象選びの採点を
リーサル圏で完全に壊す**。順序の一致率では差が出なかった（値が変わる行が 5.4%）が、
**この器では既定の `Θ` が明らかにおかしい答えを返す**＝
**`Θ` を状態の関数にする根拠が、検出力のある形で 1 つ出た**。

## 限界

- 上の §3 の 3 点（`Θ` の定数化・循環・盤面要素の欠落）が本報告の主要な限界。
- 1 コーパス（300 局・r3・`synth`）・1 設定。
- 「誤り」は**理論の値付けによる誤り**であって、実際に勝率を損ねたかは測っていない
  （それには反事実が要る・T18）。
