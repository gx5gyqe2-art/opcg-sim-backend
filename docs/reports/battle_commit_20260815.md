# 入口コミット — 防御窓を「入口で決めて実行するだけ」にする（2026-08-15）

**ユーザ決定**（2026-08-15）:「人間が実際に対戦をする時、カウンターを1枚切った後にまた
考えることはない」。従来の serve は防御窓の各ステップで独立に聞き直していた（毎回、残りの箱を
出口まで解決して value で選び直す）。本変更は**窓の入口で1回だけプランを立て、以後はその実行**に
する（`SERVE_BATTLE_COMMIT`・既定 ON）。

## 1. 何を変えたか（選び方は不変・決める時機だけ）

入口の1手は従来と**完全に同一の計算**で選ぶ（同じ決定化・同じ `resolved_branch_values`・同じ
argmax）。違いは、最良枝をもう一度解決してその過程で**自分側が選んだ後続手**（`move_sig` 列）を
採取してキャッシュし、次以降の decide はそれを返すこと。プラン手が実盤面で非合法になったら
（トリガー等の想定外）その場で1回だけ立て直し、それも失敗なら従来のステップ動作へ退化する。

期待した効果は2つ:

- **「払い始めたら払い切る」の構造保証**: 途中で聞き直さないので、「1枚払ってから素通し」という
  支配された折衷ライン（m1@15 型の病理）が原理的に発生しない。
- **高速化**: 窓のステップ数ぶんあった全枝解決が1回になる。

## 2. 初回測定は大敗（wr 0.320）→ 実装バグだった

同一 G14・CRN 100ペア200局の A/B で **0.320 CI[0.255,0.385]** と有意に負けた。診断12局
（プラン命中/手飛ばし/再計画/退化のカウンタ）では **98手すべて照合成功・skip/replan/fall=0**＝
プラン実行の機構は健全。原因は**採取側**にあった:

プラン採取の `resolve_battle_inplace` を `box_depth=0`（既定）のまま呼んでいたため、
後続手が「policy最良→PASS」という弱い選択器で決まっていた。**評価が正当化した継続**
（出口 value 最良で解決した世界）と**実行される継続**が別物になり、皮肉にも
「払った後に素通し」を量産していた。`box_depth=BOX_RESOLVE_DEPTH` を明示して規約を一致させた
（873ae5b）。

## 3. 修正後 = 同等 × 31%高速 → 既定 ON

| 腕 | 勝率（同一G14・CRN 100ペア200局） | 所要 |
|---|---|---|
| 修正前 commit | 0.320 CI[0.255,0.385] | 4915 s |
| **修正後 commit** | **0.520 CI[0.451,0.589]（0.5 を含む＝同等）** | **3380 s（−31%）** |

「途中で考え直すこと」に実戦上の利得は無い、が実測の結論。同等なら**人間と同じ意思決定構造**・
**折衷ラインの構造的排除**・**高速化**を無償で取れるため既定 ON とした
（`test_battle_commit.py` が既定値・入口一致・副作用ゼロ・キャッシュ実行・1回だけ再計画を固定）。

## 4. 測定上の副作用（ゲート計器の修正）

同一盤面に対して decide を反復するゲート測定（`decide_rate`）では、シード間でプランキャッシュが
残ると**シード1で立てたプランの続き**を返してしまい、m1@15 が 0.50 に見える汚染が出た。
`_world_seeds` と同様に `_battle_plans` もシードごとにクリアするよう修正（915ad95）。

## 5. ロールバック

`SERVE_BATTLE_COMMIT = False` で gen14 出荷時と同一挙動（席別 seam `battle_commit=` も残置＝
同一プロセスの A/B 可能）。
