# v47 手順1 — 一般盤面での本体 value 監査: 共通の系統誤差は無いが対面ごとに逆符号（2026-08-09）

「新たな指摘が出るたびにパッチを当てる前に、**本体 value が正しいかをまず確認する**」
（ユーザ方針 2026-08-09）の本体。手順0 に残った2つの疑い——(a) ラベルが `margin_blend` 混合、
(b) 盤面が出口分布に偏る——を両方消し、**純粋勝率ラベル × 木の葉が見る一般盤面**で測り直した。
本文書は 62対局・744盤面・4対面 時点のスナップショット（追記改変しない）。生成は継続中。

計器: `value_label_gen.py`（生成）/ `value_calibration_audit.py --cluster game`（監査）。

## 0. 結論

1. **手順0 の2つの所見はどちらも再現しない**。中間域の圧縮もライフ差の単調バイアスも、
   純粋ラベル×一般盤面では消える。手順0 の数値は blend ラベルと出口分布の産物だった
   （blend については `cpu_v47_step0_correction_20260809.md` で既に訂正済み）。
2. **プールすると系統誤差は検出されない**（全体バイアス +0.037 ±0.060・20層すべて 2SE 内側
   ＝有意セルは 1/20 で偶然の期待値どおり）。
3. **しかし対面別に見ると符号が逆で、2対面が 2SE を超える**。プールは打ち消し合いだった。
   ただし当該2対面は 8〜10対局しかなく、**多重比較を考えると未確定**。

## 4. 読み方（過大解釈しないための注意）

- **「本体が壊れている」ではない**。全対面に共通する誤りは無く、あるのは**訓練分布の外での
  較正の甘さ**。gen8〜gen13 はすべて `nami:shanks` 特化の教師で学習しており、その対面の
  バイアスが最小（+0.022）で、ほぼ学習していない `bg_luffy` 系で大きい——機械学習として素直。
- **未確定**。当該2対面は 8〜10対局・2SE ぎりぎりの超え方で、**4対面中2つが偶然 2SE を
  超えることは十分あり得る**（§2 で「20セル中1セルは偶然」と述べたのと同じ論理を適用する）。
  `r=0.505` の低さも標本の薄さを示す。確定には当該2対面の対局数を増やすしかない。
- **手続き上の反省**: 本作業では**プール表を先に読んで「系統誤差なし」と結論しかけた**。
  対面をまたぐ検証を設計しておきながら、対面別を見る前に全体像を述べたのは順序の誤り。
  対面別を先に見るべきだった。

## 5. 水準と順位は別問題（射程の限定）

本監査が測ったのは**水準（calibration）**であり、判断を決める**順位（ranking）**ではない。
`value_label_gen` のコーパスは 1盤面=1群なので、順位は**一切テストしていない**。

順位については v44 で別途実測済み（`plancf` 兄弟ペア・worlds=32）:

```
gen13 が δ選抜ペアで正しく並べた割合  0.760
ラベル自身の真正答率（逆算）          0.899
→ ネットの真の正答率（逆算）          0.826
```

**順位には約7ポイントの余地がある。** 過去の指摘（m1@14 の「手札2枚とライフ1の交換」など）は
すべて順位の誤りであり、水準の誤りではなかった。両者は独立で、水準が正しくても順位は誤りうる。

## 6. 現時点の方針

- **本体の再学習に進む根拠は無い**。共通の系統誤差が検出されない以上、v40（本体全面学習で
  アリーナ 0.447）の危険を冒す理由がない。
- **単調再較正も当てない**。直すべき水準の歪みが（少なくとも共通には）無い。機構は
  `ValueNet.set_calib` として実装済み（既定 None＝bit 恒等）＝必要になったとき使える状態で置く。
- **パッチ（裁定注入・出口ヘッド）は正しい戦略だったことが支持される**。誤りは分布全体の
  系統誤差ではなく点在する個別の順位誤りなので、点を直す道具が適合する。
- **未解決**: 対面依存バイアスの実在（要 `bg_luffy` 系の増量）と、順位の7ポイントの余地
  （v44 で「33群では信号が足りない」と確定した教師問題そのもの）。
