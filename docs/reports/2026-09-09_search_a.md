# WP `rs-search-a`: 探索の設定（sims 段階掃引・選択規則・根の平坦化）を 9 シナリオで測った（2026-09-09・r3）

計画 `docs/rust_engine_plan.md` §20.5 の指示書に従い、**ネット（`nrel_r3.npz`）は変えずに探索の設定だけ**を
振って 9 シナリオ（`tests/fixtures/scenarios/`）を打ち直し、思考ログ（§20.4）を機械的に集計した。
分析 #4（`docs/reports/2026-09-08_scenario_analysis_04.md`）の縛り A＝「探索の設定で動く分をまず測る」。

**この報告は数字だけを書く**（どの条件を serve／生成に採るかの判定はコーディネータ・§20.1 の運用）。

## 足した設定（既定は今までの挙動のまま）

`rust/opcg_engine/src/search/decide.rs::DecideOptions` に 3 つ足し、`opts_json`（`Game.decide`）→
`RsGame.decide`（`opcg_sim/api/engine_rs.py`）→ `rs_scenario_play.py play` の CLI まで通した。

| 欄（opts_json） | 意味 | 既定 |
|---|---|---|
| `select_rule` | 根で出す手の選び方。`"visits"`＝訪問数最多／`"q_min_n"`＝訪問数が `max(1, floor(sims * q_min_frac))` 以上の手の中で Q 最大（該当なしなら visits へ落ちる） | `"visits"` |
| `q_min_frac` | 上の訪問下限の割合 | `0.125`（sims/8） |
| `root_prior_temp` | 根の事前分布を `P^(1/t)` へ丸めて正規化（`t=2` で平坦化）。**根だけ**・子ノードには掛けない。Dirichlet 混合の前に掛ける（混合は平坦化後の P に対して既定どおり） | `1.0` |

- 選択は**等価手マージ後のグループ**（`_merge_root_stats` の並び）に対して行う＝訪問分布の候補と
  同じ粒度。`visits` はグループが訪問数降順に並んでいるので先頭＝今までと同じ手になる。
- CLI は `--select-rule` / `--q-min-frac` / `--root-prior-temp`（省略で既定）。
- **省略すれば 1 bit も変わらない**ことを 3 段で確かめた: Rust 単体テスト
  （`spelling_out_the_defaults_changes_nothing`）・pytest（`tests/test_search_options.py`）・
  CLI で既定を明示した run と省略した run の `.md` が完全一致。

### 測る前に直したこと（重要）

`rs_scenario_play.py` は探索乱数の基点（`RsGame.__init__` が global `random` から 1 度だけ引く
`_search_base`）を固定していなかった＝**同じ `--seeds` でも起動ごとに世界サンプル列が変わっていた**。
設定だけを変えた比較にならないので、`_play_one` で `random.seed(f"{name}:{seed}")` を張った。
このため S1（sims 160・既定）を回し直しても分析 #4 の出力（`scenario_out/`）と数字は一致しない
（**同じ 3 決定の向きは再現した**・下表）。以後の比較はすべて同じ基点の上で行っている。

各決定の実測時間を `decisions[i]["decide_ms"]` に載せた（`.md` の書式は変えていない）。

## 集計（seat 側の決定・機械的に数えたもの）

<!-- AGG_TABLE -->

読み方（定義は `tests/scripts/rs_search_a_agg.py` の docstring が正本）:
- **訪問された根の手の割合**: `kind=main` の決定で `n>0` の根の手 ÷ 合法手。「決定ごとの平均」は
  合法手が少ない決定に引っ張られるので、「手を全部プールした」割合も併記した。
- **Q が高いのに N で負けた手**: `n>=1`（実際に読まれた）かつ「訪問数最多の手より Q が高い」かつ
  「訪問数はそれより少ない」手の件数。訪問 0 の手（Q=0）は数えない。
- **訪問数最多と違う手を出した決定**: `q_min_n` の効き。`visits` では定義上 0 になる（自己検査）。
