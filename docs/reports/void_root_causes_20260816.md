# アリーナ void の根因 — 交差対面でしか出ない3欠陥（2026-08-16）

ランダム対面×生成デッキのアリーナ（`arena_random_leader_20260816.md`）で、対局が成立しない
**void が 20 件**（判定A 17／判定B 3）出た。void は勝率の母数から外れるだけで、**負けそうな側が
延命する形のループなら判定を歪める**ため、根因を潰す必要がある。本レポートはその調査記録。

## 1. 追い方を seed から「面」へ変えた

最初は void の seed（900002 等）を直接再現しようとしたが、**seed 単位の再現は当てにならない**。
同日入れた戦闘箱の枝予算（`BOX_BRANCH_BUDGET`）で CPU の選択が変わり、900002 は両局とも
正常決着した——ループを踏まなくなっただけで、欠陥は残っている。

そこで生成デッキ監査を**交差対面**へ拡張した（`deck_synth_audit.py --cross N`）。従来の監査は
**ミラー専用**（同一リーダー同士）で ok=137／hang=0 だったが、void は交差対面でしか出ていない。
対面の引き方はアリーナ（`promotion_gate._leader_pair`）と同じにして再現条件を揃え、
hang 時には**繰り返している対話の発生元**に加えて**繰り返している手**も記録するようにした
（対話を伴わないループは発生元が付かず、従来の集計では犯人が見えなかった）。

**修正前の実測（240件・sims=8・上限700手）: ok=237 / hang=3 / timeout=0 / error=0**
（正常決着のターン数は平均 11.6・最小7・最大18）。この 3 件がそのまま 3 欠陥だった。

## 2. 欠陥1: ドン!!を対象にしたフリーズで対局が落ちる（OP10-033 ナミ）

```
AttributeError: 'DonInstance' object has no attribute 'flags'
```

`FREEZE` は `card.flags` に "FREEZE" を書く**カード専用**アクションで、ドン!!は `is_frozen`
（`FREEZE_DON`）でフリーズする。「相手の、レストのキャラ**か**ドン‼1枚まで」の択一形（OP07-026）は
Choice に分解済みだったが、**ドン!!だけを対象にする形**（OP10-033「相手のレストのドン‼1枚までは、
次の相手のリフレッシュフェイズでアクティブにならない」）が素の `FREEZE` に落ちていた。

- パーサ: 対象がコストエリアなら `FREEZE_DON`（枚数処理・`status="OPPONENT"`）へ回す。
- エンジン: `FREEZE` ハンドラは `flags` を持たない対象を `is_frozen` で受ける（取りこぼしても
  **対局が死なない**ようにする＝アリーナでは1ペア全損になる）。

## 3. 欠陥2: 継続効果の再計算がコスト確認の対話を出す（OP09-080 サウザンド・サニー号）

「【相手のターン中】このステージをレストにできる：自分の…キャラが相手の効果で**場を離れた時**、
ドン‼デッキからドン‼1枚までを、レストで追加する。」

反応型（イベント誘発）の判定が `(された|した|受けた|なった)時、` で、**「離れた時、」を拾えず**、
この能力は常時効果として**再計算のたびに評価**されていた。任意コストなので「使用しますか？」を
訊き、拒否しても使用回数も盤面も変わらないため次の再計算がまた同じ問いを立てる——
**613回連続の同一確認**で上限手数に到達していた。

- 一般則: **再計算中はコスト確認の対話を出さない**（コストを持つ能力は継続的な修飾ではない＝
  再計算では発動しない）。これで未知のカードでも同じループ族は起きない。
- 分類: 反応型の判定に「離れた」を追加。DB 全体で該当は10節（OP07-038/OP08-046/OP08-056/
  OP10-042/OP11-041/OP16-041/OP08-105/OP12-099/OP09-080/OP13-078）で、**すべてイベント誘発**＝
  常時効果は1つも含まれない。

これは 2026-08-15 に潰した「再計算が**対象選択**の対話を出す」（OP05-097 聖地マリージョア）と
同じ原則の**コスト確認側**で、片側だけ塞いでいたことになる。

## 4. 欠陥3: 状態を変えるコストが「既にその状態」でも払える（OP15-099 ウルージ）

「【起動メイン】自分のライフの上から1枚を**裏向きにできる**：自分のリーダーかキャラ1枚に
レストのドン‼1枚までを、付与する。」

ライフが**全て裏向き**でもコストが払える判定になっており、裏向きを裏向きにする空振りで
何も消費しないまま起動メインを **297回連続**で撃っていた。

既知のクラスA（レスト済みカードを再レストするコスト・OP10-083 光月モモの助）と同じ
**「支払い可否（`_can_satisfy_node`）と実際の支払い（`_resolve_targets`）の不一致」**で、
レスト以外にも同じ穴が空いていた。規則を `_cost_state_noop` に一本化し、判定と支払いが
同じ関数を使うようにした（レスト＝既にレスト済みは不可／ライフの裏返し＝既にその面は不可）。

**挙動ベースラインの差分は1行**: `OP08-063 シャーロット・カタクリ`【登場時】ライフを裏向きに
できる：ドン‼1枚追加 → 監査盤面はライフが全て裏向きなのでコストを払えず、ドン‼が増えなくなる。
黄のライフを表向きにする構築でのみ払えるのが正しい挙動なので、意図した変更として受け入れた。

## 5. 併せて潰した「1手が終わらない」暴走（seed 904002・PairTimeout）

void 20件のうち1件は手数ではなく**1回の `decide()` が返ってこない**別種で、戦闘箱の枝が
組合せ的に膨らんでいた（155,452 枝評価で240秒経っても戻らない）。決定論を壊さないよう
**時間ではなくノード数**の予算（`BOX_BRANCH_BUDGET=8000`）を入れて有界化した。通常対局の
実測は 1決定あたり中央 153・95%点 647・最大 1,831 枝なので**予算は通常局面には当たらない**。
アリーナは本番と同じ sims=160 で回すため、これは計測の都合ではなく**出荷 CPU が固まる欠陥**だった。

## 6. 修正後の実測

同じ 240 件（同一 seed・同一対面）を修正後コードで回し直した:

| | ok | hang | timeout | error |
|---|---|---|---|---|
| 修正前 | 237 | **3** | 0 | 0 |
| 修正後 | **240** | **0** | 0 | 0 |

3件の hang はそれぞれ本レポートの欠陥1/2/3で、個別にも正常決着を確認している
（OP11-040×OP05-060: 700手打切り → 113手決着／ST05-001×OP10-099: 700手打切り → 133手決着／
OP08-021×OP09-022: 84手で例外 → 103手決着）。

### 6.1 台帳の void そのものの再生

監査だけでなく、**当時 void になったペアを実条件（sims=160・同じ対面/デッキ）で再生**した。

- 判定B（gen15 vs gen14）の void 3件 → **2件が成立**（1005002 P-047×ST13-003・
  905002 OP10-022×OP07-079）。残る 904002 は §5 の組合せ爆発局面で、枝予算で1手は返るように
  なったが**ペア全体が900秒を超える**（＝ハングではなく遅い）。
- 判定A（gen16 vs gen15）の void 17件は**再生できない**——gen16 は不採用候補でリポジトリに
  コミットされておらず、ワーカー側のファイルはコンテナ巻き戻しで失われた。欠陥自体は
  エンジン側（ネット非依存）なので、同じ対面は §6 の交差対面監査でカバーされている。

## 7. 教訓

- **ミラーでは出ない**。137リーダーのミラー監査は ok=137 で、3欠陥はすべて交差対面で初めて出た。
  対面の組み合わせは測定の広さそのもので、狭い条件の green は品質の証明にならない。
- **seed を追うな、面を測れ**。CPU の選択が変わると同じ seed でもループを踏まなくなる。
  欠陥の有無は「N件回して何件落ちるか」で見るべきで、個別 seed の再現性に依存すると見失う。
- **同じ原則の片側だけ塞ぐと再発する**。「再計算は対話を出さない」を対象選択にだけ適用して
  コスト確認に適用していなかった、「コストの空振り」をレストにだけ適用してライフ裏返しに
  適用していなかった——どちらも一本化（`_cost_state_noop` / 再計算ガード）で閉じた。
