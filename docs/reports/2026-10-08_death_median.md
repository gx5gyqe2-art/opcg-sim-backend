## 1. 式（実装の前に書いた）

採った計画（出す札の組・付与の枚数・地平 `h`）について、守る側の計算を**同じ計画・同じ地平**で「倒れた段にだけ 1 を置く」値段
（`λ_net = μ = ν = 0`・`(λ − λ_net)·L0 = 1`）で解き直し、段の損害＝**その段で守り手が倒れる確率** `p_t`（`t = 1..h`）を取る
（① 報告 §1 の器と同じ。守り手の選び方は値段に依らない＝同じ守り）。`F_t = Σ_{s ≤ t} p_s`。

- 地平の内で `F_h ≥ 1/2` なら、最初に `F_t ≥ 1/2` となる段 `t` で
  **`τ_med = (t − 1) + (1/2 − F_{t−1}) / p_t`**（時計の段の約束と同じ「段 t で倒れる ↔ (t − 1, t]」・段の中は線形に読む）。
- 時計 **`τ = min(τ_歩き, τ_med)`**。`F_h < 1/2`（半分以上が地平を生き延びる）・ライフ 0（`L0 = 0` で倒れる確率を測れない）・
  計画が無い時計は **今の歩きのまま**。
- **新定数ゼロ**（1/2 は「真ん中」の定義・当てはめた値ではない）。計画の選び方（`plans.rs` の点数）は変えない。耐久 `θ`・
  段の損害 `harm_steps`・歩きの段の値 `sched` も変えない。

### 1.1 実装の形（選んだもの）

**(1) `outer.rs` で解き直す形**（`KERNEL_FILES` の 8 ファイルは不変）。理由:

- 守る側の解き方の原文に触らないので、**既存の出力（損害・耐久・選んだ守り）のビット不変が作りから保証される**（(2) は
  `defender.rs` の状態に倒れる確率を足し、全部の解でビット不変を検算する必要がある）。
- 増える計算は**採った計画ごとに守る側の計算を 1 回**（計画の列挙と試行の中では回さない）。計画は覚え書きと計画のディスクに
  入るので、同じ盤面では 1 回きり。所要の前後は §4 に書く（予告: 冷たい計画のディスクで +5〜20%）。
- 計画の辞書の中身（`tau`・`a_time` と新しい欄 `tau_med`）が変わるので `SOLVER_VERSION` を `rd-speed-8` に上げる
  （`rd-speed-7` は不採用の 2 段の値付けが使った版なので飛ばす）。

### 1.2 時計を読む場所（1 か所にまとめる）

時計 τ を計画から読む場所は 2 つある: (a) 計画の辞書の `tau`（→ `a_time = θ / τ`＝計画の平均の速さ。`relative_ledger` が
`rate_of_row` で読む・`crossing_bridge` の行の `slope_board`・`slope_theory` もこれ）、(b) `crossing_bridge` の行の読み
`tau_theory_of`（`sched` を歩き直す。`win_calib`・`pre_settle_asymmetry` もこれを通る）。両方とも同じ関数
`outer::clock_tau(τ_歩き, τ_med)` を通す。倒れる時刻の真ん中は `outer::death_median(p)` 1 つ。

`theory_bridge`（輪郭の時計 `tau_from_profile`）・`kappa_vector`（計画を渡さない `rate_of_row`）・T18 の道具（計画を渡さない）は
**計画の時計を読まない**（読む場所を grep で確かめた: `rule_don_plan_for` を呼ぶのは `drv_cb` と `drv_rl` だけ）。

### 2.2 不変量（殺す基準を含む）

1. **殺す基準**: 半分以上が地平を生き延びる時計（`F_h` < 1/2）・ライフ 0・計画の無い時計の τ が **1 ビットでも**変わったら誤り。
2. どの時計でも新しい τ は前の τ 以下（`min` なので）。前の τ と違う時計は、`τ_med` < 前の τ のものだけ。
3. 計画は変えない: 採った計画（出す札・付与）・`θ`・切る札の期待値・`harm_steps`・`sched`・地平は全部の計画でビット同じ。
   歩きの τ（`m2_probe` の `tau_walk`）も全部の時計でビット同じ。
4. 引いた札 ≈ μ・価格・耐久は不変（計画も `θ` も変えない）。
5. golden: `rd_solve`／`rd_dp`（守る側の計算）・`theory_core`・`tests/fixtures/rs_goldens`（ゲーム）は 0 行。`theory_outer` は
   計画の辞書を返す呼び出し（`cb.rule_don_solve`・`cb.rule_don_plan_for`・`cb.threshold_parts_side` など）の行のうち、
   `τ_med` が効く盤面と `tau_med` の欄が増える行。`theory_rows` は計画の時計を通す器の通し（`crossing_bridge`・`relative_ledger`）。

1. **交点の橋は予告どおりに動いた**【実行】: 的中 実 .7051 → **.7099**・合成 .6602 → **.6643**、整数ターンの偏り +0.354 → **+0.175**／

   両席を同じ物差しで読む形にしてから**（§8 判断 1）。計算量は冷たい計画のディスクで `crossing_bridge` 実 +19%（§5）。

## 8. 司令塔への判断事項

判断事項は 2 つ。互いに独立（1 だけ先に決められる。2 は 1 を採るときの付帯）。

### 判断 1: 倒れる時刻の真ん中で読む時計を既定のままにするか

1. **何を決めるか**: 交点の時計を「歩きと、倒れる時刻の真ん中の早い方」で読む直し（この枝に入れた）を本線に取り込むか。
2. **選択肢**:
   (a) **取り込む**——時計 1 本ずつの当たりは良くなる（勝った席の終局の時刻の整数の偏り 実 +0.35 → +0.18・合成 +0.74 → +0.55、
       ぴったり当たる割合 +3〜4 点、どちらが先に勝つかの的中 +0.5 点・+0.4 点、合成の打ち切り 70 → 46）。代わりに、決着前の勝率の較正で、
       時計の差で勝ちを並べる力が下がる（実 AUC .808 → .789・Brier .178 → .187／合成 .724 → .722・Brier はわずかに良い）。
   (b) **取り込まない**（`d8228c89c` のまま）——勝率の較正は今のまま。時計 1 本ずつの遅れ（地平の外の勝った席 約 1 ターン）は残る。
   (c) **両席を同じ物差しで読む形に直してから取り込む**——片方の席だけ真ん中で読む行が並べる力を落としている（§4.3）ので、
       たとえば「両席とも真ん中が測れる行だけ真ん中で読む」「真ん中が測れない席は歩きから平均のずれを引く」などで差の物差しを揃える。
       どちらも新しい形の式で、この作業では測っていない。
3. **なぜこの問いが出てきたか**: ① の調査（`2026-10-08_late_winner.md`）で、交点の時計は「最後に残った分岐が倒れる段」を言うので遅い
   （真ん中より約 0.7 段）と分かり、真ん中で読む直しを診断の歩きで測って推薦された。ユーザ決定（10-08「小さな直し＋切り分け」）で既定に入れた。
   交点の橋の数字は予告と小数 3 桁まで一致したが、決着前の較正（`win_calib`）を回すと実の記録で並べる力が下がり、行を分けると
   「片方の時計だけ動いた行」で落ちていた。
4. **推薦**: **(c)**、ただしすぐ決めるなら (b)。時計 1 本ずつの当たりは確実に良くなったが、勝敗の説明（2 本の時計の差）が実で悪くなる直しは
   「悪化したら採用しない」（§0.7 の 6 段）に触れる。悪化の機構ははっきりしていて（片方の席だけ別の統計量で読む）、直し方の候補もある。
5. **決めないとどうなるか**: この枝は本線に入らず、①の小さな直しは保留のまま。①の芯（大きい塊）の切り分けは別の作業なので止まらない。
6. **留保**: (c) の形を決めるには、真ん中が測れない席（半分以上が地平を生き延びる・ライフ 0）の時計を何で読むかが要る——これは①の芯
   （守る側の計算が手札の厚い守り手を生き残らせ過ぎる）と同じ時計の群れで、芯の切り分けの結果に依る。
   また、並べる力の指標（AUC）が下がって的中が上がるのは、`D` の大きさの情報が歩きの方にあったことを示す【推測】——真ん中で読む方が
   「正しい時刻」でも、差の大きさの較正は表の幅（`theory` の σ_rel）だけでは戻らない。

### 判断 2: 表の `theory` の幅の取り直しを一緒に取り込むか

1. **何を決めるか**: `make theory-table` で取り直した表（`sigma_rel_whole.theory` が 実 0.387 → 0.4695・合成 0.3875 → 0.4459）を、時計の直しと一緒に入れるか。
2. **選択肢**: (a) 判断 1 で取り込むなら一緒に入れる（表は「採る式」の出力で作るもの）——`win_calib` の Brier・対数損失が時計だけのときより良い（実 .1877 → .1868・合成 .2204 → .2157）。
   (b) 判断 1 で取り込まないなら表も入れない（この枝ごと外す）。
3. **なぜ**: 予告では表は動かないと読んだが、表の `theory` の幅は交点の時計から測る欄だった（§4.2）。
4. **推薦**: 判断 1 に従う（(a)／(b) は判断 1 で自動的に決まる）。
5. **決めないとどうなるか**: 判断 1 と同じ。
6. **留保**: `w_bar` の出所は `curve` の幅しか見ないので、この欄が動いても出所の点検は落ちない——`theory` の幅が古いまま残っても誰も気づかない作り。
   出所の点検に `theory` の幅を入れるかは別の判断（今回は触っていない）。
