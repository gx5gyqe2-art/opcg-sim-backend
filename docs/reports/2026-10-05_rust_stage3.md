# Rust 化・第 3 段（2026-10-05）— Rust の核を既定にし、速くした Python の解き方を消した

状態報告（ユーザの判断が残る項目は無い）。設計は `2026-10-05_rust_design.md`（§6.3 切替・§6.4 計画の覚え書き・§9 は (B) を採用）、
前の段は `2026-10-05_rust_kernel_stage1.md`・`2026-10-05_rust_kernel_stage2a.md`。ユーザ決定（10-05・`theory_orchestrator_handoff.md` §4）:
Rust 版が動いた後に速くした Python 版を消す・答え合わせ用の原文 `tests/harness/rule_don_ref.py` は残す・確認は計算単位のビット一致を主にし、
道具全体は `crossing_bridge` の実・合成の各 5 局だけ・暦の慣らし運転は置かない。起点 `claude/cpu-spec-improvements-yw91jd@d453ac452`。

## 何を変えたか

### 切替（`OPCG_RD_KERNEL`）
| 値 | 意味 |
|---|---|
| `rs`（**既定**） | Rust の核。wheel が無い／古い／入口の版が違うと最初に解くときに落ちる（黙って戻らない）。 |
| `ref` | 速くする前の原文（`rule_don_ref`）。遅い・調べ直し用。`crossing_bridge` が `__main__` で走っていても、今動いている側の切替を写す。 |
| `both` | Rust と原文で解いて `repr` を比べ、違えば例外。**返すのは Rust の結果**（出力は `rs` と同じ）。原文は 1 問ごとに覚え書きを消して冷たく解く。 |

旧の `py`（速くした Python）と `auto`（Rust が無ければ `py`）は**消した**（`auto` を `rs` の別名にはしなかった——戻り先の `py` が無いので、
古い呼び方は黙って通すより理由つきで落とす方が安全）。指定すると `ValueError`／`SystemExit` で理由を示す。

### 消したもの（`crossing_bridge.py`）
`_ex_prep`・`_norm_seq`・`_seq_prep`・`_ex_counter_sets`・`_rule_guard_plan_ex`・`_mask_firsts`・`_ex_fit_horizon`・`_ex_count_layers`・
`_rule_don_solve`・`rules_sched`・`_tab`・`rule_don_solve` の試行のループ・`EX_LAYER_COUNT`・`_SEQ_NORM`／`_SEQ_PREP`・
`_RULE_EX_CACHE`／`_SETS`／`_MEMO`／`_CTX`・`_EX_USED`・`_ModelBudget`。`rd_kernel.py` の包み（`install` が関数を差し替える方式・
`_wrap_guard`／`_wrap_fit`／`_wrap_solve`・`_ORIG`）も消した。

### 残したもの（理由）
* `rules_steps`・`purse_plan_witness`・`_attach_gain`・**`_rule_don_masks`**: 出す札の組（`steps`）は Python が作る（第 2b 段が移す）。
  `_rule_don_masks` は設計 §9 の消す一覧に在るが、`rd_solve` への入力（出す札の組・`caps`）を作るので残した（設計の一覧との食い違い）。
* `rule_guard_plan_ex`（公開の入口）: 計画の外の呼び出し（`_rule_don_term` の地平を渡す読み・テスト）が使う。中身は Rust（`rd_kernel.guard_rs`・
  呼び出しをまたぐ予算なしの覚え書き）に置き換えた。`rule_guard_plan_bo`（使われていない互換の包み）は触らない。
* `walk_crossing`・`model_horizon`・`tau_grow`／`rate_at`・`_prices_of`・`_FEQ`・`EX_STATE_BUDGET`・`EX_SPEED_STATS`: 他の器・テスト・原文・Rust への引数が使う。
* `rule_don_solve` の外側（覚え書き・計画のディスクの覚え書き・最初の地平・予算なしの覚え書きの共有・開示）と `rd_solve` の引数づくり・計画の
  辞書の組み立ては、`rd_kernel.solve_rs`／`run_rs`／`solve_args` から `crossing_bridge` の `rule_don_solve`／`_rd_run`／`_rd_solve_args` に移した
  （中身は同じ式・同じ順）。理由: 計画のディスクの覚え書きの鍵（`plan_store.solver_reads`）は解き方の関数の原文に出てくる名前をたどって
  切替を集めるので、`g["…"]` で引く形だと `NU_MEAS`・`PWR_EPS`・`SLOPE_FLOOR` などが鍵から落ちる。

### 原文（`rule_don_ref.py`）を自己完結に
消す前に、原文が `_sync()` で借りていたもののうち**消すものだけ**（`_tab`）を原文のまま写した（`_OWN` に追加）。数値の式は 1 文字も変えていない。
借り続けるもの（`rules_steps`・`walk_crossing`→`tau_grow`・`model_horizon`・`_prices_of`・`nu_meas_of`・切替の値）は `crossing_bridge` に残っている
（第 2b 段で消すときに同じく写す）。

### 計画の覚え書きの鍵・版
* `SOLVER_VERSION` を `rd-speed-2` → **`rd-speed-3`**（値は不変・解き方の原文が変わった）。
* 鍵には**核の版**（`rs:<入口の版>:<src/theory の原文のハッシュ>`）が必ず入る（旧は `rs` のときだけ）。
* `test_rd_speed` の指紋は残った解き方の関数＋`rd_kernel` の継ぎ目（`guard_rs`・`res_dict`・`race_cap`・`rd_solve`）＋**Rust の核の原文のハッシュ**
  （設計 §6.4: `src/theory` を直して版を上げ忘れると落ちる）。
* 解き方が `rd_kernel` の関数を呼ぶようになったので、たどると `rd_kernel.STATS`（呼び出しの数え先）が鍵に入って毎回別の鍵になる——`plan_store._VOLATILE` に足した。

### テスト・道具
* `test_rd_speed.py`: 「新」は Rust。数え方の検査は Rust の段の和＝原文の動的計画の状態の数（`_mask_firsts` はテストの中に写した）。
* `test_rd_kernel.py`: 比べる相手を速くした Python から原文に（動的計画 300 問 × 予算 3 の状態の数も原文の `len(memo)` と）。既定 `rs`（別プロセス）・
  `py`／`auto` が落ちる・消した関数が戻っていない・`ref` が原文を返す・`both` が守る側の計算と計画の両方で例外・鍵に核の版。
* `test_rd_kernel_plans.py`: rs＝原文。試行の開示は**記録した値**（第 2a 段で速くした Python が出した値・`rd_solve_golden`）と 8 局面・記録 152 解 × 予算 2 で比べる。
  試行ごとの状態の数は原文の同じ地平の試行と。「Python の計画の列挙を呼ばない」試験は対象が無くなったので削除。
* `test_crossing_bridge.py`: 手で辿る歩きの `rules_sched` を原文のものに。
* `rd_kernel_golden.py`: 作り直しの答えは原文（`remake` の既定・`--rs` で Rust）。`solve-golden` は Rust で解き原文と突き合わせてから書く。
