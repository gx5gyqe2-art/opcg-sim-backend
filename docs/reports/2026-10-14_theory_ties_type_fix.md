# 訂正: 「自分の時計」「相手の時計」の取り違え（`2026-10-14_theory_ties_type.md` の読み・2026-10-14）

起点: `claude/theory-map` @ 2b3ab6ad。前の報告は書き換えない（報告は時点の記録）。ここで訂正する。

## 1. 何を取り違えたか【実行】

理論の 2 本の時計は、コードでは次の意味だった（`rust/opcg_engine/src/theory/core/drv_tb.rs::curve_d_of_row`）:

- **自分の時計（`τ_me`）** ＝ `threshold(row, 相手の手札の読み)` から作る。中身は `threshold_parts_side(side_opp = true)`＝**相手の耐久**（相手のライフ・相手の手札・相手の体）。
  **自分が相手を倒すまでのターン数**の読み。
- **相手の時計（`τ_opp`）** ＝ `state_th_me(row, 自分の手札の読み)` から作る＝**自分の耐久**。
  **相手が自分を倒すまでのターン数**の読み。
- 勝率は差 `τ_opp − τ_me` で読む（正なら自分が先に倒す）。

`2026-10-14_theory_ties_type.md` は、自分の時計を「自分が倒れるまでの読み」、相手の時計を「相手が倒れるまでの読み」と、**逆に**書いた。

## 2. 前の報告のどこが変わるか

| §1.4「戦闘解決の分」の上限 | 相手の時計の部品（相手の時計を動かすのは、攻撃の戦闘で相手が失ったものだけ） | 攻撃の戦闘で相手が失うもの（ライフ・カウンター・キャラ）は**相手の耐久**＝**自分の時計**を動かす。上限として読むべきだったのは**自分の時計の部品** |

## 3. 次の課題への影響

司令塔の次の課題「自分の時計の部品を耐久の 3 つの項に割る」は、§1 の取り違えを前提に「自分の耐久」と読める形で出ている。
