## 結論を 5 行で

1. **定義**: 手札の価値 = `H_play`（残りターンのドンで出せる最良の計画・T66）＋ `G_guard`（来る攻撃を受けるより安く止められる分）。
   `G_guard = Σ_t s^t Σ_{来る攻撃 x} max(0, 受ける損 − 守る費用(手札, x))`、守る費用は「カウンター合計 ≥ x+1000 の組の `v` の和の最小」。
   札 1 枚の価値 `ΔH = max(ΔH_play, ΔG_guard)`。定数なし。
2. **検算が通った**: 引いた札 1 枚の `max(ΔH, ΔG)` の平均は **実 0.0546・合成 0.0511**＝**μ（0.0551）に合わせずに一致**（実 0.99・合成 0.93）。
   出す用途だけ（T66）では 0.040／0.031 で μ に届かなかった分を、守る用途（0.016／0.021）が埋めた。
3. **探した札は引いた札より低い**: `max(ΔH, ΔG)` は実 0.041 対 0.055（**−0.013**）・合成 0.046 対 0.051（−0.005）。両用途を足しても T65/T66 と同じ結論。
4. **取った札の 40%（実）／30%（合成）はカウンター札**（2000 以上か【カウンター】イベント）で、守り目的の探し（`ΔG > ΔH`）は 17%／21%。
   プリン（「サンジ」かイベント）は取った札の 78% がカウンター札。**ウタ（赤髪海賊団）は 0%**で `ΔG` 0.001・`ΔH` 0.017＝どちらの用途にも効かない
   大物を取っている。
5. **理論の側はこれで閉じる**（探すものの定義＝穴を埋める札かカウンター札・数える物差し＝`max(ΔH, ΔG)`・μ との整合）。探す能力の価格を
   `E[max_{取れる札} max(ΔH, ΔG)] − E[引き]` に置くかはユーザ判定。CPU の探し方（ウタ型）は理論より下手＝改善の手掛かり。


## 3. 読み方

- **μ が出た**: 「出す計画 + 守る備え」で引いた札の価値を数えると、別の器で測った μ に合った。手札の価値の定義として自己整合している
  （ユーザの 2 つの指摘＝穴を埋める・カウンター値を上げる、がそのまま 2 本の柱）。
- **サーチは理論の探し方に届いていない**: 理論が「取るべき」とする札（穴を埋める小物か安いカウンター札）ではなく、静的に強い大物を取る
  行が多い（ウタ）。プリン型は理論どおり（カウンター札 78%）で引きに並ぶ。**探す能力の価格の前提（静的 `W` の最大）が、CPU の下手な探しを
  「良い探し」として高く評価していた**。
- 価格側の置き換え `E[max_{取れる札} max(ΔH, ΔG)] − E[引き]`（デッキから数える）は定数なしで書ける。探し方を変えた CPU で測り直せば、
  この差は正に転じるはず。
