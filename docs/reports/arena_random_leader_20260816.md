# アリーナ再測定 — ランダム対面×生成デッキ（2026-08-16）

歴代のアリーナ判定は**両者ハンニャバル固定のミラー・singleton デッキ**という1条件だけで測られていた
（`promotion_gate` 既定）。標準要件「**新カード・新リーダーに大量試行学習なしで汎化する**」を
直接測る条件が無かったので、`--leaders random --decks synth`（ペアごとに全137リーダーから2枚引き、
デッキ中身もリーダーに合わせて `deck_synth` で合成）を新設し、2本の判定を測り直した。

計測は分散ワーカー＋ローカルの再開可能台帳（`arena_resume.py`）で、条件
（seed帯・candidate/baseline・leaders/decks）はシャード間で不変。集計は `arena_breakdown.py`。

## 1. 判定A: gen16 vs gen15（出荷既定） — **不採用が確定**

| 項目 | 値 |
|---|---|
| ペア数 | **313ペア（626局）**・台帳11本 |
| 勝率 | **0.4521** |
| 95%CI（ペア単位） | **[0.4087, 0.4954]**（上限が 0.50 未満＝有意な劣化） |
| Elo | **−33.4** |
| void | 17ペア（母数から除外・下記§3） |

`gen16_negative_20260815.md` の旧判定（固定ミラー225ペアで wr 0.4533 CI[0.4150,0.4916]）と
**点推定が 0.4533 → 0.4521 でほぼ一致**した。旧判定は「条件が狭かったから負けたのでは」という
留保を付けられる状態だったが、**対面もデッキも入れ替えた条件で同じ数字**が出たため、
その留保は消える。gen16（常識の後付け矯正）は**不採用で確定**。

## 2. 判定B: gen15（出荷既定） vs gen14 — 新条件では**有意でない**

| 項目 | 新条件（本測定） | 採用時（固定ミラー） |
|---|---|---|
| ペア数 | **177ペア（354局）** | 225ペア（450局） |
| 勝率 | **0.5198** | **0.5756** |
| 95%CI | **[0.4608, 0.5787]**（0.50 をまたぐ） | [0.533, 0.619] |
| Elo | +13.7 | +52.9 |
| void | 3ペア | — |

gen15 は「歴代初のアリーナ昇格（wr≥0.55 かつ CI下限>0.50）」で採用した世代
（`gen15_adoption_20260815.md`）。**新条件では昇格基準を満たさない**（点推定 0.576→0.520・
CI が 0.50 をまたぐ）。

ただし本測定は**採用の取り消しを意味しない**。2つの読みが残る:

- (a) **汎化しなかった**——gen15 の優位はハンニャバルのミラー特有で、対面が変わると薄い。
- (b) **検出力が足りない**——177ペアの CI 幅は ±0.059 で、真値 0.52 なら有意になり得ない。
  対面ランダム化はペア間分散そのものを増やすので、同じペア数でも旧条件より CI は広がる。

**177ペアでは (a) と (b) を分離できない**。分離実験＝**gen15 vs gen14 を旧条件（固定ミラー）で
同程度のペア数で測り直す**。旧条件で 0.55 超が再現すれば (a)、再現しなければ (b)（＝旧判定自体が
運の良い1本だった）。この実験は未実施。

## 3. void（対局が成立しなかったペア）の扱い

条件をランダム対面へ広げたことで、**エンジン欠陥で終局しない対局**が現れた。1ペアの失敗で
シャードを全損させないため、`fd04ec9`/`b313821` で void として台帳に残し、
**母数から外して件数を明示する**方式にした（黙って落とすと「全部測れた」ように見えるため）。

| 判定 | ペア | void | 内訳 |
|---|---|---|---|
| A | 313 | 17（5.4%） | MAX_STEPS 17 |
| B | 177 | 3（1.7%） | MAX_STEPS 2 / PairTimeout 1 |

void を踏んだリーダー（出現数に対する void 率）:

| リーダー | void / 出現 |
|---|---|
| OP10-022 トラファルガー・ロー | 6 / 9 |
| ST13-003 モンキー・D・ルフィ | 4 / 8 |
| OP07-079 ロブ・ルッチ | 3 / 8 |
| OP11-040 モンキー・D・ルフィ | 2 / 5 |
| OP12-041 サンジ | 2 / 5 |
| P-047 モンキー・D・ルフィ | 2 / 5 |
| OP09-042 バギー | 2 / 4 |

一様ではなく**特定リーダーに集中**している＝リーダー能力に紐づく実バグの疑いが濃い（調査中）。
void は wr の母数から外れるだけで**系統的な偏りを持ち得る**（負けそうな側が延命する形の
ループなら勝率が歪む）ため、§1/§2 の数字は「void を除いた条件での判定」と読むこと。

なお PairTimeout 1件（seed 904002）は**手数ではなく1手が終わらない**別種の暴走で、
戦闘箱の枝が組合せ的に膨らんでいた（1回の `decide()` で 155,452 枝評価・240秒で戻らず）。
`9d2dcae` で決定論的な枝予算（`BOX_BRANCH_BUDGET=8000`）を入れて有界化済み——
これは計測の都合ではなく**出荷 CPU が固まる欠陥**（アリーナは本番と同じ sims=160）だった。

## 4. リーダー別の得手不得手（新設・ユーザ決定 2026-08-16）

「どの対面が強いか」を今後は記録する方針にした（台帳に `leaders`/`games` を残し、
`arena_breakdown.py` でリーダー別・対面別に割る）。判定A（候補=gen16 席）の抜粋:

- 苦手: OP01-091 キング 0.000(0/6)・ST13-003 0.000(0/4)・OP06-080 0.000(0/4)・ST10-001 0.000(0/5)
- 得意: OP15-001 クリーク 1.000(5/5)・OP05-060 0.900(4.5/5)・OP10-001 0.833(5/6)・P-076 0.812(6.5/8)

**本測定のリーダー別は各4〜9局しかなく、単独では有意でない**（0/6 でも p≈0.016 の一発芸）。
対面別に至っては2ペア以上引いた組み合わせが判定Aで3件・判定Bで0件＝**まだ読めない**。
リーダー別の傾向を判定材料にするには、同一リーダーを狙って積む専用の測定が要る。
本節は「今後の蓄積の起点」として残す。

## 5. この測定で分かった測定側の教訓

- **1条件で測っていた**こと自体が最大の穴だった。実デッキ（ナミ/シャンクス/エネル/黒黄ルフィ）は
  歴代のアリーナで一度も対局していない。判定Aで旧結論が再現したのは幸運で、
  判定Bのように**条件を変えると結論が持たない**ケースが実在する。
- 生成デッキはカードDBの広い範囲を実プレイに乗せるので、**判定のついでにエンジン欠陥が出る**
  （void 20件・箱の暴走1件）。`deck_synth_audit.py` の 137リーダー監査（別途 ok=137 に是正済み）と
  合わせ、測定の広さがそのまま品質ゲートの広さになる。
- void は**必ず件数を出す**。除外を黙ると母数が減っただけの表が「全部測れた」ように見える。
