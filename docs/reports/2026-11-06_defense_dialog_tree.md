# 相手の手番の戦闘中の効果の対話を短い木で読む（WP `rs-defense-dialog-tree`・2026-11-06）

仕様は `docs/search_efficiency_plan.md` §7.85・台帳 2+529。根拠は `docs/reports/2026-11-06_reaudit_r29f4.md` の §4・§6(A)・§9（点 4462251・4461056）。
土台は本線 `2a3cf74`。生の記録と台本は `n1_results/defense_dialog_tree/`。**エンジンの既定の挙動は変えていない**（旗の既定は off＝1 bit も同じ・golden は作り直していない）。

## 0. 結論（先に）

1. **旗 `defense_dialog_tree`（off／life1／all・既定 off）を入れた**。相手の手番・戦闘中に自分が答える効果の対話（任意の効果の確認・探して選ぶ 等。ブロッカー／カウンターは対象外）を、
   戦闘の応手と同じ短い木（`sims ÷ 候補の数`・世界 2 本）で比べる。life1 は自分のライフ ≤ 1（`window_tree_life`）のときだけ、all はライフを問わず。
2. **指示書の字面の形（候補を戦闘の終わりまで畳んでから木）では 4462251 は直らなかった**。畳むときに、受けた後の対話の続き（「どれをレストにするか」）を
   1 段浅い静的な値で選び、間違った札をレストにした先を木が読む（受ける −0.99／断る −0.987 で断る・8 seed とも）。
   **候補を当てた直後の盤面から木を回す形に替えると直る**（受ける +0.96〜+0.99 対 断る −0.99・8 seed とも受ける）。これを旗の既定の読み方にし、
   字面の形は測定専用の旗 `defense_dialog_fold`（既定 false）で残した（§2）。
3. **4462251・172**（ライフ 0・ラッキー・ルウの確認）: 16 局の打ち比べ（今のターンの残りも旗つきの出荷の設定）で **off 0／16（16 局ともこのターンに負け）→ life1・all 16／16 勝ち**。
   **4461056・63**（ライフ 3）: life1 は対象外で手は同じ。all は 8 seed とも断る（報告の b の手）。打ち比べは本当の盤面 0.75 → 0.875・配り直し 0.75 → 0.81（16 局・区間は広い）。
4. **守りの再監査（seed 4462000〜4462299・変わった局だけ打ち直し）**: 確かめ後の見逃し（甲）は
   **life1: 6 → 0**（分かれた局 52）・**all: 9 → 4**（分かれた局 119）。打ち比べで勝率に残る点は **どちらも 2 → 0**（4462251 と 4462001 が消える）。
   all で新しく出た甲の 3 点はどれも勝率に残らない（CPU の手で 1.00 が 2 点・どちらでもほぼ負け 1 点）。予告（−1〜−3 点・作る点 0〜1）より大きく減ったが、局が分かれるので点の数の差には局の入れ替わりが混ざる（§5 留保）。
5. **費用**（出荷の設定・20 局・1 コア）: 1 手の平均 off 0.641 秒 → life1 0.650 秒（**+1.4%**）→ all 0.684 秒（**+6.7%**・中央値は 0.208 → 0.320 秒）。予告（+5% 以内）は life1 は内、all は少し超える。
6. **ゲート**: cargo 643 passed・pytest 914 passed／16 skipped（`OPENBLAS_CORETYPE=Haswell`）・golden 不変（作り直し不要）・`make audit-cross` void 0。
7. **本番アリーナ**はジョブ定義 `opcg_sim/loop/jobs/arena_ddt.json` を push 済み（コーディネータが起こす・§4）。既定にするかはアリーナの結果を見てユーザ判断。

## 2. 実装（`rust/opcg_engine/src/search/decide.rs`）

- `DecideOptions::defense_dialog_tree`（`DefenseDialogTree::{Off, Life1, All}`・opts の鍵 `"off"／"life1"／"all"`・知らない値はエラー）と `defense_dialog_fold`（bool・既定 false）。
- `defense_dialog_tree_applies`: `active_battle` が在る・手番は相手・勝者なし・中断スタックの対話の答え手が自分（`active_interaction().player == name`）・
  Life1 なら自分のライフ ≤ `window_tree_life`。ブロッカー／カウンターの段は対話ではない（`pending_actor_action` の phase の側）ので対象外＝今の短い木（§7.42・§7.45）のまま。
- `window_choice`: `tree = 戦闘の応手の木 || 守りの対話の木`。木の世界の本数・予算は戦闘の応手の木と同じ（`min(K, window_tree_worlds)`・`sims ÷ 候補の数`）。
  `tree_branch_values` に「先に畳む手数」を足し、守りの対話の木は既定 0（候補を当てた直後の盤面から木）、`defense_dialog_fold` なら今の `QUIESCE_MAX_PLIES`（戦闘の終わりまで畳む）。
  戦闘の応手の木は今までどおり畳む（1 bit も変わらない）。
- **なぜ畳まないか**（4462251・`probe_4462251.py`・`reads_4462251.txt`）: 受けた後に「相手のリーダーかキャラ 1 枚をレスト」の選択（5 候補）が出る。
  ここを根で読むと OP11-077（まだアクティブのアタッカー）が −0.263・他の 4 枚が −0.742。畳む形は候補の評価の中でこの選択を `BOX_RESOLVE_DEPTH − 1` の浅い値で選び、
  −0.742 側の札をレストにする → 次のアタックで負ける盤面から木を回す → 受けるも −0.99。畳まない形は木の中で選択を読み（木の中の箱は深さ 1 の値で OP11-077 を選ぶ）、
  その後のブロッカー（OP17-029）まで読んで +0.96〜+0.99。
- 配線: `opcg_sim/api/engine_rs.py`（`defense_dialog_tree=`）・`arena.py --cand-defense-dialog-tree`・`arena_shard --defense-dialog-tree`（基準席）・
  `defense_audit.py --defense-dialog-tree`・`rs_decide_latency.py --defense-dialog-tree`・`blunder_audit.py winstab --opts`（既存の汎用の口）。畳む形は `--extra`／opts の `defense_dialog_fold`。
- 単体テスト `rust/opcg_engine/src/search/tests_defense_dialog_tree.rs`（3 本）: opts の鍵・ラッキー・ルウ（OP17-033）の【相手のアタック時】の確認で off は既定と出力まで同じ・
  life1 はライフ 1 で木（世界 2 本）・ライフ 3 は今の形・all はライフ 3 も木・畳む形も木・off なら畳む旗は効かない・戦闘の応手の窓（ライフ 1／3）は旗で出力まで同じ。

## 6. 留保・notes（迷った点）

- **指示書の「同じ `tree_branch_values`」から外れた**: 畳んでから木では 4462251 が直らない（§2）ので、守りの対話の木は候補を当てた直後から木を回す形を既定にした。
  字面の形は `defense_dialog_fold=true` で測れる。本番アリーナは畳まない形で組んだ。戦闘の応手の短い木（ブロッカー・カウンター）も同じ弱さ（カウンターの 2 枚目を浅い値で選ぶ）を
  持ちうるが、今回は触っていない（既定の挙動を変えないため・別の WP の候補）。
- **見逃しの数の減り方は大きいが、局の入れ替わりが混ざる**: 分かれた点から先は別の局になるので、点の差は「旗で直した点」と「別の局面に来たので現れない点」の和。
  直した点として確かめられたのは 4462251 だけ（4462001 は局が先に分かれた）。勝率への効き目はアリーナでしか言えない。
- **判定不能の率が入れた形で少し高い**（life1 27.5% → 32.1%・all 24.9% → 26.8%）。判定不能の点に見逃しが隠れている可能性は両方の形に在る。
- **all の手の変わり方が多い**（木が掛かる点の 25%）。ライフに余裕がある点では静的な値と木で手が割れやすく、アリーナの副が負に出る余地がある（4461056 は木の側が良い向き・16 局で有意ではない）。
- 4461056 の打ち比べは 16 局で、0.75 → 0.875 の差は区間の中（報告の確かめは 24 × 審判 2 本で +0.48 だった・こちらは今のターンの残りも旗つきの出荷の設定）。
- life1 の線は `window_tree_life` を共有する（上げると戦闘の応手と守りの対話の両方が動く）。別の鍵にはしていない。
- 作業中にワーカーの再起動が 1 回あり、life1 の部分監査を途中（48／52 局）から再開した（器は局単位で再開できる）。2 回目の打ち直しの数と一致した。
