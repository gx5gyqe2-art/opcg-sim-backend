# v47b — 対面依存バイアスの正体: エネル席の +0.42 と、その裏にあるエンジン側の疑い（2026-08-09）

v47 手順1 が残した宿題「対面依存バイアスは実在するか」に、`bg_luffy` 系を増量して答える。
結論は**実在するが、value の較正問題ではない**。本文書は 110対局・1320盤面・4対面 時点の
スナップショット（追記改変しない）。生成は `bg_luffy:shanks` のみ継続中。

計器: `value_label_gen.py`（生成）/ `value_calibration_audit.py`（監査・本作業でドン層別と
手番リーダー別を追加）。

## 0. 結論

1. **共通の系統誤差は無い**（110対局プール +0.031 ±0.060→±0.044）。v47 手順1 の結論は維持。
   **訓練対面（nami:shanks）は水準が合っている**（両席とも ±0.03）＝計器も本体も健全。
2. **対面依存バイアスは実在した**が、正体は対面ではなく**リーダー**だった。手番で割ると
   **エネル席 +0.42・相手席 −0.23〜−0.27**。自リーダーが違う2対面で +0.419 / +0.428 とほぼ同値。
3. **ただしこれを value の誤りと読んではいけない**。同じ盤面の実測ロールアウト勝率は
   エネル席で 3〜34%。**シミュレータの中のエネルがほとんど勝てていない**。ラベルは同じ
   エンジンの自己整合基準なので、エンジンがエネルを回せていなければラベルの側が誤りで、
   それに対する「バイアス」は本体 value の欠陥を意味しない。
4. したがって**次の一手は較正ではなく、p_enel が正しくプレイされているかの確認**。

## 4. 「ドン最大6枚だから楽観している」仮説の検定（ユーザ提案）

OP15-058 紫エネルのルール変更は実在する（`docs/leader_specs/OP14-15.md`）:

> ルール上、自分のドン‼デッキは6枚になる。/【起動メイン】【ターン1回】自分の第2ターン以降の
> 場合、ドン‼デッキからドン‼1枚までをアクティブで追加し、さらに4枚までをレストで追加する。
> その後、自分のキャラ1枚にレストのドン‼4枚までを、付与する。

しかしドン差で層別すると**向きが合わない**。

| ドン差(自−相) | bg_luffy:p_enel | nami:p_enel |
|---|---|---|
| < −0.5 | **+0.342 ±0.129** | **+0.210 ±0.117** |
| −0.5〜+0.5 | +0.189 ±0.277 | +0.297 ±0.259 |
| +0.5〜+2.5 | +0.153 ±0.178 | +0.184 ±0.301 |
| > +2.5 | −0.125 ±0.190 | −0.032 ±0.147 |

楽観が最大なのは**自分のドンが少ない層**で、ドンが多い層ではゼロ〜負。「相手のドンが
少ない＝有利と誤読」なら並びは逆になるはずで、**ドン数の直読みでは説明できない**。
そもそもドンキャップだけを見るなら、ネットはエネルを**過小**評価する側に倒れるはずで、
実測は逆（過大評価）。

なお `相手ドン総数` は encoder では**未付与のドンのみ**（付与済みは各キャラの
`attached_don` へ移る）なので、この層は「ドンデッキの上限」ではなく「手元に浮いているドン」を
見ている。上限の効果を直接測る層ではない点は割り引くこと。

## 5. 実測勝率——シミュレータのエネルは勝てていない

序盤帯（turn_count < 7・対面の地力に近い）に限った実測:

| 対面 | 手番 | 実測 | 予測 |
|---|---|---|---|
| bg_luffy:p_enel | エネル | **33.6%** | 58.2% |
| **nami:p_enel** | **エネル** | **5.3%** | 43.9% |
| bg_luffy:shanks | BGルフィ | 30.7% | 30.4% |
| **nami:shanks（訓練）** | ナミ | **67.6%** | 69.3% |

訓練対面では実測と予測が 67.6 / 69.3 とほぼ一致する＝計器は正しく動いている。その同じ計器で、
**エネルはナミ相手に 5% しか勝っていない**。

ユーザの実プレイ知見は「エネルはリーダー効果・6コストのキャラクターエネル・除去と多彩で、
実際は勝率が出ている」。それが正しいなら、現実から乖離しているのは**ネットではなく
シミュレータの側**である。ネットは「エネルは五分弱」と言い、シミュレータは「5%」と言っている。

**最も安い対抗仮説は潰した**: リーダー能力は発動している。エネルの自ターン盤面のうち
51.8〜54.7% で「リーダー能力ターン1回使用済み」フラグが立つ（対照: シャンクスは起動能力を
持たず 0.0%）。「能力が一度も撃たれない」型のバグではない。

残る候補（本文書では未検証）:
- 6コストのキャラクターエネル・除去カードの実装
- 「レストのドン‼4枚まで付与」の up-to 選択を探索が下手に解決している
- `tests/fixtures/decks/user_decks_20260728.json` の p_enel が意図した構築でない
- この4デッキ環境では実際にエネルが弱い（＝エンジンは正しい）

## 6. これが v47/v47b の結論をどう書き換えるか

**撤回**: 中間報告で「対面依存バイアスは実在の側」と述べ、value の較正対象として扱おうとした。
実在はするが、**value の較正問題として扱ってはいけない**。ラベルは同じエンジンの
ロールアウト勝率＝自己整合基準であり、エンジンがエネルを正しく回せていなければラベルが誤る。
これは `cpu_v47_value_calibration_audit_20260809.md` §3 で「自己整合基準の限界」として
自分で書いた注意が、そのまま現実になったもの。

**維持される結論**:
- 本体 value を再学習する根拠は無い（プール +0.031 ±0.044・共通の系統誤差なし）。
- 単調再較正も当てない。`ValueNet.set_calib` は既定 None＝bit 恒等のまま置く。
  そもそも席ごとに符号が逆の誤差は、写像を1本しか持てない単調変換では消せない。
- パッチ（裁定注入・出口ヘッド）戦略は支持されたまま。

**未解決**: `bg_luffy:shanks` のシャンクス席 −0.308（同じシャンクスが nami 対面では +0.027）。
エネルとは別系統で、BGルフィ側の要因。標本 30対局・要追試。
