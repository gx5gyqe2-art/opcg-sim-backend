## TL;DR

  244,544行**・v6符号化・生成ネットは gen8 の v6 恒等拡張＝挙動 gen8 同一）。
- **判定: 昇格なし（FAIL）**。防御混合腕はコーチゲート v3 **PASS**（セッション初・6.1 vs 4.7・

  serve の ctx(v6・+5列) を v5 policy の `_fit_actions` が行動特徴の末尾ズレと誤解釈し、
  **行動特徴全列が5列ずれた重みで読まれ priors が無意味になる**（クラッシュせず黙って壊れる）。
  `dense_finetune` が候補 policy を value と同版へ恒等拡張して保存するよう修正済み（テスト追加）。
- **フェーズ2の主要測定は全て本欠陥の産物だった**（§3 正誤表）。「防御単独学習で分布崩壊
  (0.042)」も「守り採択率 0.289→0.55 の機構成立」も誤り。正しい計器では、防御CFコーパス

## 2. 判定（すべて版整合の正しい計器）

| 計器 | 主腕 | 防御混合腕 |

| アリーナ screen | 0.438（48局・reject） | 0.550（40局）→ 追加40局込み 0.5125 |

読み: コーチゲート初 PASS は実質的な前進（人間検証14点の軸では gen8 より明確に良い手を

「コーチ改善とアリーナは別の量」の最も精密な実測。密度レシピは v16(gen7)・v19(gen8) の
2勝から v17・v25 の2敗となり、勝敗は**分布の新規性の有無**と揃った（gen7=初の密度、
gen8=初の対面特化。v17/v25=新規性なしの再生成）。

## 3. フェーズ2測定の正誤表（計器欠陥: value v6 / policy v5 の版不整合）

| 測定（`defense_cf_phase2_20260731.md` 記載） | 旧値（壊れた計器） | 正値（版整合） | 帰結 |
|---|---|---|---|
| 腕C（防御単独）アリーナ screen | 0.042 → 「分布崩壊」 | **0.550**（40局） | 「狭分布の単独学習で崩壊」という結論は**誤り**。崩壊は版不整合の産物 |
| 腕F（密v19混合）アリーナ screen | 0.479 | 再測定不能（対局が異常長時間化・打切り。v25 防御混合腕が正しい後継） | — |
| 守り採択率（腕、45窓×8seed） | 0.55–0.56 → 「機構成立」 | **0.286**（gen8 0.289 と同値） | 「def_temp CF 教師で守り採択が動く」は**未実証に戻る**。旧値は壊れた priors がランダム寄りに守っただけ |
| コーチゲート（腕C/E: 5.1 vs 4.7） | 改善 OK | （腕は上記のとおり無効。v25 の版整合腕で PASS を実測） | フェーズ2の腕の coach 値は無効 |

フェーズ1（def_temp プローブ・人間整合 12/13）は**影響なし**: ロールアウトは出荷 gen8
（v5 value + v5 policy＝整合）で行われており、本欠陥の経路を通らない。

教訓: (1) **異常に良い/悪い測定値はまず計器を疑う**（0/48 全損が発見の入口だった。0.042 の
時点で疑うべきだった）。(2) 符号化版は value/policy/ctx の**三者で一致**が契約＝
`dense_finetune` は候補 policy を value と同版へ恒等拡張して保存する（回帰テスト
`test_dense_finetune.py::test_policy_copy_follows_value_enc_version`）。(3) `_fit_actions` の
「黙って合わせる」互換層は ctx 幅の変化を検出できない＝新しい符号化版を足すときは
serve 経路の全ネットの版を揃えてから測る。

## 5. 次の一手の材料（判断はユーザと）

1. **コーチ PASS × アリーナ僅差負けの解釈**: 人間検証点の改善は本物（退行ゼロで +1.4）。
   アリーナの -3〜5pp は自己対戦分布での総合力。両者を同時に満たす学習信号が次の課題。
2. 密度レシピは新規性が無いと効かない、が3例目で確定的に。次に新規性を足す候補:
   別対面の追加（ユーザ4デッキの残り対面）・L1 混合席・def_temp 生成の本格混合。
3. 手札集約特徴（v6）は恒等スタートから 2 epoch では武器になっていない（採択率不変）。
   特徴が効くには防御の結果差が出る教師（フェーズ1の def_temp 世界）を密で回す必要がある。
