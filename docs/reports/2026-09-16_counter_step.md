## 結論を 5 行で

1. **相手が実際に切る枚数を超過 `x` の 1000 刻みで並べると、x=0: 1.0・x=1000: 1.2〜1.3・x=2000: 1.9・x=3000: 2.3・x=4000: 3.5〜3.7**。
   これは費用曲線 `CBAR_CURVE`（1.00／1.28／2.25／2.78／3.63）を **1 段ずらした値** `c̄(x+1000)` に乗る。旧 `c_of(x)` は `c̄(x)` を引いていた。
2. **理由はルール**: 戦闘は「攻撃側 ≥ 対象で命中」（`rules/battle.rs`・同値は命中）。生き残るには超過を**上回る**合計（x+1000 以上）が要る。
   曲線の節は `deck_profile.c_min`（合計 ≥ v）で作ってあるので、超過 x には節 x+1000 を引くのが正しい。x=0 だけ偶然合っていた（罠 33）。
3. **直した結果（`CBAR_MODE=strict`・2026-09-16 から既定）**: 攻撃の `実現/価格` は **実 1.20 → 1.05・合成 1.34 → 1.14**。
   x=2000 のリーダー攻撃 1.48 → 1.20／1.44 → 1.17・キャラ狙い 1.81 → 1.12／1.73 → 1.10。`ν` の中盤の帯も 0.94 → 1.09／0.84 → 0.96。
4. **残りの 5〜15% は相手の状態**: 受けるか切るかは相手の手札枚数で決まる（x=2000 で手札 0〜1 枚なら 92〜96% 受け・6 枚以上なら 37〜49%）
   ＝デッキ側の「止められない確率」と同じ向き。低ライフほど切る（受けられない）。式の `min` は「選べる・選ぶ」を仮定している。
5. **橋の `ΔG` は 0.700 → 0.678／0.695 → 0.672 と下がる**が、攻め側は不変（0.721 → 0.724／0.795 → 0.783）で、下がったのは**守り側**

   曲線を戻す理由にはならない。

## 3. 読み方

- **不足の本体は曲線の 1 段のずれ**だった。式の形（`min`）は正しく、引き方が違っていた。訂正は新定数ゼロ。
- 残りは「選べない」（手札・デッキ側の `p_cant`）と「選ばない」（低ライフで受けられない＝相手側の `λ(L)`）。前者は理論の側で
  書ける（相手デッキ既知・手札枚数は状態）が、今の平均では x=2000 で +4% 程度。後者は相手側の状態依存の価格＝T19 の `λ` の水準差の話。
- **守りの半分が橋を引き下げる**: 守りの `g` は費用だけを数えるので、費用が正しく高くなるほど「守る席は損」に見える。守って残した
  ライフ・体の価値を `g` に足す（P8 の守りの半分・記録の項目）まで、`ΔG` 全体の数字は守りに引きずられる。

## 4. 次（ユーザ判定）

1. `CBAR_MODE` は `strict` を既定にした（ルールの訂正）。戻す理由は無いが、以前の数字と比べるときは `loose` を明示する。
2. 守りの `g` に「残したもの」を足す（P8 の守りの半分）——`ΔG` 全体の改善はここで止まっている。
3. 「選べない」を価格に入れるか（`p_cant(x+1000 | 相手の手札)` で `min` を期待値に・新定数ゼロ・効きは小さい見込み）。

## 限界

- 切った枚数は手札の差分（イベントの +3000 等で枚数は下がる）。応答は差分から読む（T48 と同じ）。
- **観察であって因果ではない**。
