**回帰しない・当てはめない**（**新定数ゼロ**・攻撃の価格は `attack_value_don`・枠と切れるかは規則）。本報告は特定時点のスナップショット。
器は `crossing_bridge.THETA_HAND_MODE=cuttable`・`SLOPE_MODE=hand`・`playable_attack_price`・`seat_slope`。他の切替は T76 のまま。

## 結論を 6 行で

1. **置き場所を分けた**: 手札の札の**出す価値**は「1 ターンに積む損害」（**速さ**）へ、**守る価値**は「殺すのに要る損害」（**しきい値**）へ。
   T67 以来 `max(ΔH_play, ΔG_guard)` で 1 つに潰していたものを、潰さずに別々の場所へ置いた。
2. **守る側の形は T76 の失敗から決めた**: **`F`（損害）と `Θ`（耐久）は同じものに同じ値段を付けなければならない**。`F` は切らせた札 1 枚を `μ` で
   数えるので、`Θ` の手札項も切られる札 1 枚 `μ`・**切られない札（カウンター値 0）は 0**（`cuttable`）。T76 の失敗は `F` が `μ` で数えている物に
   機会費用という別の値段を付けたことだった。
3. **T76 の交絡が消えた**: `cuttable` の 1 枚あたりは**勝った席 0.0380 対 負けた席 0.0387**（実）＝ほぼ同じ。T76 の `quality` は 0.0377 対 0.0454 と
   負けた席の方が高かった（＝強さと逆）。予告どおり、切れるかどうかで数えると偏りが消える。
4. **効いたのは速さの側**: 勝者の的中は 実 0.609 → **0.635**（速さだけ）→ **0.637**（両方）・合成 0.636 → 0.637 → **0.640**。
   `cuttable` 単独では実 0.603／合成 0.638＝**単独では動かないが、速さと組むと両方の記録で最良**になる。
5. **いちばん大きく動いたのは時計**: 終局の予測の偏りが **6.6 → 3.0 ターン**（実）・6.7 → 3.2（合成）、σ 5.1 → 4.1／5.3 → 4.4、
   `τ` の中央値 9.0 → 4.6／9.0 → 4.6（実際の対局の長さに近づいた）。**手札を数えないと、理論は相手が死ぬ時刻を 6 ターン先に見積もっていた**。
6. 線形の橋は**既定（`flat`）では `Θ` も速さも使わない**ので不動（再実行して数字が完全に一致することを確認: `ΔG` 0.9202・接戦帯 0.6631・傾き 10.934）。既定の切替は**ユーザ判定**。ゲート green（Rust 429・pytest 1,157）。

## 1. 器（式は 2 行）

```
しきい値  Θ = λ·L + μ · #{手札のうちカウンター値 > 0 の札} + Σν_meas(アクティブなブロッカー)      （THETA_HAND_MODE=cuttable）
速さ      A = Σ(今の盤面の攻撃手の攻撃の価格) + Σ(今のドンで手札から出せる体の攻撃の価格)        （SLOPE_MODE=hand）
τ = Θ_相手 / A_自分（あと何ターンで届くか）・勝者 = τ が小さい席
```

- 「今のドンで出せる体」は費用の合計がアクティブなドンを超えない範囲で攻撃の価格の和が最大になる組（小さなナップサック・規則どおり）。
  イベント・ステージ・パワーの無い札は 0。**新しい定数は無い**。
- 手札の中身はその席の行にしか無い（記録に相手の手札は無い）＝**両方とも「その席自身が見ている手札」から作る**。攻める席から相手の手札を
  推定する器（残りの山の平均）はまだ無い（T75 が `κ` でそうしたのと同じ順序＝**まず項が正しいかを確かめ、推定器は次**）。

## 3. 読み方

- **上手くいった**: ユーザの提案どおり 2 つの価値を分けて別の場所に置くと、**両方の記録で勝者の的中が上がった**（T52 以来はじめて）。
  分けたこと自体より、**出す価値を速さに移したこと**が効いている。理論は今まで「手札は耐久」としか扱っておらず、
  **手札から出て殴る分を 1 ターンの損害に数えていなかった**。だから終局を 6 ターン先に見積もっていた。
- **`cuttable` は単独では動かないが、交絡は消えた**（勝／負の `g` がほぼ同じ）。T76 の退行が「量の誤り」ではなく「値段の付け方の誤り」
  だったことの確認になる。単独で効かないのは、切れない札の割合が席によってあまり変わらないため（1 枚あたり 0.038〜0.039＝`μ` の約 0.7 倍で安定）。
- **単位の検算は少し悪化する**（`F_end/Θ_start` 1.137 → 1.180・1.049 → 1.092）。`Θ` から切れない札を抜いた分だけ小さくなるので当然で、
  **`F` の側も「切られた札」だけを数えるべき**（今は相手の手札の減りをすべて `μ` で数えている）＝次の整合。
- **時計が合ってきた**: `τ` の中央値 9.0 → 4.6 は実際の残りターン数に近い。交点の橋は「どちらが先に届くか」を見る器なので、
  両席の時計が同じだけ速くなっても勝者の的中は変わらない。**変わったということは、手札の分が席によって違う**＝情報が入った。

## 4. 次（ユーザ判定）

1. **既定を `cuttable` ＋ `hand` にするか**（交点の橋という計器の既定。CPU の打ち方は変わらない）。**推奨: する**（両方の記録で改善・内部矛盾も 1 つ減る）。
2. **攻める席から相手の手札を推定する器**（残りの山の平均で「切れる札の割合」と「出せる体」を見積もる）＝**この 2 つを CPU が使える形にする段**。
3. `F` の側の整合（切られた札だけを `μ` で数える）。
4. §0.6 の残り 3（アタック時・常時の能力を攻撃の価格に載せる）。

## 限界

- 両方とも**その席自身の手札**を使う＝攻める席が持たない情報。推定器は未実装（次）。
- 速さは「今のドンで今出せる体」だけ。次のターン以降にドンが増えて出せる札は入らない（T73 の時計は計画側にしか入っていない）。
- 出した体は召喚酔いで次のターンから殴るが、速さには即座に入れている（複数ターンの地平では近似）。
- 線形の橋の `curve`（`W_MODE=curve`）は自分側だけ `cuttable` になる＝非対称のまま（T76 と同じ・推定器待ち）。
- **観察であって因果ではない**。
