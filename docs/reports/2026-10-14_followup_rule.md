## 0. まとめ（カードゲームの言葉で）

1. **攻撃の候補の後続**【コード】: その攻撃（ドンを付けてから殴る箱）を盤面に適用し、**その 1 回の戦闘だけをエンジンで解決**してから時計を読む。
   - 守る側のカウンター・ブロック、攻める側の選択は、探索の葉と同じ既定の規則（ネットの方策が一番高い手 → パス → 先頭）で決まる。
   - そのターンに残る他の攻撃は、エンジンでは解決しない。
2. **殴らない候補（出す・付ける・起動）の後続**【コード】: その手を適用し、開いた窓（【登場時】の選択など）だけを同じ規則で閉じて時計を読む。**そのターンにはまだ攻撃が残っている盤面**を読む。
   - パス（ターン終了）は、そのターンの行動を全部手放した盤面（アクティブなドン 0・攻撃できる体なし・出せる札なし）を読む。
3. **大事な点**【コード】: 時計の読み（相手の耐久）は、どの後続でも「**そのターンに残る攻撃**」を理論の計画（ドンの付け方・出す札・守る側の最善の守り）で数えている。
   - 殴らない候補の後続でも、残りの攻め手で殴る計画は入っている。「まったく殴らない」と読んでいるわけではない。
   - 違いは、**最初の 1 回の攻撃を、エンジンが解決した結果で読むか、理論の計画（守る側の最善の守り）で読むか**だけ。
   - 攻撃の候補では、その 1 回はエンジンの守り（ネットの方策）で解決済み。殴らない候補では、同じ攻撃が理論の計画の中で「守る側の最善の守り」で止められる見込みで読まれる。
   - `2026-10-14_counter.md` では、理論は手札で止める攻撃を実際の 2〜3 倍に見込んでいた。殴らない候補はこの見込みの中で読まれるので、損に読まれる【推測】。
4. 「両方の後続を同じ地点で比べる」形は、**殴らない候補の後続でも、理論の計画が最初に殴る 1 回をエンジンで解決してから読む**のが、攻撃の候補の値段を 1 ビットも変えない形（§4）。
   - どの 1 回を殴るかに判断が要る（§3）。
5. 判断を求めることは無い（読み取りの報告）。式の候補はユーザの判断の後。

## 1. 攻撃の候補の後続（コードの場所つき）【コード】

### 1.1 後続の盤面の作り方（表）

後続の盤面は、手の値段の表（`tests/scripts/clock_succ.py`）が局ごとに作る。理論（Rust）はその表を読むだけ。

- `clock_succ.py::replay_game` が記録の局を記録と同じ設定で打ち直す。自席ターンのメインの行（候補 2 本以上）ごとに、候補（束の代表手）ごとの後続を `successor()` で作る。
- `successor(game, name, turn, mv, opts)` の流れ:
  1. 盤面の複製 `game.fork()`。既定は並びを知らない形で、行ごとに 1 回混ぜ直した複製 `game.fork_shuffled(seed × 100003 + step)` を元にする。
  2. `apply_search_move(name, mv)`（`rust/opcg_engine/src/py_game.rs::apply_search_move` → `search::apply::apply_move_inplace`）。
     - 攻撃の候補は `DON_BOX`（対象つき）＝**付与 k 回 ＋ 攻撃宣言に展開**して適用する（同じ関数の注記）。
  3. `resolve_windows(opts)`（`py_game.rs::resolve_windows`）: 戦闘・対話の窓を、**探索が葉を評価する前に閉じる規則**で閉じる。
     - 「対話の窓 → 戦闘の窓」を最大 4 巡。`search::quiesce::resolve_battle_inplace(…, box_value=false, box_depth=0)`。
  4. 状態の判定: 終局（勝ち・負け）／ターンが渡った／窓が残った／メインの判断に戻った。メインに戻ったときだけ、自分の側・相手の側の符号化した行を表に書く。

### 1.2 戦闘の窓の決め方

`search/quiesce.rs::resolve_battle_inplace` の各手は、次で決まる（`box_value=false`・`box_depth=0` なので枝の評価はしない）。

- 原則は `quiesce_choice`（同ファイル）: **ネットの方策の事前確率が最大の手** → `PASS` → 先頭。
  - 守る側のブロック（`SELECT_BLOCKER`）、カウンター（`SELECT_COUNTER`）、【トリガー】の発動の可否、攻める側の対象選択が、すべてこの規則で決まる。
- 例外（`sel_branch_left`）: 「自分が選ぶ最初の対象選択」だけは、選択の分岐（`select_branch_on`）が入っていれば 1 段だけ枝の値で選ぶ。相手側（守る側）のブロック・カウンターは対象外。
- **どの攻め手が誰を殴るか**: 候補の手そのもの（`DON_BOX` の攻め手 `uuid`・対象 `target_ids`・付けるドン `don_k`）で決まっている。窓の規則が決めるのは、守る側の応じ方と、戦闘中に開いた効果の選択だけ。

### 1.3 戦闘の結果の反映

エンジンが規則どおり反映した盤面を、そのまま符号化した行で読む（Python・Rust の理論は介在しない）。

- 相手のライフが減る（めくれたライフは手札へ・【トリガー】は上の規則で発動の可否）
- 使ったカウンターは手札からトラッシュへ
- ブロックした体はレスト
- KO されたキャラはトラッシュへ
- 攻め手はレスト・付けたドンは付いたまま

### 1.4 時計の読み

理論の側（`rust/opcg_engine/src/theory/core/drv_tb.rs`）:

- `clock_prices` が表の行を読み、候補ごとに `clock_read(後続の自分の側の行, 後続の相手の側の行)` を呼ぶ。
  - その間だけ `leaves_to::set_mid_turn_rules(true)`＝「ターンの途中の局面を規則どおりに読む」（`leaves_to.rs` の `MID_TURN_RULES`）が入る。
- `clock_read` → `curve_d_of_row`。
  - **自分の時計** ＝ `threshold(row, 相手の手札の読み, 攻め手の文脈)`＝相手の耐久。
  - 攻め手の文脈（`outer.rs::attacker_ctx`）は、**そのターンにまだ殴れる攻め手**で作る。
    - リーダーは `leader_attacks_now`（規則どおりの読みでは「今攻撃できる」印が立っているときだけ）。
    - キャラは「攻撃できる」印のあるものだけ。
  - さらに、アクティブなドン（`budget`）・手札から出せる札（`hand_items`・速攻など）・後のターンの攻め手（`later`・このターンに付けたドンの分は `later_don_off` で外す）も入る。
  - 相手の耐久の手札の項は、この攻め手の文脈で**守る側の最善の守り**（`outer.rs::rule_don_term` → `rd_run` → `defender.rs`）を解いて作る。止める数・出す枚数は計画の `stopped`・`cut`。
- したがって、攻撃の候補の後続では、次の 2 つを合わせた盤面から相手の耐久を読む:
  - 最初の 1 回の攻撃をエンジンが解決した結果
  - 残りの攻め手で殴る計画（理論の最善の守りで止める見込み）

## 2. 殴らない候補の後続【コード】

- **出す・付ける・起動**: §1.1 と同じ `successor()` で作る。
  - `apply_search_move` で手を適用し、`resolve_windows` で開いた窓（【登場時】の対象選択・サーチなどの対話の窓）を同じ規則で閉じる。
  - **攻撃は宣言しない**。メインの判断に戻った盤面（そのターンの攻め手はまだ全員殴れる）を読む。
- **パス（`TURN_END`）**: `clock_succ.py::end_of_turn(mine)`。今の盤面で、このターンの行動を全部手放した局面を作る。
  - 自分のアクティブなドン 0
  - リーダーと場の体の「攻撃できる」印を全部 0
  - 手札の「出せる」印を全部 0
  - 相手の側の行は今のまま
- **時計の読み**: §1.4 と同じ `clock_read`。殴らない候補の後続でも、攻め手の文脈には**そのターンに残る攻め手が全員入る**。
  - 相手の耐久は「そのターンに残りの攻め手で殴る計画を、守る側が最善の守りで止める見込み」で読まれる。
  - 「まったく殴らない」とは読んでいない。

**まとめると、攻撃の候補と殴らない候補の違いは、最初の 1 回の攻撃の扱いだけ**:

| | 最初の 1 回の攻撃 | 残りの攻撃 |
|---|---|---|
| 攻撃の候補 | エンジンが解決（守る側はネットの方策の最大） | 理論の計画（守る側の最善の守り） |
| 殴らない候補 | 理論の計画の中（守る側の最善の守り） | 理論の計画（守る側の最善の守り） |

`2026-10-14_counter.md` では、理論の最善の守りは手札で止める攻撃を実際の 2〜3 倍に見込んでいた。そのため、同じ 1 回の攻撃でも、殴らない候補の中では「止められる」と読まれやすい。攻撃の候補ではエンジンの解決（実際に近い守り）で読まれる【推測】。

## 3. (1) の規則を殴らない候補の後に適用できるか【コード＋推測】

「殴らない候補の後続でも、1 回の攻撃をエンジンで解決してから読む」とするときの論点:

| 論点 | 規則から一意に決まるか | 中身 |
|---|---|---|
| (a) どの攻め手が殴るか | **判断が要る** | 攻撃の候補は手そのものが攻め手を決めている。殴らない候補には「次に殴る攻め手」が無い。<br>候補: 理論の計画の 1 段目の最初の攻撃（`xs_first` は付けるドン込みの並びだが、「最初」がどれかは計画の中で順序として持っていない＝順序を決める規則が要る）、または探索の方策が最大の攻撃（ネットの判断が入る） |
| (b) 対象（リーダー／キャラ） | 判断が要る | 理論の計画の 1 段目の攻撃は、相手のリーダーに対する超過で並ぶ（`own_attackers_of` の `x`＝パワー − 相手のリーダーのパワー）。キャラへの攻撃が計画の中でどう扱われるか（除去の効果の項など）はこの報告では辿っていない。対象をリーダーに固定すれば一意 |
| (c) 付けるドンの枚数 | 計画を使えば一意 | 計画の `k`（攻め手ごとの付与）。ただし後続の盤面のアクティブなドンで上限を切る |
| (d) 出したキャラは同じターンに殴れない（速攻を除く） | **一意**（エンジンの規則） | 後続の盤面で「攻撃できる」印が立たない。攻め手の文脈から自動で外れる |
| (e) 付けたドンで攻め手のパワーが変わる | **一意** | 後続の盤面のパワーに入っている（エンジンが反映） |
| (f) 起動効果の後の盤面 | **一意** | `resolve_windows` が対話の窓を閉じた後の盤面。起動で攻め手がレストになる効果なども盤面に入る |
| (g) ターンに残るドンの数 | **一意** | 後続の盤面のアクティブなドン |
| (h) 殴れる攻め手がいない | **一意** | 解決する攻撃が無い＝今の後続のまま |
| (i) パス（ターン終了） | **一意** | 攻撃しない（行動を手放した局面）＝今のまま |
| (j) 戦闘の窓の守り | **一意** | 攻撃の候補と同じ `resolve_windows`（ネットの方策の最大 → パス → 先頭） |
| (k) 盤面を作る場所 | 規則上は一意だが**実務の制約** | 後続は `clock_succ.py`（エンジンでの打ち直し）が作る。記録は古いエンジンで打たれたので、表の作り直しは**記録を作ったエンジン（`a28ededa`）**で行う必要がある（新しいエンジンでは記録と分かれる・`2026-10-14_play_gap.md` §7） |
| (l) 並びを知らない形 | 一意 | 後続を作る前に混ぜ直す種（`seed × 100003 + step`）は候補で共通。追加の攻撃でも同じ複製の続きで解決する |

判断が要るのは (a)・(b)（と (a) に付く (c) の順序）。残りはエンジンの規則か今の後続の作り方で決まる。

## 4. 「両方の後続を同じ地点で比べる」式の候補の形【式の候補だけ・まだ変えない】

### 4.1 形

**殴らない候補（出す・付ける・起動）の後続で、メインの判断に戻った盤面から、攻撃を 1 回だけエンジンで解決してから時計を読む**。

- 攻撃の候補の後続は今のまま（最初の 1 回がエンジンで解決済み）。
- 比べる地点が「エンジンで 1 回殴った後」でそろう。
- 解決する 1 回の決め方（§3 (a)(b)(c) の判断・新定数ゼロ）は、次の 2 つが候補:
  - **A（理論の計画で選ぶ）**: 後続の盤面で理論の計画を解き、1 段目の攻撃のうち最も大きい超過（`x + 1000·k`）の攻め手で、対象は相手のリーダー、付けるドンは計画の `k` とする。理論で選ぶので、新しい判断の源は増えない。順序の規則（最大の超過から）だけを決める。
  - **B（探索の方策で選ぶ）**: 後続の盤面で、探索の葉と同じ既定の規則（ネットの方策の最大）で「攻撃の手」の中から 1 つ選ぶ。窓の規則と同じ源。
- **攻撃しない場合**（殴れる攻め手がいない・パス・相手のリーダーに届く攻め手がいない〔A のとき〕）は、今の後続のまま。

### 4.2 切替と不変量

- 切替の名前: `OPCG_CLOCK_VALUE_FOLLOWUP`。値は `off`（既定）／`plan`（A）／`policy`（B）。
  - 後続の表は別の置き場（例: `<記録>/clock_succ_followup_plan/`）に作る。`theory_bridge.py` は切替に合わせて表を選ぶ。
- **既定は変えない**。既定の表・既定の値段は 1 ビットも変わらない。
- 不変量（切替を入れたときに確かめる）:
  1. **攻撃の候補（`DON_BOX` 対象つき）の値段は 1 ビットも変わらない**（後続を作り直さない）。
  2. パス（`TURN_END`）の値段は変わらない。
  3. 殴れる攻め手がいない行の殴らない候補の値段は変わらない。
  4. 打つ前の局面の読み（`W0`・`κ0`）は変わらない＝値段の差は後続の側だけから来る。
  5. 理論の側（Rust）のコードは変えない。表の作り方（`clock_succ.py`）だけを切替で変える。

### 4.3 留保

- 1 回だけ解決するのは「攻撃の候補と同じ地点」にそろえるため。残りの攻撃は、どちらも理論の計画のまま（最善の守りの読み過ぎは残る）。
- A では「最大の超過から殴る」という順序を新たに決める（定数ではないが選び方）。B ではネットの判断が値段に入る（理論の外の源）。
- 表の作り直しは古いエンジン（`a28ededa`）での打ち直しが要る（実 w41 で約 73 分〔`2026-10-11_theory_map.md` の実績〕・合成も同じく）。

## 5. 測るときの基準（司令塔が固定・そのまま写す）

- **当たり**: 次の 3 つがそろう。
  1. CPU と深い探索が一致した点で、理論がその手を指す割合 **0.45 → 0.6 以上**。
  2. 「正しい手を禁じる率 ÷ 外した手を禁じる率」**0.83 → 0.5 以下**。
  3. 交点の的中（実 **.7260**・合成 **.6717**）が **0.01 以上下がらない**。
