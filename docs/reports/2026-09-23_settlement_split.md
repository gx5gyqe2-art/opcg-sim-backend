# T139: 「詰みを逃した」か「定義に無い守り」かを記録から切り分けた（2026-09-23）

ユーザ指示「そのままT18の前段まで進めたい。もう1段階具体的なタスクに落とし込んでください。」の
タスク分解に基づく実行。T136（決着の定義）が残した 2 種類の不一致——**敗者側の宣言**（決着と
宣言した席が実際には負けた・実 13 行／合成 55 行）と**取りこぼし**（勝者の実際の最終ターンなのに
宣言できなかった・実 38 行／合成 177 行）——を、記録から機械的に切り分ける。

**器**: `tests/scripts/settlement_split.py`（新規）・`tests/test_settlement_split.py`（新規・9 本）。
**記録**: 実 = `w41`（300 局）／合成 = `w39 + w42`（900 局）。テスト 30 → 40 本（`lethal_rule` 側の
`settled_map` 分離を含む・T138a）。

---

## 0. 結論（先に書く）

1. **式（新定数ゼロ）**: そのターンに実際に選んだ攻撃の本数 `attacks_made`（`move_family` が
   `"attack"` と分類する選択の数・`theory_bridge` の T86 `atk_turn_n` と同じ数え方）を、ターン開始時点で
   攻撃できた体の数 `xs`（`lethal_rule.lethal_of_row` が返す）と比べる。**`attacks_made >= xs`（全力で
   殴った）なら定義の穴の候補・`attacks_made < xs`（全力ではなかった）なら CPU の見落とし候補**。
2. **実測（既定＝`LETHAL_STOP_MODE=max`）**:

   | | 実 | 合成 |
   |---|---|---|
   | 敗者側の宣言・全力で殴った | **5／13（38.5%）** | **37／55（67.3%）** |
   | 敗者側の宣言・全力でなかった | 8／13（61.5%） | 18／55（32.7%） |
   | 取りこぼし・全力で殴った | **27／38（71.1%）** | **133／177（75.1%）** |
   | 取りこぼし・全力でなかった | 11／38（28.9%） | 44／177（24.9%） |

   **きれいに 1 つに割れない**——両カテゴリとも「全力」と「一部」が混在する。**実と合成で敗者側の宣言の
   構成比が逆転している**（実は「一部」優勢・合成は「全力」優勢）のも見た目のまま報告する。
3. **事後の観察（測る前の予告には無かった・診断であって式の変更ではない）**: `margin = hits −(life+1)`
   （理論の判定の余裕）を見ると、**両カテゴリともほぼ 1 点に集まる**:

   | | 実 | 合成 |
   |---|---|---|
   | 敗者側の宣言の `margin` | **0（10／13）・1（3／13）** | **0（51／55）・1（4／55）** |
   | 取りこぼしの `margin` | **−1（30／38＝79%）・−2（7）・−3（1）** | **−1（150／177＝85%）・−2（26）・他 2** |

   **敗者側の宣言は 1 度も margin ≥ 2 にならない**（宣言は必ずぎりぎり）。**取りこぼしは 1 度も
   margin ≥ 0 にならない**（見逃しは必ず「あと 1〜2 本」）。**取りこぼしの 8 割が margin = −1 ちょうど**。
4. **`margin=-1` の機構を 1 つ疑い、測って外した**——「守り手がどこまで切るか」（`LETHAL_STOP_MODE`）を
   `max`（切れるだけ切る・既定）から `econ`（T130・受けるより安いときだけ切る）に替えれば、
   理論の予測する stops が減って margin=-1 の取りこぼしが減るはず、と予告して測った。
   **外れた**——`econ` は**両記録・両カテゴリで悪化**:

   | | 実 `max`（既定） | 実 `econ` | 合成 `max`（既定） | 合成 `econ` |
   |---|---|---|---|---|
   | `precision_winner` | **0.9612** | 0.9237 | **0.9368** | 0.9166 |
   | 敗者側の宣言（行数） | **13** | 28 | **55** | 72 |
   | 取りこぼし（行数） | **38** | 40 | **177** | 220 |
   | 取りこぼしの `margin=-1` 割合 | 79% | 80% | 85% | 84% |

   **`margin=-1` の割合はほぼ動かず、行数だけ悪化した**＝原因は守り手の切り方の規則ではない。
   **副産物**: 「詰みの判定には `max`（切れるだけ切る）が正しい既定」という T136 の設計判断を裏付けた
   （`econ` は生死の判定には弱すぎる——受けるほうが得なら切らないという経済合理性は、負ければ終わる
   場面には当てはまらない）。
5. **採否の推薦: 器は採用・機構の探索は打ち切る**（この T では）。**測った量は正確**（規則だけ・
   新定数ゼロ・両記録で符合する `margin` の偏り方）だが、**「なぜ margin がほぼ 1 点に集まるか」は
   1 回の反証で終わらせず、ここで止める**——次の候補は記録に無い情報（個々のカードの保護・トリガー・
   防御側 CPU の探索の精度）で、**P8（記録拡張）か §8.5（CPU の打ち筋）の領域**。

---

## 1. なぜこの切り分けが要るか

T136（`docs/reports/2026-09-23_settlement_definition.md`）は「`precision_winner` が 1 に届かない分は
(a) 定義の誤りか (b) 詰みが在ったのに CPU が決めなかったかのどちらかだが、記録からは分けられない」と
書いて止めていた。本 T はその宣言のとおり、切り分けを実装した。

---

## 2. 器

`attacks_made_by_turn(dirs)` — 局×席×ターン → 実際に選んだ攻撃の本数（`theory_bridge.move_family`
で `"attack"` と分類される選択のみ・`ATTACK` または対象付き `DON_BOX`）。**T86 の `atk_turn_n` と
同じ数え方**を独立に書き直した（`theory_bridge` を import して使い回すと `k>=2`〔スコアリング専用の
制約〕が混ざるので、数えるだけの薄い関数として分離）。

`_classify(rows, attacks_made)` — 行の集合を `attacks_made >= xs` で 2 分し、`margin` を添えて返す。

`collect(dirs)` — `lethal_rule.collect(dirs, dump=…)` の `dump`（T138a で追加された**全宣言行 ＋
勝者の最終ターン行**）から、敗者側の宣言（`declared and winner != w`）と取りこぼし
（`not declared and winner == w and t == t_end`）を抽出し、それぞれ分類する。

**判定の式は 1 か所のまま**（`lethal_rule.lethal_of_row`）——本器は数えて比べるだけで、決着の定義
そのものには 1 行も触れていない。

---

## 3. 上手くいったこと／いかなかったこと

**上手くいった**:
* **T138a（決着フラグの分離）が本 T をほぼ無料にした**——`dump` を渡すだけで欲しい行が全部手に入り、
  新しい記録の読み直しが要らなかった。段取り通りの積み上げ。
* **`margin` を事後の診断として明記して測った**——予告に無い量だが、「式は変えない・観察であることを
  明記する」を守ったので、机上の言い訳ではなく検証可能な事実として残せた。
* **`econ` の予告を立てて測り、外れをそのまま報告した**——「守り手の切り方」という尤もらしい仮説を
  1 回の測定で正確に棄却できた。**この T では 1 回で済んだ**（T129〜T132 のように 4 回外すことなく、
  1 回の反証で「この方向ではない」と判定できた）。
* **`econ` の敗北が副産物として T136 の既定選択を裏付けた**——狙っていた検算ではないが、無駄にならなかった。

**いかなかった／自己批判**:
* **`margin=-1` の真の機構は未解決のまま残した**。「守り手の切り方」を外した後、次の候補（防御側 CPU の
  探索の質・記録に無いカード個別の保護効果）まで測る時間を本 T では取らなかった——**T18 の前段としては
  ここで十分**（切り分け自体は完了し、残りは P8／§8.5 の領域だと分かった）という判断だが、機構を追う
  好奇心を優先して深追いしなかったことは書いておく。
* **敗者側の宣言の実/合成の非対称**（38.5% 対 67.3% が全力）を深掘りしなかった——n=13 は小さく、
  この差が本物か振れかは分からない。次に測るなら合成をもっと大きく取るか、実記録を増やす必要がある。

---

## 4. ユーザ判断をお願いしたいこと

1. **T139 はここで一区切りとする**（推薦）——切り分けの器は完成し、両カテゴリとも「単純な CPU の
   見落とし」だけでは説明がつかないことが分かった（margin の集中は理論側に何かが残っていることを
   示唆する）。**残りの探索（防御側 CPU の探索精度・個別カードの保護効果）は P8／§8.5 に送る**。
2. **次は T137a（2 本の曲線の器）に進む**——設計は完了。`theory_order.score_candidate` と
   `attack_response.parts`（`crossing_bridge.harm_of` と同じ式）を再利用し、局×席ごとに理論の累積
   `G(t)` と実現の累積 `R(t)` を並べる。配線の検算は「勝った席の `R` の合計」を `crossing_bridge` が
   独立に出す `F_end` と突き合わせる。
