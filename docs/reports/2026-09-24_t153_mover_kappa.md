# T153: 線形の橋のκに手番の半ターンをずらす形は要らない——dが進み具合を既に読んでいる（2026-09-24）

T151-6 で `W_MOVER_MODE=half` を採用した際、**1 行の器（線形の橋のκ・`relative_ledger`・`kappa_vector`・
`kappa_needed`）には掛けない**（`mover=False` が既定）とした。理由は「一律 +1/2 は最初の手以外で行き過ぎる」
（T151 で `dG` が両記録で悪化）。理論上の「正しい形」として `theory_order.py` の注に **T153（ターン内の進み具合で
+1/2 → −1/2 に線形にずらす）** を候補として残していた。本 T は**その候補を実装する前に、機構を検証してから決める**
（ユーザ指示 2026-09-17「理論の改善は §0.7 の 9 段のフロー」）。

**手段**: (1) 反証込みの調査ワークフロー（研究 3 本 → 仮説 → 反証 3 本）で機構を確認、(2) ワークフローが予告した
「殺す基準」の 1 つ（`corr(d, moves_played_this_turn)`）を実測。**新しいコードは書いていない**（既定は変えない・
T153 は保留のまま閉じない——下記結論）。

## 0. 結論（先に書く）

**T153（明示的な線形シフトの実装）はビルドしない。理由は「規則上不可能」ではなく「実測で冗長」**——`d` は
すでに**ターン内の進み具合を自然に読んでいる**（下表）。明示のシフトを重ねると同じ効果を二重に数えることになる。

| ターン内の手番位置（`pos`） | 行数（実 `w41`） | mean(`d`) |
|---|---|---|
| 1（そのターンの最初の main） | 3,731 | **0.015** |
| 2 | 3,462 | 0.325 |
| 3 | 3,055 | 0.562 |
| 4 | 2,505 | 0.754 |
| 5 | 1,941 | 0.816 |
| ≥6 | 4,121 | 0.809 |

`pos=1`（ターン開始直後）で `mean(d)≈0`——シフト前提が想定していた「最初の手は +0.5 が正しい」という基準点
そのものが、`d` の生の値でちょうど 0 に近い（シフト無しの `d` の中心が「ターン開始点」に一致）。以降 `pos` が
進むほど `d` は単調に増え（+0.8 程度・ちょうど提案されていたシフトの振幅 `+0.5→−0.5`＝1.0 と同じ桁）、5 手目
あたりで飽和する。**`d` は自席の行動でτ_meが縮み・相手の盤面（静的）に対するτ_oppが動かないことで、ターンの
中で自然にτ_me側が縮む**——これは提案していたシフトが「手で」再現しようとしていた効果そのもの。

**ワークフローの結論（3 本の反証を経た後）**: 「`mover=False` を今のκの既定にする」という運用上の結論は
3 本の反証すべてで支持された。ただし仮説が最初に出した「κは構造的にmoverを受け取れない・T153は撤回すべき」
という**カテゴリカルな主張は 3 本とも反証で退けられた**（`state_factor` の `KAPPA_SIGMA_MODE=match` に
既に時計を渡す前例がある・T153は「保留」のまま台帳に残っている・zero-new-constant は定数の話でシグネチャの
話ではない）。**今回の実測でそのギャップを埋めた**——T153 が要らない理由は「原理的に無理」ではなく
「測ると、その情報はもう `d` に入っている」。

**採用する既定**: 変更なし（`W_MOVER_MODE=half`・κ 等の 1 行の器は `mover=False`・T151-6 のまま）。
**台帳の扱い**: T153 は「保留」から「**検証済み・実装しない（不要と実測）**」に変える。

## 2. 調査（新しいコードは書いていない）

ワークフロー `wgr3cx2wz`（研究 3 本 → 仮説 → 反証 3 本、計 7 エージェント）:

* **R1（dG/dS の機構）**: `g_row = g_v * kap`／`s_row = (played_v - max(scored)) * kap`
  （`theory_bridge.py:757-758`）——**乗数 `kap` は同一**。差は入力の作られ方: `g_v` は
  `LEDGER_HARM_MODE="realised"`（既定）で**次の同席行までの区間に束ねた実現値**に書き換えられ（区間が閉じない
  行は 0・T84 で 2 ターン遅延・T85 で付与はゼロ）——**符号混在・時間的に構造化された生の和**。
  `played_v` は常に単一の `_score(b+ch)` の理論値のまま。
* **R2（dの分布）**: `d` は**手番側の視点**（`τ_opp − τ_me`、自分が先に届くなら正）で、`_kappa_of_row` は
  **その行の実際のライブな盤面**（`sc, tok`＝行 i の生の状態）から計算される——固定されたターン開始のスナップ
  ショットではない。実測（w41・κ が発火した 21,483 行）: mean(d)=0.396・61% が d>0。
* **R3（κの設計意図）**: `κ=w(D)/w̄` は `W` の**導関数**（局所量）として設計されており、`prob_of_d` の
  手番シフトは**ターン開始で固定した2本の時計の積分形**の話——両者は「同じ種類の量」ではない、という
  区別が `theory_order.py` の注に書かれている。

**仮説（反証前）**: 「κは構造的にmoverシフトを受け取れない・T153は撤回すべき」——**3 本の反証すべてが
この結論の一部を退けた**:
* 機構レンズ: dG/dSの非対称の説明が「aggregation（和の形）」ではなく「`g_v` だけが `realised` 規約で
  書き換えられているから」だと訂正（aggregation自体はdG_atk/dS_atkとも同じ「セット合計→対で差」の形で同じ）。
* 概念レンズ: `state_factor(KAPPA_SIGMA_MODE="match")` が既に `t_me`/`t_opp` を受け取る前例がある
  （呼び出し元 `_kappa_of_row` が渡していないだけ）ので「κの定義がmoverを受け取れない」は言い過ぎ。
  「ターン内の位置」は**新しい定数ではなく新しい引数**——zero-new-constant のルールが禁じるのは当てはめた
  数値であって、関数の形ではない。
* 完全性レンズ: `docs/cpu_theory_gap.md` 台帳の T153 はもともと「保留（予告つき）」であり「撤回」と書くのは
  台帳の実際の状態と矛盾する。

## 3. 実測（本 T で追加した検算・§0 の「殺す基準」の 1 本）

ワークフローの仮説が予告 (3) として挙げた検算——**「`corr(d, moves_played_this_turn)` を先に測り、強い正の
相関があれば `d` はもう進み具合を読んでいる＝シフトを足すのは二重計上」**——を実行した（新しいコードは
使い捨てのスクリプトのみ・`theory_bridge.collect()` の該当ループを最小限だけ写し、価格付け〔`ctx`／候補〕は
一切呼ばない。手札価格 `g_hand_of_*` は `None`＝T76 の加点無し）。

* 記録: `w41`（実・300 局・18,815 行）。
* `pos`＝そのターンの何番目の own-turn main 行か（1 始まり）。
* Pearson `corr(d, pos) = 0.1555`（相関係数自体は d の分散が大きく後半で飽和するため弱めに出るが、
  **`pos` 別の平均は単調**——§0 の表）。

**読み**: `pos=1` で `mean(d)≈0`——**まさに「手番シフトが直そうとしていた基準点」**（ターン開始の瞬間は
シフト無しの `d=0` が「五分」であるべき、という直感）に一致している。`pos` が進むほど `d` は単調に増え、
振幅（+0.8 程度）はシフト案の `+0.5→−0.5` の振幅（1.0）と同じ桁。**別の変数を足さなくても、`d` は既に
ライブな盤面から読んでいる**（R2 が示した「行の `sc,tok` はその時点の実際の盤面」という事実の直接の帰結）。

## 4. 不変量

* 本測定は既存の `theory_bridge.collect()` を呼ばずスクリプト内で完結——**既定・出荷コードは 1 バイトも
  変えていない**。
* `curve_d_of_row` の `g_hand_of_opp`／`g_hand_of_me` はどちらも `None`（関数の既定と同じ）——手札価格の
  加点を欠いた `d` である点は注意（T76/T79 の効果はここには乗っていない）。全行を通した傾向（単調増加）
  への影響は小さいと見るが、厳密な値は `theory_bridge.collect()` を通した `d` とは一致しない可能性がある。

## 5. 上手くいったこと／いかなかったこと

**上手くいった**:
* 反証を経たことで、T151-6 で書いた「1 行の器はシフトしない」という運用上の結論を**より正しい理由**
  （d が既に進み具合を読んでいる）に置き換えられた。当初の「aggregation（和の形）の違い」という説明は
  間違っていた（R1 の反証で訂正）。
* 予告していた検算（corr）を実際に走らせたことで、**測らずに書いた式（線形補間シフト）を実装せずに
  棄却できた**——§0.7 のフロー（式の前に検算の予告、実装の前に実測）が機能した実例。

**いかなかった**:
* `w39+w42`（合成）側の同じ検算はやっていない（w41 のみ）。実記録と合成記録で τ の読み筋がどれだけ揃うかは
  T151/T152 で既に確認済みなので優先度を下げたが、**未確認のまま「実測で冗長」と結論している**——今後
  合成側でこの表が崩れる場合は再検討が要る。
* 相関係数（0.1555）だけを見ると弱いという印象を与えかねない——`pos` 別の平均（単調・飽和）のほうが
  実際に効いている構造をよく表す。数字を選ぶ基準を先に決めていなかった（自己批判）。
