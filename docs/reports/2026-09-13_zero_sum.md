# 零和の制約が破れている——両席の値の和が 0 ではなく −0.138

2026-09-13 実測。計器 `tests/scripts/zero_sum_check.py`（新規）。
**二人零和ではミニマックス値は反対称**（`V_me(s) = −V_opp(s)`）で、これは学習した価値が
**満たすべき制約**である（`docs/game_theory.md` §2-2）。にもかかわらず一度も検査していなかった。
本報告は特定時点のスナップショット（追記・改変しない）。

## 測り方

エンジンは盤面を席視点で符号化するので、同じ盤面を 2 回符号化すれば両席の値が出る:

```
h    = game.hidden_json()
V_p1 = net_eval(encode_state(h, "p1"))["value"]      V_p2 = net_eval(encode_state(h, "p2"))["value"]
sum  = V_p1 + V_p2                                    ← 0 であるべき量
```

ネット **r3**（出荷既定）・自己対戦 **24 局・3,380 判断点**・serve の sims。

### 判定に使う量を測る途中で直した（重要）

最初は「1 局面ごとのずれ `|sum|` が 0.2 を超えたら破れ」を事前基準にしたが、**これは誤り**。
2 つの値は**違う私的情報**に条件付けた期待値（p1 は p1 の手札を知り p2 の手札を知らない）なので、
**局面ごとにずれるのは正常**——`|sum|` の大きさは私的情報の量であって欠陥ではない。

零和が縛るのは**平均**である（`z_p1 = −z_p2` と全期待値の法則から、どの情報集合で条件付けても
`E[V_p1] + E[V_p2] = 0`）。よって判定は **`mean(sum)` の 95% CI が 0 を含むか**に変え、
**標準誤差は対局でクラスタ**した（同じ局の行は独立でない＝行数で割ると SE を 10 倍以上過小に見る）。

## 結果

```
sum_mean = −0.13845     対局クラスタ 95% CI [−0.18679, −0.09169]      n = 3,380 / 24 局
abs_mean =  0.19959     （参考・判定には使わない＝私的情報の量の目安）
v_p1 の平均 = 1 席側が高い（先手の利＝実在する）
```

**CI は 0 を含まない**＝零和の制約は破れている。確率に直すと両席の `P̂` の和が
**0.93**（1.00 であるべき）＝**片側あたり約 3.5 ポイントの悲観**。

## これが何を意味するか

`V` は**片側から見た量**を作るのに使われている。例:

- `V_guard − V_take`（守りの読み・`2026-09-13_time_plan_map.md`）
- `V_face − V_board`（攻めの読み）
- 探索の窓のミニマックス（**相手側の価値を自分の価値の符号反転として使う場面がある**）

3 つ目が本質的で、**悲観の偏りが両席に乗っていると窓の畳み込みが系統的にずれる**。
1・2 は「同じ席から見た差」なので偏りの多くは打ち消えるが、**打ち消えるのは偏りが
盤面に依らないときだけ**で、それは確かめていない。

## 切り分けが 1 つ残っている（未実施）

観測された偏りには 2 つの説明があり、**手番側の較正**で分かれる:

| 説明 | 予測 |
|---|---|
| **価値が全体に悲観** | 手番側の `mean P̂ − mean z` も負（例 −0.03） |
| **手番でない席の評価が分布外** | 手番側の較正は 0 付近で、非手番側だけ低い |

後者だとしても**実害は残る**——探索は窓で相手側（＝そのとき手番でない側）の価値を使うので、
分布外の評価がそのまま畳み込みに入る。訓練の行は「決定点の席」からしか作られていないので、
**非手番側の評価は構造的に教わっていない**（`is_my_turn=0` の行は「攻撃を受けている窓」に偏る）。

## 限界

- 1 つのネット（r3）だけ。r5／r10 でも同じ向きかは未確認（**同じ計器で測れる**）。
- 24 局＝局のばらつきは CI に入っているが、リーダー・デッキの偏りは入っていない。
- **`--blind` は対照として無効だった**（設計の誤り）: 両席の手札を落とすと `sum_mean` は
  **−0.665**（CI [−0.788, −0.578]）と**悪化**した。手札が空の盤面は実プレイにほぼ存在しない
  （あれば負け濃厚）ので、**分布外の入力を作っただけ**で私的情報の成分は分離できていない。
  もし `abs_mean` が下がっていれば「ずれの多くは情報差」と結論していたので、
  **この確認が誤った結論を止めた**。私的情報の成分を分離する別の設計が要る
  （例: 相手の手札を**真の中身で**符号化した仮想の「完全情報版」と比べる）。
  副産物: 手札を全部落とすと V が大きく下がる＝**ネットは極端な側では「手札が少ない方が良い」とは
  思っていない**（`∂V̂/∂手札` の符号検査の予備情報になるが、データから遠い外挿）。

## 次

1. **手番側の較正を測る**（上の切り分け・安い）。
2. **r5／r10 でも測る**（世代で悪化しているか・生成役と出荷既定の両方）。
3. 偏りが盤面に依るか（ライフ帯・ターン帯で `sum_mean` が動くか）＝本器の `by_band` で読める。
4. 直し方の候補（**ユーザ決定が要る**・訓練の変更）: 訓練に**反対称の正則化**を足す
   （同じ盤面の両席を評価して `V_me + V_opp` を 0 へ罰する項）。教師は要らない＝
   `z` を増やさずに制約だけ入れられる。
