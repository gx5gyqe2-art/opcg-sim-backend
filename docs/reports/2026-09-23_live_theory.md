# T140: 理論を生の局面から読む橋と「生 = 記録」の検算（2026-09-23）

T18／T141（打ち回しへの介入）は記録の外で理論を使う——打っている最中の対局に「この手は理論なら
禁じる」と問う。T121〜T143 の理論の道具は**すべて記録（npz ダンプ）の行から読む**ので、まず
**記録を経由しない生の局面**から同じ理論値が読めることを確かめる。器は `tests/scripts/live_theory.py`
（新規）・`tests/test_live_theory.py`（新規・24 本）。

**記録**: 実 = `w41` の先頭 10 局（seed 8800〜8811）／合成 = `w39` の先頭 10 局（seed 9700〜9710）。

---

## 0. 結論（先に書く）

**橋は生の局面から記録と同じ理論値を読める**。状態と `Θ`／`A` はビット一致、**候補ごとの理論値は
「記録と同じ精度で比べれば」全 13,483 件が一致**。**全精度どうしでは 0.2% が食い違う**が、これは
**配線の誤りではなく格納精度（float16）の丸めが判定の分岐（しきい値）をまたいだだけ**——原因を
特定し、両方の比較（全精度／キャストを揃えた比較）を器自身に持たせて切り分けた。

|---|---|---|

| **`Θ`／`A` の一致**（自席ターン開始行） | **117／127**（残りは比べる相手が無い先手の初手） | **119／129**（同左） |

## 1. 問い

T121〜T143 の理論の道具（`kappa_vector.state_of_row`／`theory_order.score_candidate` など）はすべて
記録の行から読む——`sc`／`tok`／`ci` は生成時に一度 `game.encode()` した後、float16／int16 へ落として
保存したもの。T18／T141 は生成の外で理論を使うので、**記録を経由しない生の局面から同じ理論値が
読めることを先に確かめておく必要がある**。

## 2. 式（新定数ゼロ・既存の道具の再利用のみ）

* **状態**: `game.encode(name)` が返す `scalars`／`tokens`／`card_idx` を、記録の `sc`／`tok`／`ci` と
  **同じ形**（`record_gen._Recorder.__call__` と同じ reshape・同じ `MAX_CI` パディング）に組む
  （`raw_row`）。
* **候補**: `game.decide(name, opts)` が返す `out`（`stats.legal`／`groups`）と `game.dump_index_json`
  から、**記録の `pol_*` 列と同じ関数**（`record_gen.move_sig`／`record_gen._don_k`／`n_rel.cand_ids`）
  で候補記述子を組む（`raw_candidates`）——独立実装ではなく意図的な共有。
* **理論値**: 状態＋候補記述子から既存の価格式をそのまま呼ぶ——`kappa_vector.state_of_row`
  （`Θ_me`／`Θ_opp`／`A_me`／`A_opp`。`A` は `two_curves_state.state_by_turn` と同じ「両席の直近の
  自席ターン開始行」の運び方をその場で行う・`_LiveState`）・`two_curves._price_row`
  （`theory_order.score_candidate` を帳簿の規約で読み直したもの・T137a の再利用）。

## 3. 検算の作り（「生 = 記録」）

**同じ seed の対局を、記録を作ったのと同じ設定**（`sims=64`・既定ネット・`dirichlet_eps=0.25`・
`temp_turns=4`・`worlds=4`・記録の `decks` モード）**で今ここに打ち直す**
（`opcg_sim.loop.driver.run_game` を直接呼ぶ・`record_gen.play_one` が呼ぶのと同じ経路・対局は seed
から決定的）。打ち直しながら 3 つを比べる:

1. **状態の一致**（`compare_state`）: 生の `(sc, tok, ci)` を記録と同じ float16／int16 へ落とし、
   既存のダンプの同じ行とビット一致するか。
2. **理論値の一致**: 生の状態から読んだ `Θ_me`／`Θ_opp`／`A_me`／`A_opp` と、ダンプの行から
   `two_curves_state.state_by_turn` が読んだ同じ量が一致するか。
3. **候補ごとの理論値の一致**: その行の全候補について、**生の状態**（全精度）から読んだ
   `score_candidate` と、**ダンプの `pol_*` 列**（float16 に一度落ちている）から読んだ同じ候補の値が
   一致するか。**併せて、生の状態にダンプと同じキャストを掛けてから**同じ比較をもう一度行う
   （`diff_candidate_prices` が両方を返す）。

## 4. 予告と当否

| 予告 | 結果 | 当否 |
|---|---|---|
| 状態は完全に一致するはず（同じ関数を同じ引数で呼ぶだけ） | **20 局・3,066 行すべて食い違い 0.0** | **当たり** |
| `Θ`／`A` も完全に一致するはず | **236／256 行が一致・残り 20 行は片方が「比べる相手が無い」で除外＝`missing_offline=0`** | **当たり** |
| 候補の値は**キャストを揃えれば**一致するはず | **13,483 件すべて一致**（`n_diff_after_cast` は 20 局全部で 0） | **当たり** |
| **全精度どうしでは一致しないことがありうる**（しきい値をまたぐ判定がある・配線の誤りではない） | **29／13,483 件（0.22%）が食い違う・`diff_after_cast` を取ると全て消える** | **当たり** |

## 5. 何が起きているか（`PLAY` 系の食い違いの機構）

診断（`d_full` と `d_cast` を候補ごとに並べる）で確認した——**食い違うのは常に `PLAY` 系の候補
（`ATTACH_DON`／`DON_BOX` の付与も一部混じる）で、キャストを揃えると必ず 0 になる**（例: 実 seed 8803
の行 66 で `p_full=0.15379` 対 `p_off=0.14335`・`d_full=0.0104`・キャストを揃えた `d_cast=0.0`）。

`PLAY` の理論値（`theory_order.score_candidate` の `PLAY` 分岐）は**手札の計画価値**
（`ΔH_play` 対 `ΔG_guard` の `max` など・T67／T77）を経由する。この経路には**しきい値の比較**
（条件が成立するか・どちらの値が大きいか・容量の上限に達しているか等）が複数あり、**float16 の
格納精度**（相対誤差 1e-3 程度）が**比較の向き自体を変える**ことがある——値がなめらかに動く量では
なく、**分岐そのものが切り替わる**ので、差の大きさ（0.003〜0.039）は個別の分岐の性質に依る。
**攻撃（`ATTACK`）の価格はこの機構を通らない**ので、20 局とも 1 件も食い違わなかった
（T81 以来「攻撃の型は恒等式が立つ・`PLAY` は粗い」と繰り返し出ている非対称と符合する）。

## 6. 不変量・検算

* **`cand_rows_len_mismatch`＝0**（20 局すべて）——生の候補列と記録の `pol_*` 列は**常に同じ本数**。
  候補の食い違いは「値」だけで「集合」ではない。
* **`rows_kind_mismatch`＝0**（20 局すべて）——生成時の手順（`who`／`turn`／`kind` の並び）を
  1 手もずれずに再現できている。
* **`theta_rows_missing_offline`＝0**（20 局すべて）——「生では読めたのにダンプに無い」
  「ダンプにあるのに生で読めない」という片手落ちが 1 件も無い。

## 7. 上手くいったこと／いかなかったこと

**上手くいった**:
* **`record_gen.play_one` と同じ経路で打ち直すだけで、20 局・3,066 行の状態がビット一致した**
  ——生成の決定性（seed → 対局）を、記録を作った後で独立に検証したのは本 T が初めて。
* **`record_gen.move_sig`／`_don_k`／`n_rel.cand_ids` をそのまま import して再利用した**ので、
  「候補の集合」がずれる余地が最初から無かった（`cand_rows_len_mismatch`＝0 はほぼ保証されていた
  が、実測でも裏付いた）。
* **候補の値の食い違いを見つけたとき、「配線の誤り」と決めつけずに切り分ける対照
  （キャストを揃えた比較）を器自身に持たせた**——結果、原因が格納精度だと 1 回の測定で特定できた
  （`d_cast=0.0` が全件で確認できたため）。

**いかなかった／自己批判**:
* **最初の設計では全精度どうしの比較しか無く、`PLAY` の食い違いを「配線の誤り」と誤読しかけた**
  ——測定して初めて `d_cast=0.0` に気づき、器に `max_abs_after_cast`／`n_diff_after_cast`／
  `diff_full_by_family` を追加した。予告に「一致しないことがありうる」と書けたのは、この診断の
  後だった（測る前には想定していなかった）。
* **`Θ`／`A` の一致率が 92%（117/127・119/129）に見える表示だったが、残りは全部「比べる相手が
  無い」行**（先手の初手）で、実際の不一致は 0 件——表の作り方に注意が要る（本報告では分けて書いた）。

## 8. ユーザ判断をお願いしたいこと

1. **T140 はここで一区切りとする**（推薦）——生の局面から理論を読む橋が動くことを確認し、
   T141（影の介入）で使う土台ができた。
2. **`PLAY` の 0.2% の食い違いへの対応**（推薦: b）:
   a. 何もしない——T141／T18 は生の全精度をそのまま使う（記録経由の比較は本 T のような検算専用）。
   b. **T141 でも「全精度」と「キャストを揃えた値」の両方を出せるようにしておく**——ある手が
      「理論なら禁じる」と判定されたとき、それが安定した判定か、しきい値のすぐそばの判定かを
      区別できる（`live_theory.diff_candidate_prices` の対照をそのまま流用できる）。
3. **次は T141**（影の介入——打ち回しは変えずに「理論なら禁じた手」の率と型を数える）。
