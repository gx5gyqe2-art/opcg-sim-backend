# v26 失敗の原因分析 — 選択的相関破壊と「対比の無いデータ」の構造問題（2026-08-01）

スナップショット（追記・改変しない）。`cpu_v26_forced_defense_20260801.md` §3 の機序を
深掘りし、**なぜ一様強制がダメで、何なら効くのか**を構造として同定する。

## TL;DR

- v26 コーパスの相関破壊は**選択的**だった: 全60スカラーの |corr(特徴, z)| 平均は
  v25 比 **0.97（ほぼ無傷）**、盤面・ライフ系の主要特徴（idx 47-50）は 1.00。壊れたのは
  **手札資源系だけ**（カウンター総量 **0.23倍**・カウンター札枚数 **0.45倍**・手札系
  0.82-0.87倍）。＝コーパスは一般プレイの教師としてはほぼ健全で、**狙った軸だけを
  逆向きに教えた**。腕がパリティ近傍に留まった（全損しなかった）ことと整合する。
- 根本原因は **「周辺相関」と「条件付き対比」の取り違え**: 学ばせたい信号は
  「**同じ局面で**守る/素通しの結果差」（条件付き対比）だが、z ラベルが与えるのは
  状態と勝敗の周辺相関。一様強制は各局面で**片方の枝しか観測しない**まま自然な相関
  （持っている→勝つ）だけを切断するので、対比は生まれず相関だけが消える。
- フェーズ1の CF 測定（同一局面・全枝・同一世界）が人間と整合したのは、まさに
  条件付き対比を直接測っていたから。**測定として正しかった方式を、生成では
  周辺化してしまった**のが v26 の設計ミス。

## 1. 選択的相関破壊の実測（各30シャード・v25 57,236行 / v26 58,619行）

|---|---|---|---|
| 47-50（盤面・ライフ系の主要4特徴） | ±0.37〜0.58 | ±0.36〜0.58 | **0.94〜1.02** |
| 55 手札カウンター総量（v6） | +0.090 | +0.021 | **0.23** |
| 56 手札カウンター札枚数（v6） | +0.158 | +0.072 | **0.45** |

読み: ε強制は「勝敗を決める主要因（盤面・ライフ）」には触れず、「カウンターの保有と
勝敗の結びつき」だけを切った。**value はこのコーパスから『手札資源は勝敗に関係ない』を
学ぶ**——守り採択率が動かなかった（0.289→0.297）直接の説明。アリーナ 0.383 は
40〜120局スクリーンの分解能では v25 の 0.44-0.45 と統計的に強くは区別できず、
「明確に悪化」ではなく「良くならず、狙った軸は逆向き」が正確な総括。

## 2. 構造の同定: なぜ一様強制では対比が生まれないか

欲しい教師: 「局面 s で守った場合と素通しした場合の**結果差** Δz(s)」。
- **フェーズ1 CF**（正しいが高い）: 同一 s から全枝を同一世界・共有乱数でロールアウト＝
  Δz(s) を直接測る。1窓あたり 枝数×worlds 本のロールアウトが必要（438行で頭打ちの理由）。
- **v26 ε強制**（安いが誤り）: 各 s で片枝だけを確率的に踏む。コーパス全体では
  「守った状態」「守らなかった状態」の両方が入るが、**別々の局面**なので差 Δz は
  局面差と交絡する。しかも強制は文脈を見ない一様抽選なので、「守るべきでない場面の
  防御」が z を下げ、保有と勝敗の自然な相関まで消す。

＝**枝をペアにしない介入は、相関を作らずに壊す**。v16/v19 で密度×新規性が効いたのは、
新規分布の中でも「特徴と勝敗の相関」が自然に保たれていたから（新規性は方向を持つ、
の機序的な言い換え）。

## 3. 何なら効くか（次に試すならこの形）

**フォーク生成＋ペア順位学習**: 密自己対戦の防御窓で状態を clone し、
「素通し」と「最有力の守り」の**両方**を同一世界 seed・共有乱数で終局まで打ち切り、
両枝の z を**同一グループ ID** で記録する。学習は絶対値（z 回帰）でなく
**グループ内順位損失**（v12.1 で実装済みの機構）を使う＝「この局面では守る方が
勝った」という条件付き対比だけを教え、周辺相関は壊さない。
- コスト: 窓ごとに対局が2本に分岐（全体 ~1.5-2倍）＝フェーズ1 CF（枝数×worlds 倍）より
  一桁安く、438行ではなく数万ペア規模が狙える。
- ただし v27 診断（コーチ14点の正解軸と全分布の最適のねじれ・防御標的の効果量
  3/45窓）を踏まえると、**防御軸への再投資自体の期待値が低い**。この方式は
  「効果量の大きい標的が見つかった時」の道具として温存するのが妥当。

## 4. 記録上の限界（次回への注意）

- v26 コーパスは**強制窓のタグを行に残していない**ため、「強制された防御の直後の状態」
  だけを事後抽出して分析することができない。介入つき生成では `forced` フラグ列を
  スキーマに足すこと（今回の分析は周辺相関の比較で代替した）。
