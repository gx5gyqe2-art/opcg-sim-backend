## 2. 何が効いたか（4つの合わせ技）

1. **リーダー物理要約24**（ユーザ提案 2026-08-14・`leader_feat`）: リーダー能力の木を歩いて
   「毎ターンのドン増減・ライフ回復・パワー修正・除去・展開…」を12次元×自/相手に要約。
   接戦帯の帰趨を支配するリーダー再帰効果が現行特徴に**0ビット**だった欠陥への処方で、
   ID非依存＝**新リーダーへ学習なしで汎化**する（標準要件）。コストはカードID キャッシュで実質ゼロ。
2. **B/G混合コーパス**: 実デッキ 17,912行 ＋ **合成リーダー世界 8,048行（card_idx=UNK）**。
   「IDが分からない時はリーダー物理要約で読む」経路を数百種の合成リーダーで教える。実データのみでは
   未見リーダー（ハンニャバル）で過適合（+0.684→+0.365）したものが混合で +0.622 へ回復＝
   **B系の存在意義が G系の数字で初めて実証された**。
3. **入口コミット**（ユーザ決定 2026-08-15・`SERVE_BATTLE_COMMIT`）: 防御プランを窓の入口で
   1回立て、以後は実行のみ。人間の意思決定（カウンターを切った後に考え直さない）に合わせる。
   A/B は同一G14・CRN100ペアで **wr 0.520 CI[0.451,0.589]＝同等**、かつ**31%高速**
   （4915s→3380s）。「払い始めたら払い切る」が構造で保証される。
4. **戦闘出口ヘッドの載せ直し**（v43 レシピ・裁定注入8点32群136盤面・margin0.03/hidden4/e64・
   defcf 1198盤面で中心化）。出口順位正答 0.917→1.000。

## 3. v12＝リーサル距離Δを外した理由（本世代の設計判断）

v11 候補（gen15b）はゲートを PASS したが **decide 13.5s＝本番予算1秒の28倍**だった。原因は
v10 のリーサル距離Δ3列で、エンジンで台本を再生する実測特徴のため **~25ms/盤面**かかる
（探索は1手で数百回符号化する）。v9=1.3ms / v10=25.1ms / v11=23.8ms の実測で、
**リーダー要約は無料・Δだけが重い**ことが確定した。

Δ自体も v53（2026-08-12）で G系・B系とも転移せず**効果未実証**のままだったため、
**出荷実績のある v9 系譜に無料の24列だけを継ぐ** v12（94列＝v9 70 + リーダー24）を新設した。
v11 の行から列 `[0:70]+[73:97]` の切り出しで教師が作れる（**コーパス再生成は不要**・
`corpus_v11_to_v12.py`）ため、やり直しのコストは訓練数分で済んだ。

発覚の経緯: アリーナが 10分/ペア（33時間コース）になって初めて表面化した。v10 導入時に
「~25ms/盤面」は測っていたが、**探索1手あたりの総コストと予算の突き合わせ**をしていなかった。
再発防止として候補の検証チェーンに**レイテンシ関門を最前段**へ追加した
（レイテンシ → ns2 → ゲート → アリーナ）。

## 4. ロールバック

既定を gen14 に戻すだけ（`_DEFAULT_VALUE`/`_DEFAULT_POLICY`）。符号化はネットの入力次元から
自動判別するため配線変更は不要。入口コミットを戻すなら `SERVE_BATTLE_COMMIT = False`
（gen14 出荷時と同一挙動・`test_battle_commit.py` がロールバック経路を固定）。
