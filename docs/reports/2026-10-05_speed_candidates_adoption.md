# 保留していた速さの 3 候補を既定に採用（2026-10-05）

ユーザ決定 2026-10-05「全て正しい方式にしてください」——保留にしていた 3 つの候補を、**規則どおりの形**として全て既定にした。
旧い値（`const`／`off`／`abs`）は切替として残してある（死んだ切替の掃除は、凍結ブランチを切ったあとの別の波で行う。本作業では何も削除していない）。

* 測定は別セッション 3 本（ブランチ `claude/cand-base`・`claude/cand-take`・`claude/cand-block`）が実 100 局・合成 100 局（帳簿は 60 局）で行った。数字は各ブランチの `cand_wip/results/*.json` の原本から写した。
* 採用の根拠は**数字ではなく規則どおりであること**（ユーザ決定）。取りの読み方と、ブロッカーの読み方は 100 局の揺れの範囲内で、`κ` の物差しだけは明確な改善がある。
* 採否の判定に数字を使わない前例は、他の「規則どおりの形」の採用と同じ（T103／T106／T108 など）。

## 判断の記録（ユーザ指示の形式）

### 何を決めたか

交点の橋の速さと、相対の帳簿の勝率の物差しを、3 点とも規則どおりの形にそろえて既定にした。

1. 攻撃の価格のうち「受けられたとき」を、守る側の残りライフで読む（旧は一定の値）。ライフが 0 の攻撃は「通れば勝ち」として見えるようになる。
2. 速さの盤面の項に、相手のアクティブなブロッカーを入れる（旧は渡していなかった）。ブロッカーは攻撃を横取りできるので、取れる額が下がる。
3. `κ`（局面の傾き）の物差しを、勝率の式が使っている物差しと同じにする（旧は定数の物差しで、勝率より約 2 倍鋭かった）。

### 選択肢と帰結

* (a) 3 つとも既定にする（採用）。交点の橋の的中は実 0.749 のまま・合成 0.661 → 0.664（取り）。相対の帳簿の位置のみの腕（`abs_kappa`）の見分ける力が実 0.778 → 0.840 に上がる。
* (b) 数字が良くなるものだけ既定にする（`κ` の物差しだけ）。取りとブロッカーは旧のまま。数字の差は揺れの範囲内なので、(b) にしても数字は事実上同じだが、規則との食い違いが残る。
* (c) 今は替えない。

### なぜこの問いが出てきたか

2026-09-18〜20 に、速さの 3 点を「規則どおりの形」として作り（ブロッカーを渡し忘れていた穴・受ける額を定数にしていた穴・`κ` の物差しの食い違い）、いずれも切替として残して**既定は据え置き**にしていた。理由は、替えると的中や偏りが少し動くのに、切り分けの手が無かったため。2026-10-04 に切替の整理が始まり、保留の 3 つを先に測ることになった。そこで別セッション 3 本が、同じ標本に対して出荷の標準と各候補を並べて測った。結果は下の表のとおり、取りとブロッカーは差が 100 局の揺れの内、`κ` の物差しは帳簿の 1 腕だけが明確に良くなり、他は動かなかった。

### 推薦とその理由

(a)。差は小さく向きも割れているが、悪化と呼べる大きさのものは無い。規則どおりの形を既定にしておけば、以後の比較の基準が「規則どおり」の一本になる。ユーザ決定で採用済み。

### 決めないとどうなるか

旧い形が既定のまま残り、規則に反する数字（ブロッカーを無視した速さ・定数の受ける額・食い違った物差し）が以後の測定の基準になり続ける。

### 留保

* 測定は 3 つを**個別に**行った（3 つ同時の測定ではない）。3 つ同時の数字は 100 局では測っていない。下の「確認」の 20 局は、既定の切り替えがコードとして意図どおりに入ったこと（同一性）の確認であって、同時採用の数字の比較ではない。
* ブロッカーを入れると、帳簿の位置のみの腕の見分ける力は実で 0.778 → 0.760 に少し下がる。
* `κ` の物差しを替えると、位置のみの腕の偏りは実で −0.092 → −0.189、勝ちと負けの平均の差（理想 1.0）は 0.807 → 0.581 に動く（合成は −0.094 → −0.116、0.574 → 0.395）。順序づけは良くなるが、尺度の較正は離れる。
* **ばらつき（σ）と損害の輪郭の表（`tests/fixtures/harm_profile.json`）は、旧い既定（切替前）のまま意図して据え置く**（ユーザ決定 2026-10-05・以後の比較は切替前の測定に対して行う）。3 つの切替が交点の橋に与える影響は小さい（上の 100 局の数字）。
