## 1. 規則としての 4 ゾーンと「使う」（エンジンの全経路を数え上げた）

ユーザが挙げた 4 箇所は**エンジンの型そのもの**（`rust/opcg_engine/src/journal.rs`）:

```rust
pub enum DonZone { Deck, Active, Rested, Attached }
```

| 使い道（ユーザの言葉） | ゾーンの動き | 場所 |
|---|---|---|
| **追加**（ドン!!フェイズ） | デッキ → アクティブ（1 ターン目 1 枚・以降 2 枚） | `rules/turn.rs::don_phase` |
| **追加**（効果） | デッキ → アクティブ／レスト | `effects/actions/don.rs` |
| **支払い**（登場・イベント・起動） | アクティブ → レスト（足りなければ付与 → レスト） | `ops.rs::pay_cost` |
| **付与** | アクティブ → 付与 | `rules/actions.rs`・`ops.rs::attach_don` |
| **マイナス**（戻す） | レスト／アクティブ／付与 → デッキ | `ops.rs::return_don` |
| **付与ドンの移動** | 付与 → レスト（持ち主が場を離れる）／付与 → アクティブ（リフレッシュ） | `ops.rs`・`turn.rs` |
| **リフレッシュ** | レスト → アクティブ（自分のターン開始） | `rules/turn.rs` |

**ドンは 4 ゾーンの間を動くだけで増えも減りもしない**——だから**席ごとの合計は不変量**。
**「使えるドン」＝自分のターン開始時のアクティブ**（リフレッシュ＋追加の後）で、
**支払いも付与もここから出る**＝**財布は 1 つ**。これが本 T の式の全部である。

## 2. 不変量を測る前に、**不変量の値そのもの**が規則だと判った

**合計は 10 ではない**——`py_game.rs::leader_don_deck_size`／`gamestate._apply_leader_don_deck_rule`:
**リーダーが「ルール上、自分のドン!!デッキはN枚になる」と書いていればその N**（既定 10）。
実測で当たったのは **OP15-058 エネルの 6 枚**だけ。

**これを知らずに 10 と比べると壊れて見える**——記録 40 局の 5,918 席行のうち **1,520 行（25.7%）が合計 6**。
**「符号化の欠陥」に見えていたものが規則だった**（`model.rs` の `don_deck` の組み立てを疑って読んだが、
`hidden_build.py` には「リーダー依存なので 10 を仮定して逆算できない」とすでに書いてあった）。

**破れ 0**（5,918 席行・両席・全ターン）。**丸めだけは切る**——記録は float32 で `/5`・`/10` された値なので
掛け戻すと 1 枚あたり 1e-7 ずれ、6 項足すと 1e-6 に届く（切らないと 4,407 行が「破れ」に見えた）。

## 3. 記録が言う「使ったドン」（実 40 局・自席ターン 502 本）

| 量 | 1 自席ターンあたり |
|---|---|
| **使えるドン**（ターン開始のアクティブ） | **6.01** |
| 使ったドン（アクティブの減り） | **5.48** |
| 遊んだドン（ターン終わりのアクティブ） | 0.53 |
| うち **支払い**（レストの増え） | 2.82 |
| うち **付与**（付与の増え） | 2.62 |
| **追加**（ターン中のデッキの減り＝効果のランプ） | 0.094 |
| **マイナス**（デッキの増え） | 0.133 |

**支払い 2.82 ＋ 付与 2.62 = 5.44 ≒ 使った 5.48**＝**帳尻が合う**（残りは追加・マイナスの分）。
**付与は支払いと同じ桁**——「ドンを使う」の半分は付与である。

## 4. 理論の側は**在るドンより多くを要求していた**

`off`（T108 までの形）は 3 つの経路が**別々に同じアクティブを使える**:

* `stock`（T77）＝`playable_attack_price` が詰めた手札の体（コストの和 4.37）
* `e₁`（T108）＝`hand_effect_harm` が選んだ 1 枚（コスト 1.25）
* `attach`（T45）＝`attack_value_don` が場の攻め手に**無料で付けている**ドン（0.10）

| 財布の形 | 要求 ÷ 在る | **在るドンより多く要求した自席ターンの割合** |
|---|---|---|
| `off`（旧） | 0.952 | **22.0%** |
| `one`（手札だけ 1 つの財布） | 0.760 | **4.4%** |
| **`all`（付与も同じ財布）** | 0.727 | **0.0%** |

**T108 の報告 §5「上手くいかなかった 2」で名指しした穴がこれ**（「`e₁` はドンの枠を見ているが、
体を出すのと同じドンを二重に使える前提」）。

## 5. 式（**新定数ゼロ**）

```
財布 P = 自分のターン開始時のアクティブ（記録の sc[2]）
組ごとに 1 つだけ選ぶナップサック（purse_plan）:
  手札の 1 枚      … 重み = そのカードのコスト（1 回だけ）
                     値  = 体の攻撃（素殴り） ＋ その札自身の効果の損害
  場の攻め手 1 体  … 重み = 付与 k 枚（k = 0..ATTACK_DON_MAX）
                     値  = attack_value(P + 1000k) − attack_value(P) − k·δ   ← T45 と同じ値付け
盤面の項は素殴りに戻す（付与を財布で買うので二重に数えない）
```

**部品はすべて既に在ったもの**（`attack_value`・`removal_harm`・`c_of`・`δ`）。
**変えたのは「どこからドンを出すか」だけ**。

**副産物として 2 つ正しくなった**:

1. **イベント・ステージも除去なら値を持つ**——`playable_attack_price` は**体を持つ札だけ**を候補に
   していたので、**除去を持つイベントは丸ごと落ちていた**。
2. **出した札はどれも自分の効果を撃つ**——T108 は「1 枚だけ数える」過小側の規約だった
   （実測 `e₁` 0.0299 → **0.0333**／0.0250 → **0.0295**）。

### **`δ` を落とす版は測って捨てた**（本 T で一番危なかったところ）

「財布の制約が値段そのものだから `δ` を引くのは二重払い」と考えて `−k·δ` を落とした版を先に測った。

| | 勝者の的中 | 終局の偏り | σ_T | **速さの検算（とどめ除く）** |
|---|---|---|---|---|
| 既定（`off`） | 0.6628／0.6421 | +2.39／+2.44 | 4.202／4.134 | 0.97〜1.12／0.87〜1.19 |
| **`all`・`δ` なし（捨てた）** | 0.6563／0.6336 | **+1.12／+1.16** | **2.668／2.548** | **1.25〜1.59／1.17〜1.63** |
| `all`・`δ` あり（採った） | **0.6654**／0.6381 | +2.44／+2.60 | 4.190／4.186 | 0.99〜1.13／0.90〜1.20 |

**偏りと σ_T は劇的に良くなるが、速さの検算が壊れる**＝**`A` が 3〜6 割膨らんで、
`Θ` が小さすぎるぶんを埋め合わせている**。**採ってはいけない形**。
**理由は実測で分かる**——**財布はふつう余る**（要求 5.78 対 在る 6.01）ので
**制約が値段の代わりにならない**。落とせば付与が無料になるだけだった。

## 8. 読み方

- **上手くいった（本命）: 帳尻が合った**。**ユーザの指示はここで閉じている**——
  **4 ゾーンの不変量は破れ 0**・**使い道 6 種はすべてゾーンの動きとして数えられ**・
  **理論が在るドンより多くを要求する行はゼロになった**。
- **上手くいった: 費用ゼロ**（帳簿・`curve` はビット一致）＝**線形の橋の数字は 1 つも失わない**。
- **上手くいった: 実は単調に良くなった**（0.6628 → 0.6642 → **0.6654**＝歴代最良）。
- **上手くいかなかった 1: 合成はわずかに下がる**（0.6421 → 0.6381）。**向きが記録で逆**なので
  「数字で採る」とは言えない。**採る理由は規則の側**（T103／T106 と同じ型）。
- **上手くいかなかった 2: 偏りは縮まなかった**（+2.39 → +2.44）。**`δ` を落とせば縮むが
  それは埋め合わせだった**（§5）＝**偏りの正体は財布ではなく `Θ` の側**にまだ在る。
- **上手くいかなかった 3: 予告 2 が外れた**——合成の序盤の行き過ぎ（1.19 → 1.20）は
  **ドンの二重使用のせいではなかった**。T108 §5 の診断は誤りだった、と記録する。
- **新しく見えた穴: 理論は使えるドンを 1.1 枚/ターン 使い残す**（要求 4.37 対 実際に使った 5.48）。
  **理論が知っている使い道が 2 つ（体を出す・付与）しか無い**ためで、
  **カウンター・守りのためのブロッカー・サーチ・起動メイン**は 1 枚も数えていない。**次の穴はここ**。

## 9. 手続きへの自己批判（残す）

**`δ` を落とした版を先に作ったのは、論理の誤りだった**——「制約が値段の代わりになる」は
**制約が縛っているときにだけ**正しい。**縛っていないことは測れば 1 分で分かった**（要求 5.78 対 在る 6.01）。
**偏りが +2.39 → +1.12 に縮むのを見て一瞬良い形に見えた**のが危なかった。
**速さの検算（別の指標）が壊れたので捨てられた**——**指標を 2 本以上持っていたことが効いた**。

## 10. 次

1. **理論が使い残す 1.1 枚/ターン**（§8 の「新しく見えた穴」）——**カウンター・守りのブロッカー・
   起動メイン**を財布の使い道に入れる。**どれも規則から出る**（`rules/battle.rs::apply_counter`・
   `has_blocker`・`ActivateMain`）。
2. **歩き（将来のターン）の財布はドンデッキで上限が付く**——`rate_at` は今のドンで出せる体を
   毎ターン繰り返すが、**ドンは毎ターン 2 枚増えて上限（10 か 6）で止まる**。
   **今の形は将来を過小に見ている**（保守側）が、規則としては欠落。
2. **偏り +2.44 は `Θ` の側**（§8 の 2）。
3. **接戦帯の必要な `κ`**（0.555／0.628）＝帳簿の側。
4. **出口 T18**。

## 限界

- **使い道の名付けは符号から決まるぶんだけ**（`flows_between`）——1 つの差分に複数の使い道が
  混ざりうるので、**どれが先かは推測しない**。「支払い 2.82」は**レストが増えたぶん**であって、
  「登場に払った」と「イベントに払った」を分けてはいない。
- **理論の財布は「1 ターンの中」しか見ない**——ドンは次のリフレッシュで全部戻るので
  **ターンを跨ぐ機会費用は `δ` が代表している**（T57 の実測）。**そこは変えていない**。
- **`attach` の値付けは T45 のまま**（`−k·δ`）＝**出所だけを変えた**。値付け自体の正しさは別の問い。
- **理論が使い残す 1.1 枚**（§8）＝**過小側**。**全部の使い道を数えていない**という意味で未完。
- **観察であって因果ではない**。
