# v41: 戦闘出口専用ヘッド — 機構は成立、教師が不足（2026-08-07）

対象: `opcg_sim/src/learned/value_net.py`（`EXIT_HEADS`）・`mcts.py`・`plan.py`・`cpu_learned.py`、
計器 `tests/scripts/exit_head_finetune.py` / `exit_head_probe.py`。
本文書は**この時点のスナップショット**（追記・改変しない）。

## 1. なぜこの設計にしたか

直前の2サイクルはどちらも「本体 value を動かして防御の交換レートを直す」方向で、
どちらも失敗している。

| | やったこと | 結果 |
|---|---|---|
| v38 | ターン出口教師を**既存 value ヘッド**へ同居 | m5@7/m2@66 は満点になるが m1@15 が 1.00→0.00。8点合計 **3.06 < 本番 3.44**。α補間でも救えない（gen12 の m1@15 の正しいマージンが +0.062 しかなく、共有重みへ逆向きの勾配が掛かればどの混合比でも先に潰れる） |
| v40 | 防御CF＋裁定済みペアで**本体 value を全面順位学習** | コーチゲート **8.00/8.00 満点**（m1@14/m2@44 を含め全点正解）に対し、アリーナ **0.447 CI[0.409,0.485]**（284ペア／568局）＝**有意な退行**。全面学習は盤面評価そのものを全域で動かすため、8点で得た分より他所で失う分が大きい |

真の勝率は盤面ごとに1つに定まるので、戦闘出口の真実とターン末の真実は**論理的には矛盾しない**。
競合は「1組の重みで両方を表す」という工学的制約に由来する。ならば**出力を分ければ**共存でき、
しかも影響範囲が「その箱の出口を比べるとき」に限定される——これが v41 の仮説。

## 2. 実装

v39 のターン末ヘッドと同じ機構を `EXIT_HEADS` 表として一般化し、"battle" を追加した。

- 構造は**既存ロジットへの残差 MLP**: `exit = tanh(Z2 + W2ᵀrelu(W1ᵀA1+b1) + b2)`。
  出力層ゼロ初期化＝有効化直後は既存ヘッドと bit 一致。
- `backward_exit(cache, y, kind)` は**そのヘッドの4パラメタだけ**を返す。胴体（Emb/W1/b1）にも
  既存ヘッド（W2/b2）にも他階層のヘッドにも勾配が流れない＝既存挙動は**物理的に**不変。
  蒸留アンカー（v33 以降の錘）が要らなくなる（錘と教師の綱引き自体が消える）。
- 結線: `resolved_branch_values` に渡る `value_fn` が「戦闘箱の物差し」であることを規約化し、
  `_battle_window_choice` / `TreeMCTS` の箱化 / `resolve_turn_inplace` の戦闘窓 / `plan` の
  戦闘窓が `LearnedEngine._battle_value_fn()` を使う。
  木の葉の**絶対評価**は本体 value のまま（他の葉と物差しが違うと backup が壊れる）。
- npz 互換のため turn の属性名は v39 の `We1..be2` を維持、battle は `Wb1..bb2`。
  旧 npz は幅0で読め、`predict_exit` は既存ヘッドへフォールバックする。

機構が意図どおり効いていることの直接確認（m1@14 の真盤面）:

```
候補の本体 value : 0.022217   ← gen12 と bit 一致（胴体凍結）
候補の戦闘出口   : 0.351611   ← +0.329 動いた
```

## 3. 判定: 既存の防御CFコーパスでは教えられない

土台 gen12・教師 defcf（19シャード 2,198盤面 **584群 775ペア**）で `--head battle` を学習し、
`exit_head_probe.py` で2列を測った。

**(1) 出口順位（`resolved_branch_values` の argmax が裁定と一致するか）**

| 腕 | ep / lr / 幅 | m1@14 | m2@44 | 出口順位 |
|---|---|---|---|---|
| gen12 | ヘッド無し | ✗ | ○ | 4/8 |
| a | 8 / 1e-3 / 32 | ○ | ✗ | 4/8 |
| b | 2 / 1e-3 / 32 | ✗ | ○ | 4/8 |
| c | 8 / 2e-4 / 32 | ✗ | ○ | 4/8 |
| d | 8 / 1e-3 / 8 | ○ | ✗ | 4/8 |
| e | 4 / 5e-4 / 16 | ✗ | ○ | 4/8 |

**m1@14 を直す腕は必ず m2@44 を壊し、m2@44 を保つ腕は m1@14 を直さない。**
コーチゲート（腕 a・16seed・160sims）でも同じ入替が出た: m1@14 **0.00→1.00**、
m2@44 **0.88→0.00**、m1@15/m2@58 は 1.00 を維持、m1@3 は 1.00→0.75（ノイズ幅 0.35 以内）。

**(2) ヘッドのオフセット分布（`predict_exit("battle") − predict()`・680盤面）**

| 腕 | 平均 | 標準偏差 | 性格 |
|---|---|---|---|
| a | −0.0264 | **0.2677** | 盤面ごとの差 |
| b | +0.0765 | 0.0863 | ほぼバイアス |
| c | +0.0599 | 0.0730 | ほぼバイアス |
| d | −0.0252 | **0.2309** | 盤面ごとの差 |
| e | +0.0501 | 0.0558 | ほぼバイアス |

**核心**: gen12 の**枝間マージンは 0.02〜0.03**（プローブの gap 列）。
一方、順位を動かせるだけの容量を持つ腕（a/d）の摂動は**標準偏差 0.23〜0.27＝マージンの約10倍**。
つまり順位はマージンではなく**ノイズの当たり外れ**で決まっている。
held-out の順位正答も全腕で悪化した（0.701 → 0.639〜0.701）＝汎化していない。
弱い腕（b/c/e）は一律バイアスしか学ばず、そもそも順位を動かさない。

## 4. 結論

- **機構は成立**した。防御較正が戦闘箱の枝順位づけだけに効き、本体 value は bit 不変。
  v40 の失敗（全域を動かしてアリーナが落ちる）は構造的に再発しない。
- **足りないのは学習の工夫ではなく教師**。マージン 0.03 を超える信号を持つラベルが要る。
  worlds=4 の因果 z は粒度 0.5 で、584群では平均のばらつきがマージンを覆い隠す。
- したがって次の分岐は「どの教師を作るか」であり、腕を増やすことではない。
  `exit_head_probe.py` の2列は、腕を回す前にコーパスの信号がマージンを超えているかを
  判定するための足切りとして残す。
