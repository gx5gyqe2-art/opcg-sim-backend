# T142b: T18 の器が攻撃（`DON_BOX`）にも介入できるようにする（2026-09-23）

T142（`2026-09-23_t18_arena.md`）は、理論の最善が攻撃（`DON_BOX`＝「ドンを k 枚付けてから殴る」
箱レベルのマクロ手）のとき置き換えられなかった。エンジンの `apply_game_action` は原始手しか受け付けず、
`DON_BOX` をそのまま渡すと対局が異常終了するからである。**介入できたのは禁じられた行の 27.7%／23.5%**
にとどまり、理論が最も多く薦める型（攻撃）に手が出せなかった。本 T はその壁を取り除く
（ユーザ指示「その 3 つを順に閉じてください」の 1 つ目）。

**記録**: T142 と同じ seed（実＝60000〜60009・`--decks user`／合成＝61000〜61009・`--decks synth`・各 10 局）。
介入の中身が変わるので、打たれる局面は T142 と別物になる（行数が違うのはそのため）。

---

## 0. 結論（先に書く）

**解けた。エンジンは 1 行も変えていない。** 探索自身が `DON_BOX` を打つときの仕組み（最初の 1 原始手を
打ち、残りを `commit` に積んで次の決定点で 1 手ずつ打つ）を Python でそのまま真似た。20 局とも最後まで
打て、置き換えた箱は 1 つも途中で壊れなかった。**`attach` 以外の禁じられた行はすべて介入できた**。

| | 実（10 局） | 合成（10 局） |
|---|---|---|
| 例外終了 | **0／10** | **0／10** |
| 測れた main 行 | 647 | 589 |
| 禁じられた行 | 320 | 331 |
| うち `attach` で対象外 | 94 | 134 |
| **実際に介入した行** | **226（対象外を除いた全部）** | **197（同）** |
| うち置き換え先が `DON_BOX` | 125 | 101 |
| 置き換えた箱が最後まで打たれた | **125／125** | **101／101** |
| 箱が途中で壊れた | 0 | 0 |
| 見つからなかった置き換え | 0 | 0 |

T142 では介入は禁じられた行の 27.7%／23.5% だった。本 T では `attach` を除いた全部（70.6%／59.5%）になった。
残る 29%／40% は `attach`（純付与）で、これは T141 の申し送りどおり対象から外している。外す理由（物差し `s` が
付与の価値を測れていない）は T144 が扱う。

## 1. 問い

理論の最善が `DON_BOX` のとき、それを実対局に届けられるか。届けられるなら、T18 は理論が最も多く薦める型
（攻撃）への介入を含めて測れる。

## 2. 機構（エンジン側の仕組みを読んで、同じことを Python でする）

`rust/opcg_engine` を読んで確かめた探索の打ち方:

* 探索は `DON_BOX` を選ぶと、`don_box_first_primitive(box)` の**最初の 1 原始手**だけを実対局に出し、
  残りを `carry.commit = [{"kind": "box", "sig": move_sig(box), "left": 総数 − 1}]` に積む。
  総数は「付けるドン k 枚 ＋ 殴るなら 1」。
* 次の決定点で `commit_step` が残りを打つ。`left ≤ 1` で的があれば `ATTACK`、それ以外は `ATTACH_DON`。
  `sig` が合法手に見つからなければ、`commit` を**黙って畳む**。
* `driver.run_game` は `swap` の後に `carries[name].put(out)` で `out["commit"]` を読む。

器（`tests/scripts/t18_arena.py`）の変更:

* `box_total`／`box_first_primitive`／`expand_replacement` を足した。上の規則の Python 版である。
* `make_swap` は、置き換え先が `DON_BOX` なら最初の原始手を返し、**`out["commit"]` を新しい箱の残りに
  書き換える**。
* **元の手の `commit` は必ず捨てる。** 探索が `DON_BOX` を選んでいた行を置き換えると、元の箱の残りが次の
  決定点で打たれてしまう。T142 の器にも潜んでいた欠陥で、置き換え先が原始手のときも同じだった。
* `commit_step` は黙って畳むので、箱が最後まで打たれたかは `make_box_tracker`（`observer`）が数える
  （`box_completed`／`box_broken`）。

## 3. 予告と当否

| # | 予告（器の docstring に測る前に書いた） | 結果 | 当否 |
|---|---|---|---|
| 1 | 20 局とも例外なく最後まで打てる | 0／20 が異常終了 | **当たり** |
| 2 | `attach` 以外の禁じられた行はすべて介入できる（`n_forbidden == n_exempt + n_intervened`・`n_no_replacement == 0`） | 320 = 94 + 226／331 = 134 + 197・0 件 | **当たり** |
| 3 | 置き換えた箱はほぼ最後まで打たれる（`box_broken` ≪ `box_completed`） | 壊れた箱 0 件 | **当たり** |

## 4. 不変量（配線の検算）

* 内訳の取りこぼしが無い。`n_forbidden == n_exempt + n_intervened + n_no_replacement` が両記録で成り立つ。
* 置き換えた箱の数と、最後まで打たれた箱の数が一致する（125／101）。
* 注入するのは合法手の要素とその規則どおりの原始手だけである。20 局で異常終了 0 件がその実地の証拠。

## 5. 上手くいったこと／いかなかったこと

**上手くいった**:

* **エンジンを変えずに解けた。** T142 の §8 は「エンジン側の拡張が要る・規模が大きい」と見積もっていた。実際は、
  探索が既に持っている `commit` の入口を使えば足りた。
* **T142 の器に潜んでいた欠陥（元の箱の `commit` を捨てていなかった）を同時に直した。** T142 の 20 局でも、
  探索が `DON_BOX` を選んだ行を原始手に置き換えた後に、元の箱の残りが打たれていた可能性がある。
  T142 の数字（介入の頻度）そのものは決定点の数なので影響は小さいが、打たれた局面の中身はずれていた。

**いかなかった／残り**:

* **この乾式運転は両席とも介入している。** T18 の判定には「片方の席だけ介入し、もう片方は素の探索」の
  対局が要る。器の `swap` は席の名前を受け取るので、片席に絞るのは小さな変更で済む。
* **`attach` はまだ対象外である。** 付与の価値を `s` が測れないためで、T144 の結果次第で外す。

## 6. T142 の報告の訂正

T142 の報告 §3・§8 の「`DON_BOX` は置き換え先にできない」「エンジン側の拡張が要る」は、本 T で取り下げる。
T142 の報告は時点のスナップショットなので書き換えず、訂正は本報告と台帳に置く。
