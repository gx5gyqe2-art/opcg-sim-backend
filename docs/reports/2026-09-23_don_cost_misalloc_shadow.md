# T150f-3: misalloc/misalloc_play を shadow_forbid で測る（2026-09-23）

T150f-1（`misalloc`）・T150f-2（`misalloc_play`）を、T150c と同じ手順（新しい seed で今ここに打つ・
打ち回しには介入しない）で shadow_forbid にかける。T150c の最も重要な結果——`--seq attack_le` と
組み合わせると純付与の禁じ率が両記録とも下がる——が `misalloc` でも再現するかを見る。ユーザ指示
「この構成で進めてください」の一部。

**記録**: T144／T147a／T150c と同じ seed（実 50000〜50009・`--decks user`／合成 51000〜51009・
`--decks synth`・各 10 局・介入なし・今ここに打つ＝静的記録の再生ではない）。

---

## 0. 結論（先に書く）

**`misalloc` は T150c の目玉（`attack_le` との組み合わせで付与の禁じ率が下がる）を再現しない——
完全に不動**。一方、**攻撃だけの禁じ率は両記録で同じ向き（下がる）に動く**——`opportunity` は
記録間で向きが割れていたので、こちらは `misalloc` の方が良い。`misalloc_play` は合成だけ
`opportunity` と同じ改善を再現するが、実は `off` より悪化する。

| | 実（off→opportunity→misalloc→misalloc_play） | 合成（off→opportunity→misalloc→misalloc_play） |
|---|---|---|
| 攻撃の禁じ率（`--seq` 不問） | 0.4932→0.5101→**0.4865**→0.5068 | 0.4010→0.3911→**0.3960**→0.3663 |
| 純付与の禁じ率（`--seq off`） | 0.9306→0.9236→**0.9306**（不動）→0.9306（不動） | 0.9134→0.9134（不動）→0.9134（不動）→0.9134（不動） |
| 純付与の禁じ率（`--seq attack_le`） | 0.6319→**0.6111**→**0.6319**（不動）→0.6389（悪化） | 0.5984→**0.5827**→**0.5984**（不動）→**0.5827**（改善・opportunity と同値） |

## 1. 検算の予告と当否

前回のチャットで立てた予告:

| # | 予告 | 結果 | 当否 |
|---|---|---|---|
| 1 | 最良の体への `DON_BOX` の禁じ率が下がり、他の体は上がる | **個別の体ごとの内訳は本 T では測っていない**（家族単位の集計のみ・下記「いかなかったこと」） | **測れず** |
| 2 | 全 k>0 候補が最良の体の行は `off` と一致 | 未検証（同上の理由） | **測れず** |
| 3 | `misalloc_play` で攻撃禁じ率が上がるなら `best_family_when_forbidden==play` に集中する＝二重計上の署名 | 実の攻撃禁じ率は `misalloc_play` で**上がった**（0.4865→0.5068）が、合成は**下がった**（0.3960→0.3663）——**上がる／下がるが記録で割れ、署名の検証自体が成立しなかった** | **測れず（前提が崩れた）** |
| 4 | `attack_le` と組み合わせると `misalloc` も付与の禁じ率を下げる（T147a の悪化は起きない） | **外れた**——`misalloc` は `off` と完全に同値（不動）。**悪化はしないが改善も無い** | **半分当たり（悪化は避けたが改善は無い）** |

**予告 1・2・3 が測れなかった理由（自己批判）**: `shadow_row` は型別の集計（`by_played_family`）
しか返さず、**候補の体が貪欲の最適かどうかの内訳**は本器に元から無い——T150f-3 を計画した時点で
「新しい列を足す」と書いたが、実装では既存の `shadow_forbid.py` をそのまま再利用し、新しい列を
追加しなかった（測る前の計画と実装がずれていたことに気づかず進めてしまった）。**予告 3 は結果の
方向自体が記録で割れたことで、検証しようとした前提〔misalloc_play が攻撃禁じ率を一方向に動かす〕
が崩れ、内訳が無くても不成立と分かった**。

## 2. `misalloc` が `attack_le` の改善を再現しない理由（考察・当てはめない）

付与の禁じ率が `--seq off`／`--seq attack_le` の両方で `off` と完全に同値（1 ビットも動かない）に
なるのは偶然ではない——`misalloc` の費用はこの記録（654／505 行）では**その体が貪欲の最適でない
ときだけ**非 0 になる。`attack_le` は純付与の価格を**同じ体・同じかそれ以下の k の攻撃候補**の最大
価格に読み替えるので、**読み替えた価格も同じ体の misalloc 費用を払う**——付与も攻撃も同じ体・
同じ費用を引かれるので、**この体が最良かどうかに関わらず、付与と攻撃の価格差（読み替えの効果）
そのものには misalloc の費用が影響しない**。`opportunity` は候補非依存の定額を引くので、行の中の
「他の体」（比較相手）の価格だけが変わり、相対順位が動いて禁じ率が変わっていた。**`misalloc` は
まさにこの「他の体との比較」でしか差が出ないので、比較相手が同じ体（読み替えの場合）だと差が
出ない**——理論的には筋が通るが、**測る前には気づいていなかった**。

* 局数（10／10）・行数（654／505）は全条件で同じ（介入しない測定）。

## 4. 上手くいったこと／いかなかったこと

**上手くいった**:
* **`misalloc` の攻撃禁じ率は記録間で同じ向き**（実 −0.0067・合成 −0.0050）——`opportunity` の
  記録間の分裂（実 +0.0169・合成 −0.0099）より一貫している。小さいが、方向の一致自体は前進。
* **`misalloc` は `attack_le` の悪化を起こさない**（`off` と同値・T147a のような一方的な悪化は無い）。

**いかなかった／自己批判**:
* **T150c の目玉だった改善（付与 63.19%→61.11%・59.84%→58.27%）が `misalloc` では再現しない**——
  `misalloc` に切り替えた時点でこの改善も失われる。§2 の考察のとおり構造的な理由がある。
* **計画した「候補の体が貪欲の最適かどうかの内訳」を実装しなかった**——予告 1〜3 を検証する材料が
  無いまま実測に進んでしまった。次に同じ種類の予告を立てるときは、器を先に確認してから予告を
  書くべきだった（T144・T147a・T150c に続き 4 回目の同じ教訓）。

## 5. ユーザ判断をお願いしたいこと（T150e/T150f-5・最終）

T150f-1〜4 の全体像:

| 器 | `opportunity` | `misalloc` | `misalloc_play` |
|---|---|---|---|
| shadow_forbid（付与・attack_le） | 実改善／合成改善 | **両記録とも不動** | 実悪化／合成は opportunity と同値 |
| shadow_forbid（攻撃・記録間の一致） | 分裂（実+・合成−） | **両記録とも−（一致）** | 分裂（実+・合成−） |
| relative_ledger（before AUC） | 実+/合成+ | 実+（弱い）／合成≈0 | 実++／**合成−**（悪化） |
| theory_bridge（`dS_atk` AUC） | 実−／合成−（悪化） | **実+／合成≈0**（改善） | 実++／合成−− |
| two_curves（attack 増分相関） | 実−／合成−（悪化） | **実≈0／合成≈0**（悪化が縮小） | 実−−／合成−−（大きく悪化） |

1. **`misalloc` は「候補依存にする」という診断は正しかったが、shadow_forbid の目玉（付与の禁じ率
   改善）は再現しない**——静的記録の器（帳簿・橋・曲線）では `opportunity` より一貫して良いが、
   実際の対局に対する影の判定では `opportunity` の改善が消える。**器によって答えが違う**という
   T150d 以来のパターンが、`misalloc` でも繰り返された。
2. **推薦: 既定は `off` のまま維持を継続**——`misalloc` は `opportunity` より無難（一方的な悪化が無い）
   が、shadow_forbid という最も直接的な指標での改善を示せていない以上、採用する強い根拠が無い。
   `opportunity`／`misalloc`／`misalloc_play` はいずれも不採用のまま、コードとして残す（診断・
   将来の材料）。
3. **`misalloc_play` は明確に推薦しない**——FP(k) が候補非依存という新しい欠陥を持ち、帳簿・曲線
   ともに合成で悪化する。
4. **これで T150（ドンの機会費用）の一連の作業は打ち切りを推薦する**——T150a（棚卸し）→T150b/c
   （opportunity）→T150f-1/2/3/4（misalloc/misalloc_play）と 3 世代の式を試し、どれも「一部の器で
   改善・一部の器で悪化」という同じパターンに収まった。**この経路をさらに改良する式（4 世代目）を
   探すより、T149（決着前の較正）や他の未着手の課題に進むほうが見込みが高いと考える**——これは
   推薦であり、続けるかどうかはユーザ判断に委ねる。

## 6. 再現

python3 -c "
import theory_order as TO, shadow_forbid as SF
for mode in ('off', 'opportunity', 'misalloc', 'misalloc_play'):
    TO.set_attack_don_cost_mode(mode)
    for seq in ('off', 'attack_le'):
        SF.set_seq_mode(seq)
        rows, _ = SF.collect(range(50000, 50010), 'user')
        print(mode, seq, SF.summarise(rows)['by_played_family'])
"
