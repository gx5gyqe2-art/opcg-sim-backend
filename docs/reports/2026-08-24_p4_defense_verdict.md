# P4（防御）判定: 出口採点ルートは打ち止め・D族ヘッドは不採用（2026-08-24）

スナップショット。マクロ手化 P4（`docs/cpu_macro_plan.md` §5）のうち、**P4-a 防御監査**と
**P4-b 防御評価教師（D族）**の測定・判定の記録。

## 経緯

1. **P4-a 防御監査**（`tests/scripts/defense_audit_probe.py`）: 自己対戦の被攻撃窓で
   結合防御の変種（素通し／最小で守る／+1000余裕）を台本適用→戦闘出口 value で順位づけし、
   エンジン実選択との乖離を測った。**乖離 21%・型は過剰防御が主・「守る価値」の中央値 +0.000**
   ＝現行 value は防御変種の差をほぼ感じていない。
2. **P4-b D族教師**（`tests/scripts/plandef_gen.py`）: π非依存の支配対
   （D1=印字総量<必要値→素通しが任意の支払いを支配・D2=最小札組が+1枚を支配）を生成
   （plandef 410 対）。gen15 土台で battle 出口ヘッドを再学習:
   - cand_D0 = defcf のみ（レシピ再現の対照）: val 順位正答 0.621→0.655
   - cand_D1 = defcf＋D族: val 0.764→0.764（横ばい）。分解精度は
     **D族 0.995／defcf 0.771**（gen15 素は D族 0.956／defcf 0.586）＝紙上は明確な改善。

## 判定材料

### coach_gate（13点・16seed）: cand_D1 は FAIL

- 改善: NG（chall計 5.6 vs base計 9.0）
- 非退行: NG — **m1@3・m1@14・m2@58 が 1.0→0.0**（bar 0.35 を大きく超える確定退行）
- m1@14・m2@58 はどちらも**素通しが正**のユーザ裁定点。m2@58 は D1 型（総量不足）の
  代表例そのもの＝**D族が教えたはずの内容を実挙動で落とした**。

### 枝別診断（`tests/scripts/d1_branch_probe.py`・resolved_branch_values を両ネットで直接比較）

| 点 | gen15 既定 | cand_D1 | cand_D0 |
|---|---|---|---|
| m1@14 | **PASS 1位**（-0.644 / 払い -0.655〜-0.661） | 払いが1位（-0.449）・PASS 最下位（-0.601） | 払いが1位（+0.249）・PASS 3位（+0.241） |
| m2@58 | **PASS 1位**（-0.191 / 払い -0.236〜-0.302） | 払いが1位（-0.307）・PASS 最下位（-0.494） | 払いが1位（-0.859）・PASS 2位（-0.863） |

読み取り:

1. **gen15 既定は両点とも素通しを正しく1位に置けている**（枝間の差 0.01〜0.05）。
2. cand_D1 は**順位を反転**（素通しを最下位へ）。しかも cand_D0（defcf のみ＝レシピ再現）でも
   同様に壊れ、値のスケールが大きく漂移（m1@14 で +0.25 帯・m2@58 で -0.86 帯）し、
   **枝間の差が ~0.005 に平坦化**する。
3. つまり **D族の行が原因ではない**。margin 順位損失＋小ヘッド（hidden 4）＋小コーパスで
   ヘッドを再学習すること自体が、対内の順位正答（紙上）を保ったまま**実盤面の枝判別を
   平坦化・反転させる**。出荷 gen15 ヘッドがゲートを通っているのは学習ランの個体差の
   側面がある（同レシピの再現学習 cand_D0 が通らないことがその証拠）。

## 判定

- **cand_D0 / cand_D1 とも不採用**（coach_gate FAIL・裁定点の反転）。アリーナは不要
  （行動ゲートの確定退行で棄却条件成立）。
- ネットとコーパスは規約どおり**保存**: `origin/claude/moveaudit-shard0-bk` の
  `audit_results/p4b/`（cand_D0・cand_D1・plandef_a・plandef_smoke・defcf_v12・train_d1.sh）。

## 教訓（次の設計を拘束する）

1. **防御知識は出口採点の層に既在**: gen15 の素 value ですら D族対の 95.6% を正しく順位づける。
   防御の実失敗（過剰防御）は出口の物差しではなく**候補の解決過程**の側にある。
2. **出口ヘッド再学習ルートは打ち止め**: 紙上指標（対内順位正答）が上がっても実枝の判別が
   壊れる。防御ヘッドの再訓練を再開する場合は、裁定点の枝順位（本報告の表）を
   学習時の検証に組み込まない限り着手しない。
3. **coach_gate はヘッド差し替えの欠陥を検出できる**（箱/プラン系の変更はアリーナ必須のままだが、
   ネット差し替えは 13点ゲートが一次フィルタとして機能した）。
4. **P4-c の提案**: D1/D2 の支配則は学習ではなく**エンジン側の防御箱の候補整形**として実装する
   （総量不足→素通し以外を候補から落とす／最小札組があるとき+1枚の過剰払いを落とす。
   どの出口になるかは印字値の算術で確定＝`plandef_gen.battle_need` と同じ規約）。
   ネット不変・seam（config OFF 既定）・アリーナ2条件で判定。
