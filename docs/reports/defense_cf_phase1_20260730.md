# 防御応答矯正フェーズ1 — 防御温度ロールアウト・人間整合・CRNバグの発見と修正（2026-07-30）

手札（カウンター）の価値が測定・学習から構造的に消える循環（ロールアウト役が守らない→
温存の価値が勝敗に現れない→ネットが手札軽視を学ぶ→…）を、**L1 を教師にせず**切る計画の
フェーズ1。スナップショット（追記・改変しない）。

## 1. 実装

- `counterfactual_referee.rollout` に **def_temp**: 防御窓（SELECT_BLOCKER/SELECT_COUNTER）の
  応答のみ両席とも訪問数比例サンプリング＝「温存したカウンターが将来使われる世界」を生成する。
  既定 0＝挙動不変
- `defense_cf_probe.py`: ユーザ実対局5リプレイの**人間側**防御窓を真盤面復元し、各選択肢
  （素通し/各カウンター/ブロック）を同一CRN世界×def_temp ロールアウトで終局測定、
  **人間の実選択との整合**（top一致/band内）を検証。人間選択はラベルでなく監査に使う

## 2. 副産物: 全反実仮想計器の CRN バグを発見・修正

初回測定の band 外不一致 m2@48 をユーザがレビューし「**素通りしない攻撃なのでパスが正解**」と
指摘 → 追跡の結果、即時の戦闘解決は正しく（素通し＝ライフ不変・手札温存＝機械的に厳密優位）、
「カウンター8/8勝 vs 素通し4/8勝」は**枝ごとにロールアウト乱数を変えていた設計が CRN の
対照性を壊して作った偽の差**と確定。乱数を枝間で共有すると 10/16 vs 9〜11/16 の同値に収束した。

**`referee_position`（本家レフェリー）も同じ手別乱数だった**＝v18/v3 を含む過去の全裁定の
マージンはこのノイズで水増しされていた可能性がある。両計器の rng_seed を世界のみの関数に修正
（差は「最初の手」だけから生まれる）。以後の裁定は修正後の計器で行い、薄マージン裁定の
再読み込みは worlds16＋本修正を標準とする。

## 3. 人間整合の結果（CRN修正後・worlds16・def_temp0.7）

- 走査: 5局72決定 → **測定可 13窓**（50 は復元不能＝旧録画×新エンジンの後半乖離・9 は非窓）
- **top一致 10/13・band内 12/13**
- band 外 1窓 = m2@32（人間: 素通し 4勝 / 測定: カウンター 8〜11勝）。ユーザレビュー:
  「手札に2000カウンターが1枚だけ・次ターン以降にリーダー強化を出せそうだったので通したが、
  **守っても良い場面だった**」＝測定の主張はユーザの自己評価とも矛盾しない
- m2@48（初回の異常）は修正後 band 内に収束＝ユーザ判断どおり

**結論: 防御温度つき反実仮想測定は人間判断と 12/13 で整合＝フェーズ2（防御窓コーパスの量産→
学習）に進んでよい健全性**。

## 4. 教訓

- 人間レビューが計器バグ（CRN 破れ）を1窓で特定した。「人間マークは薄マージン測定より強い証拠」
  という運用は、教師としてだけでなく**計器の検定器**として機能する
- 反実仮想測定の鉄則: **世界（隠れ情報）だけでなくロールアウト乱数も枝間で共有**する。
  差は比較対象の手そのものからのみ生まれるべき
- 旧 gen7 録画は新エンジンでの後半再生が壊れやすい（効果既定の変更が無記録の自動解決を変える）。
  人間防御データを増やすには**新エンジンでの対局録画**が必要（ユーザの新規マーク採取と同時にできる）
