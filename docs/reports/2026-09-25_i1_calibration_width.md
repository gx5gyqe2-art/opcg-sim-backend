# I-1: 決着前較正に残る「両側対称な幅」の診断——決着までの残りターン数が機構として生き残った(2026-09-25)

`crossing_bridge.py` の決着前較正（T146a〜c／T151／T154）は、優勢側だけの過大評価という非対称を
T151（相手の時計の鮮度・手番の半ターン）で解消し、残る課題を「両側同じ大きさ（≈0.04〜0.15）の
対称な行き過ぎ」と名指ししていた（`2026-09-24_opp_clock_freshness.md`）。下位機構は T149c（生存の
選択）・T149g（劣勢側デッキの揺れやすさ）の2回で、実・合成の向きが割れて特定できていなかった。
本作業はまず σ 表の前提を確認し、続けて帯・優劣・実合成の既知軸を再確認したうえで、まだ試していない
2 本の新軸（決着までの実際の残りターン数・交点の橋の生の |D|）を測った。**新定数ゼロ・診断のみ・
式は実装していない**。

コーディネータ側で独立に確認済み: `tests/scripts/crossing_bridge.py`は`effect_value`をimportしない
（`grep`で確認）——`COST_AFFORD_MODE`（D-4/D-6）は`effect_value.py`にしかない切替なので、この経路で
crossing_bridgeが動くことは構造的にありえない。一方`theory_bridge.is_decision_row`（D-5の
`DECISION_ROW_MODE`）は実際にimportして窓の判定に使っており、これは構造的な独立ではなく実測による
近似不変（すでにD-6の報告で確認済みの「交点の橋・2本の曲線は不動」）である点は本報告の記述と一致する。

## 0. 結論(先に書く)

**σ表(T154)は作り直し不要**——D-5/D-6（`DECISION_ROW_MODE=main`・`COST_AFFORD_MODE=check`）は
crossing_bridge の出力を動かさない（D-5 の実測がビット近似不変を報告済み・§1）。

**新軸のうち1本が判定基準を満たした**——「決着までの実際の残りターン数」（`t_me_act`・規則から出る
完全情報の事後量）は、実・合成の両方で、かつ序盤/中盤/終盤の各帯で条件づけても消えない一貫した方向
を示した（優勢側6/6・劣勢側6/6で「残りターンが少ないほど較正誤差が的中側に寄る」）。これは
T149b の `clock_scale`（モデル自身の残り時間の読み）が帯内条件づけで消えたのと対照的——**帯とは
別の、独立した軸**。もう1本（交点の橋の生の |D|）は実がほぼ平坦・合成が単調増加で向きが割れ、
T149c・T149g と同じ理由で不採用。

**推薦: 「機構未特定のまま閉じる」ではなく、この軸を式に落とす後続タスクを起こすことを推薦する**
（本作業では実装していない）。

自分でも favorite/underdog gap を再計算し確認: `--pre-settle on`・今の既定の上で

## 2. 既知軸の再確認(帯×優劣×実合成)

| | 序盤 | 中盤 | 終盤 |
|---|---|---|---|
| 実・優勢 | −0.029 | +0.054 | +0.076 |
| 実・劣勢 | +0.033 | −0.130 | −0.107 |
| 合成・優勢 | +0.037 | +0.065 | +0.152 |
| 合成・劣勢 | −0.054 | −0.098 | −0.115 |

優勢側は両記録で序盤→終盤に単調増加——T146c の「終盤ほど大きい」を今の既定でも再確認。劣勢側は
序盤→中盤の悪化は両記録一致だが、中盤→終盤の向きは実（やや改善）と合成（さらに悪化）で食い違う
（既報の残存非対称・新しい軸ではない）。

## 3. 新軸1(採用可): 決着までの実際の残りターン数

`crossing_bridge.collect` が各行に既に持つ `t_me_act`（その席の残りの自席ターン数——局が
実際に終わるまで。規則から出る完全情報の事後量・新定数ゼロ）で4分位に割った。

**全体**（優勢側・実 少→多: +0.125→+0.049→+0.067→**−0.036** ／合成: +0.394→+0.099→+0.082→
**+0.018**。劣勢側・実: −0.030→−0.070→−0.123→−0.093／合成: −0.011→−0.064→−0.076→**−0.165**）。

**帯で条件づけても消えない**（T149b の `clock_scale` は帯内条件づけで消えたのに対し本軸は残る）:

| 帯 | 優勢・実（少→多） | 優勢・合成（少→多） | 劣勢・実（少→多） | 劣勢・合成（少→多） |
|---|---|---|---|---|
| 序盤 | +0.044→−0.078 | +0.218→−0.004 | +0.172→+0.005 | +0.089→−0.105 |
| 中盤 | +0.107→+0.025 | +0.103→+0.033 | +0.008→−0.223 | +0.052→−0.136 |
| 終盤 | +0.397→+0.028 | +0.388→+0.103 | −0.027→−0.165 | −0.020→−0.195 |

優勢側6/6・劣勢側6/6が同じ向き（残りターン少→多で gap が下降）——**実・合成の向きが一致し、かつ
帯で条件づけても消えない**。判定基準（両記録で向きが一致する軸だけを機構と認める）を満たす、
これまでで最初の候補。

**読み**: 同じ経過ターン数（帯）でも、その後の局がどれだけ長引くかによって較正誤差の大きさが違う。
決着が近い行ほど優勢側は的中に近づき（実はわずかに過小評価側へ超えることさえある）、劣勢側も
的中に近い。決着から遠い行ほど優勢側の過大評価・劣勢側の過小評価が両方拡大する——σ が
「その後どれだけ長引くか」という情報を織り込めていない可能性を示す。

## 4. 新軸2(不採用): 交点の橋の生の |D|

同じ4分位法で `win_calib.rows_of` の生の交点ギャップ `|D|`（σを通す前）を割った:

| | q1(小) | q2 | q3 | q4(大) |
|---|---|---|---|---|
| 優勢・実 | +0.043 | +0.023 | +0.039 | +0.037 |
| 優勢・合成 | +0.052 | +0.057 | +0.105 | **+0.129** |

実はほぼ平坦・非単調、合成は単調増加——**向きが一致しない**。劣勢側も形が食い違う（実は q2 に谷、
合成は q1 だけ低く以降平坦）。**T149c・T149g と同じ理由で機構と認めない**。

## 5. 器・再現

新規スクラッチ器（リポジトリ非追跡・診断専用・新定数ゼロ）は既存の関数だけを呼ぶ:

```python
# crossing_bridge.collect() の既存フィールド t_me_act と
# win_calib.rows_of() の既存フィールド d をそのまま読む。新しい価格式は書いていない。
rows_out, ... = CB.collect(dirs, 0, TO.THETA, TO.MU, "const")   # CB.set_pre_settle_mode("on") の上
rs = WC.rows_of(rows_out, "theory"); p = WC.probs_of(rs, CB.sigma_rel_for(dirs))
```

記録: 実 `w41`（300局・pre-settle on で3255行）・合成 `w39+w42`（900局・9367行）。
σ_rel は T154 の表（`sigma_rel_for`）をそのまま使用（§1 で作り直し不要と確認済み）。

## 6. 推薦

「機構未特定のまま閉じる」には当たらない——**決着までの実際の残りターン数**が判定基準（実・合成の
向きが一致・既知の帯軸で条件づけても消えない）を満たした。次に進むなら、この軸を σ か τ の式に
落とすタスクを起こす（本作業では実装していない・候補: crossing_bridge が既に持つ
`tau_me`/`tau_opp`——これらは `t_me_act` と相関するはずの既存量なので、そこを経由すれば新定数ゼロで
σ の残り時間依存を作れる可能性がある。要検算）。採否・次段の着手はユーザ判断。
