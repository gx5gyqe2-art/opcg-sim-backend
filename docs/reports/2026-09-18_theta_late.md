## 1. 問い（T95 が指した先）

偏り +2.9 は**モデルが決着を実際より遅く言う**という意味で、**速さを上下どちらに動かしても直らない**（T93〜T95）。
残るのは**的（`Θ`）の側**。T89 は「**残りターンが 1〜2 の行でも τ が 5 ターン先を指す**」と測っていたが、
**`Θ` のどこが悪いか**は分かっていなかった。

## 2. 器（新定数ゼロ・読み取りだけ）

```
勝った席の自席ターンごとに
  Θ_j            = λL + g·H + Σν(体)             （`threshold_parts` で 3 項に割る）
  要った損害_j    = F_end − F_j                   （そこから終局までに**実際に**与えた損害）
  Θ_j / 要った損害_j  を**残りターン別**に並べる     （1 なら `Θ` の大きさは正しい）
```

## 4. 原因——T83 の問いの立て方

T83 は耐久の体を「**殴れるか**」（`declare_attack` の的になれるか）で決めた。しかし `Θ` が答えるべき問いは
「**避けて通れるか**」である。

| | 殴れるか | **避けて通れるか** | 耐久か |
|---|---|---|---|
| レストの体 | ○ | **○（攻め手は的を選べる。リーダーだけ殴って勝てる）** | **×** |
| アクティブなブロッカー | × | **×（横取りされる）** | **○** |
| アクティブな非ブロッカー | × | ○ | × |

**とどめのターンに相手の盤面がレストで埋まっている**（自分のターンに殴ったから）のに、
`attackable` はそれを全部「壊さないと勝てない量」として数えていた。**規則上は 1 体も壊さずに勝てる。**

## 6. 2 つの橋が反対を向いた——なぜか

**帳簿が `A` を好む理由は「`Θ` が正しいから」ではない**。帳簿が `Θ` を使うのは **`κ = w(D)/w̄` の `D`（到達ターンの差）**
だけで、`D` は**両席の `Θ` の差**から出る。体の項を落とすと `Θ` はライフと手札が主になり、**両席で似た値**になる
＝**`D` が 0 に潰れる**。実際 **`|D| > 3` の行は 319 → 68（実）・253 → 49（合成）**。
`κ` は `D` の広がりで効く重みなので、**広がりが消えれば重みが効かなくなる**。

＝**`A` の優位は「耐久として正しい」ではなく「`D` が散らばる」**。T82 で `all` が見かけ上良く見えたのと同じ型。
**`D` を `W(D)` に写す `σ_D` は T75 以来 1.0 の借り物**のままなので、**`D` が縮んだら `σ_D` も縮めなければ**
同じ土俵で比べたことにならない。**ここが未解決の交絡**。

## 7. レストのブロッカー——符号化の制約を 1 つ見つけた

ユーザ指摘「レストのブロッカーの意味も考えてみてください」から規則を確かめた:

- `has_blocker` は **`!is_rest`** を要求する＝**レストのブロッカーは横取りできない**（レストがブロックの費用）
- `refresh_phase` で**アンタップする**＝**次の攻撃ターンには戻っている**
- **ブロックに召喚酔いは無い**（ユーザ指摘・`has_blocker` に `is_sick` の検査が無い）＝
  **出した次の相手ターンから遅延なく使える**

＝**今は耐久ではないが、次のターンからは耐久**。**`Θ` は在庫・時間は流れの側**（T90）に従えば、
置き場所は**補充 `r` の側の「`j ≥ 2` の段差」**。

**ところが最初の実装は 1 件も拾えなかった**（767 自席ターンで 0 件）。原因は**符号化**——
トークンの 6 列目は `is_blocker_active`（`tokens.rs`: `on_board && Character && !rest && has_keyword(BLOCKER)`）で、
**レストのブロッカーは 0**＝**レストの素の体と区別がつかない**。
**札の id から原本のキーワードを引く形に直した**（`ci_row`／`idx2cid`／`cards`）。直したうえでの結果が上表の C で、
**効果は微小かつ逆向き**（的中 0.6541 → 0.6498・偏り +2.53 → +2.59）——**段差は的を遠ざける**ので、
**モデルが既に遅すぎる**いまは T95 と同じ理由で悪化する。

## 8. 読み方

- **上手くいった 1: `Θ` の壊れ方が初めて見えた**。**両端に 1 つずつ**（終盤 4.07・序盤 0.78）で、
  **終盤は体の項・序盤は補充の欠落**（T91 の `r` が既定でないこと）と、原因も分かれている。
- **上手くいった 2: 規則から出る耐久の集合が確定した**——**「避けて通れるか」**。
  これは T83 の「殴れるか」より狭く、**`blockers` と一致する**。交点の橋では**両記録・3 指標すべてで B が A に勝つ**。
- **上手くいかなかった: 帳簿が逆を向く**（`ΔG` AUC −0.09・必要な `κ` 0.78 → 0.57）。
  **ただしその優位は `D` の広がり由来**で、**`σ_D` が借り物のままなので公平な比較になっていない**。
  **既定は据え置き**（`attackable` のまま）——**`σ_D` を直してから判定するのが筋**。
- **上手くいかなかった 2: レストのブロッカーの段差は微小かつ逆向き**。規則としては正しいが、
  **「遅くする直し」は今のモデルでは全部悪化する**（T95 と同じ）。

## 9. 次（ユーザ判定）

1. **`σ_D` を交点の橋の `σ_T` から置く**（最優先・T75 以来の宿題）——`D → W(D)` の写像が借り物の 1.0 なので、
   **`Θ` の形を変えると `D` の広がりが変わり、帳簿の比較が壊れる**。`σ_T`（1.08〜1.29・実測）を入れてから
   **A と B を測り直す**。これをやらないと**体の集合を判定できない**。
2. **序盤の 0.78 を埋める**（`Θ` の補充＝T91 の `r` を既定にするかどうか）——`Θ` は序盤に小さすぎる。
   `r` は既に規則から出る形で在る（`--race deck`）。**1 と同時に測る**。
3. **手札の項を終盤で見直す**（残り 1 で 0.181 ＝ 要った損害 0.169 とほぼ同額）——
   **切れる札が「必ず μ ずつ吸う」前提**が終盤で破れている（大きい攻撃はカウンター 1 枚では止まらない・`c(x)`）。
4. **相手の手札のブロッカーを耐久に入れる**（未実装・ブロックに召喚酔いが無いので**出せば次の私のターンに効く**）。

## 限界

- **`Θ`/要は勝った席だけ**（負けた席は `F_end` が途中で切れる）。
- **「実際に要った損害」は実際の打ち筋の結果**——より上手い攻め手ならもっと少なくて済んだかもしれない
  ＝**上限ではなく実績**。`Θ` が「必要量」なら実績より小さいはずで、**終盤 4.07 はその意味でも過大**。
- **レストのブロッカーは札の id 経由でしか判別できない**（符号化の制約・上記）。
  記録に `card_idx` が無い経路では 0 になる。
- **段差は 1 回だけ**（`j = 2`）。実際にはその後もブロッカーは毎ターン戻る（生き残れば）。
- **2 つの橋の比較は `σ_D` が借り物のままなので公平ではない**（§6）。
- **観察であって因果ではない**。
