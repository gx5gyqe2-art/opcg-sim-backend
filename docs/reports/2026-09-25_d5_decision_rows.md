# D-5: 物差しの窓を効果の解決後まで伸ばす（2026-09-25）

D-4 見直し（`2026-09-25_d4_review.md`）で、手の実現を測る窓が**効果の途中の選択の問い**（ドン‼️−N で戻すドン・
サーチで取る札など）の行で閉じ、効果の解決前を読んでいたと分かった。ユーザ決定「(a) 先に物差しを直す」
（2026-09-25）を受けて直し、D-1（型ごとの値段と実現の食い違い）とコスト判定を新しい物差しで測り直した。
新定数ゼロ・既定は旧（`any`）のまま（採否はユーザ判断）。

## 式（計器の直し）

エンジンは選択の答えを**自分の kind 0 の行**（候補が全部 `RESOLVE_EFFECT_SELECTION`）として記録する。
問いの行の候補に通常の手が混ざる行は実 0／合成 0（実 2052 行・合成 2374 行は全部「問いだけ」）。

`theory_bridge.py` に `DECISION_ROW_MODE`（`any`＝旧／`main`）と判定 `is_decision_row` を置き、
「次の判断点」の窓を作る **10 計器**（`price_realised`・`theory_bridge`・`crossing_bridge`・`two_curves`・
`attack_response`・`hand_plan`・`nu_ledger`・`nu_stock`・`play_body_check`・`search_gain`）に通した。`main` では
問いの行を窓の**終わりにも始まりにもしない**（T47 が kind 1/2 に当てた直しと同じ）。CLI は `--decision-rows`。
`any` は旧 `kind == 0` と 1 行も違わない（検算: `price_realised` の要約が D-2 の `off` と完全一致）。

### 実装中に踏んだ二重計上（直した）

最初の版は問いの行を窓の**終わり**からだけ外し、始まりには残していた。交点の橋は「次の判断点が無ければ
そのターンの最後の行で閉じる」（T113）ので、行き先を失った問いの行が**ターン末までの損害をもう一度**足し、
`curve` 読みの偏りが実 −0.35→−0.78 に崩れて見えた。始まりからも外して解消（下の表は直した後）。
10 計器すべてで始まりの判定も共通化し、テスト（`tests/test_decision_rows.py`）が両方をラチェットする。
`two_curves --verify`（交点の橋の損害の和と独立実装の突き合わせ）は `any`・`main` とも差 0.0。

**`ΔG` が下がる理由を確かめた**: 今の帳簿（`LEDGER_HARM_MODE=realised`・T87）は値付けできた行の「相手が
実際に失った額」を次の判断点まで数える。旧では登場時効果の除去（KO 等）が問いの**後**に解決するので、その
損害は値付けできない問いの行の窓に落ちて**帳簿から丸ごと消えていた**。新ではそれが登場の行に入る。入った
損害を局×席で勝敗に分けると、実では**負けた側が 4.6 倍**（1 局あたり 0.0250 対 0.0055・変わった行は登場
114 行だけ）、合成では 1.4 倍（0.0079 対 0.0057）。劣勢の側ほど登場時の除去を使う——D-1 の「ドン加速は
負けた側に偏る」と同じ種類の打ち方の偏りで、物差しの誤りではない。`ΔS` は動かない（実）・4 桁目（合成）。

## 読み

* 物差しの直しは D-1 の 2 つの食い違い（play「?」の符号・effect の実と合成）を**両方とも**解いた。
  D-2〜D-4 が値段の側で追っていたものは、物差しの側の早閉じだった。
* 直した物差しの上で、エンジンと同じ規則のコスト判定は値段と実現の一致を両記録で改善する。
  `ΔS`（実）の −0.006 は傾きの 95% 区間（0.038〜0.198）の中。
* 線形の橋の本体（`ΔG`）は新しい物差しで下がる。帳簿の抜けが埋まった結果で、下がった分は「劣勢の側の
  除去」という打ち方の偏り。#43（`ΔG` の傾き→1）はこの直しでも閉じない（むしろ遠ざかる）。
