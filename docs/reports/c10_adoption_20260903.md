# c10 採用報告 — 出荷既定を G15 から N系 c10 へ（2026-09-03）

**ユーザ決定（2026-09-03）「一旦 c10 を正式昇格させましょう」**。出荷既定 CPU を G系最終世代
**G15**（`gen15_value.npz`+`gen15_policy.npz`）から **N系 c10**（`neff_c10.npz`・効果構造符号化ネット・
カード ID 埋め込みなし）へ切り替える。N系は 2026-08-27 に始めた自己対戦ループ（c1→…→c11）の
系統で、c10 は era5 の生成役（c11 は非昇格・`2026-09-03_c11_judgment.md`）。

結果が出たら本報告とは別に記録する（報告は追記しない規約）。

## 2. 何が変わるか（serve）

- **1本の npz**: value と policy を同じネットが出す。`LearnedEngine` は npz の鍵（`Wa` あり・`Emb` なし）
  で N系と判別し、value は `NEffValueAdapter`（vnet ダックタイプ）、方策は `priors_override`
  （G 形式の `pnet` を経由しない）に配線する。`_DEFAULT_POLICY` は None。
- **出口ヘッド無し**: 箱（戦闘/対話）の出口も本体 value で測る（`_exit_value_fn` は None）。
  G15 の戦闘出口ヘッド（v41）は N系には無い＝**防御較正は本体の学習に任せる**。
- **語彙**: 同梱 npz に **vocab_ids（gen15 系譜と同一・2,652 枚）** を焼き込んだ。N系の全世代は
  この vocab で訓練されているので、vocab_ids を持たない旧 N系 npz（`claude/n1-results` の
  `neff_net_c*.npz`）も同梱既定の vocab_ids へフォールバックする（現行 DB ソート＝2,803 枚へは
  落とさない。2026-07-15 の索引ズレ事故の再発防止）。OP17 の新カード 119 枚は UNK=0。
- **正本の移動**: forward・効果ベクトル化・語彙表・候補素性・priors は
  `opcg_sim/src/learned/n_eff.py` が唯一の正本。`tests/scripts/n_eff_feat.py`（再輸出）・
  `n_eff_train.py`（継承して backward/Adam）・`n_eff_gate.py`（`neff_engine` は
  `LearnedEngine(value_path=...)` の別名）は互換窓口。訓練器は保存時に vocab_ids を焼き込む。
- **表の前計算はプロセス内共有**（パス単位）・`vnet` はエンジンごとの別インスタンス
  （net-vs-net の契約維持）。

## 3. ロールバック

既定を G15 ペアへ戻すだけ（`_DEFAULT_VALUE=_G15_VALUE`・`_DEFAULT_POLICY=_G15_POLICY`）。
判別は npz の鍵で自動＝配線変更不要。G15 の契約テストは明示パスで残してある
（`test_exit_heads.py::test_gen15_pair_is_v12_with_battle_head`）。

## 4. 既知のコスト: レイテンシ

同一盤面 5 点（m2@10/30/50/70/90・sims160・本コンテナ・単独実行）:

| | 平均 | 最大 | 盤面別 |
|---|---|---|---|
| G15 | 0.78 s | 1.48 s | 0.03 / 1.40 / 1.01 / 1.48 / 0.00 |
| c10 | 1.33 s | 3.12 s | 0.03 / 1.70 / 1.81 / 3.12 / 0.00 |

プロファイル（m2@70）では NEff 固有の計算（priors 1.3 s／value forward 0.5 s・cProfile 込み 7.0 s
中）より、**木の形が変わって戦闘解決（`resolve_battle_inplace`）を多く通る**ぶんが大きい＝
方策が違えば探索が違う。priors の uuid 走査は索引化した（本 PR）。gen15 採用時の予算
「decide 1 秒」（当時の実測 0.49 s・本コンテナは当時より遅い）に対して c10 は約1.7倍＝
**アプリ体感では手が遅くなる**。ユーザ判断で受容（私用・CPU はほぼ未使用）。
