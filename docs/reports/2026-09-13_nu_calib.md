# `ν` の較正——**当てずっぽうを実測に替えたら、理論は少し悪くなった**

2026-09-13 実施・判定（ユーザ指示・選択肢 2「`ν` の較正」）。`nu_calib.py`（新規・**記録だけ**）を
300 局（seed 帯 9700〜9999・sims 64・worlds 4・生成役 r3）の **3,139 自席ターン・守りの窓 10,574** に。
本報告は特定時点のスナップショット（追記・改変しない）。

## 結論を 3 行で

1. **`block_p` は値ではなく「種類」が誤っていた**——**ブロックできるのはブロッカーだけ**なのに、
   定数 0.3 を全キャラに掛けていた。実測は**ブロッカーなら 0.773・それ以外は 0**で、
   **ブロッカーは自場のキャラの 10.4% しか居ない**＝母平均 0.080 に対し**旧定数は 3.7 倍の過大**。
2. **3 定数を実測に替えると `ν` は非ブロッカーで 21% 下がる**（0.164 → 0.130）。
   **私の仮説（`ν` が低すぎる）は逆向きに否定された**。
3. **較正すると理論と探索の一致は全帯・全指標でわずかに悪化した**
   ＝**定数ではなく式の構造が足りない**。**場に居ること自体の価値**が 4 通貨に無い。

## 1. 測った 3 つ（と現在の定数）

| 量 | 実測 | 現在の定数 | 判定 |
|---|---|---|---|
| **ブロッカーの割合**（自場のキャラのうち今ブロックできる） | **0.104** | —（**区別していない**） | **種類の誤り** |
| **`block_p`（ブロッカー 1 体・相手ターン 1 回あたり）** | **0.773** | 0.30 | **2.6 倍の過小** |
| `block_p`（守りの窓あたり） | 0.034 | 0.30 | 参考（別の量） |
| **`ko_p`** | **0.289** [0.276, 0.302] | 0.25 | 16% の過小 |
| **`R`（残りの自席ターン）** | **4.128** | 代理 3.977（相手ライフ） | 代理が **0.151 低い**（CI が 0 を含まない） |

**守りの窓の内訳**（10,574 窓）: `PASS` 63.9%・`SELECT_COUNTER` 32.7%・**`SELECT_BLOCKER` 3.4%**。

> **`block_p` を 2 通りに分けて数えたのが要点**。窓あたりは 3.4% で「ブロックは稀」に見えるが、
> それは**ブロッカーが居ない相手ターンで薄まっている**だけ。**ブロッカーを持っていた相手ターンでは
> 77.3% でブロックが起きている**＝**居れば必ず使う**。`ν`（キャラ 1 体の価格）が欲しいのは後者。

## 2. `ν` を引き直すと下がる

| | `ν` | 現行比 |
|---|---|---|
| 現行（`R`=代理・`block_p`=0.3・`ko_p`=0.25） | 0.16425 | — |
| 較正後・**ブロッカー** | 0.16510 | ×1.005（ほぼ不変） |
| 較正後・**非ブロッカー**（キャラの 89.6%） | **0.13028** | **×0.793** |

ブロッカーがほぼ不変なのは、**ブロック率の上昇（0.3→0.773）と KO 率の上昇（0.25→0.289）が
打ち消し合う**ため。非ブロッカーはブロック項を失うだけなので 21% 下がる。

> **私の事前の読みは外れた**。「`ν` が低すぎるから理論が登場を過小評価している」という仮説に対し、
> **較正は `ν` をさらに下げる**＝**その仮説は成立しない**。

## 3. 較正した理論で食い違いを測り直すと、**悪化した**

同じ 300 局を `theory_vs_search.py` で引き直した（`q_recovered`＝無作為 0・探索の結論 1）:

| 帯 | 指標 | 較正前 | 較正後 |
|---|---|---|---|
| close | `q_recovered` | 0.3221 | **0.3111** |
| close | top1 一致（訪問） | 0.3691 | **0.3603** |
| mid | `q_recovered` | 0.3390 | **0.3071** |
| mid | top1 一致 | 0.3900 | **0.3766** |
| decided | `q_recovered` | 0.4187 | **0.4107** |
| decided | top1 一致 | 0.4271 | **0.4216** |

**全帯・全指標で小さく一貫して悪化**（個々の差は小さいが、**3 帯 × 2 指標が揃って同じ向き**）。
「理論はターン終了・探索は登場」の割合も動かなかった（接戦帯 0.1199 → 0.1182）。

### これが意味すること

**より正しい定数を入れて当てはまりが悪くなるのは、式が間違っているときの徴候**である。
いちばん素直な説明:

> **旧定数 `block_p = 0.3`（全キャラ）は、たまたま「場に居ること自体の価値」の代理になっていた。**
> 正しく（ブロッカーだけに）直すと、その代理が消え、**代わりが無いので `ν` が足りなくなる**。

4 通貨の `ν` は**攻める・ブロックする・KO される**の 3 つしか価格化していない。
実際のキャラにはもう 1 つ channel が在る:

- **身代わり（lightning rod）**——相手がキャラを殴れば、その攻撃は**リーダーに来ていない**
  ＝ライフもカウンターも払わずに攻撃 1 回を消している。これは**守り側の利得**だが、
  `ν` は攻め側の視点（`min(c(x)·μ, ν)`）でしか登場しない＝**`ν` の中に入っていない**。

これは記録から測れる（`race_state` が `n_face` 対 `n_board` を持っている）。
**次の一手は定数の較正ではなく、この項を式に足すこと**。

## 4. **パワーが `ν` に入る経路は 1 本しかない**（ユーザ指摘 2026-09-13）

ユーザの問い「価格に対してキャラクターのパワーとかは考慮されてる？」への答え＝
**されているが `attack_value(パワー, 相手リーダーのパワー)` の 1 か所だけ**で、
そこに 3 つの穴が在る（相手リーダー 5000・`R`=4 で引いた値）:

| パワー | 攻撃 1 回の価値 | `ν`（非ブロッカー） |
|---|---|---|
| 1000 | 0 | **0** |
| 3000 | 0 | **0** |
| 5000 | 0.055 | 0.157 |
| 6000 | 0.055 | 0.157 |
| 7000 | 0.063 | 0.180 |
| 10000／12000 | 0.063 | **0.180** |

1. **リーダー未満のキャラは価値が文字通り 0**（`x<0` で `attack_value=0`）。
2. **飽和点を超えるとパワーは無価値**（12000 と 7000 が同値）。
3. **`ν` は実質 3 段の階段**（0／0.157／0.180 の 3 値しかない）。

**そして 1 が §3 の「理論はターン終了・探索は登場」の正体だった**——実測（同じ 300 局）:

| | リーダー未満（`ν`=0） | リーダー〜+2000 | +2000 以上 |
|---|---|---|---|
| **登場候補のキャラ** | **71.8%** | 21.3% | 6.9% |
| 自場に居るキャラ | 28.4% | 33.2% | 38.4% |

**登場候補の 71.8% はパワーがリーダー未満**＝`ν = 0` ＝
`play_value = 0 − μ − cost·δ` は**必ず負**＝**理論は「安いキャラを出すな」と常に言う**。
§3 で「`ν` が低すぎる」と曖昧に診断したものは、**ここに特定できた**。

### パワーに依るべきなのに依っていない項

| 項 | 現状 | 本来 |
|---|---|---|
| **キャラを殴る価値** | **無い**（リーダー狙いだけ） | パワーで勝てる相手キャラを KO できる |
| **身代わり** | **無い** | パワーが高いほど殴られにくい／生き残る |
| **`ko_p`** | 定数 0.289（全キャラ同じ） | **パワーが高いほど低いはず** |
| ブロック項 | 定数（パワー非依存） | 高パワーのブロッカーは繰り返し使える |

**`ko_p` をパワー非依存の定数にしているのは、§1 で見つけた `block_p` の誤りと同じ形**である
（キャラの素性を無視して定数を全体に掛けている）＝**同じ直し方が要る**。

## 限界

- **`blocker_share` は自席ターン開始時の枠で数えた**（そこでは全員アクティブなのでキーワード保有率に
  近い）。相手ターン中のアクティブ率は別の量で、ブロック後のレストも効く。
- **`ko_p` は「体数の差」で測った代理**——KO 以外の退場（自分の効果でトラッシュ、置換）も混ざる。
  枠の同一性を追っていない（dump に枠の uuid が無い）。
- **`nu_effect` はキャラのパワーを 5000 に固定**して比較した（分布を使うと `R` の効果と混ざるため）。
- `R` の代理と実測のずれは小さい（0.151 ターン）＝ここは主要因ではない。
- 1 設定・1 ネット（r3）・生成時の探索（Dirichlet 雑音と温度が乗っている）。

## 次

**定数の較正は終わり。次は式にパワー依存の項を足す**（§4）。優先順は「抜けの大きさ」順:

1. **キャラを殴る価値**——`ν` はリーダー狙いしか値付けしていないので、
   **パワーがリーダー未満のキャラ（登場候補の 71.8%）が一律 0** になっている。
   相手キャラを KO できるかは自分のパワー対相手のパワーで決まる＝**記録から測れる**。
2. **身代わりの項**（相手がキャラを殴る確率 × その攻撃がリーダーに来ていたときの損）。
   係数は記録から出る（`race_state` の `n_face` 対 `n_board`）＝また当てずっぽうを置かない。
3. **`ko_p` をパワーの関数にする**——`block_p` と同じ誤りの形。
   枠のパワー帯ごとに退場率を数えれば出る。
4. 足した後に §3 の表を引き直す。**一致が改善すれば「式の構造が足りなかった」が裏付けられる**。
   改善しなければ `ν` の外に原因が在る（`μ + cost·δ` の請求過多など）。
5. 較正済みの定数は `theory_order.BLOCK_P_BLOCKER` / `KO_P` が正本（`nu_of` は
   `is_blocker` を受け取る）。**過去の数字を再現したいときは `block_p`/`ko_p` を明示する**。
