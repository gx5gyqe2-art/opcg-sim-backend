# T26 を `pair` で回し直した——**「体を出すな」の矛盾は 3 段で解け、`pair` が最後の段を担った**

2026-09-15 実施。ユーザ指示「全て再測定して体系的に整理」→「T26 から先に回してください」。
`ν` の既定を `pair` にした（`2026-09-15_nu_pair_default.md`）ことの**独立の検算**として、
橋（T28 系）とは別の器 `mu_branch.py`（T26）を回した。本報告は特定時点のスナップショット。

## 結論を 6 行で

1. **T26 の「理論は 98.5% の行で体を出すなと言う」（2026-09-14）は、今日の `base` で既に消えていた**
   ——`mu_branch` を **T30・T33 の後に一度も回していなかった**。合成 900 局で「出すのは得」の行は
   **1.46% → 25.8%**（体だけ）／**40.2%**（イベント込み）に動いていた。
2. **どの変更が動かしたかを commit ごとに切り分けた**（同じ記録・同じ器）——
   **T30（全動作の値付け）で 3.7% → 22.6%・T33（登場時効果）で → 40.2%**。T31・T34・T35 は 0。
3. **`pair` はさらに動かす**——体だけで **25.8% → 41.4%**（合成）・**31.5% → 41.4%**（実デッキ）。
4. **`μ_develop`（体になった札の価値）の平均が `pair` で `μ` に並んだ**——合成 **0.0471**・
   実デッキ **0.0574** 対 `μ` = 0.0551。`base` は 0.0083／0.0158（≈ 0）。
   **「札 1 枚を体に換えると札 1 枚ぶんの価値」は §17.1.2 の `μ = max(μ_guard, μ_develop)` が
   要求する釣り合い**で、当てはめていない量がそこに寄った。
5. **T26 の判定 `guard_binds` は `base` でも `pair` でも `both_bind_state_dependent` に変わる**
   （`c̄` の 3 通りのうち `row` だけ `base` で `guard_binds` に残る）。
   **＝`Θ = λ/μ − 1 − τ` の導出は「常に守る枝」を前提にできない**——帯（手番・手札）で切り替わる。
6. **器の訂正 1 つ**——P2-1 以降の `mu_branch` は**イベント・ステージも「作る枝」に混ぜていた**
   （`PLAY` 候補に値が付くようになったため）。**T26 の問いは体の話**なので `--play-kind char` を足し、
   本報告の「体だけ」はそれで出した。

## 3. 読み方

- **`pair` の効果は「弱い体の穴」から来る**——`base` は 3000 の体を 0 と言い、`pair` は 0.043 と言う。
  「出せる体」の多くはリーダー未満なので、そこが 0 だと「出すな」になる。**T21 が実測で示した
  0.0690 を式が持てば、出す理屈が出る**——順序の話（橋）と水準の話（本器）が同じ向きを向いた。
- **「41% しか得と言わない」は矛盾ではない**——比べているのは**その行に実際に在った候補の最良**で、
  ドンが足りない・小さな体しか無い行は本当に出さない方が良い。**矛盾だったのは 1.46%** の方。
- **ただし `μ_develop ≈ μ` は事後の整合であって予測の的中ではない**——`pair` を入れる前に
  「`μ_develop` は `μ` に並ぶはず」と書いていない。次に何かを変えるときは**先に書く**。

## 限界

  実害**——他の C 層の器（T1・T24・T28 系・中間ゲート・Phase 1c）も同じ疑いが在る。

  当時の 1.46% を「体だけ」で再現することはできない（当時は体しか値が付かなかったので実質同じ）。

  「理論が得と言う行」と「CPU が出した行」の一致率は次の器。
- **観察であって因果ではない**（§0.3 の限界はそのまま）。
