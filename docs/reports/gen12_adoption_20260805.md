# gen12 採用報告 — バトルを「箱」として扱う探索規約の統一（v35）2026-08-05

## 1. 何を採用したか

**重みより先に、探索の規約が本世代の核**である。ユーザ整理（2026-08-05）の言葉を借りれば:

> バトルを一つの箱としてまとめて、探索と value は「バトルをするかどうか」「バトルの結果、
> どのような盤面・手札・ライフ状況になるか」のみを判断する

これを3つの機構で実装し、**すべて既定 ON**にした（片方だけ ON は train/serve skew になるため、
旧世代へ戻すときは3つとも False に戻す）。

| 機構 | config | 何をするか |
|---|---|---|
| 静止探索 | `SERVE_QUIESCE` | 葉が戦闘中なら**解決するまで進めてから**評価する |
| 戦闘窓の読み出し | `SERVE_BATTLE_READOUT` | 実対局の防御窓は full-tree の root Q でなく**出口 value** で選ぶ |
| 木の中の箱化 | `TREE_BOX_BATTLE` | 木の戦闘窓ノードも**出口最良の1手へ畳む**（戦闘＝1本のマクロ手） |

解決規約の単一の正は `mcts.resolve_battle_inplace`（policy 最良手→PASS→先頭手）で、
**探索・実対局・教師コーパス生成の3者が同じ関数を使う**。これにより「木の中と実対局で同じ場面を
違う規約で扱う」ずれが初めて解消した。

重みは `gen12_value.npz` ＝ **gen11 と「防御窓CF順位学習の腕」の線形補間 α=0.5**。
policy は gen11 と同一バイナリ（v12 確定＝policy 微調整は有害・符号化 v8 の一致が必須）。

## 3. なぜ効いたか（機序）

### 3-1. 戦闘中の葉は「命が助かるか」を符号化できていない

m1@15（攻撃7000・防御6000・既カウンター1000）で gen11 の1手先評価は、正解の 2000 カウンターが
3択の**最下位** −0.4502、止まらない 1000 が最高 −0.4281 だった。戦闘が未解決の盤面では
「1000 を切った子」と「2000 を切った子」がどちらも手札−1・ライフ不変で**ほぼ同一の入力**になり、
どちらが命を救うかは解決後にしか盤面へ現れない。手札の最大カウンターを温存する汎用癖が
逆向きに働いていた。

同じ理由で v34 の教師は**学習不可能**だった（戦闘途中の子を符号化＝ほぼ同一入力に異なるラベル）。
v35 で教師の符号化を解決後へ揃えたところ、1手先の順序は正しくなった（正解が +0.117 上）。

### 3-2. それでも探索後 Q は逆転していた — アンカーが交換レートを固定していた

1手先が正しくなっても、探索後 root Q は PASS が上のままだった（−0.029）。葉トレースで
**木の葉の68%が「次の自ターン」の通常盤面**であることが判明し、そこは蒸留アンカー
（dense 一般盤面 16,000点・約41.5%が相手ターン）が gen11 の予測へ引き戻すため、
**ライフ↔手札の交換レートという動かしたい尺度そのもの**が固定されていた。

アンカーの層別化を4設計試したが（相手ターン全除外／1/3残す／コーパスをz水準で繋ぐ／全面）、
除外すると今度は自ターン判断 m1@3 が 1.00→0.12-0.38 へ崩れた。**手番フラグでレートだけを
解放することはできない**（未来の自ターン盤面にも同じレートが書かれているため）。
結論として、**読み出し側で箱を畳むのが筋**である。

### 3-3. 木の箱化がドン付与を動かした

木の中の戦闘窓を畳んだところ、狙っていた m2@66（攻撃）は動かなかった一方、
**ドン付与2点（m2@44・m5@7）が初めて 0.00 から動いた**。

機序は「攻撃の帰結が具体的な出口として立ち上がる」ことにある。攻撃は相手に
**「手札−1（カウンターを絞り出す）」か「ライフ−1・手札+1（通す）」か**の二択を強いるので、
止められること自体は無駄ではない（ユーザ指摘 2026-08-05）。ドン付与は「その攻撃を通す/
止められない形にする」投資なので、帰結が見えて初めて是非を判断できる。訪問混合ではこの利得が
平均に埋もれていた。

### 3-4. 幅の懸念は誤りだった

当初「相手の応手を1本に確定させると幅が失われる」と懸念したが、ユーザ指摘のとおり誤りだった。
木には別の攻撃順・別盤面の戦闘が無数にあり、各々が独立した箱を持つので幅は残る。失われるのは
**同一の戦闘状況における応手の混合**だけで、それは設計された保険ではなく**MCTS が収束して
いないことの副産物**である。二人零和では相手が最善応手を返すのが正しく、畳む方がミニマックスに近い。

  を seed-base 979000/981000/982000/983000 で**4セッション並列**生成（19シャード・2,198行・584群。

  --lr 8e-5 --delta 0.3 --anchor-dirs /tmp/dense_v30 --anchor-scale 1.5`（順位正答 0.594→0.688）。
- 補間: 上記の腕と `gen11_value.npz` を α=0.5 で線形結合（float 配列のみ・vocab_ids は同一）。
  α=0.3 も両立点（ガード満点×m1@15=1.00）、α=0.7 以上で m1@3 が劣化。
- 判定: `coach_gate` 相当（候補席のみ3機構 ON・16seed）＋ `arena_resume --cand-tree-box
  --pairs 100 --bands 4` を seed-base 71000/72000/73000/74000 で**4セッション並列**（計400ペア）。

## 5. 残課題

- **m2@66（未解決・0.00）**: 自分のターン10・ドン8枚すべてレスト（使い切り）・ライフ2 で、
  ニコ・ロビン8000 → 相手リーダー シャンクス7000 の攻撃が正解。候補は本番の枝刈り後も
  合法手に残っているため「枝刈りで消えている」説は否定済み。CPU が実際に何を選んでいるか
  （TURN_END か、レストキャラへの攻撃か）と各攻撃候補の出口 value の比較が次の一手。
- **m2@44 / m5@7 は部分解決**（0.62 / 0.56＝seed 依存）。残り4割で何に流れているかは未調査。
- 木の箱化は相手の防御窓も畳む＝「相手は評価器の最善で守る」という相手モデルを置いている。
  実害は測っていない（アリーナ中立）。悪化の疑いが出たら「自分の防御窓だけ畳む」限定版、
  あるいは出口 value の softmax（温度は def_temp と同じ思想）へ後退できる。
