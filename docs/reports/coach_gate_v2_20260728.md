# コーチゲート VERIFIED v2 — gen7 実対局マークのレフェリー裏取り（2026-07-28）

gen7 相手の実対局5局・人間マーク34件（`tests/fixtures/replays/gen7_marks_20260728/`）を
レフェリー（gen5 錨・プラン列挙＋同価値バンド・worlds=8・`mark_referee_verify.py`）で裏取りし、
コーチゲートの判定基準を **VERIFIED v2（13点・4対局・両対面方向）** に更新した。
旧 g3（単一対局・gen4期・7点）は `--profile g3` で診断用に存続。スナップショット（追記・改変しない）。

## 1. 裏取りの結果

34マーク → 真盤面復元＋ターン一致 **17点** → 裁定可能 **14点**（バンド外=レフェリーがマークを支持 **9**・
バンド内=同価値 **5**）→ 採録 **13点**（捲り1/32勝ちの極薄点 m1@94 は旧@137型の反省で不採録）。

## 2. 裏取り中に発見・修正した再生系の欠陥2件

1. **早停止バグ**: `state_at_action` の停止が決定数ベース（`stop_after_decisions=upto`）だったため、
   注入 auto_skip のぶん**手前の盤面を黙って返していた**（実測: 1対局の11点が全く同一の評価値）。
   停止を「記録 index 到達」へ変更し、復元盤面のターン照合を裁定側に追加（黙って別局面を裁かない）
2. **ATTACH_DON 照合不能**: 合法手列挙が付与先を「今アタック可能なユニット＋レスト中の自キャラ」に
   限定しており、「アタックできないリーダーへの守りの付与」が**列挙されない**。再生側は API 適用層
   互換の直接構築で吸収した

## 3. ⚠️ 製品側の発見: ドン付与の行動空間に穴

上記2の列挙制限は再生だけの問題ではない。**CPU 自身も「攻撃後・アタック不能なリーダー/味方に
ドンを付与して守る/次ターンに備える」手を原理的に選べない**（探索の候補に出ない）。
実測の傍証: m5 の @61（マーク「ドンが余っているので次ターンのリーダー効果条件のために付与すべき」）で
CPU の候補が TURN_END 1本（visit 100%）だった。今回のマークで最頻の「ドン付与の下手さ」の一部は
学習の問題でなく**行動空間の問題**。修正は core 合法手の変更＝挙動ベースライン再生成を伴うため、
独立の作業単位として提案する（本 PR では変更しない）。
