# 詰みの証明の費用を下げる（WP `lethal-speed`・2026-10-22）

`docs/search_efficiency_plan.md` §7.25。台帳 2+344。§7.21（WP `rs-lethal-root`・`2026-10-22_lethal_root.md`）の続き。
ブランチ `claude/lethal-speed`・成果物 `n1_results/lethal_speed/`。

**目標**: 打つ手（証明される点の集合と証明した手）を変えずに、`root` の費用を 1 手 +37% → +15% 以下。
**結果**: 1 手 **+37% → +10%**（出荷の設定・1 コア・20 局）。不変量は 300 局 13,497 点の全点で成立
（win が減った点 0・証明した手が変わった点 0・証明できていた点が判定から外れた点 0・unknown → win 25 点）。

## 1. 入れた変更（候補 1 と 4・候補 2 は入っていた・候補 3 は曲線だけ）

1. **発動条件を締める（§7.25 の 1）**: 旧い上界は「手札・場・トラッシュの札の本文のどこかに打点を増やしうる文言が在れば上界なし」で、
   速攻の説明文「(このカードは登場したターンにアタックできる)」・【トリガー】・【カウンター】の本文まで数えていた。新しい上界
   （`Solver::attack_bound`）は**今この手番で使える札**（場の札・今のアクティブのドン!!で払える手札。使える札の本文に「登場させる」
   「コスト-」が在れば手札は全部・「トラッシュ」が在ればトラッシュも・「登場させる」が在れば山札も）の、**このターンに働きうる能力**
   （`Ability::raw_text`＝解釈された能力の本文だけ。【登場時】は手札の札だけ・【アタック時】は場の札か速攻の札だけ・相手のターン／
   カウンター／トリガー／ターン開始・終了時は数えない・無効化された札は数えない）に文言が在るときだけ上界なし。無ければ
   「今アタックできるユニット＋払える速攻の手札＋【ダブルアタック】の札」。同じ上界を木の中の自分のメインの節点の枝刈りにも使う。
   健全性: 締めた条件で判定に入らなくなった点に、旧い実装で証明できていた点は **0**（§3）。
2. **配り方の順（§7.25 の 2）**: 守りの強い 2 通りを先に読むのは §7.21 の実装で既に入っていた（`make_deals` の並び）。変更なし。
3. **打ち切りの節点数（§7.25 の 3）**: 曲線だけ測った（§4）。上限を下げると証明できる点が減る＝採らない。
4. **実装の速度（§7.25 の 4・打つ手を変えないことが自明なもの・節点数は 1 つも変わらない）**:
   - 置換表の鍵: `DefaultHasher`（SipHash）→ `fxhash`。盤面の欄を `format!("{:?}")` で文字列にして混ぜていた箇所
     （制限・置換・戦闘・誘発・継続効果・**中断スタック**）を欄の直接のハッシュに（`Hash` を derive）。可変の欄が全部既定の札
     （山札・トラッシュ・ライフのふつうの姿）は 1 バイトで済ませる。中断スタックの Debug 文字列は 1 節点 14 µs かかっていた。
   - 対話の分岐の重複の除去を JSON の文字列化ではなく値の比較に。
   - 試して戻したもの: 相手の判断点にも置換表を引く（節点 −0.5%・鍵の費用の方が大きい）。

## 3. 不変量（300 局 13,497 点・`tests/scripts/lethal_speed_check.py`）

盤面の正本は**記録した手**: §7.21 の打ち直しの監査と同じ設定（両席 r13d・1 本 × 1,280 回・枝予算なし・`root_reply`・
random × synth_roles・seed 3012000〜3012299）で局を打ち直して打った手を全部記録し（`record`・基準の wheel）、記録した手を
探索なしで当て直して各点の盤面を再現し、`Game.lethal_json`（`force`・配り方の seed は監査と同じ `seed * 1000 + step`）で
判定だけを打ち直す（`judge`）。記録 v5 の `hidden` 経由は `known_by` が失われて公平な配り方が別物になるので使わない。
基準の wheel での打ち直しは監査の点と**全点で一致**（点の数・判定・節点数）。

| 監査（前）＼ 後 | 証明（win） | 無い（no） | 打ち切り（unknown） |
|---|---|---|---|
| 証明（win）1,150 点 | **1,150** | 0 | 0 |
| 無い（no）8,449 点 | 0 | 8,449 | 0 |
| 打ち切り（unknown）3,898 点 | **25** | 181 | 3,692 |

- 証明した手: 1,150 点の全部で前後同一。unknown → win の 25 点（相手のライフ 0: 11・1: 11・2: 3）は、締めた上界で木が小さく
  なり節点 20,000 の中で読み切れるようになった点（新しい証明＝打つ手は変わる。win が減る側ではない）。
- 発動条件: 判定に入っていた 12,349 点のうち **1,431 点（11.6%）が判定に入らなくなった**。その旧い判定は「無い」1,373・
  「打ち切り」58 で、**証明できていた点は 0**（候補 1 の健全性の条件）。`force` で判定しても win にならない。
- 節点: 全点の合計 8,553 万 → 8,012 万（×0.94）。「無い」の点で ×0.81（木の中の枝刈りが効く）・打ち切りの点は上限で変わらない。
- 判定の秒: 合計 1,693 → 618 秒（×0.37・前は監査の打ち直し〔4 ワーカ〕・後は 3 ワーカの計測＝目安）。
- 後も打ち切りの 3,692 点のうち 2,937 点（80%）は「今アタックできるユニットの数」だけで相手のライフ＋1 に届く＝発動条件では落ちない。
- 出力: `n1_results/lethal_speed/`（`record_3012000_300.jsonl.gz`＝記録した手と基準の判定・`judge_after.jsonl.gz`・
  `compare_after_vs_audit.json`・`compare_record_vs_audit.json`〔基準の wheel の打ち直しが監査と全点一致〕）。

## 7. 残る問題と次の段

- 判定に入る点のうち打ち切り（unknown・節点 20,000）が 35%（20 局で 420／1,216・不変量の 300 局では 27%） で、費用のほとんどはここ。打ち切りの点の 72% は「今アタック
  できるユニットの数」だけで相手のライフ＋1 に届く＝発動条件をどう締めても判定に入る。上界なしの点では、場の札の
  【アタック時】【起動メイン】の本文の「ダメージ」「相手のライフ」等が原因（上位: OP11-082・OP05-094・OP15-086・OP16-079・OP10-094）。
- 残りの費用はエンジンの適用と合法手（1 節点 4.9 µs）。木を小さくする余地として **同じ札の畳み**（同じ持ち主・同じ札・同じ置き場・
  可変の欄が全部同じ・盤面のどこからも個体として参照されていない 2 枚は入れ替えても盤面が同型＝一方の手だけ読む。打ち切りの点の
  40% で相手の手札に同じ札が在る）が残っている。結果を変えない（節点が減るだけ）が、同型の判定に手間がかかるので今回は入れていない。
- 上限 20,000 は下げられない（証明の 14% が 5,000 節点を超え・6.5% が 10,000 を超える）。
