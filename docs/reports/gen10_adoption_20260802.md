# gen10 採用報告 — 登場時オプション特徴（v7）を土台として確定（ユーザ判断採用）2026-08-02

スナップショット（追記・改変しない）。前提: `cpu_v30_option_feature_20260802.md`（v30 の学習と
交換曲線）、`cpu_v29`（v7 特徴の実装）、`gen9_adoption_20260801.md`。

## 何を採用したか

- `gen10_value.npz` = gen9 に**符号化 v7（登場時オプションの実測3値）**を積んで追い学習した
  distill0.5 腕（`/tmp/cand_v30_d`）。密対面コーパス（nami:shanks・512局・54,511行・v7・
  マーク局面シード0.25）を gen9 の v7 恒等拡張ネットで生成、ep2・lr2e-4・混合ラベル α=0.5・
  **distill0.5**（gen9 への value アンカー＝一般対局の忘却抑制）。
- `gen10_policy.npz` = gen9 policy の v7 恒等温スタート拡張（挙動恒等・value との符号化版一致が必須）。
- 既定切替: `cpu_learned._DEFAULT_*` → gen10。gen9 以前は同梱維持（ロールバックはファイル差替のみ）。

v7 特徴の本体（`cpu_ai.onplay_option_scan`）: 手番の意思決定点で、手札の各 ON_PLAY 持ちを
make/unmake で試し「バニラ設置以外の何かが起きるか」をエンジン自身に確かめさせる実測。
**ドン非依存**（コスト分の一時ドンを txn 内で補い巻き戻す）＝支払い能力でなく手札の構成で決まる。
「手札のパワー6000を2枚公開」のようなカード間関係の登場時条件は埋め込みの線形和で表現できず
（v24 representation-bound）、実測でしか全カードに一般化しない。

## 採用の性格（明示）

**昇格基準（wr≥0.55 かつ CI下限>0.50）では FAIL**。採用は 2026-08-02 のユーザ判断による:
アリーナは gen9 と**統計的に同等**（0.509・CI が 0.5 を跨ぐ・点推定はわずかに正）＝退行なしの
純増で、コーチ13点が +0.4、かつ **v7 という新しい表現能力を土台として搭載**する。v30 レポートの
方針「(A) 特徴を土台確定 → (B) ペア順位損失で標的直撃」の (A)。gen7→gen8 型の Elo 昇格ではなく、
**次段（m4@2 の符号反転）のための表現基盤の確定**という性格。

## リスクと監視

1. **decide +77%（546ms）**。1秒予算内だが、実プレイで応答が気になる場合はファイル差替で
   gen9 へロールバック可能（gen9 同梱維持・フラグ不要）。v7 スキャンは手番の意思決定点のみ
   （戦闘応答中は (0,0,0) で即返し）なので、全手番で一律に重くなるわけではない。
2. **標的 m4@2 は未解決**（選択はイワンコフのまま・value 差のみ −0.140→−0.106 に前進）。
   gen10 は m4@2 を直したネットではなく、それを直すための特徴を載せたネット。
3. 次段のコーチゲート base は gen10 になる（比較基準値 4.6→5.0 相当）。
