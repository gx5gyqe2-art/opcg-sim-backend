# T144: ドンの付与を「それが準備する攻撃」の価格で読む（2026-09-23）

T141（`2026-09-23_shadow_forbid.md`）では、ドンの純付与（殴らずに付けるだけの手）の 93%／91% を
理論が「純損」と判定した。T142 以降の器はこの型を介入の対象から外している。本 T は、付与を 2 手の系列
（付けてから殴る）として読む式を書き、その判定がどう変わるかを測る（ユーザ指示「その 3 つを順に
閉じてください」の 2 つ目）。

**記録**: T141 と同じ seed（実＝50000〜50009・`--decks user`／合成＝51000〜51009・`--decks synth`・各 10 局）。
介入しない測定なので、打たれる局面は T141 と行ごとに同じ（654／505 行）。変わるのは付与の価格だけである。

---

## 0. 結論（先に書く）

**付与の禁じ率は 93%／91% から 63%／60% に下がった。他の型の判定は 1 行も動いていない。**
ただし最初に書いた式（同じ枚数の攻撃候補で読む）では 83%／81% にしか下がらず、予告は外れた。
外れた理由を調べて第 2 の読み（枚数が同じか少ない攻撃候補で読む）を足し、それで 63%／60% になった。
第 2 の読みは**測った後に足したもの**である。

| 付与の行 | 実 | 合成 |
|---|---|---|
| 付与の行数 | 144 | 127 |
| 禁じ率・T141（静的な価格） | 0.931 | 0.913 |
| 禁じ率・`attack`（同じ枚数） | 0.826 | 0.811 |
| **禁じ率・`attack_le`（同じか少ない枚数）** | **0.632** | **0.598** |
| 読み替えられた付与・`attack_le` | 112（78%） | 98（77%） |
| うち禁じられた | 65（58%） | 56（57%） |
| 読み替えられなかった付与 | 32 | 29 |
| うち禁じられた | 26 | 20 |
| 参考・攻撃の禁じ率 | 0.493 | 0.401 |

| 全体 | 実 | 合成 |
|---|---|---|
| 禁じ率・T141 | 0.551 | 0.543 |
| 禁じ率・`attack_le` | **0.485** | **0.463** |
| 付与以外の型の禁じ率 | 変化なし | 変化なし |

## 1. 問い

付与の価格は「攻撃の価値の**増分**」で、攻撃候補の価格は「**総額**」である。同じ行に並べると単位がずれ、付与は
構造的に必ず負ける。これを直せば、付与の判定は他の型と同じ土俵に乗るか。

## 2. 式（新定数ゼロ）

規則: 付けたドンは**自分のターン中だけ** +1000 で、次のリフレッシュで戻る。付与そのものは損害を生まない。
価値は、同じターンにそのカードがそのドンを乗せて殴る攻撃にしかない。その攻撃は同じ行の候補に
`DON_BOX(同じカード, 対象, k)` として既に在り、`score_candidate` が +1000k 込みで値付けしている。

* **`attack`（測る前に書いた式）**: 純付与（カード X・k 枚）の価格 ← X が k 枚乗せて殴る攻撃候補の最大価格。
* **`attack_le`（測った後に足した式）**: 同じく、ただし攻撃候補の枚数が k 以下のものの最大価格。

どちらも、読みに合う攻撃候補が無ければ静的な価格のままにする。今のターンに殴れない体への付与は【ドン!!×N】
の条件付けなど別の用途で、T74 が扱う。実装は `tests/scripts/shadow_forbid.py` の `seq_prices`、
切替は `--seq off|attack|attack_le`（既定 `off`）。

## 3. 予告と当否

`shadow_forbid.py` の docstring に測る前に書いた予告:

| # | 予告 | 結果 | 当否 |
|---|---|---|---|
| 1 | 付与の禁じ率は大きく下がり、攻撃の禁じ率（49%／40%）の近くまで落ちる | `attack` は 83%／81%。`attack_le` は 63%／60% | **外れ**（`attack`）。`attack_le` でも攻撃の水準には届かない |
| 2 | 付与以外の型の禁じ率は下がらない | 全型で 1 行も動かない | **当たり** |
| 3 | 読み替えできない付与が一定数残る | `attack` で 105／92 行、`attack_le` で 32／29 行 | **当たり**（量は `attack` で予想より大きかった） |

## 4. 予告 1 が外れた理由（診断）

8 局ぶんの付与 126 行を、読み替えられなかった理由で分けた:

| 理由 | 行数 |
|---|---|
| 読み替えられた（`attack`） | 40 |
| **そのカードの攻撃候補はあるが、枚数が違う** | **58** |
| そのカードに攻撃候補が無い | 17 |
| 攻撃候補がそもそも 1 つも無い | 11 |

枚数が違う 58 行のうち、**最多は「1 枚付ける・そのカードの攻撃候補は 0 枚のものだけ」**（30 行）だった。
次は「1 枚付ける・攻撃候補は 0 枚と 2 枚」（12 行）。

**原因は箱の生成器が選ぶ枚数の組が 2 種類で違うこと**（`rust/opcg_engine/src/search/macro.rs` で確かめた）:

* 攻撃の箱（`attack_box_candidates`）の枚数は **0・相手の体を越える最小・カウンター 2 枚を要求する枚数** の 3 つだけ。
* 純付与の箱（`don_alloc_candidates`）の枚数は **1・アクティブなドン全部・【ドン!!×N】の不足分** の 3 つだけ。

2 つの組はめったに重ならない。1 枚付ける付与に、1 枚乗せた攻撃候補が在るのは、1 枚でちょうど相手の体を越えるときだけである。
攻撃の箱に無い枚数は、どのしきい値も越えない枚数である。そこで「しきい値を越えない分は攻撃の価値を変えない」と読み、
枚数が同じか少ない攻撃候補の最大で読むのが `attack_le` である。

`attack_le` でも付与の禁じ率（58%／57%、読み替えた行）は攻撃（49%／40%）より高い。禁じられた付与で理論が
薦めた手は、出す手（28／30 行）・別の付与（24／15 行）・攻撃（12／11 行）だった。

## 5. 不変量

* 行は T141 と同じ（654／505 行・seed が同じで介入しない）。
* 付与以外の型の禁じ行数は T141 と完全に一致する。読み替えは付与の価格だけを動かす。
* キャストを揃えた判定の一致は 99.85%／99.80% で、T141 と同じ。

## 6. T18 の器への配線

`t18_arena.py` に `--seq`（既定 `off`）を足した。`off` 以外では、読み替えられた付与の行は `attach` でも対象外に
しない。読み替えられなかった付与は今までどおり対象外にする。

`--seq attack_le` で T142b と同じ seed の 20 局を乾式運転した（両席とも介入・判定はしない）:

| | 実 | 合成 |
|---|---|---|
| 例外終了 | 0／10 | 0／10 |
| 禁じられた行 | 290 | 328 |
| 対象外（読み替えられない付与） | 6 | 15 |
| 実際に介入した行 | 284 | 313 |
| 置き換えた箱／最後まで打たれた箱 | 164／164 | 190／190 |

禁じられた行の 98%／95% に介入できるようになった（T142b は 71%／60%・T142 は 28%／24%）。

## 7. 上手くいったこと／いかなかったこと

**上手くいった**:

* **付与の「9 割が純損」の大半は物差しの単位のずれだったと示せた。** 付与の禁じ率は 3 割下がり、他の型は動かない。
* **外れた予告を、候補の中身まで降りて診断できた。** 枚数のしきい値という箱の生成器の性質が原因だった。

**いかなかった／自己批判**:

* **最初の式は箱の生成器を読まずに書いた。** `macro.rs` の枚数の組を先に読んでいれば、`attack_le` を最初から書けた。
* **`attack_le` は測った後に足した式である。** 別の seed で追試し、同じ形が出た（§4.5）。
* **読み替えた付与でも攻撃より禁じ率が高い。** 付与した後の攻撃は、付与と攻撃の 2 手分のドンを使う。この読みは
  攻撃候補の価格をそのまま移すだけなので、付与が先に場を固めることの損得は測っていない。

## 8. ユーザ判断をお願いしたいこと

1. **T18 で付与を対象に含めるか。** 推薦は `--seq attack_le` で読み替えた付与だけを含めること。読み替えられない付与は
   外したまま。事後の式だが、別の seed の追試で同じ形が出ている。
2. **`attack_le` を `s` の既定にするか。** 推薦は保留。T18 の器の切替として持つだけにする。
