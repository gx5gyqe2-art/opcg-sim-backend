# P2-1——**効果の半分が値付けできた。自由なつまみは 1 つも足していない**

2026-09-14 実施。ユーザ決定「イベント、起動メイン等の効果については**コストと実行内容で整理する**」
（`game_theory.md` §14.1.3）の実装。同梱の `opcg_effects.json`（**3,386 能力**）が対象。
本報告は特定時点のスナップショット（追記・改変しない）。

## 結論を 5 行で

1. **能力の 51.8%（1,754 / 3,386）が値付けできた**——**新しい定数を 1 つも足さずに**。
2. **写像表だけで書けた**のは、**コストも `actions` で表現されている**から
   ——ユーザの整理（コスト＋実行内容）が**そのまま実装形**になった。
3. **検算になる数字が出た**——**値付けできた能力の中央値は 0.0554**、
   これは**手札 1 枚の価格 `μ = 0.0551`**。**「能力 1 つ ≈ カード 1 枚」**である。
   **合わせ込んでいない**（写像表に自由なつまみが無い）ので、これは独立の一致。
4. **残りは 3 系統にきれいに分かれた**——**情報 1,182・テンポ 681・能力付与 417**・その他 161。
5. **`RETURN_DON` の向きを取り違えていた**のをテストが捕まえた（§4）。

## 1. 何をしたか——**写像表だけ**

```
効果の価値 = Σ（実行内容が動かした通貨 × その価格） − Σ（コストが動かした通貨 × その価格）
```

| 動作 | 動く通貨 | 新しい定数 |
|---|---|---|
| `KO` / `TRASH`(場) | `ν`（体が消える） | **不要** |
| `PLAY_CARD` | `ν`（体が増える・**符号が逆**） | **不要** |
| `BOUNCE` | `ν` − `μ`（体が消え手札が増える） | **不要** |
| `DRAW` / `DISCARD` / `TRASH`(手札) | `μ` | **不要** |
| `HEAL` / `LIFE_RECOVER` | `λ` | **不要** |
| `RAMP_DON` / `ACTIVE_DON` / `ATTACH_DON` / `COST_REDUCTION` | `δ` | **不要** |
| **`RETURN_DON`** | `δ`（**減る側**） | **不要** |
| **`BUFF`** | **`δ` 換算**（`+1000` パワー ≈ ドン 1 個） | **不要** |

**`BUFF` を `δ` で換算したのが鍵**——ここに独自の係数を置くと自由度が 1 つ増える。
**ドン 1 個が +1000 パワーを買う**というゲームの規則から換算率が決まるので、選ぶ余地が無い。

> **符号は `target.player` から決まる**（`OPPONENT` なら零和で反転）。
> **増える動作と減る動作は向きが逆**（`DRAW` 対 `DISCARD`・`RAMP_DON` 対 `RETURN_DON`）。
> **コストは必ず引く**（絶対値で減算・符号で二重に扱わない）。

## 2. 実測

| | |
|---|---|
| 能力の総数 | **3,386** |
| **値付けできた** | **1,754（51.8%）** |
| 値付けできない | 1,632 |

**値付けできた能力の分布**（勝率の単位）:

| | 値 |
|---|---|
| 平均 | 0.0538 |
| **中央値** | **0.0554** |
| p10 / p90 | −0.0274 / 0.1108 |
| **負の割合** | **11.9%** |

> **中央値 0.0554 は `μ = 0.0551`**——**能力 1 つがだいたいカード 1 枚**。
> 写像表に自由なつまみが無いので、**これは合わせ込みではなく独立の一致**である。
> （p90 の 0.1108 は `2μ` にほぼ等しく、`ν`・`λ` の水準でもある。）

**負が 11.9% 出るのも筋が通る**——コストが実行内容を上回る能力（強い条件付きの札を
条件なしで評価した場合など）は理論上損になる。**0 に丸めていない**のでそのまま出る。

**情報・デッキ順が最大**で、これは**4 通貨のどこにも無い**
——`game_theory.md` §14.1.3 に書いたとおり、**第 5 の通貨かもしれない**。

## 4. 器の訂正（テストが捕まえた）

**`RETURN_DON` の向きを取り違えていた**。ドンの動作を一律「対象が得る」として扱っていたので、
**相手のドンをドンデッキへ戻す効果が「自分の損」**になっていた。
**増える動作と減る動作を分けた**（`DRAW` 対 `DISCARD` と同じ形）。

> **`REST_DON` を `δ` に写さなかったのは正しい**——**レストしたドンは次のターンに戻る**ので、
> `δ`（ドン 1 個の恒久的な価値）の損ではなく**テンポ**である。**系統を分けて保留した。**

## 限界

- **条件を読んでいない**（`ab["condition"]`）——「自分のキャラが 3 体以上なら」等が付いた能力を
  **無条件として値付けしている**＝**過大**の向き。§14.1.1 の項 10 が別の穴。
- **`ν` は平均値 0.1087 を使っている**——対象のパワーが判る場合（`power_max` 等）は
  帯で置き換えるべきで、**まだしていない**。
- **`is_up_to`（「〜まで」）を満額で数えている**——得なら全部取るという前提（#39 と同じ形）。
  **損な効果を強制されるわけではない**ので向きは正しいが、**上限として読む**。
- **`count_dynamic`（「トラッシュの枚数ぶん」）を読んでいない**＝固定個数で代表している。
- **カードの値付けであって、盤面での値付けではない**——同じ KO でも相手の体が
  2000 か 10000 かで価値が違う（`ν` の帯）。**橋に入れるときは盤面から引く。**
