# 除去を打つべき展開は起きているか（2026-09-10・合成デッキ vs 実デッキの census・計画 §20.8.9）

ユーザの問い「サンプルデッキ同士の対局は、除去を打つべき展開になっているか」。波 29（合成 synth_roles・3 シャード
1,440 局）と、ユーザの実デッキ 4 本（`--decks user`・240 局・seed 3100000〜・同じ生成設定＝sims 160・worlds 4・R2・
ε 3%・生成役 r3）で同じ census を取った。実デッキの棋譜は**教材にしない**（census のみ）。

| 指標 | 合成（波 29）| 実デッキ |
|---|---|---|
| main 決定のうち除去が合法 | 40.6% | 43.7% |
| そのうち探索が除去を Q 最大と読んだ | 14.3% | 15.1% |
| 最良の除去 Q − 最多訪問手の Q | −0.174 | −0.146 |
| 次の相手ターンに失うライフのうちキャラ攻撃由来 | 57% | **63%** |
| 相手の盤面（次の自分ターン開始時・体数／パワー合計）| 2.2／10,400 | **2.6／14,200** |
| z: 木が除去以外を選んだ（基準）| +0.021（n 31,945）| −0.193（n 6,741）|
| z: 同じ母集団で除去を**強制** | −0.036（n 990・−0.057）| −0.267（n 202・−0.074）|
| z: 木が自分で除去を選んだ | −0.080（n 5,632）| −0.274（n 1,531）|
| z: 木が除去を選んだのに保留 | −0.091（n 154）| −0.216（n 51）|
| 強制除去のうち 6〜8 ターン | −0.23（基準 −0.04）| **−0.59**（基準 −0.18）|

## 読み
1. **世界は原因ではない**。実デッキは合成より除去を打ちたくなる構造（盤面が大きく、キャラ打点の比率が高い）だが、
   探索が除去を最良と読む割合（15%）も、強制除去が損になる向き（−0.06〜−0.07）も、合成と同じ。ユーザの疑い
   （合成デッキだと除去の展開が無い）は「合成は実デッキより除去の価値が出にくい」の範囲では正しいが、主因ではない。
2. **この CPU の打ち回しでは、除去を（木の判断に反して）打つと平均して損**。特に中盤（6〜8 ターン）が大きく損。
   木が自分で除去を選ぶ局面は元々不利な局面（z −0.08／−0.27）。
3. 合成では「除去の後に 2 回以上攻撃できる局面」で損が小さかった（−0.10 vs −0.30）。実デッキでは n が小さく
   （30／108）読めない。
4. 除去の「中身」（型・対象・その後）で層別するには強制した手そのものが要るが、今の dump は π を守るため木の選択
   しか残していない → `forced_sig` 列を足した（次の生成から）。

## 結論
- 「除去を打つべき展開が無い」のではなく、「**この CPU は除去を打っても得にできない**」。V が除去を低く見るのは
  この打ち回しの実績と整合しており、V を教師で直しても、打ち回しが変わらない限り実績は変わらない（鶏と卵）。
- 卵を割る側は打ち回し: 除去の**後**（対象の選び方・除去した後に殴りに行く・テンポ）を CPU が実現できるように
  する。候補: (a) 除去の対象選択を方策で学べる符号化（候補行に対象を載せる＝符号化 v14）、(b) 除去後のテンポを
  V が見える補助教師（除去後の自分の攻撃回数と通った打点＝aux にある `my_turn_attacks`／`my_turn_opp_life_lost`
  を除去直後の行で強調）、(c) 人間の棋譜の「得だった除去」を局面として抜き出して、CPU の打ち回しとの差を読む
  （分岐点シナリオの除去版・判定はユーザ）。
