# T91——補充 `r` を**打ち筋から規則へ**（`r = μ ×`デッキの切れる札の割合）。**大きさはほとんど変わらない**（0.0384 → 0.0400／0.0393 → 0.0397）が、**帯ごとの当たりは大きく戻る**（`W(D)` の両端 実 0.231／0.681 → **0.090／0.899**・合成 0.318／0.695 → **0.261／0.779**）＝**汚染は `r` の水準ではなく「行ごとのばらつき」に在った**。それでも `static`（0.060／0.963）には届かない＝**既定は据え置き**。**予告した「`r` は小さくなる」は外れ**（切れる札の数え方を符号化に合わせると 0.585 → 0.729）

2026-09-18 実施（ユーザ指摘「穴の大きさを測るのは CPU の打ち方によるんじゃない？」→「それで進めてください」）。
**当てはめない・新定数ゼロ**（`μ` とデッキ表の掛け算だけ）。本報告は特定時点のスナップショット。
器は `tests/scripts/deck_refill.py`（新規）と `crossing_bridge.RACE_MODE=deck`・`--race deck`。

## 1. 問い（ユーザ指摘）

T90 は動く的の下がる速さ `r` に**帳簿の `g`**（＝その席の**手札** 1 枚あたりの価格）を使っていた。
手札の中身は**その席がどう打ったかの結果**なので、**記録を取り直せば別の値**になる＝**打ち筋が式に入っていた**
（`CLAUDE.md`／§0.1 の「打ち筋は式に入れない」に反する）。**ユーザの指摘のほうが正しい。**

## 2. 分け方（どこまでが規則か）

| | 誰が決めるか | `r` に入れてよいか |
|---|---|---|
| 毎ターン **1 枚引く**・ドンが 1 枚増える | **規則** | ○ |
| 引いた 1 枚が**切れる札**である確率 | **デッキの中身**（デッキ表から数えられる＝既測の量） | ○ |
| その札を**手札に残すか出すか** | **打ち方** | **×** |

3 番目は **`Θ` の中の引っ越し**（手札の項 `μ` ↔ 体の項 `ν`）であって `Θ` の増減ではない＝`r` には入らない。

## 3. 式（新定数ゼロ）

```
RACE_MODE = deck
  r = μ × （その席のデッキの切れる札の割合）        # 記録も打ち回しも読まない
  切れる札 = 印字カウンター > 0 **または**【カウンター】でパワーを上げるイベント
             （`n_rel_feat` の `counter_value` 欄と同じ式＝`Θ` の手札項が読んでいる物と一致）
  デッキは seed から決定論で作り直す（`decks.build_pair`・記録の `meta_games.json` に seed と
  decks モードと leaders が在る）＝記録の拡張は不要
```

的の解き方（`tau_net`／`tau_from_profile(r)`）は T90 と**同一**。**変わるのは `r` の出どころだけ**。

## 4. 予告した検算（測る前に書いた）とその答え合わせ

| 予告 | 結果 |
|---|---|
| 1. `r` が小さくなるので τ が伸びる | **外れ**——`r` は**大きくなった**（下記 §5 の訂正）。τ は伸びた（`tau_net_start` 29.3 → 30.0）が理由が逆 |
| 2. 行ごとの当たりが `static` と `net` の中間に戻る | **半分当たり**——合成は中間（0.6102 → **0.6233** 対 `static` 0.6304）・**実は `net` をわずかに下回る**（0.5605 → 0.5571） |
| 3. 終盤に `r` はゼロへ向かう | **取り下げ**——**規則からは `r` は一定**（毎ターン必ず 1 枚引く）。「終盤に縮む」は `Θ` の**構成**（ライフは補充されない）の話で、`r` の話ではなかった＝私の予告が混線していた |

## 5. 訂正——切れる札は 0.585 ではなく 0.729

チャットで「実デッキの切れる札は 117/200 = 0.585 → `r` = 0.0322＝今より 13% 小さい」と答えたが、
**印字カウンターしか数えていなかった**。`Θ` の手札項が読んでいるのは `hand_guard.counter_of`
＝**印字 ＋【カウンター】イベントの上げ幅**なので、**同じ定義で数え直す**と:

| 実デッキ | 印字だけ | **印字 ＋ カウンターイベント** |
|---|---|---|
| ナミ | 34/50 = 0.68 | 34/50 = 0.68 |
| エネル | 21/50 = 0.42 | **38/50 = 0.76** |
| 黒黄ルフィ | 32/50 = 0.64 | **40/50 = 0.80** |
| シャンクス | 30/50 = 0.60 | 33/50 = 0.66 |

記録の seed 分布で重みを付けると **実 0.7286・合成 0.7192** ＝ **`r` = 0.04014／0.03963**。
**`r` は 13% 小さいのではなく 4.4%／1.1% 大きい。**

## 7. 読み方

- **上手くいった 1: 汚染の正体が分かった**——**`r` の水準はほとんど汚れていなかった**（0.0384 対 0.0400＝4%）。
  汚れていたのは**行ごとのばらつき**で、`g` は**守る席の手札の中身**（＝打った結果）と一緒に動くため、
  `D`（到達ターンの差）に**打ち筋由来の揺れ**を入れていた。デッキごとの定数に替えると
  **`W(D)` の両端が戻る**（実 0.231／0.681 → 0.090／0.899＝`net` が壊した幅の 7〜8 割を回収）。
- **上手くいった 2: 式から打ち筋が消えた**。`r` は `μ` とデッキ表だけで決まり、**記録を読まない**。
  記録が変わっても、CPU が変わっても、**同じデッキなら同じ `r`**。これは数字の良し悪しとは別の、**正しさの改善**。
- **上手くいかなかった: それでも `static` に届かない**（実 0.5571 対 0.5816・合成 0.6233 対 0.6304）。
  **動く的そのものが、この輪郭の上ではまだ損**。**既定は `static` のまま**（ユーザ判定）。
- **なぜ届かないか（次の T の材料）**: `r` を足すと的が遠ざかるので τ が伸び、**偏りが +0.84 → +2.11 に増える**。
  T89 が示したとおり**`A` は上限で 1.26／1.20 倍多い**ので、**`A` を下げずに `r` だけ足すと二重にずれる**
  ——`A` を上限から実効へ落とす手当てと**対で入れないと釣り合わない**。
- **予告 1 の外れが教えたこと**: **定義は必ず符号化（`Θ` が実際に読んでいる式）に合わせて数える**。
  「カウンター」を印字だけで数えると実デッキで 0.585、符号化どおりなら 0.729＝**24% も違う**。

## 8. 次（ユーザ判定）

1. **`A` の通る率を規則から出す**（最有力・`r` と対）——攻撃の価格は相手の守りで割り引かれる。
   **実効は上限の 0.79／0.83 倍**という測定はあるが、**率を定数で掛けるのは当てはめ**なので、
   `Θ` の手札項と同じ考え方（**相手の切れる札とブロッカーで決まる**）で式にする。
   **`r` と `A` が揃ってから `static` 対 `deck` を測り直す**——片側だけでは判定にならない。
2. **接戦帯を正しい価格から組み直す**（T88 の結論・1 のあと）。
3. **効果の型を種類別に割る**（実デッキで実現 −0.487・価格 −0.127・T81 §5 の 2・未着手）。

## 限界

- **デッキは seed から作り直している**（記録にデッキの列は入っていない）＝生成時と同じ決定論の経路を通る前提。
  `meta_games.json` の `decks` モードと `leaders` が正しいことに依存する。
- **`r` は局を通して一定**（デッキの割合は山札が減っても数え直さない）。規則上は引くたびに残りの構成が動くが、
  7 ターン前後の対局で 50 枚のうち 10 枚強しか引かないので**分布はほとんど動かない**（未測定）。
- **ドンの増加（毎ターン +1）は `r` に入れていない**——ドンで出せる体は `Θ` の体の項に入るが、
  それは**手札からの引っ越し**なので `r`（新しく入ってくる量）ではない。§2 の 3 番目と同じ理由。
- `deck` は `net` と**同じ解き方**なので、動く的そのものの当否は T90 の限界をそのまま引き継ぐ。
- **観察であって因果ではない**。
