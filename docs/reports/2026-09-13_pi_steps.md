## 問い

r7 は π のデータを 2 倍（波 2 → 4）にして方策が 3 波とも改善したが、V が r5 水準へ後退した。
この取引は **π に割く更新回数**で決まっているのか。損失に重みを掛けても Adam が正規化するので、
比は回数で作る（`--pi-steps-mult 1.0` は 1 bit も変わらないことをテストでラチェット済み）。

**対照は成立**: 両方の log が value 5,966,525 行（val 853,742）・policy 1,624,058 点（val 232,147）＝
r7／r8 と完全一致。ステップ数も指定どおり（V 19,971 + π 21,748×mult＝r7 41,719／r9 63,467／
r9h 30,845 と一致）。**ワーカーの note の「1.52 倍・0.74 倍で指示どおりではない」は誤読**——
log の `step N/M` の M は V と π の合計で、π だけを見れば正確に 2.0 倍・0.5 倍になっている。

## 判定: **(c)＝回数は効かない。候補 A は閉じる**

π のステップを 2 倍にして買えたのは **top1 +0.0012／+0.0042／+0.0024（3 波平均 +0.0026）**。
これは**事前に「動かない」と定義した帯（±0.01）の中**で、行数 19,000〜32,000 の二項の標準誤差
（約 0.0035）と同じ大きさ＝**測れていない**。アリーナも動かない。事前基準 (a) の「3 波とも高い」は
形式的には満たすが、**大きさが基準の帯の内側なので (a) の判定にはならない**（ワーカーの
RESULT.json は 3 波平均が r7 を上回った＝True と記録しているが、これは向きだけの判定）。

**代わりに分かったこと（比は実在するが片側だけ急）**: π を**半分**にすると
V が 2 波で明確に改善する（波 30 −0.0118／波 32 −0.0091・波 28 −0.0031）一方、
方策の代償は小さい（top1 −0.0047／−0.0044／−0.0060）。**上げても買えないが、下げれば売れる**＝
現在の比はすでに「π の伸びが飽和した側」に居る。r9h の V は **r5 水準（波 30 0.5150 対 r5 0.5155）
までは戻ったが r6 水準（0.5115）には届かない**＝事前基準 (d) は部分的にのみ支持。

**機構の読み**: **律速は π の更新回数ではなく、π の相異なるデータ量**。同じ 1.6M 点を
シャッフルし直して 2 周しても（r9）方策は +0.003 しか動かないのに、**データを 2 倍にした r7 は
波 28 +0.052／波 30 +0.029／波 32 +0.011 動いた**（`2026-09-12_r7_pi_window.md`）＝
同じ「2 倍」でも**情報が増えたときだけ効く**。π の飢え（`search_vs_prior` の H_p ≒ ln k）は
予算の問題ではなく情報の問題である。

**副産物**: r9 は best epoch が ep1（r7 は ep0）＝π のステップを増やすと ep1 まで改善が続く。
r9h は ep1 で明確に過学習（v_mse 0.4917 → 0.5001・top1 0.632 → 0.613）＝**比はエポック数と
絡んでいる**ので、比を動かすなら epochs も一緒に見ないと交絡する。

## 次

- 候補 A は閉じる（**mult 4.0 へは進まない**・高分解能アリーナも回さない）。
- π を伸ばす道は**教材の側**（相異なる π の量＝波数、または教師の作り方）に限られる。
  ただし「π は現 era のみ」の規約の見直しは**ユーザ決定**なので、B（高分解能アリーナ r7 vs r5）で
  r7 の +25.4 が本物かを確かめてから諮る。
- **V を戻したいときの安いつまみとしては `--pi-steps-mult 0.5` が使える**（V −0.01・方策 −0.005）。
  探索の value の精度を上げたい局面（候補 C・F）で手札として残す。
- 順番の変更なし: 次は H（時間軸を補助ヘッドへ）。
