# C 層を `pair` で全部回し直した——**順序を測る器は良くなり、水準を測る器は悪くなった**

2026-09-15 実施。ユーザ指示「全て再測定して体系的に整理」の 2 本目（1 本目は T26＝
`2026-09-15_t26_pair_remeasure.md`）。**式（`nu_of`）を使う器を全部**、同じ記録で `base` と `pair` の
両方で回した。本報告は特定時点のスナップショット（追記・改変しない）。

## 結論を 6 行で

1. **式を使う器は 8 本**（`grep` で確定・§1）。**記録から直接測る器（A 層）は式を通らないので回さない**
   （回しても同じ数字が出る）——`price_scaling`（T24）・`ko_by_power`・`shield_rate`・`exit_ledger` 等。
2. **順序を測る器は `pair` で良くなるか動かない**——橋（前報）・T26（前報）・T1 実デッキ
   0.496 → **0.511**・中間ゲートの順序 0.504 → **0.516**・`theory_vs_search` は CI 内で不動。
3. **水準を測る器は `pair` で悪くなる**——**中間ゲートの `position` 0.211 → 0.066**（終盤の
   AUC 0.773 → 0.728）・**Phase 1c で `q_nu_sum` が「足す価値のある残差」に浮上**（β = −0.83・
   ネットは理論より体を安く見ている）・**`nu_measure` の全体水準の超過 +0.049 → +0.090**。
4. **3 つは同じことを言っている**——`pair` は**形**（弱い体が 0 でない・パワーに対する向き）を直し、
   **水準**（全体で実測の 1.8 倍・中盤帯 +0.060）を上げすぎた。**中盤帯の攻撃項の過大**（前報で
   「次」に挙げた宿題）が、水準を読む器では主役になる。
5. **既定は `pair` のまま**——順序の改善は理論の目的（打ち回しの教師）に直結し、水準の超過は
   **原因が特定できている**（身代わりではなく攻撃項）。**ただし水準の器 3 本の数字は「`pair` で
   悪化」として定点に残す**＝当てはめて消さない。
6. **正本に 3 層の索引を置いた**（`cpu_theory_gap.md` §9.1）——A 記録の量／B 式の予測／C 突き合わせ。
   **C 層の各行に「どの `ν` の形・どの commit の数字か」を書く**。T26 の古び方がその必要を示した。

## 4. 3 つの器が同じことを言っている

```
順序（同じ行の中の比較）   ← 形が効く   → pair で良くなる（弱い体が 0 でない・パワーの向き）
水準（行をまたぐ比較）     ← 大きさが効く → pair で悪くなる（中盤帯 +0.060・全体 1.8 倍）
```

- **中間ゲート**は状態の点数 `S = λ·ライフ + μ·手札 + Σν + …` を**行をまたいで**勝敗と比べる。
  `Σν` が大きすぎると**体の多い側を勝ちと言いすぎる**——**終盤で悪化する**のはそのため
  （終盤は体が並ぶ）。
- **Phase 1c** は同じ `Σν` がネットの残差を説明するかを見る。β < 0 は**理論の `Σν` が大きい行ほど
  ネットは理論より低く見ている**＝ネットは体をそこまで買っていない。**`base` でも符号は負だった**
  （CI が 0 を含んだだけ）＝**水準の過大は `pair` が作ったのではなく、`pair` が広げた**。
- **`nu_measure`** はその水準を直接測る。**中盤帯の攻撃項が過大**（`base` で既に +0.018）で、
  そこに身代わり 0.0409 が乗り、`ko_p` の峰（0.33）で割り引いても足りない。

**帰結**: **直すべきは身代わりではなく中盤帯の攻撃項**（`Θ·μ` の頭打ちと `c(x)` の段）。
身代わりを下げれば弱い帯の穴が戻る（そこは `pair` の正しい部分）。

## 5. 既定を `pair` のまま置く理由（判断はユーザ）

| | `base` に戻す | **`pair` のまま** |
|---|---|---|
| 順序の器（橋・T26・T1・ゲートの順序） | 元に戻る（悪い方へ） | **良い方のまま** |
| 水準の器（ゲート `position`・1c・勘定） | 元に戻る（良い方へ） | **悪い方のまま**（定点に残す） |
| 理論の目的（打ち回しの教師＝順序） | — | **直結** |
| 次の作業 | 弱い帯の穴が戻る | **中盤帯の攻撃項**（原因が特定済み） |

**私の判断は `pair` のまま**——**順序の改善が理論の目的に直結し、水準の超過は原因が 1 か所に特定できて
いる**。戻す理由が出るのは「攻撃項を直しても水準が戻らない」と判ったときである。

## 限界

- **水準の器の悪化は CI が重なる**（ゲート `position`）——3 本の向きが揃うことを根拠にしている。
- **T1 の判定は変わらない**（`price_does_not_teach`・順序 0.51 < 0.55）——`pair` は順序を「少し」動かすだけ。
- **Phase 1c・T1 実デッキは 2026-09-13 の記録（w32 ホールドアウト 1,041 局）と別の記録**で回した
  （w32 は手元に無い）。**`base` 対 `pair` の対照は同じ記録**なので結論に影響しないが、
  09-13 の数字との横並びはできない。
- **観察であって因果ではない**（§0.3 の限界はそのまま）。
