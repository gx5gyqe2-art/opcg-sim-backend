# v44 ターン出口教師の予算判断 — ラベルは足りていた、群数が足りない（2026-08-08）

gen13 採用（`gen13_adoption_20260808.md`）の残件は「ターン系の未取得は戦闘出口ヘッドの
管轄外＝次はターン末ヘッド（v39 実装済み）の教師問題」だった。本文書はその教師に
**13〜15時間の本生成を買うべきか**を、買う前に測って答えた記録（この時点のスナップショット・
追記改変しない）。

## 0. 結論

1. **ラベルの品質は律速ではない**。worlds=32 の因果 z は真正答率 0.899（16世界・逆算）。
   worlds をこれ以上増やしても δ選抜後の一致率は +0.05 程度しか動かない。
2. **律速は群数**。33群＝順位ペア75本では学習が起きない（ヘッド摂動 std 0.0075＝実質恒等）。
   gen13 は既に 57/75 を正しく並べており、正味の教える余地は約9.4ペアぶんしかない。
3. **本生成は買わない**。教師の唯一の消費者はプラン読み出しだが、その読み出しを ON にしても
   8点は 7.44→7.50＝ノイズ幅（2σ=0.35）の内側で、**安全になったが得も無い**（§5）。
   読み出しが得を生まないなら、その出口を較正するヘッドも得を生まない。

## 1. なぜ測ったか

v41 は「学習しても直らない」で1周、v42 は「アリーナで有意退行」で568局を溶かした。どちらも
**教師の信頼度を先に測っていれば着手前に分かった**。生成コストのほぼ全部は
`worlds × プラン数 × 終局までのロールアウト`（実測 245秒/窓 @worlds8）なので、
`plan_cf_gen` に**世界ごとの生の結果**（`win_w`/`life_w`）を保存させ、1回の生成から
任意の予算 K≤worlds の z を再計算できるようにした（`label_reliability.py`）。

## 2. ラベル信頼度（worlds=32・33群174ペア・分け方16回平均）

互いに素な K世界の組を2つ取り、それぞれ独立にラベルを作って比べる（`2K ≤ worlds` が必要）。

| 予算K | 半々一致率 | δ選抜後 | 選抜数 | ラベル1σ |
|---|---|---|---|---|
| 2 | 0.629 | 0.656 | 59.4 | 0.716 |
| 4 | 0.680 | 0.698 | 88.5 | 0.467 |
| 8 | 0.701 | 0.769 | 94.2 | 0.347 |
| 16 | 0.722 | **0.818** | 86.2 | 0.242 |

独立2組の一致率 A から真正答率 q は `A = q² + (1−q)²` で逆算でき、**q(16世界) = 0.899**。

**過去の2つの数字はどちらも小標本の偶然だった**: 腕A（worlds=8・11群55ペア）の δ選抜後
0.231 と、worlds=32 の初回シャード（5群30ペア）の 0.841 は矛盾していたが、174ペアで測り直すと
K=4 で 0.698 に落ち着く。**5〜11群の測定値は読んではいけない**というのが実務上の教訓。

## 3. 33群では学習が起きない（その分解）

gen13 の上にターン末ヘッドを v43 の working point（margin 0.03 / hidden 4 / 中心化）で学習:

```
収集: 3シャード・123盤面・33群・順位ペア 75（tr 65/va 10）
turn 出口順位正答(val) 学習前 0.800 → 学習後 0.800
ヘッド摂動: W2 std 0.0078（v43 の battle ヘッドは std 0.038）＝実質恒等
```

なぜ動かないかは gen13 側を測ると分かる。

- **δ=0.25 の75ペアのうち gen13 は 57本を既に正しく並べている**（一致率 0.760・
  95%CI [0.663, 0.857]）。
- **|gap| の中央値は 0.179**＝ヒンジのマージン 0.03 の約6倍。損失が立つのは 29/75 だけ。
- 不一致18本の内訳（ラベル真正答率 0.928＝32世界外挿を仮定）: ネットが誤り・ラベルが正が
  13.7本（直せる）、ネットが正・ラベルが誤りが 4.3本（壊す）＝**正味 9.4ペア**。

500群（15.2倍）まで買えば正味 ~143ペアになり v43 の 84ペアを上回る計算になるが、
上の 0.760 の 95%CI 上端 0.857 では**ネットの真正答率がラベルとほぼ同じ＝直す余地ゼロ**に
なる。**33群は自分が答えるべき問い（gen13 のターン出口は本当に誤っているか）に
答えられる標本量ではない**——これが段階1の正直な結果。

## 4. 計器の欠陥（v44 で発見・修正済み）

`exit_head_probe` は `turn_all` 形式の accept（`{"turn_all": {...}}`＝ターン内で全ての攻撃と
起動を消化することが条件・m2@66）を dict のまま `coach_gate.hit` に渡していた。`hit` は
`(at, card) in accept` を見るので**辞書のキー文字列と照合され、黙って常に不一致**になる。

- 影響: gen13 のターン出口を **7/8 と過小に表示**していた。修正後は分母から除外して
  **7/7**（判定可能な点はすべて正しい）。
- 腕どうしの比較は同じ偏りを共有していたため、**過去の採否判定は無傷**。ただし
  「m2@66 は確信を持って誤っている」という読みは誤りで、撤回する。
- 正しい計器はコーチゲートの `turn_all_rate`（初手1手の枝順位では原理的に判定できない）。

## 5. 決定打: プラン読み出しを ON にしても得が無い

ターン末ヘッドの**唯一の消費者**はプラン読み出し（`SERVE_PLAN_READOUT`）である
（`SERVE_TURN_QUIESCE` も False）。つまり「良い教師 → 良いヘッド」の価値は、すべて
**読み出し ON の価値**を経由してしか実現しない。そこでヘッドが恒等であることを利用して、
**読み出し ON 単体の損得**をそのまま測った（8点・16seed・160sims・base=gen13 /
chall=gen13+恒等ヘッド。両列が全点一致することがヘッド恒等の追認にもなっている）。

| 点 | 出荷 gen13（読み出し OFF） | 読み出し ON |
|---|---|---|
| m1@3 | 1.00 | 1.00 |
| m1@14 | 1.00 | 1.00 |
| m1@15 | 1.00 | 1.00 |
| m2@44 | 0.75 | **0.88** |
| m2@58 | 1.00 | 1.00 |
| m2@66 | 0.69 | 0.62 |
| m4@2 | 1.00 | 1.00 |
| m5@7 | 1.00 | 1.00 |
| **計** | **7.44** | **7.50** |

- **良い報せ**: v37②（1.00→0.25）と v39（1.00→0.50）で読み出しを OFF にさせた **m1@3 が
  1.00 のまま**。`PLAN_MIN_SPREAD=0.15`（平坦な箱は箱にしない）と gen13 の戦闘出口ヘッドで
  当時の退行原因は解消している。**読み出しはもう危険ではない**。
- **しかし得も無い**: 差は m2@44 の +0.13 と m2@66 の −0.07 だけで、どちらも
  **測定ノイズの下限 2σ=0.35 を大きく下回る**（ゲート自身も「bar を超えた点: なし」と報告）。
- **コストは実在する**: 8点ゲートは読み出し OFF で約10分、ON では約50分（m2@66 単独で約40分）。
  毎ターン 6世界×6提案の立案が走るため、**serve コストは約5倍**。

したがって「13〜15時間の本生成 → ターン末ヘッド → 読み出し ON」という経路は、
**終点に測れる利得が無い**。経路の途中（教師の質）がいくら改善しても終点は動かない。

## 6. 生成の実務（次に同じことをする人向け）

- `--workers` は**シャード内の局を並列化**する。`--shard-games 1` だとプールに1タスクしか
  入らず1コアしか回らない。一方で resume 判定が `既存シャード数 × --shard-games` なので、
  **既存 out ディレクトリに対して `--shard-games` を変えると「消化済み」と誤判定して即終了**する。
  変えるときは**新しい out ディレクトリ＋ずらした seed-base**（群IDは `(seed_base + 局番号) * 100`
  なので衝突する）。
- シャードは**全局が終わってから書き出す**ので、待ち時間は平均でなく**最長の局に律速**される。
  4コア機で worlds=32・6窓×4局は 2h41m 経っても1シャードも出なかった。
- 同じ seed の局は決定論的に同一なので、**seed が衝突した分は独立標本にならない**（破棄した）。

## 7. 次にやるべきこと

- **本生成（500群・13〜15時間）は買わない**。§5 の通り終点に利得が無い。
  ワーカー3台の生成も止めてよい。
- **プラン読み出しは OFF のまま**。安全にはなったが、得が無く serve コストが約5倍。
  `PLAN_MIN_SPREAD` を再較正した将来（教師が増えたとき）に再判定する余地は残る。
- **効いた路線は裁定拡充**。gen9〜gen13 で実際に点を取ったのはすべて
  「人間裁定を増やして注入する」であり（gen13 の m1@14 0.00→1.00）、コストは計算時間ではなく
  裁定の手間。残る唯一の常時未達点は **m2@66（0.62〜0.69・turn_all 形式）**で、
  ここは戦闘出口ヘッドの管轄外・プラン読み出しでも動かない＝**新しい裁定と、
  それを流し込める第3の箱（ターン内の攻撃順）**が要る。
