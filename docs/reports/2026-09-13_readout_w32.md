## 4. ライフ予算の監査——**価格もしきい値も使われていない**（137,711 窓）

領域の内訳: **1（守るのが純粋な無駄）4.8%・2（価格で決まる）67.3%・3（足りない）27.9%**。

- **領域 1 でも 38.2% 守っている**＝全部受けても死なない窓で手札を払っている。
- **`p<=0` の帯**（その攻撃ではライフが減らない）は 31,478 窓＝**全体の 23%** で、
  **守り率 0.524・払った枚数 0.95**＝**無駄がこの規模で起きている**。
- **領域 2 の順序の誤り**: `c(x) < c̄` を**受けた 47.9%**（30,430 窓）・
  `c(x) > c̄` を**守った 30.3%**（18,574 窓）＝**安いものを受け、高いものを守っている**（片方向は基準超え）。
- **`θ` は使われていない**: `L − θ` が −4 から +4 まで動いても守り率は **0.33〜0.39 で平ら**
  （しきい値を割ってから守り始める形が**無い**）。
- **払い過ぎ**: `greedy_gap` 平均 **+0.406 枚**・守った窓の **52.3%** で正
  ＝止めるのに要る最小枚数より多く払っている。
- **7000 理論が実プレイで再現**: 帯ごとの最小枚数 1.00／1.31／2.22／2.64／3.85 は、
  デッキから独立に出した `c̄` 曲線（1.00／1.28／2.25／2.79／3.63・`2026-09-13_deck_profile.md`）と
  **ほぼ一致**＝予算モデルの入力は正しい。守り率は 0.457→0.350→0.277→0.214→0.188 と下がるが、
  同時に「止められない確率」も 0.12→0.26→0.41→0.57→0.84 と上がるので、
  **下がり方の大半は能力の限界**（合理の証拠ではない）。

## 5. 決着時間の分布——**ハザードに形が在る**（92,800 行）

`hazard_spread`（帯内の `h(t)` の振れ幅）は全体 0.254 だが**帯ごとに 0.26〜0.63**。例（自ライフ 3・相手 4）:

```
p(T=t)  : 0.008 / 0.183 / 0.337 / 0.269 / 0.131 / 0.073   (t=1..5, 6+)
h(t)    : 0.008 / 0.184 / 0.416 / 0.569 / 0.641 / 1.000
P(win|T): 0.043 / 0.254 / 0.421 / 0.524 / 0.618 / 0.709
```

事前基準「0.3 以上なら形が在る」を**満たす**。さらに**同じ帯の中で `P(win|T=t)` が大きく動く**
（自ライフ 4・相手 5 の帯では T=2 の 0.121 から T≥6 の 0.527）＝
分解 `P(win) = Σ_t P(T=t)·P(win|T=t)` は**実際に働いている**。
**時間軸ヘッドが学ぶべきは平均 1 個ではなく `h(t)`**（`game_theory.md` §15 の主張が実測で立った）。

## 7 本を合わせた判定——手当ての順番が変わった

| 層 | 状態 |
|---|---|
| **探索** | 律速ではない（被覆 1.000・`worlds` に効果の証拠なし・融合は接戦帯 2%） |
| **価値（符号）** | 正しい（手札の向きは 3 ネットとも合格）＝守りの読みの土台は無事 |
| **価値（水準）** | **零和が破れている**（`V_p1+V_p2 = −0.138`・別報告） |
| **方策（順序）** | **壊れている**（接戦帯でコイン・失う Q が後悔の全量） |

| **打ち回し（攻め）** | ドンを 2.3 個余らせる（77% のターン）・リーサル圏でいちばん余らせる |

**一次対象は方策の順序**（`order_acc` がコイン水準で、その損が後悔の全量）。
価格（予算）はその下の層で、**順序を直す教師として価格が使える**という関係になる
——`c(x) − c̄` は「どちらの手が良いか」の**符号を与える量**なので、
順序の教師そのものになりうる。

## 候補 F への帰結（設計の見直しが必要・着手はユーザ指示により最後）

`game_theory.md` 第 VI 部の F は「**価格を評価（value）の入力に足す**」という設計だった。
本日の測定はその前提を 1 つ壊し、1 つ補強した:

- **壊した**: 「評価が正しければ探索が拾う」——**方策の順序がコインなら探索は拾えない**
  （PUCT は事前分布で枝を選ぶので、順序情報が無い事前分布は探索の入口を塞ぐ）。
  したがって**価格は評価だけでなく方策の教師にも入れる**必要がある。
- **補強した**: 価格そのものは実プレイで正しい（`c̄` 曲線がデッキ側と一致）。

**F は「価格を方策の順序の教師にする」形へ組み直す**のが本日の測定からの帰結。
具体の設計はユーザ指示（2026-09-13「F は最後」）に従い、残りの未定量を片付けた後に書く。

## 残る限界

- 順序精度は**探索の Q を正としている**＝「方策が探索に追いついていない」ことの測定で、
  「方策が真に誤っている」ことの測定ではない（`game_theory.md` §5-6 の探索の誤りは別問題）。
- 予算監査の `A`／`B`／`K_atk` は上限側の近似（§近似）。`S` は上限＝領域 3 を過小に数える。
- 読まれやすさは多数決予測器＝**より強い予測器なら読める**余地は残る（勾配ブースティング等）。
- 攻め側の `don_plays` は札のコストだけ＝【起動メイン】のコストを含まない（`don_idle` はやや過大）。
