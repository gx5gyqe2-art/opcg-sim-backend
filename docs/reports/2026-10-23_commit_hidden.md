# 続きを決めた時点で見えていなかった札を選ぶ対話は、続きを使わず読み直す（WP `rs-commit-hidden`・2026-10-23）

`docs/search_efficiency_plan.md` §7.39。台帳 2+368。根拠は `2026-10-23_commit_sig.md` §2.2（照合の修正後に残った commit 由来の見逃し 2 点）。
ブランチ `claude/rs-commit-hidden`（土台 `ddcf0df`）・成果物 `n1_results/commit_hidden/`。

## 1. 直したもの

**欠陥**: 箱の commit（窓の根畳み・登場時の対話・準備箱が決めた自分側の手順の続き）は、決めた時点の**引き直した世界**（公平な配り直し）の上で
打ち直して作る。続きの中に「commit した時点で自分に見えていなかった札から選ぶ」段（山札の上から見て選ぶ・引いた後に手札から捨てる 等）があると、
世界の中身で選んだ札を本当の盤面で照合して打っていた。本当の候補は盤面で初めて見えるので、その選択には根拠が無い。

**修正**（`rust/opcg_engine/src/search/decide.rs`・`quiesce.rs`・`macro.rs`）:
- 箱の commit を作るときの手の列（trace）に、各段の**打つ前の対話の候補の札**（`candidates`＋`selectable`・ドン!!は除く）を持たせた
  （`quiesce::TraceStep`・`dialog_cards`。trace を取らない探索の中では何も計算しない）。
- `hidden_at_commit(state, me)`: commit した時点で自分に見えていない札の印（両者の山札・裏向きのライフ・相手の手札のうち `known_by` に自分の bit が無い札）。
  **公平な引き直しが混ぜる枠と同じ集合**で、引き直しは札の位置だけを混ぜる（札の index と印は動かない）ので、本当の盤面でも世界でも同じ印になる。
  印は commit を作る世界の**根**（続きを打ち始める前）で取る＝続きの中で「見た」「引いた」札も、commit の時点で見えていなければ印のまま。
- `trace_to_steps`: 自分の段の候補に印の札が 1 枚でも在れば、**その段と先を積まない**。続きはそこで尽き、その判断点は普通に読み直す（窓の根畳み）。
  相手の段の候補は見ない（そもそも積まない）。
- 対象は trace から作る 3 つの続き（窓の根畳み・登場時の対話〔単一世界・複数世界の両方〕・準備箱）。付与 → 攻撃の箱（`Step::Box`）は自分の場の札しか選ばないので対象外。
- 「攻めの手順の続きも同じ規則」（§7.39 の 3）は、自分の手番の登場時の対話・準備箱の続きが同じ `trace_to_steps` を通るので同時に満たす（golden の差分 2 局はどちらも自分の手番のこれ）。

**判定の形の選択**（§7.39 の 2 の「既知の札の集合を持たせるか・置き場で判定するか」）: **commit した時点の既知の札で判定する形**を採った。ただし印を
続き（carry）へ持ち越して消化のときに照合するのではなく、**commit を作るとき**に、世界の上で打ち直した各段の候補へ当てて段を切る。
- 正しさ: 置き場で判定する形（山札・ライフから選ぶ対話は全部読み直す）は、引いた札が手札に入ってから選ぶ対話（「2 枚引いて 1 枚捨てる」）を取りこぼす
  （候補の置き場は手札）。また見て戻した山札の上（知っている札）を不要に読み直す。
- 費用: 続き（Python との受け渡しの JSON・`DecideCarry`）の形を変えずに済む（段を短くするだけ）。消化側（`commit_step`）は 1 行も変えていない。
  印は札の数ぶんの bool を commit を作るときに 1 回作るだけ。

**測定用の旗** `DecideOptions.commit_hidden_legacy`（opts の鍵・既定 false＝修正後）: true で全部積む旧い形。
`engine_rs.py`（`commit_hidden_legacy=`）・`arena.py --cand-commit-hidden-legacy`（候補席）・`arena_shard --commit-hidden-legacy`（基準席）・
`defense_audit.py --commit-hidden-legacy`・`rs_decide_latency.py --commit-hidden-legacy`（出力に決め方ごとの手数 `kinds` を足した）。`docs/SPEC.md` §2.5.11。

**テスト**（`rust/opcg_engine/src/search/tests_commit_hidden.rs`・5 本）: 印の集合（席で変わる・知っている札は印にならない）・段の打ち切り（相手の段は見ない・
最初の段で切れれば commit 無し）・実カード たしぎ（OP06-050・山札の上から 5 枚を見て《海軍》を 1 枚）の登場時の続きで、既定は山札から選ぶ段の直前で止まり
そこまでは旧い形と同じ・旧い旗は選んだ札まで積む・山札の札を全部知っていれば旧新で同じ・opts の鍵。

## 7. 留保

- 印は「commit を作った世界の根」で取るので、**続きの中で相手が公開した札**（commit の時点では見えていない）を候補に含む段も切る。本当の盤面では公開済みでも、
  世界では別の札が公開されていた＝切るのが正しいと読んでいる。
- `known_by` の無い盤面（記録 v5 の `hidden` から組んだ盤面＝`decide_json` の経路）では相手の手札・山札の札が全部印になる（読み直しが増えるだけ・安全側）。
  生成・アリーナ・serve は生の盤面（`Game.decide`）なので当たらない。
- 守りの監査は 300 局で消えた点が 1 点＝強さへの効果は小さいはず。強さはアリーナでしか分からない。本番アリーナ（候補席＝修正後・基準席＝`--commit-hidden-legacy`・
  両席 r13d・出荷の設定・random × real・seed 3271000〜）はコーディネータが起こす。打つ手が変わる局は golden の a1 で 2／50・守りの監査で 38／300。
- 3013217 型（commit と読み直しの答えが割れる・候補は見えている）は §7.40 の監査の対象で、この WP では触っていない。
