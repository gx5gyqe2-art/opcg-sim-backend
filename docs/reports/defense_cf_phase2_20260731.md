# 防御応答矯正フェーズ2 中間報告 — 機構は成立・採用は未達（2026-07-31）

スナップショット（追記・改変しない）。フェーズ1は `defense_cf_phase1_20260730.md`
（def_temp ロールアウト＋防御窓CFプローブ・人間整合 12/13・CRNバグの発見と修正）。
本報告はフェーズ2＝**防御窓CFコーパスで gen8 を微調整して守り採択を矯正する試み**の中間結果。

## TL;DR

- **機構は成立**: 防御窓CF教師で微調整した候補は、人間マーク由来の45防御窓での
  守り採択率を **0.289 → 0.55** に動かした（人間は同窓で 0.356）。動かしたい軸は動く。
- **採用は未達**: アリーナスクリーン（48局 vs 出荷gen8）で、防御コーパス単独学習は
  **勝率 0.042（分布崩壊）**、汎用密コーパス混合でも **0.479（同等止まり）**。昇格なし。
- 次の一手は本命 **(d) 修正済みエンジンでの密対面コーパス再生成**（別報告予定）。
  gen7/gen8 を作った密コーパス197k行は、効果対話の既定解決が壊れた
  エンジン（`default_interaction_fix_20260730.md`）の上で生成されたものだから。

## 2. 守り採択率 — 機構の成立（45人間防御窓・8seed×45=360判定）

| 方策 | 守り採択率 |
|---|---|
| gen8（出荷） | 0.289（104/360） |
| 候補A（防御CF微調整） | 0.550–0.561（複数測定） |
| 人間（同窓・参考） | 0.356 |

防御CF教師は守り採択を確実に動かす。ただし 0.55 は人間の 0.356 を大きく超えており、
**矯正ではなく過剰旋回**の疑いがある（コーパスが防御窓しか含まないことの帰結）。

## 4. アリーナスクリーン — 採用の失敗（48局 vs 出荷gen8）

| 腕 | 勝率 | 読み |
|---|---|---|
| C（防御コーパス単独・蒸留0.5） | **0.042**（2/48） | **分布崩壊**。防御窓だけの狭い分布で上書きすると汎用プレイが壊れる |
| F（密v19コーパスと混合） | 0.479（23/48） | 崩壊は防げるが同等止まり。昇格には届かない |

**コーチゲート改善（C: 5.1 vs 4.7）とアリーナ崩壊（0.042）は同居する**。
本セッションで最も極端な実例であり、screen-first（先にアリーナで粗く弾く）の
規律を再確認した。

## 5. 教訓（次の試行の前提）

1. **狭分布コーパスの単独学習は禁止**。防御窓のような偏った分布は必ず汎用
   コーパスと混合する（それでも今回パリティ止まり）。
2. **coach改善 ↔ arena崩壊は両立する**。coach v3 は14点の局所検証であり全体分布を
   見ない。判定順序は arena screen → coach → 800局 arena_gate。
3. **CF教師の効果量に対してコーパスが小さすぎる**（438行 vs gen8 の裏にある197k行）。
   採択率は動くが、動かし方の品質（0.55 への過剰旋回）を制御する行数がない。
4. 生成スループット（ターン中フォアグラウンド限定）が律速。CF方式の高コストを
   考えると、防御矯正は (d) の密再生成の**副菜**（混合成分）として続けるのが妥当。

## 6. 次: (d) 修正済みエンジンでの密対面コーパス再生成（本命・確度40–50%）

gen7（+50 Elo）・gen8（+49 Elo）を生んだ「密度×分布の新規性」レシピ（2戦2勝）を、
効果対話の既定解決を直したエンジンの上でもう一度回す。旧197k行は
「公開したベン・ベックマンを自動で捨てる」ような壊れた解決の下の対局分布・勝敗から
生成されており、修正後エンジンの正しい分布での密ラベルは未取得。
`dense_selfplay_gen.py --matchup nami:shanks --base gen8 --enc-version 6` で生成し
（v6符号化＝手札資源集約を密データで学習可能にする）、防御CFコーパスは
混合の一成分として同伴させる。判定は arena screen → coach v3 → 800局 arena_gate。
