# T150b/T150c: 攻撃・純付与にドンの機会費用を入れる切替（2026-09-23）

T150a（`2026-09-23_don_cost_inventory.md`）は、`ATTACK`／`DON_BOX`（対象あり・k>0）と純付与が
`score_candidate` でドンの機会費用を払っていないのに、`PLAY` は既に払っている（`don_opportunity`／
`_attach_total`・盤面依存）と分かった。T147a は付与の借りた価格だけに**定額**の `δ` を引いて悪化
させた——比較相手が同じ費用を払わなかったため。本 T はその欠落を、`score_candidate` の**両方の型に
同じ既存の機会費用の式**で入れる切替を書き（T150b）、測る（T150c）。ユーザ指示「両方とも追いましょ
うか」→「その10個をまとめてお願いします」の束 2。

**記録**: T144／T147a と同じ seed（実＝50000〜50009・`--decks user`／合成＝51000〜51009・
`--decks synth`・各 10 局・介入なし）。

---

## 1. 式（新定数ゼロ）

`theory_order.py` に `ATTACK_DON_COST_MODE`（既定 `off`）を足した。`opportunity` のとき、
`score_candidate` の `ATTACK`／`DON_BOX`（対象あり）と純付与（`ATTACH_DON`／`DON_BOX` 対象なし）の
両方から `attack_don_cost(ctx, k, theta, mu)` を引く——`PLAY` が既に使っている
`don_opportunity`／`_attach_total`（盤面の実際の攻撃手一覧・実際のアクティブなドンの枚数）を
再利用する。`k<=0` または盤面情報が無ければ 0（既定 `off` は常に 0＝T41 以降の実測は 1 ビットも
動かない・回帰テストで確認済み）。

## 2. 検算の予告（測る前に書く）

1. **k=0 の素殴りは切替の前後で価格が変わらない**（`attack_don_cost` は `k<=0` で常に 0）。
2. **k>0 の攻撃の禁じ率は切替を on にすると上がる**（価格が下がるので `s` がより負に振れやすい）。
3. **`--seq off` のときの純付与の禁じ率も上がる**（`attach_value` の増分から同じ費用が引かれ、
   選んだ付与自身の価格が下がる）。
4. **`--seq attack_le` と組み合わせると、T147a の一方的な悪化は起きない**——借りる攻撃の価格も
   同じ費用を払うので、付与の借りた価格と攻撃自身の価格が**同じ基準で**下がる。T147a
   （付与だけに定額を課した・96%／93%へ悪化）と違う結果になるはず。

## 3. 実測

**記録**: T144／T147a と同じ seed（実 654 行・合成 505 行・介入なし）。

| | `--seq off` | `--seq attack_le` |
|---|---|---|
| 攻撃の禁じ率（cost off → on・実） | 0.4932 → **0.5101** | 0.4932 → 0.5101 |
| 攻撃の禁じ率（cost off → on・合成） | 0.4010 → **0.3911** | 0.4010 → 0.3911 |
| 純付与の禁じ率（cost off → on・実） | 0.9306 → 0.9236 | 0.6319 → **0.6111** |
| 純付与の禁じ率（cost off → on・合成） | 0.9134 → 0.9134（不動） | 0.5984 → **0.5827** |
| 禁じられた行の `s` の平均（実） | −0.0795 → −0.0776 | −0.0663 → −0.0660 |
| 禁じられた行の `s` の平均（合成） | −0.0782 → −0.0774 | −0.0633 → −0.0639 |

**最も重要な結果**: `--seq attack_le` と組み合わせると、純付与の禁じ率は**両記録とも下がった**
（実 63.19%→61.11%・合成 59.84%→58.27%）。T147a の一方的な定額 `δ`（63%→96%・大きく悪化）とは
**逆の方向**——**攻撃候補（借りる側）も同じ機会費用を払うようにしたことで、悪化ではなく改善が出た**。

## 4. 予告と当否

| # | 予告 | 結果 | 当否 |
|---|---|---|---|
| 1 | k=0 の素殴りは価格が変わらない | `attack_don_cost` は `k<=0` で常に 0（コードの構造で保証・回帰テストで確認済み） | **当たり**（測るまでもない） |
| 2 | k>0 の攻撃の禁じ率は on で上がる | 実は上がった（+1.7pt）が**合成は下がった**（−1.0pt） | **記録間で割れた** |
| 3 | `--seq off` の純付与の禁じ率も on で上がる | 実は**むしろ下がった**（−0.7pt）・合成は**不動** | **外れた** |
| 4 | `--seq attack_le` と組み合わせると T147a の悪化は起きない | **両記録とも悪化ではなく改善**（§3） | **当たり（想定より良かった）** |

**予告 2・3 が外れた理由（考察）**: `s = played_v − max(scored)` は**行の最大値**で決まる。この行に
`DON_BOX` 攻撃候補が複数（違う k・違う対象）在れば、機会費用は**それらの価格も同時に下げる**——
`played_v` だけでなく `max(scored)` も動くので、**どちら向きに `s` が動くかは行ごとの候補の組み合わせに
依る**。単純に「1 つの候補の価格が下がれば禁じられやすくなる」という予告 2・3 の読みは、**行の中の
他の候補も同じ費用を払うことを見落としていた**——これは予告 4 が当たった理由（対称に払えば悪化しない）
とちょうど裏表の関係にある。

## 5. 不変量

* 既定 `off`（`cost_off_seq_off`）の数字は T141／T144 の元の測定と完全に一致する（実 0.5505・
  合成 0.5426・付与の禁じ率 0.9306／0.9134）——切替を足したことが既定の測定を 1 ビットも動かして
  いない。
* `--seq attack_le`（`cost_off_seq_attack_le`）の数字も T144 の測定と完全に一致する（0.4847／0.4634・
  付与 0.6319／0.5984）。
* 行数（654／505）は 4 条件すべてで同じ（介入しない測定なので打ち回しは変わらない）。

## 6. 上手くいったこと／いかなかったこと

**上手くいった**:
* **T150a で見つけた「付与だけに定額の費用を課すと非対称になる」という診断が、実測でも裏づけられた**
  ——両方に同じ盤面依存の費用を入れると、T147a の一方的な悪化ではなく小さな改善になった。
* **既定 `off` で過去の測定が一致することを、実際の記録でも確認できた**（コードレベルの回帰テストに
  加えて、シャドー計測でも）。

**いかなかった／自己批判**:
* **予告 2・3 の理由付けが浅かった**——「この候補の価格が下がれば禁じられやすい」という単純な読みで、
  同じ行の他の候補も同じ費用を払うことを見落としていた。T144・T147a に続き、**候補どうしの相互作用を
  予告の前に考える**という同じ教訓を 3 回目に繰り返した。
* **効果の大きさは小さい**（数 pt）——T147a のような大きな悪化は避けられたが、T18 の判断を変えるほどの
  改善でもない。

## 7. ユーザ判断をお願いしたいこと

1. **T150b の切替はコードとして残す**（既定 `off`）——実測は小さな改善で、悪化はしていない。
2. **既定を `opportunity` にするかは保留を推薦**——効果が小さく、T146（決着前の自信過剰）を解決する
   ものでもない。T18 の判断を変える強さではない。
3. **次は T150d（2 つの橋・帳簿・曲線への影響）を測ってから、最終判断（T150e）に進む**（推薦）。
