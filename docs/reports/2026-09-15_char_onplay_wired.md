# キャラの登場に効果を足した——**攻め側が動いた（中盤が `no_link` → `bridge_holds`）**

2026-09-15 実施。§0.5 の順序 1「**キャラの登場に効果を足す**」。
足す向きは**前作業（T32）で確定した**——`ν` は登場時効果を含まないと測れたので、
**引くのではなく足す**のが正しい。本報告は特定時点のスナップショット（追記・改変しない）。

## 結論を 5 行で

1. **`キャラの登場 = ν(パワー) + 登場時効果 − μ − 費用·δ`** にした。
   **新しい定数はゼロ**（効果の値は既存の価格からの導出・条件は状態から判定）。
2. **配線で罠が 2 つあり、どちらも潰した**——(a) `ON_PLAY_TRIGGERS` は**体なしカード用に
   `ACTIVATE_MAIN` まで含む**ので、キャラに使うと**場に出しただけで起動メインが発動**する。
   (b) `card_value` は**「登場時能力が無い」も `None`** を返すので、
   そのままだと**素のキャラが全部無言**になる（`no_ability=0.0` で分けた）。
3. **橋は攻め側で動いた**——**中盤が `no_link` → `bridge_holds`**（+0.940 → **+1.659**・
   CI が 0 を離れた）・**接戦帯の攻め半分が +0.478 → +0.865**（+81%）。
4. **全体の傾きは下がった**（+4.475 → **+4.274**）が **CI は大きく重なる**＝動いていない。
   **守り側は不動**（−3.754・候補リストを使わないので影響を受けないのが正しい）。
5. **独立の突き合わせは「桁は合うが帯は合わない」**——足した額（パーサ経路 0.029〜0.081）と
   実測の登場時利得（記録経路 0.024〜0.053）は**同じ桁**だが、**帯ごとの比は 0.55〜2.3 倍**。

## 1. 何を足したか

```
キャラの登場 = ν(パワー・ブロッカー・相手の場) + 登場時効果(条件で判定) − μ − 費用·δ
```

**足す根拠**（前作業・`2026-09-15_nu_onplay_split.md`）:

- `ν` は帯 `(自ライフ, 相手ライフ, ターン帯, 手札)` の中で自場の体数に付く係数なので、
  **手札・ライフに現れる効果は条件付けられている＝`ν` の外**に在る。
- **直接測っても上乗せは出なかった**（`onplay_power`・6 帯中 4 帯で負・
  2 本の土台で一致する符号はリーダー未満の**負**だけ）。
- **相手の場に現れる分（登場時除去）だけは `ν` が吸いうる**が、実測 **0.0016**＝`ν` の 1.5%。

## 2. 配線の罠 2 つ（どちらも「混ぜてはいけないものを混ぜる」形）

| 罠 | 何が起きるか | 直し方 |
|---|---|---|
| **契機の集合を流用する** | `ON_PLAY_TRIGGERS` は**イベントの本文が `ACTIVATE_MAIN` に入る**ため広げてある。キャラに使うと**起動メインを登場時に足す**＝場に出しただけで発動したことになる | **`CHAR_ON_PLAY_TRIGGERS = ("ON_PLAY",)`** を別に持つ |
| **「能力が無い」と「読めない」が同じ `None`** | `card_value` はその契機の能力が無いとき `None` を返すので、**素のキャラ（同梱の 1,863 枚）が全部無言**になる | **`no_ability=0.0`** を渡して分ける。**効果 JSON に無いカードは `None` のまま**（読めないものを 0 で隠さない） |

> **2 番目は「`0` と `None` を混ぜない」の裏返し**——これまでは「読めないものを 0 にするな」
> だったが、ここでは**「本当に 0 のものを `None` にするな」**が問題だった。
> **同じ規約の両側**である。

## 3. 橋（§0.5 の受け入れ基準）

実デッキ 300 局・`--silent exclude`・`Θ = 1.15`。**前段（P2 全部＋条件）** と比べる:

| 帯 | 前段 | **キャラに効果を足した後** | 判定の変化 |
|---|---|---|---|
| **全体** | +4.475 [3.49, 5.64]・AUC 0.710 | **+4.274 [3.39, 5.26]・AUC 0.707** | `bridge_holds`（変わらず） |
| 接戦 | −1.659 [−3.24, +0.18] | **−1.546 [−3.16, +0.29]** | `no_link`（変わらず） |
| 　**接戦の攻め** | +0.478 | **+0.865** | **+81%** |
| **中盤** | +0.940 [−0.51, +2.43] | **+1.659 [0.07, 3.29]** | **`no_link` → `bridge_holds`** |
| 決着 | +2.144 [1.44, 2.84] | +2.055 [1.42, 2.66] | `bridge_holds`（変わらず） |
| **守り** | −3.754 | **−3.754（完全に同一）** | — |

**無言の行は 608 のまま**（キャラは元から値が付いていたので減らない）。

**読み方**:

- **攻め側は正の方へ動いた**——接戦帯の攻めが 1.8 倍・**中盤の判定が変わった**。
  §0.5 の受け入れ基準（傾きが正の方へ動いたか）は**攻め側について満たした**。
- **全体が少し下がったのは母数の話ではない**（行は同じ）——**決着帯がわずかに下がった**ぶん。
  ただし **CI が大きく重なる**ので、**下がったとは言えない**（罠 22）。
- **守りが 1 桁も動かないのは正しい**（守りは候補リストを使わない）＝**差が配線に由来する検算**。

## 4. 独立の突き合わせ——**桁は合うが帯は合わない**

**2 つの経路で同じ量を出した**（§0.1 の条件 3＝当てはめていない量で検算する）:

| パワー帯 | **足した額**（カード本文 → 既存の価格） | **実測の登場時利得**（記録の通貨の差分） | 比 |
|---|---|---|---|
| リーダー未満 | **0.0538**（中央値 0.0274・非ゼロ 88%） | 0.0238 [0.020, 0.027] | **2.3×** |
| リーダー〜飽和 | **0.0294**（中央値 0.0000・非ゼロ 50%） | 0.0533 [0.046, 0.060] | 0.55× |
| 飽和超え | **0.0813**（中央値 0.0616・非ゼロ 82%） | 0.0518 [0.048, 0.056] | 1.6× |

**桁が合うこと自体は意味がある**——**材料が完全に別**（片方はカード本文の構文解析、
もう片方は棋譜の通貨の差分）なのに **0.03〜0.08 の同じ範囲**に入る。

**ただし帯ごとの対応は取れていない**。しかも**記録側の水準は信用できない**——
**登場時能力を持たないキャラでも「利得」0.024〜0.064 が出る**（`without_onplay`）＝
`entry_gain` は**登場の行から同ターンの次の main 行までの差分**を取るので、
**同じターンの他の行動（攻撃でライフが減る等）を拾っている**。
**＝この突き合わせは「桁の確認」までで、帯の一致を要求できる精度が無い。**

## 5. 副産物——**架空の cid ではもう体の値付けも試せない**

配線でゲートが 1 本落ちた（`test_nu_calib.py::test_play_value_passes_the_blocker_flag_through`）。
**キャラの登場が効果 JSON を引くようになったので、架空の cid（`C_BLK` 等）を使うテストは
「読めない」で `None` になる**。**これは仕様どおりの挙動**なので、**テスト側を実在する
素のキャラで書き直した**（効果が 0 なので差はブロッカー項だけになる）。

> **同じ形のテストを 3 本直した**（`test_nu_calib` 1 本・`test_theory_order` 2 本）。
> **スタブの cid で済んでいたのは、登場の値付けが盤面と素性だけで決まっていたから**で、
> **カードの中身を読むようになった時点で前提が変わった**。

## 限界

- **`ν` は対象のパワーの帯を見ているが、効果の中の `ν` は平均 0.1087 のまま**
  （例: 登場時 KO の対象が 2000 でも 10000 でも同じ値）。
- **条件の判定できない 1,567 件は変わらず**（`FIELD_COUNT` の絞り込み付き）。
  前作業で**上限・下限どちらでも橋が動かない**ことは確かめてある。
- **登場時除去の分（0.0016）は二重計上のまま**——`ν` が吸っている分を引いていない。
  `ν` の 1.5% なので放置した（引くなら `progress` 帯で `ν` を測り直すのが筋）。
- **`entry_gain` の器が汚れている**（§4）＝**記録側の登場時利得を綺麗に測る器が無い**。
  直すには**登場の行の直後の状態**が要る（P8 の家族）。
- **観察であって因果ではない**（§0.3 の限界はそのまま）。
