## 何を採用したか

- `gen9_value.npz` = **gen8 value と v25 防御混合候補の重み線形補間 α=0.5**（float 配列のみ
  α:1−α で結合・メタ/EffF/vocab_ids は同一性 assert 済み）。符号化 v6（60スカラー＝
  手札資源集約つき・feat_dim 140 から自動判別）。
- `gen9_policy.npz` = **gen8 policy と同一重みの v6 恒等温スタート拡張**（挙動は gen8 policy と
  恒等。value との符号化版一致が必須——不一致は行動特徴が5列ずれて黙って壊れる:
  2026-07-31 の dense_finetune 修正参照）。
- 既定切替: `cpu_learned._DEFAULT_VALUE/_DEFAULT_POLICY` → gen9。gen8 以前は
  リプレイ再現・A/B・ロールバック用に同梱維持（レフェリー錨は gen5 固定のまま）。

候補側（α=1 端）の由来: 修正済み効果解決エンジン（`default_interaction_fix_20260730.md`）上の
密対面コーパス（nami:shanks・2,048局・244,544行・v6符号化・生成ネット=gen8 の v6 恒等拡張）
＋防御CFコーパス438行で gen8 を追い学習（ep2・lr2e-4・混合ラベル α=0.5・aux 0.25）。

## 採用の性格（明示）

**昇格基準（wr≥0.55 かつ CI下限>0.50）では FAIL**。採用は 2026-08-01 のユーザ判断
（「0.5のものを採用しましょう」）による: アリーナ（CPU 同士の自己対戦均衡での強さ）よりも、
**人間がマークした失敗局面での正解率（コーチ14点 4.7→5.6・退行ゼロ）**を優先し、
自己対戦で最大 ~2-3pp（CI 上は parity も否定されない）を許容する取引。
gen7→gen8 型の「Elo 昇格」ではない点で従来の世代交代と性格が異なる。

## リスクと監視

1. **自己対戦均衡での小幅劣化の可能性**（CI [0.426, 0.524]）。実プレイで気になる負け筋が
   増えた場合はファイル差し替えだけでロールバック可能（gen8 同梱維持・フラグ不要）。
2. **v6 特徴の実効性は未確立**（守り採択率は動いていない）。gen9 の意義は補間による
   14点改善の取り込みであり、手札特徴が働き始めたわけではない。
3. 次の学習試行は gen9 が生成・比較の基準になる。**コーチゲートの base も gen9 になる**ため
   次回から比較基準値が変わる（4.7→5.6 相当）ことに注意。
