# エンジンの全変数を洗った——**残る交絡は「これから来るもの」。ただし帯に入れても効かない**

2026-09-14 実施・判定（ユーザ指示「今あるエンジンの変数から効きそうなものを洗えたりする？」）。
合成 300 局・実デッキ 300 局・`scalars` 127 列。本報告は特定時点のスナップショット
（追記・改変しない）。

## 結論を 4 行で

1. **選ぶのをやめて採点できるようにした**（`band_screen.py`）——交絡の定義そのもの
   `bias ≈ (z を予測する強さ) × (説明変数と相関する強さ)` で全 127 列を並べる。
2. **実デッキで残る上位は、ほぼ全部「これから来るもの」**——`leader_pair`・`deck_big`・
   `my_deck_agg`・`deck_draw`・`my_deck_apex_*`・`opp_pool_max_power`。
   **合成では同じ列のスコアが 4〜8 分の 1**（全員の未来が同じだから）。
3. **これは §17.1.5c に書いた限界そのもの**——`A_opp` も `Σc(x)` も**今の盤面の 1 手番ぶん**で、
   **時計の未来側が入っていない**。デッキ残量の列はエンジンがそこを符号化したもの。
4. **しかし帯に入れても改善しなかった**（`progress_fwd`）。**行が 4 割落ちて合成の値が動く**＝
   標本の脱落。**＝「相関の上位」＝「帯に入れるべき」ではない**。

## 1. 採点の基準

ある列 `c` を帯から落としたとき `ν` に乗るバイアスは、およそ

```
bias ≈ （c が z を予測する強さ） × （c が説明変数と相関する強さ）
score = max_k | corr(c, z | 帯) · corr(c, 帯 k の体数 | 帯) |
```

**両方が要る**——z だけ予測する列も、説明変数とだけ相関する列も、バイアスを生まない。
**今の帯（進行 v3）の中で中心化**してから計算するので、**既に帯に入っている列は 0 に潰れる**
（＝帯が効いていることの検算にもなる）。

**`own_board` 印**を器が持つ——**自分の場に由来する列は交絡ではなく処置**なので、
高い score が出ても帯に入れられない。

> **初版は `attackers_left`（まだ攻撃できる自キャラ数）に印を付けず、交絡候補の 4 位に出した。**
> `my_field_n` と `r_x` が **0.693 対 0.691** とほぼ同じ動きで、**実質 `my_field_n` の言い換え**
> だった。名前で拾って印を付けた。

そのまま出た**。ただし正体は**デッキの identity ではなく、時計の未来側**である。

## 3. **入れてみたら効かなかった**

上位のうち帯に入れられる 3 つ（`my_deck_apex_power`・`opp_pool_max_power`・`deck_draw`）を
2 値に潰して足した（`--band progress_fwd`）:

| | リーダー未満 | 〜飽和 | 飽和超え | 行 |
|---|---|---|---|---|
| **合成** 進行 v3 | 0.0605 | 0.1442 | 0.2147 | 2,271 |
| **合成** 進行 v4（＋未来） | 0.0731 | **0.2115** | 0.1878 | **1,337（−41%）** |
| **実デッキ** 進行 v3 | **−0.0078** | 0.1210 | 0.1620 | 2,725 |
| **実デッキ** 進行 v4（＋未来） | −0.0146 | 0.1133 | 0.1674 | 2,227 |

- **合成で行が 4 割落ちて値が大きく動く**（〜飽和 0.1442 → 0.2115）。
  **交絡が無いのに動くのはおかしい**＝**標本の脱落**の兆候（デッキラベルのときと同じ・
  `2026-09-14_progress_band.md` §2.2）。
- **実デッキでも改善しない**——弱い体の帯は −0.0078 → −0.0146 と**むしろ 0 から離れた**。

**＝「相関の上位」は「帯に入れるべき」ではない。** 事前登録どおり
（器の docstring に「本器は絞り込みで、実際に効くかは入れて確かめる」と書いてから回した）。

## 4. 判定と、そこから出る方針

| 問い | 答え |
|---|---|
| 全変数を機械的に洗えるか | **洗える**（`band_screen.py`・順位が出る） |
| 実デッキで残る交絡は何か | **「これから来るもの」**（リーダーとデッキ残量）＝**時計の未来側** |
| それを帯に入れれば直るか | **直らない**——行の脱落の方が大きい |
| では未来側はどこに入れるか | **帯ではなく式**（下記） |

> **帯は交絡を取り除くことしかできない。** 未来側は**取り除く対象ではなく、
> 価格そのものの入力**である——`ν` は「残り `R` ターンぶんの攻撃の価値」なのだから、
> **`R` と `A` を先を見た値にする**のが筋であって、**帯を細かくする話ではなかった**。
> **＝`progress_fwd` は設計として筋悪**で、v3 が帯の止めどころである。

## 限界

- **線形・単変量のスクリーニング**。交互作用・非線形の交絡は拾えない。
- `score` の**絶対値に意味は無い**（順位を見る）。
- `progress_fwd` の 3 変数は**2 値に潰した粗い版**＝細かくすれば違う結果になる可能性は残る
  （ただし行はさらに落ちる）。
- 各 300 局・1 設定・生成役 r3。

## 次

1. **帯は進行 v3 で止める**（本報告の §4）。
2. **時計の未来側は式に入れる**——`ν` の `R`（残りターン）と `A`（1 手番の攻撃数）を
   **デッキ残量から先を見た値**にする。これは `game_theory.md` §17.1 の
   「`A_opp` は 1 次近似」という限界に直接対応する。
3. **T24（4 つの価格が 1 つの `w` を共有するか）**は進行 v3 の帯で回せる。
