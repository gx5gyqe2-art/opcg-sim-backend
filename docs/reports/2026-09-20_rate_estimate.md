## 1. 直した欠陥

### 1.1 何が起きていたか

橋は `deck_ids` を渡していた（`crossing_bridge.collect`・`stats.a_flow_missing = 0`）。

```python

## 3. `A` の誤りは「ばらつき」だった（新しい器）

### 3.1 何を測ったか（当てはめゼロ・新定数ゼロ）

行は**席 × 自席ターン**（`crossing_bridge.collect` の `turn_harm`）。
**とどめのターンは外す**（`t_left >= 2`・**T107 の規則**——勝った席の最後の自席ターンは
相手のライフが尽きた時点で終わるので、`A`〔打てる量〕と損害〔打った量〕が構造的にずれる）。

```
harm    … そのターンに実際に与えた損害         （実測）
A       … そのターンの理論の速さ                （理論・状態から）
prof[j] … 自席ターン番号 j の損害の平均の輪郭   （`curve` が使う物・**別のセットの表**）

**輪郭は測る記録と別のセットから引く**（§0.1 条件 1）——同じ記録の平均を使うと
3 番目が自分自身との相関になる。**`r²` は係数を合わせない**（予測をそのまま引く）。

## 3.5 副産物: **死んでいた切替を 1 つ見つけて直した**（`RATE_DECAY_MODE`）

`A` の形を疑ったとき、**盤面が `ko_p` で減る**（T95）を入れて測ろうとした。
**出力が既定とバイト一致した**——`--rate-decay ko` が **1 ビットも効いていない**。

**機構**: `rate_at` は**列（`sched`）が在ると先頭で返す**:

```python
if sched:
    return float(sched[...]) + RATE_RAMP * (j - 1)     # ← ko_p も速攻も効果もここで無視される
```

**`RATE_DON_MODE=flow` は 2026-09-19 から既定**（T114）なので**列は常に作られる**。
`seat_slope_sched` は速攻・効果・T1 の規則は自分で持っているが、**減衰だけ持っていなかった**。
**つまり T114 が既定になった時点で、T95 の切替は黙って死んでいた。**

**直した**——`seat_slope_sched` に `q = 1 − ko_p` を入れた（`rate_at` と同じ数え方:
`i` 段で入った体は `j` では `j − i` ターン場に居た・**リーダーと効果は減衰しない**）。
**既定は `off` のままなので出荷の値は 1 つも動かない**。テストで**切替が名乗ったことをするか**を固定した。

> **教訓**: **切替を足したら、次に既定を動かしたとき「その切替がまだ効くか」を確かめる。**
> ここでは **T114 の既定化が T95 の切替を無効にした**のに、**どちらの報告にも書かれていない**。

## 4. 何が分かったか（次の道）

**T127 の「`A` そのものが患部」は正しかったが、患部の中身は予想と違った。**

> **`A` の水準も形も合っている。合っていないのは「この局のこのターン」の当たり外れである。**
> **`curve` が強いのは、それが「当たり外れを一切主張しない平均」だから**——
> **`A` は主張するが、主張の半分以上が外れている。**

**だから次の一手は「`A` に別の項を足す」ではない。** 足しても平均が動くだけで、当たり外れは動かない。
**当たり外れを作っている当のものを式に入れる**しかない:

1. **守り側**——序盤の損害のばらつきは**相手が守ったか**で決まる。
   理論では**相手の手札は的の側（有限の盾・T102）**に在り、**`A` の側には 1 つも入っていない**。
   ただし**両側に入れれば二重計上**になるので、**「盾が `A` の分散をどれだけ説明するか」をまず測る**のが筋
   （足す前に量を数える＝T106 で学んだ手順）。
2. **攻撃の本数**——`A` は「殴れる体の総額」だが、**実際に何本通るか**は相手の盤面とライフで決まる。
   `SLOPE_BLOCK_MODE`（既定 `off`）はアクティブなブロッカーだけを見ている。
3. **P8（記録 v5）が開けば直接見える**——「その窓で実際に何本殴り、何本が守られたか」。
   **本 T の残差（+0.32）が何でできているかは、それを待たずに測れる量ではないかもしれない。**

**測る順序の推薦**: **1 → 2**（どちらも既にある量で、新定数ゼロ）。
**1 で分散の大半が説明できなければ、`A` を時計に入れる道は当面閉じる**——
**`curve`（平均）を使い続けるのが正しい**という結論を、**測った上で**確定できる。

## 5. 上手くいったこと／いかなかったこと

**上手くいった**:
* **橋と器を突き合わせた**ので欠陥が見つかった。**`a_flow_missing: 0`（橋）と

  「直したことで何が動き、何が動かないはず」が**事前に言えて、そのとおりになった**。
* **`curve_scaled` の P5 破れが 657 → 0 になった**——**直したことの独立な証拠**（予想していなかった副産物）。
* **`A` の悪さを「水準・形・ばらつき」に割ってから測った**ので、
  **T107／T108 の結論（水準と形は合っている）を再現しつつ、残る 1 つを名指しできた**。
* **測る前に予告を書いた**（残差の相関が 0 なら「平均としてしか効いていない」・正なら「時計の側に戻る」）。

**いかなかった／自己批判**:
* **`seat_slope` が `deck_ids` を取らない形だったことを、T121 で器を作るときに見ていない**。
  **橋の呼び出し（`seat_slope_terms(..., deck_ids=dk)`）と私の呼び出し（`seat_slope(...)`）は

  **関数名が似ていることを根拠に同じ量だと書いた**のが誤り。
* **前回のチャットで「`A` の伸びが丸ごと消えている」と言ったのは、半分だけ正しかった**。
  **平らだったのは `seat_slope_sched` の列**（別の対象）で、**`A` 自身は旧のままでも伸びていた**
  （0.0618 → 0.2533）。**欠けていたのは 20〜28% の水準で、「伸びが無い」ではない。**
  **1 つの器の出力を見て、別の器の結論を言った。**
* **T126 の追記で「`A` の推定の尾が患部」と書いたが、測ったら尾ではなく分散だった**
  （水準も形も合っている）。**打ち切りに貼り付く行を見て「尾」と呼んだのは `curve_scaled` の話**で、
  **`A` 自身の話ではなかった**——**2 つを混ぜていた。**

## 6. ユーザ判断をお願いしたいこと

1. **`curve` を既定のまま据え置く**（推薦）。**本 T で `A` を正しくしても差は 0.17／0.06 残る**。
2. **次は「守り側が `A` の分散をどれだけ説明するか」を測る**（推薦・§4 の 1）。
   **足す前に量を数える**（T106 の手順）——説明できなければ、
   **「`A` を時計に入れない」を測った上での結論にできる**。
3. **T121〜T127 の報告は訂正しない**（特定時点の記録）。**本報告が訂正の正本**——
   **`curve` の数字は全部そのまま有効**、**`A` を時計に入れた読みの数字だけ §2 の表に差し替わる**。
