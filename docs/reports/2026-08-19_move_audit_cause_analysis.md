# 手の監査 段3裁定の原因分析（2026-08-19）

対象: 段3裁定（`tests/fixtures/move_audit_stage3.json`）で原因分析要求が付いた
#1, #2, #5, #10, #13, #14, #15。測定コミット `7dd7260`・ネットは出荷既定 G14・sims=160。
プローブのスクリプトと生ログは `claude/moveaudit-shard0` ブランチ `audit_results/stage3/` に退避。

**結論（要旨）**: 根本は「ターン中のプランを立てて実行する機構が働いていない」こと
（ユーザ仮説どおり）。その下に4つの独立な欠陥が層をなす:

1. **構造: プラン不在** — 1手ずつの読み出しがターン内のコミットメント（付与→その攻撃で回収）
   を持てない。実装済みのプラン読み出し（`SERVE_PLAN_READOUT`・v37②）は**既定OFF**。
   ONにするだけで非整合ファミリー（順序逆転・回収漏れ・早すぎる終了）は構造的に消える（プローブF）。
2. **評価: ターン末価値のバイアス** — 価値ネットが「付与済み/レストへの追い付与」状態を
   正解の展開より**高く**評価する逆転。探索を増やしても直らない（プローブA/B）。
   これは v37② が過去に FAIL した正確な原因で、v39（出口専用ヘッド）が前提条件。
3. **候補生成: フィルタ例外(B)の粗さ** — 【ドン!!×N】条件持ちへの付与を無条件で通し、
   「条件が既に達成済みか（attached≥N）」「トリガー窓（アタック時）が消化済みか」を見ない。
4. **測定: worlds=6 の量子化と手札固定** — ほぼ同値の手対に見かけの regret が付く（P8・
   プローブD）。相手手札が真値固定の世界は情報集合ベースの判断（#15）の裁定に不適（プローブE）。

## 2. 評価の欠陥: 価値ネットの逆転（プローブA/B/C）

502006@130（#1: 手札にひばり2枚・正解=登場 wr1.000、打った手=レストのドレークへ付与 wr0.333）:

| 選択肢 | V(s')（ネット直接評価） | 段2実測 wr |
|---|---|---|
| ドン付与→イッショウ | **+0.201**（1位） | — |
| ドン付与→ドレーク(休) | **+0.188**（2位） | 0.333 |
| 登場 錦えもん | −0.034 | 0.167 |
| アタック イッショウ→各種 | −0.181 | — |
| **登場 ひばり（正解）** | **−0.352**（下から2番目） | **1.000** |

- フラット（識別不能）ではなく**逆転**。sims=40/160/640 いずれも ATTACH_DON を選ぶ
  （@127/@130 で15/15）＝**探索分解能の問題ではない**。
- 方策プライアはしばしば正しい（@130 P首位=イッショウでリーダーアタック・@121 P首位=先に付与）。
  誤った価値がプライアを上書きする。
- ネット自身のV は手を浪費するたびに下降する（T12: +0.66→−0.32・実際にこの対局は敗北）＝
  局面評価は悪化を知っているのに**手レベルの信用割当が無い**。
- 符号化は場キャラごとに `[cost, power, is_rest, attached_don]` を持つ＝表現の欠落ではない。
  自己対戦の訓練データで「付与＝優勢の相関」だけを学び「レストへの付与は死にドン」の対比例が
  無いブートストラップバイアス。
- 例外: #5（500003@86）は sims=640 で正着（菊之丞登場）に収束＝探索で救えるゾーンも存在する。

## 3. 構造の欠陥: プラン不在（プローブF・ユーザ仮説の実証）

同一ネットで `plan_readout=True`（ターン出口ヘッド無し＝出口評価は素ヘッドへフォールバック）
に切り替えただけの介入:

| 局面 | plan OFF（本番） | plan ON |
|---|---|---|
| 503002@8（#6 受動性） | TURN_END×2/付与×2/登場×1 | **TURN_END 0/5**。ドン箱攻撃→サンジ登場→終了 |
| 502006@121（#1 T12冒頭） | 攻撃を先行→付与×8 回収なし | **付与→攻撃の順序が正常化**・ひばり登場・ターン完結 |
| 500003@86（#5） | 牛マル(休)へ先に付与 | 菊之丞登場に**5/5収束**・付与はヤマト→攻撃で回収 |
| 502006@127/@130 | ドン浪費 | 攻撃は入るが**ドレーク過剰付与は残る** |

- **プラン構造だけで非整合ファミリー（順序逆転・回収漏れ・早すぎる終了）は消える**。
- 残るドン浪費は §2 の価値バイアス＝ドン浪費を含むプランが高く評価される。プラン読み出しが
  2026-08-06 に FAIL した原因（ターン末価値のバイアスはK世界平均で消えない）と同一で、
  v39 の出口専用ヘッド＋ターン出口教師が前提条件（config.py の経緯コメント参照）。
  既定 G14 ネットは battle 出口ヘッドのみ搭載・**turn 出口ヘッド未搭載**（`has_exit_head`実測）。

## 4. 候補生成の欠陥: フィルタ例外(B)（静的分析）

`cpu_ai._attach_don_meaningful` は P1/P2（レスト・登場直後への付与は無意味）を実装済みだが、
例外(B)「【ドン!!×N】条件持ちは無条件で意味あり」が先に効く。

- X・ドレーク ST02-014 = 【ドン!!×1】【自分のターン中】**このキャラがレストの場合**、
  海軍リーダーとキャラ全員+1000 → **レスト・ドレークへの1枚目は正しい手**（チームバフ起動）。
  しかし条件は×1なので**2枚目以降は純損**。(B) は attached≥N の達成済み判定を持たないため
  2〜6枚目が候補に残り続けた（#1 のターンで計5枚が死にドン）。
- 霜月牛マル ST09-008 = 【ドン!!×1】**アタック時** → 攻撃消化後の付与は死に手だが (B) は
  トリガー窓の消化を見ない（#5）。
- トニートニー・チョッパー EB02-003 = 【ドン!!×2】**相手のターン中**+2000 → こちらは
  **レスト付与に守備的意味がある**。#10 cf@2 への指摘はカード効果上は CPU 側に理がある
  （2枚まで。P1 の例外として裁定へフィードバックすべき知見）。

→ 機械的修正: (B) を「条件未達成（attached<N）または相手ターンに働く常在」のみに絞る。
  安価・独立に実施可能（挙動変更なのでベースライン再生成と検証済みデッキ確認が必要）。

## 5. 測定の欠陥（プローブD/E）

### 5.1 worlds=6 の量子化（#13/#14・P8）

worlds=24（6世界×4オフセット・CRN）で再測定:

| 点 | 段2 regret (worlds=6) | worlds=24 | 内訳 |
|---|---|---|---|
| #13 506006@101 | +0.333 | **+0.083** | 打った手0.417／最良(バルトロメオ)0.500／段2の「最良」ホーキンスは**最下位**0.333 |
| #14 500000@31 | +0.333 | **+0.167** | 打った手(攻撃)0.500／ドール0.667／アラマキ0.333 |

- **#13 は量子化ノイズと確定**: regret は半世界分（0.083）に縮み、しかも「最良」の顔ぶれが
  入れ替わった＝worlds=6 の順位は信用できない。ユーザ裁定「CPUも推奨手も誤りではない・
  順序が違うだけ」と整合（q_margin=0.006 のほぼ同値手対）。
- **#14 は部分的に残る**: worlds=24 でもドール登場が最良（0.667 vs 0.500・4世界差）。
  ドール OP11-008 は素のパワー1000ではなく**【ブロッカー】＋登場時に相手キャラ1枚を
  ターン中パワー−6000**（実質除去級）で、審判の選好には実体がある。段3の裁定
  （CPUが正しい・「1000のドールより…」）は効果テキストが見えない旧台帳での判断だった
  可能性があり、**効果表示つきの現行台帳での再確認を推奨**（裁定へのフィードバック）。

### 5.2 手札固定の世界は情報集合の裁定に不適（#15）

- ユーザ台本（ドン全付与→リーダー総攻撃）を強制: **wr 0.000（12世界全敗）**。
  この対局の相手手札（世界間で固定の真値）はカウンター値が足りており総攻撃は通らない。
- 参照（同局面から本番CPU）: wr 0.500。受動線が5割勝つのは、返しの最大打点
  （10ドン付与の16000スイング）を審判の相手側CPUが実行し切れていない疑いが濃い。
- **方法論の穴**: 段2の世界は山札順のみ振り、手札は真値固定（serve_referee 規約）。
  「実際に何が起きたか」の測定には正しいが、「カウンター値次第で通る」という
  **情報集合ベースの判断の裁定には相手手札もサンプルした世界が必要**。#15 の裁定
  （最良手も誤り）は手札サンプル世界での再測定まで確定保留とする。

## 6. 対策ロードマップ（優先順）

1. **プラン読み出しの再判定を主線に昇格**（構造欠陥の解消・F で症状消失を実証済み）:
   G14 向けターン出口教師（今回の裁定・指摘34件＋対比局面の機械生成）で turn 出口ヘッドを
   訓練 → `SERVE_PLAN_READOUT=ON` を8点ゲート＋アリーナ2条件で再判定（§5.05 準拠）。
2. **フィルタ例外(B)の閾値化**（§4・安価な機械修正・独立に実施可）。
3. **段2計器の改良**: q_margin<0.02 の候補は worlds 自動増額／順序同値の手対を除外／
   情報集合依存の判断（防御・リーサル）には手札サンプル世界のモードを追加。
4. 注入教師（当初計画の P1 対比コーパス）は 1. のターン出口教師に統合する。
