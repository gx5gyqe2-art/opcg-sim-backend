# B: 止められる本数を1本少なく見積もる偏り——`avg_counter`の実装バグを直すと42行中15行(36%)が閉じる(2026-09-25)

P8-7(b)(`2026-09-25_p8_7b_defender_actuals.md`)が見つけた「理論の`stops`(守り手が切れるだけ切ったときに
止まる本数)が実際の`counters_used`より系統的に低い」という偏り(全力で殴って負けた42行・実15/合成27)を、
4つの候補に分けて検算した。

## 診断(B-1・読み取りだけ・新定数ゼロ)

### 候補(d): 組み合わせ探索(`max_stops`/`stop_min_counter`)が最適解に届いていない

**完全に反証**。42行全て、貪欲解と全探索の厳密解が一致した(`/tmp/b1_diag/exact_stops.py`)。
探索アルゴリズムは原因ではない——差があるなら`lethal_of_row`への**入力の値**が実際とズレている。

残る3候補をワークフローで並行調査した。

### 候補(a): 攻め手のドン配分の仮定違い(`attach_don`)

**部分的に支持**。`attach_don`は「アクティブなドンを全部・安い体から使う」と仮定するが、実測では
平均9.62枚に対し実際の使用は3.12枚(約1/3)・完全一致は42行中2行のみ。方向としては42行中最大24行で
「stopsの過小評価」を後押しするが、-1ヒットのパターンは対象を絞った27行**全部**に出るため単独では
閉じない(例: seed 8934は実使用ドン0でも最大攻撃力が理論と一致し、ギャップが説明されない)。
**「全額投入」の代替仮定は設計判断が必要**(単純な定数修正では済まない)——次の着手候補として残す。

### 候補(b): 守り手の手札の読み違い(`hand_plan.hand_items`)

**支持されなかった(0/42行)**。42行・延べ約150枚のカードのコスト・カウンター値・EVENT判定は、
全てカードDBおよび実際の能力テキストと完全に一致した。副産物として`hand_guard.counter_of`が
条件付きカウンター能力の条件(リーダー特徴など)を評価しない limitation を見つけたが、方向が逆
(過大評価)で今回の偏りには無関係。

### 候補(c): ライフ札の平均カウンター値の仮定(`avg_counter`)

**支持された・実装バグと特定**。`lethal_rule.avg_counter`は印字カウンターだけを数えるが、
同じコードベースの他の場所(`deck_refill.is_cuttable`・`hand_guard.counter_of`・`n_rel_feat.profile`が
既に使っている定義)は【カウンター】イベントの上げ幅も数える。42行の防御側デッキの66.7%(28/42)がこの
種のEVENTを含み、平均カウンター値は803.8→1026.7(+27.7%)に補正される。**この補正だけでstopsを
再計算(貪欲・厳密解の両方で確認)すると、42行中15行(実5/15・合成10/27)で必ず+1され、いずれも
「決着」宣言が取り消されて実際の生存結果と整合する**。残る27行のうち14行は防御側デッキに
【カウンター】持ちEVENTが1枚も無く(補正がno-op)、12行は補正が効いてもギャップが大きすぎ、
1行はライフ0(この機構の対象外)。

## 実装(B-2)

`lethal_rule.py`に`AVG_COUNTER_MODE`(`printed`=既定・旧来／`rules`=候補(c)の修正)を追加。
既存の`is_cuttable`/`counter_of`と同じ定義(印字カウンターと【カウンター】イベントの上げ幅の
大きい方)に揃えるだけで、新定数はゼロ。`settlement_split.py`にも`--avg-counter`を素通しした。
回帰テスト5本(`test_lethal_rule.py`・実カード`EB01-028`/`EB01-022`で両モードの値を固定)。

## 計測(B-3・切替on・実300局・合成900局)

| | 実(printed→rules) | 合成(printed→rules) |
|---|---|---|
| `declared`(宣言した行の総数) | 332→289 | 928→880 |
| `precision_winner`(宣言した側が実際に勝った割合) | 0.9337→**0.9481** | 0.9591→**0.9682** |
| `precision_kill`(そのターンに終わった割合) | 0.747→**0.8097** | 0.7985→**0.8227** |
| `recall_end`(勝者の最後のターンで宣言できた割合) | 0.8267→0.78 | 0.8233→0.8044 |
| `recall_game`(局のどこかで宣言できた割合) | 0.8367→0.7867 | 0.8289→0.8089 |
| `false_declared`(敗者側の宣言の総数) | 22→**15** | 38→**28** |
| `lead`平均(宣言から終局までのターン数の先読み) | 0.494→0.339 | 0.414→0.364 |

`settlement_split.py`の内訳(全力で殴って負けた行=`full_swing`):

| | 実 | 合成 |
|---|---|---|
| `false_declared`のfull_swing | 15→**10** | 27→**17** |
| `missed_lethal`(取りこぼし・逆方向)のfull_swing | 28→38 | 119→130 |

**読み**: 修正は診断どおりに効く——`false_declared`のfull_swingが実5行・合成10行減り(合計15行・
候補(c)の予告と一致)、宣言の精度(`precision_winner`/`precision_kill`)が両記録で一貫して上がる。
**ただし副作用がある**——`declared`の総数が減り、`recall_end`/`recall_game`がわずかに下がり、
`missed_lethal`(理論が「勝てたはず」と言えなかった行)が増える。これは**同じ機構の裏側**——
守り手の耐久を正しく(高く)見積もるほど、理論は宣言に慎重になり、際どい勝利を宣言し損なう回数が増える。
**決着前の較正(`win_calib`・`--pre-settle game`・`slope=theory`)への影響はほぼゼロ**——
実 LL(rel) 0.6019→0.6094・AUC 0.7883→0.7883(不変)・ECE 0.0773→0.0782／
合成 LL(rel) 0.7232→0.7214・AUC 0.7292→0.7310・ECE 0.1154→0.1153。両記録とも小数点第3位以下の
ゆらぎで、方向も一定しない(実はわずかに悪化・合成はわずかに改善)——**実質的に無視できる**。
既定の`PRE_SETTLE_MODE=off`では`settled_map`自体を呼ばないため、`pre-settle`を使わない通常の
交点の橋・帳簿・2本の曲線の既定計測にはこの切替は一切影響しない。

## 結論

**候補(c)は42行中15行(35.7%)を、実装の一貫性を取るだけ(新定数ゼロ)で説明する**。副作用は
「宣言の精度が上がる代わりに宣言そのものが減る」という一貫したトレードオフで、決着前の較正には
ほぼ影響しない。**採用するかどうかはユーザ判断**——採用すれば`avg_counter`の既定を`rules`に切り替え、
残る27行(候補(a)の設計判断待ち14行・ギャップが大きすぎる12行・ライフ0の1行)は別の機構として残す。
