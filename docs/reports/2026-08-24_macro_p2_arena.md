# マクロ手化 P2（アタック箱）アリーナ A/B — 判定: 現形は不採用（PAR下限・P1比で微減） — 2026-08-24

スナップショット。計画の正本: `docs/cpu_macro_plan.md`。台帳: `origin/claude/arena-m2-shard0{r,m}`
（ローカルのみ・96ペア×2条件・void 0）。

## 1. 測定（候補=gen15＋P2マクロ（配分箱＋アタック箱）／基準=gen15既定・P1と同一シード）

| 条件 | 有効ペア | 勝率 | 95%CI | 参考: P1 |
|---|---|---|---|---|
| 主: ランダム対面×合成デッキ | 96 | **0.474** | [0.395, 0.553] | 0.505 [0.431, 0.580] |
| 副: 固定ミラー | 96 | **0.458** | [0.399, 0.518] | 0.510 [0.449, 0.571] |

判定基準（96ペア・CI半幅≤0.08）で両条件 PAR。ただし**両条件そろって P1 を3〜5pt 下回り**、
decide 実時間も約2〜3倍（中央1.0s・P0比）——**増分は無く、コストは増えた＝P2 現形は不採用**
（seam は既定 OFF のまま維持。コードとテストは P2改の土台として残す）。

## 2. 運用検出2件

- **初回測定は void 88%**: ハングではなくスループット——マクロ辺（付与k＋攻撃＋戦闘解決）は
  journal 再適用が重く、4並列の CPU 競合で 900s ペア上限を超過。`--pair-timeout 1800・
  --workers 3` で void 0 に。**マクロ系の測定は必ずこの設定を使う**。
- 単独実行の実測: 1ゲーム104s・decide 中央1.0s/最大4.7s（`p2_slow_decides` プローブ）。

## 3. 敗因仮説（次の診断対象）

P1（配分箱のみ）が PAR、P2（＋アタック箱）で微減した差分から:

1. **意図の分断（有力）**: アタック箱は「付与k→攻撃」を1手として**評価**するが、実行は
   ステートレスに先頭原始手（ATTACH_DON 1枚）だけを出し、次 decide で再探索する。
   付与だけ実行されて攻撃の意図が引き継がれない＝プランA6で見た病の箱粒度での再発。
   検証: マクロ席の「k>0箱由来の付与が同ターン内に当該攻撃者の攻撃に接続した率」を実測。
2. 重い辺で実効 sims が目減り（同 sims でも journal 再適用コストが探索の質を下げる）。
3. k>0 箱が行動特徴上「マージン付き ATTACK」として prior を吸い、過剰付与へ誘導。

## 4. 次の一手

- 診断①（接続率の実測）→ 有力仮説が立てば **P2改: マクロの sticky 実行**（選んだ箱の原始列を
  ターン内キャッシュから順に出す＝プラン sticky と同じ機構・箱1個ぶんだけの短い約束）で
  意図の分断を断つ。プラン全体の sticky と違い、箱1個は「約束が短い」ので
  誤りの固定リスクが小さい。
- それでも par 止まりなら、P2 は「P3以降の語彙の土台」として seam に留め、
  P3（カード使用箱）・P4（防御箱）＝P0 実測で残る浪費（効果選択10%・カウンター25%）の
  除去へ進む。
