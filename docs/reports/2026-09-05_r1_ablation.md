# r1 の要因分解（2026-09-05・切り分け a1／a2／c12）

**結論: r1 が c10 に勝った要因は「盤面を 22 枠のトークン＋状態 S で見る構造」であり、
関係 R（対の特徴）と相手デッキ知識（opp_pool 列）は強さに寄与していない。**

ユーザ要望（2026-09-05「その前に切り分けできる？」）を受け、r1 の 3 要因（構造・R・相手デッキ知識）を
同じ教材・同じ訓練手順で 1 つずつ落とし、r1 と主条件アリーナで直接対決させた。

## 段 1: serve 時の遮断（訓練なし・r1 がその入力に依存しているか）

評価帯（波23 w01＋w02 holdout・38,164 行）で r1 の入力をゼロにして v_mse を見る（`n_rel_band.py --zero-rel/--zero-opp-pool`）。

| 遮断 | v_mse | v_sign | turn 1〜4 |
|---|---|---|---|
| なし（r1） | 0.531 | 0.806 | 0.714 |
| 関係 R をゼロ | 0.574 | 0.789 | 0.781 |
| 相手デッキ知識をゼロ | 0.637 | 0.766 | 0.890 |
| 両方ゼロ | 0.751 | 0.727 | 1.069 |

r1 は両方に依存して育っている（特に序盤は相手デッキ知識）。ただし訓練に使った入力をゼロにするのは
分布外なので、「無くても同じ強さに育つか」は段 2 で確かめる。

## 段 2: 訓練して落とす（同じ教材・同じ手順・r1 との直接対決）

| 名前 | 何を落としたか | 訓練 |
|---|---|---|
| a1 | 関係 R（`n_rel_train.py --ablate rel`・forward の入口で遮断・npz の meta に焼き込み serve でも遮断） | r1 と同じ（π＋z＝波23〜24・epochs 2・lr 5e-4・hidden 192・best ep0） |
| a2 | 相手デッキ知識（`--ablate opp_pool`） | 同上 |
| c12 | 構造ごと（c10 を同じ教材で warm-start 再訓練・`n_eff_train.py`・lr 2e-4） | 教材だけで c 系譜が伸びるかの対照 |

3 本は r1 と同じ逐次手順で 3 セッション並列（1 本の訓練を複数セッションに分けると手順が変わり
切り分けにならない。4 スレッド化も効果なし＝1 シャード 276s→272s）。

## 読み

- **効いたのは構造**。c10 と同じ教材で再訓練した c12 は r1 に 0.430 で負け、R と相手デッキ知識を
  落とした a1・a2 は r1 と区別がつかない。設計計画（`docs/n_attention_plan.md` §2.2／§2.4）で
  「型 A（減算＋しきい値の組）」と「相手の動きの想像」に置いた 2 つの仕掛けは、価値の当てはまり
  （評価帯）にはわずかに効くが、対局の強さには出ていない。
- 一致率の差が小さかった（r1 0.355 vs c10 0.322）ことと整合する: 組を読む機構が効いたのではなく、
  盤面の見え方が良くなった分が勝率に出た。
- R の一致率への効果（h2〜h4 の PLAY）は a1 の一致率が出れば分かる（計測中・台帳に追記）。

## 判断材料（ユーザへ）

1. **出荷既定**: 強さは r1 ≒ a1 ＞ c10。レイテンシは a1 1.67 倍・r1 1.83 倍（関門 1.3 倍は未達）。
   a1（R なし）を採れば serve コードから関係の計算を外せる。
2. **次の改良の向き**: R をさらに作り込む方向ではなく、状態 S（枠ごとの実値）の充実と、
   序盤に効いた相手デッキ知識を「強さに変換する」教材（序盤の分岐が勝敗に効く局面）が候補。
3. **生成役の交代（era6）**: r1 または a1 を生成役に波25 以降を作るか。
