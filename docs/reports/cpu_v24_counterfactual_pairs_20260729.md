## 4. 本 v24 の主産物: 失敗の形が示すもの

**m1@3 と m4@2 は同じ「イワンコフ（ST30-004）を出す」手**で、レフェリー裁定は逆
（m1@3=出すのが正着・防御文脈／m4@2=出さないのが正着・turn1）。cf 教師で学習した結果:

- m1@3（マージン薄の**正しい**展開）→ 出さなくなった（1.00→0.12・退行）
- m4@2（マージン −0.38 の**誤った**展開）→ まだ出す（0.00 のまま）

つまり value は **deploy という方向を1本の軸としてしか動かせず、文脈（どの盤面でどのキャラを
出すか）で条件付けできない**。因果ラベルは正しく作れても（§1）、それを吸収する側の表現が
「出す=良い/悪い」の一律シフトしかできないため、**薄いマージンの正着から先に壊れ、
厚いマージンの誤着は最後まで残る**。エコー遮断だけの B も同型のシーソー（m5@7↑ m1@42↓）。

**結論: ボトルネックは v19 までの「ラベルの種類」から「表現の容量/条件付け」へ移った。**
v23 は「特徴追加単独では反転しない見込み」と書いたが、正確には
**「相関ラベルの下では特徴追加は無力・因果ラベルの下では特徴が律速」**——両方が要る。

付随して、cf 教師は付与/攻撃系の点（m2@44・m4@8）には bar 超〜bar 近傍の改善を出しており、
**方向づけとしては機能している**（教師の情報が無効なのではない）。

## 5. 次の一手（v25 候補）

1. **特徴設計 × 反実仮想ラベルの併用**（本命）: 展開判断を文脈で条件付けできる特徴
   （例: 出すキャラの盤面文脈適合＝防御が要る局面か・テンポが要る局面か、
   出す対象の効果種別と現局面の噛み合わせ）を encoder に足し、**cf コーパスで学習**する。
   ユーザが当初求めた「2（特徴設計）」に、v24 で得た因果教師と実証根拠を接続する形
2. 安価な代替として **within-point 順位損失**（v12.1 の機構再利用）: 同一親の子盤面ペアの
   順位のみを教える＝絶対値の全域シフトを起こしにくい。ただし表現が同じなら
   文脈判別の限界も同じ＝1 の補助と位置づける
3. cf コーパスの増産は単独では非推奨（96局で方向シグナルは十分取れており、
   吸収側が律速というのが本測定の結論）
