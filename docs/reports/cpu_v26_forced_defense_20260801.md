# v26 ε強制防御 — 失敗と、防御矯正プログラム全体の診断（2026-08-01）

スナップショット（追記・改変しない）。前提: `defense_cf_phase1_20260730.md`、
`defense_cf_phase2_20260731.md`、`cpu_v25_dense_regen_20260731.md`（§3 の正誤表を含む）。

## TL;DR

- **ε強制防御は失敗**。1,024局 / 124,889行を生成（守る手を確率0.6で強制＝訪問分布を無視）、
  3腕とも**アリーナ一次スクリーンで棄却**（0.375 / 0.425 / 0.350・合算 46/120 = **0.383**）。
  守り採択率も **0.289 → 0.297**（誤差内）＝機構は動かなかった。
- **機序が判明**: 一様ランダムな強制防御は**下手な防御**を大量に含むため、
  「カウンターを持っていること」と「勝つこと」の相関を壊す
  （corr(手札カウンター, z) = **+0.090 → +0.021**）。つまり本コーパスは value に
  「カウンターは勝敗に効かない」と教えており、**元より悪い**教師だった。アリーナ 0.383 と整合。
- **policy prior も律速ではない**（新規診断）: prior を一様にしても守り採択率は
  0.289 → 0.303 にしか動かない。**value 教師でも prior でも防御決定は動かない**。
- **そもそも矯正すべき差が小さい**（本セッション最大の再解釈）: 計器修正後の実測は
  gen8 **0.289** / 人間 **0.356**（45窓）。差は 45窓中およそ **3窓**で、
  「CPUは守らなすぎる」という前提を支えるほどの効果量が無い。防御矯正プログラム
  （v24 CF・v25 密再生成・v26 ε強制）は**弱い標的を3度追った**というのが総括。

## 1. 実施内容

`p3_loop._forced_defense_index`（v26・実装は本 PR）: 防御窓で確率 ε のとき訪問分布を無視して
「守る手」から一様抽選する。policy 教師（visit）は探索の訪問分布のままで、value ラベルが付く
**状態分布だけ**を「守った世界」へ広げる設計（v12 の policy 微調整有害の知見と両立）。
ε=0 で挙動不変・乱数も引かない（既存コーパスとの rng 消費順互換）。

| 項目 | 値 |
|---|---|
| コーパス | nami:shanks・ε=0.6・**1,024局 / 124,889行**・v6符号化・生成ネット gen8(v6恒等拡張) |
| 分布の新規性（走行中モニタ） | 手札カウンター保有平均 **0.078**（v25 = 0.115・**-32%**）＝狙いどおり切られている |
| 腕A | v26 単独（124,889行） |
| 腕B | v26 + v25（369,433行） |
| 腕C | v26 + v25 + 防御CF（369,871行・distill 0.3） |

## 2. 判定

| 腕 | アリーナ screen（40局・vs 出荷gen8） |
|---|---|
| A（v26単独） | 0.375 |
| B（v26+v25） | 0.425 |
| C（+防御CF・distill0.3） | 0.350 |
| **合算** | **46/120 = 0.383**（SE 4.4pp → 五分から -2.7σ） |

守り採択率（45人間窓×8seed=360判定・版整合の計器）: 腕B **0.297**（gen8 0.289・人間 0.356）。

**分布の新規性は作れたが、方向が有害だった**——v16/v19 の勝ちパターン（密度×新規性）の
反例。新規性は必要条件であって十分条件ではない。

## 3. 機序（なぜ有害だったか）

コーパス内の「手札カウンター保有」と勝敗の関係:

| コーパス | corr(手札カウンター, z) | カウンター0枚の z平均 | 1枚以上の z平均 | 差 |
|---|---|---|---|---|
| v25（ε=0・通常生成） | **+0.090** | -0.228 | -0.025 | **+0.203** |
| v26（ε=0.6・強制防御） | **+0.021** | -0.139 | -0.025 | **+0.115** |

通常生成では「カウンターを持っている＝勝ちやすい」という（弱いが正しい向きの）信号がある。
ε強制はこれを**半減させた**。理由は明快で、強制抽選は「守るべき場面かどうか」を一切見ずに
一様に守るため、**下手な防御（無意味な場面でのカウンター消費）が大量に混入**し、
「カウンターを失った状態」と「負け」の結びつきが薄まる。

言い換えると: 欲しかった信号は「**適切な場面で**守ると勝つ」だが、一様強制が与えるのは
「守る/守らないと勝敗は無関係」。フェーズ1の反実仮想（CF）測定はこの点で正しかった
（同一局面内で選択肢を比較する＝場面の適切さを保持）が、438行しか作れず力が無かった。
**正しい信号は高コスト、安い信号は誤り**という構図が本プログラムの根本的な壁。

## 4. 追加診断: policy prior は律速か（新規・`/tmp/prior_bound_probe.py` 方式）

`dense_finetune` は policy を学習せず gen8 のコピーを載せる（v12 の知見）。
「守らないのは prior が PASS に張り付いているからでは」を直接測った:

| 条件 | 守り採択率 |
|---|---|
| gen8（prior あり＝通常 serve） | 0.289 |
| gen8（**prior 無し＝一様**） | 0.303 |
| 人間（同窓） | 0.356 |

prior を完全に外しても 1.4pp しか動かない＝**prior は律速ではない**。
value 教師（v24/v25/v26）でも prior でも動かないということは、防御決定は
**探索が評価する子盤面の相対順序**として頑健に「PASS 優位」になっている。

## 5. 総括と再解釈（次の判断材料）

1. **標的の効果量が小さい**。計器を直した後の実測は gen8 0.289 / 人間 0.356＝45窓で約3窓差。
   ユーザ自身のレビューも m2@32「守っても良い場面であったとは思います」（＝断定していない）、
   m2@48「素通りしない攻撃なのでパスで正解」（＝CPU が正しい）であり、
   「守らなすぎる」という当初の見立てを支える効果量は、この計器では確認できていない。
   **防御矯正はいったん打ち切り、より効果量の大きい標的へ移すことを推奨する。**
2. 一方 **v25 防御混合腕がコーチゲート v3 で PASS**（改善 6.1 vs 4.7・退行ゼロ）した事実は残る。
   人間検証14点で測れる改善は実在し、アリーナ総合（-3〜5pp）とトレードオフになっている。
   次に投資するならこの**トレードオフの正体**（14点で良くなる手が自己対戦分布で損をする理由）。
3. 手法上の教訓: **分布の新規性は方向を持つ**。「見たことのない状態を見せる」だけでは足りず、
   その分布の中で**目標の量と勝敗の相関が保たれている**必要がある。生成側の介入は
   corr(目的の特徴, z) を生成中に監視すべき（本 PR の `hand_counter_mean` はその第一歩だが、
   相関そのものを出す方が有効）。
