# v20 — 未解決点の prior/value 分解: 「prior は犯人ではない」と第3の機序の発見（2026-07-29）

gen8 採用レポート §5 の問い「VERIFIED v2 の改善ターゲットが value 較正2周（gen7・gen8）でも
0.00 のままなのは policy prior が候補を沈めているからか、value が差を感じないからか」を
直接測定した（`tests/scripts/prior_bound_probe.py`・読み取り専用）。
スナップショット（追記・改変しない）。

## 1. 測り方（4列・すべて現既定 gen8・製品コード無改変）

真盤面復元（`state_at_action`）＋レフェリー検証済み accept 集合に対し:

| 列 | 内容 | 何の証拠か |
|---|---|---|
| `prior 質量 / 順位` | 合法手上の policy prior のうち accept 集合が占める確率質量と最良順位 | **探索を介さない一次証拠**＝候補として見えているか |
| `dv` | accept 最良手 − 非accept最良手の**着手後 value** 差 | 1手先 value が正着を上に見ているか |
| `deep` | sims 160→1600 の accept 率 | 探索の浅さが原因か |
| `flat` | prior 一様化での深探索 accept 率 | policy 起因の分離（mark_deep_probe と同機構） |

## 2. 結果（13点・gen8）

| 分類 | 件数 | 点 |
|---|---|---|
| OK（現既定で正着） | 5 | m1@3, m1@14, m1@15, m1@42, m2@58 |
| **PRIOR_BOUND** | **0** | — |
| EXPLORABLE（探索の浅さ） | 1 | m2@12 |
| **VALUE_BLIND**（value が正着を下に見る） | 4 | m2@64, m2@66, m4@2, m4@8 |
| **SEARCH_AVERSE**（第3の機序・下記） | 3 | m2@44, m4@12, m5@7 |

### 2-1. prior は犯人ではない（本 v20 の主結論）

accept 集合の prior 質量は未解決点でも **0.28〜0.74**、順位は 1〜4 位が大半。
唯一薄いのは m2@64（0.08・10位）だが、そこは dv=−0.27 と value も明確に誤っており、
`flat`（一様prior 深探索）でも 0.00＝**policy を外しても解けない**。
**「policy prior が正着を沈めている」という仮説は棄却**された。
v12 以来の「policy には触らない」方針は正しく、次の打ち手を policy 側に置く理由は無い。

### 2-2. VALUE_BLIND 4点 — value が符号レベルで逆

| 点 | dv | 内容 |
|---|---|---|
| m4@2 | **−0.42** | turn1 イワンコフ出しを value が強く支持（人間・レフェリーは TURN_END） |
| m2@64 | −0.27 | クマシー出しを攻撃より上に見る |
| m4@8 | −0.11 | イワンコフへの付与をリーダー付与/攻撃より上に見る |
| m2@66 | −0.09 | 攻撃しないほうを上に見る |

いずれも**低コストキャラの展開・そこへの付与を過大評価**という一貫した形。
密ラベル2周（gen7・gen8）で動かなかったのはこの符号を反転させられていないため。

### 2-3. SEARCH_AVERSE 3点 — prior も 1手先 value も支持するのに深探索が離れる

| 点 | prior 質量/順位 | dv | base/deep/flat |
|---|---|---|---|
| m4@12 | 0.74 / **1位** | +0.15 | 0.00 / 0.00 / 0.00 |
| m5@7 | 0.64 / **1位** | +0.05 | 0.20 / 0.00 / 0.00 |
| m2@44 | 0.29 / **1位** | +0.02 | 0.00 / 0.00 / 0.00 |

**prior が1位に置き、1手先 value も正の差を付けているのに、sims を10倍にしても選ばない**。
探索の多手先の読み（相手応答後の評価の積み上げ）が、正着から系統的に離れている。
prior でも 1手先 value でもない**第3の機序**として本報告で初めて分離した
（分類 `SEARCH_AVERSE` を計器に追加・`tests/test_prior_bound_probe.py` で境界を固定）。

## 3. 含意（次に何を教えるか）

1. **policy 側の打ち手は不要**（PRIOR_BOUND 0件）。v12 の凍結方針を継続する
2. **VALUE_BLIND 4点は「低コスト展開の過大評価」で一貫**。ここは教師の量ではなく
   **教師の種類**（展開の損得が結果に効く局面を狙って集める／特徴で手札消費を表現する）の問題。
   密ラベルの汎用周回でこれ以上動く見込みは薄い
3. **SEARCH_AVERSE 3点は探索/読み出し側**。root 読み出し（二重ゲート則）・終局減衰・
   相手応答モデル（防御温度）のいずれかが疑わしい。**1手先 value と多手先探索の不一致**を
   直接追える計器（各深さでの Q 推移）が次の診断に要る
4. 「深探索で解ける（EXPLORABLE）」は 13点中 1点のみ＝**深探索再ラベルは今の主戦場ではない**

## 4. 計器としての注意

- `dv` は 1手先（着手直後の子盤面）の葉評価であり、探索を経た評価ではない。
  SEARCH_AVERSE はまさにこの2つの乖離を捉えた分類なので、`dv` 単独を「value の正しさ」と
  読まないこと
- `flat` は prior を一様にするだけで探索構造は変えない。`flat` が立ち上がらないことは
  「policy が原因でない」ことの証拠にはなるが、「value が原因」の証明ではない（SEARCH_AVERSE の
  存在がその反例）
