# 条件を読んだ——**過大の向きは正しかったが、配線した経路では偽が 1 件も無かった**

2026-09-14 実施。§0.5 の順序 2「**条件（`ab["condition"]`）を読む**」。
ユーザ確認「**効果は条件＋コスト＋アクションの要素で考えるという認識で良い？**」への回答込み。
本報告は特定時点のスナップショット（追記・改変しない）。

## 結論を 6 行で

1. **認識は合っている**——`Ability = 契機 + 条件 + コスト + 実行内容`（`effect_types.py`）。
   **ただし条件は足す項ではなく掛かる側**: `価値 = P(条件) × (Σ実行内容 − Σコスト)`。
2. **起動メインは割り引いてはいけない**——エンジンは `has_activatable_main` で
   **条件・ターン回数・コスト充足・空振りでないこと**を確かめてから候補に出す。
   **一律に割り引くと、エンジンが検査済みの能力の 36.6% を潰していた**（実測）。
3. **条件は確率ではなく述語として解いた**——記録は判断点の状態を持っているので、
   **成立率を推定せずにその場で真偽を決める**。判定はエンジンの `effects/cond.rs` を写した。
4. **実測: 配線した経路で偽は 0 件**（判定できた 4,951 件すべて真・判定できず 1,681 件）。
   **真の 4,729 件は `LEADER_NAME`**＝**そのリーダーのデッキに入っているカードだから当然成立**。
5. **橋は動かない。しかも上限・下限の両方で動かない**——判定できなかった分を
   **全部偽と置いても** 1 手あたりの傾きは **4.475 → 4.388**（CI が重なる）。
6. **「プール全部で測ると 66% が偽」は母集団の誤り**——値を使う母集団は
   **「その時手札に在るカード」**であって「全カード」ではない（`measurement.md` の罠 26）。

## 1. 条件はどこで効きうるか——3 か所を分けて数えた

| 値の使いどころ | 条件の扱い | 実測 |
|---|---|---|
| **起動メインの候補**（6,080 行） | **`P = 1`**（エンジンが検査済み） | 一律割引なら **36.6% が偽**になっていた＝過小への振れ |
| **体なしカードの登場**（13,081 候補） | **状態から判定**（`PLAY` の合法性はコストだけ） | **偽 0 件**（下記） |
| **キャラの登場** | **効果を別項で足していない**——実測の `ν` の中に入っている | 足すと二重計上（T16 の罠） |

> **キャラの登場に効果の項が無いのは手抜きではない**——`ν = 0.1087` は
> **登場したキャラの限界価値を棋譜から測った値**なので、**平均的な登場時効果は既に入っている**。
> 上に効果を足すと同じものを 2 回数える（T16 が「勘定は複数の仕方で閉じられる」と言って
> 止まった形）。**正しい形は「平均からの差」を足すこと**で、それは別の作業になる（§4）。

## 2. 体なしカードの登場——**偽が 1 件も無い**

実デッキ 300 局・自席 main 行・候補ごとに条件木の葉を判定した:

| | 件数 |
|---|---|
| 体なしカードの `PLAY` 候補の評価 | **13,081** |
| そのうち条件を持つ能力 | **6,632** |
| **真** | **4,951** |
| **偽** | **0** |
| 判定できず | 1,681 |

**葉の内訳**:

| 葉 | 真 | 判定できず |
|---|---|---|
| **`LEADER_NAME`** | **4,729** | — |
| `DON_COUNT` | 222 | 114 |
| `FIELD_COUNT`（絞り込み付き） | — | **1,567** |

**`LEADER_NAME` が真なのは構造的**——**そのカードはそのリーダーのデッキに入っている**ので、
「自分のリーダーが〇〇なら」は**必ず成り立つ**。**これはゲームの事実であって偶然ではない。**

> **エンジンが濾しているのではない**ことも確かめた——`event_has_main_play_state` は
> **契機の種類だけ**を見て条件を見ない（`rules/actions.rs:194`）。
> つまり**エンジンは条件が偽のイベントも候補に出す**が、**実際には偽の行が出てこなかった**。

## 3. 橋（§0.5 の受け入れ基準）——**上限も下限も動かない**

実デッキ 300 局・`--silent exclude`・`Θ = 1.15`。**`--cond-unknown` は判定できなかった
条件の扱い**（1.0＝割り引かない＝上限／0.0＝全部偽＝下限）:

| 帯 | 上限（`1.0`） | **下限（`0.0`）** |
|---|---|---|
| **全体** | +4.475 [3.49, 5.64]・AUC 0.710 | **+4.388 [3.40, 5.52]・AUC 0.707** |
| 接戦 | −1.659 [−3.24, +0.18] | **−1.644 [−3.19, +0.18]** |
| 中盤 | +0.940 | **+0.939** |
| 決着 | +2.144 [1.44, 2.84] | **+2.114 [1.41, 2.81]** |

**幅が 2% 以下**＝**この穴は結論を動かさない**。§0.4 の感度の規則により**優先度は低い**。
**点推定だけでなく下限でも動かないこと**を示したので、「まだ測っていないから判らない」ではなく
**「埋めても動かない」と言える**（罠 22 を避けるため、狭い幅であることを明示して読む）。

## 4. 器（`condition_value.py`）——**規則を発明していない**

**正本は `rust/opcg_engine/src/effects/cond.rs`**。写したもの:

| 写した規則 | 中身 |
|---|---|
| `compare` | `EQ/NEQ/GT/LT/GE/LE`・**`HAS` は常に偽** |
| `offset_threshold` | 「相手より N 枚以上 少ない/多い」＝**`LE/LT` は引く**・他は足す |
| `TURN_COUNT` | **手番プレイヤー自身の第 N ターン**（`(turn_count + 1) // 2`） |
| `FIELD_COUNT` | **ステージも数える**（`field.len() + stage.is_some()`）。**絞り込み付きは判定しない** |
| `DON_COUNT` | `active + rested + attached`。**付与ドンが記録に無い**ので**区間で判定** |
| `CONTEXT` | `MY_TURN/SELF_TURN`・`OPPONENT_TURN` だけ見て**他は真** |
| `TURN_LIMIT` | **常に真**（回数は解決側が守る） |

**母数はエンジンの `ConditionType`＝42 メンバ**（動作 62 種と同じ作法）。
**3 値で返す**（`True`／`False`／**`None`＝判らない**）——ここを 2 値に潰すと
「成り立たない」と「判らない」が混ざって**値が黙って 0 になる**。

**状態は記録だけで作れる**——`scalars` の列（ライフ・ドン・手札・場・ターン・手番・
デッキ÷50・トラッシュ÷20）と、**`card_idx` の 0/1（両リーダー）・22/23（ステージの有無）**。

## 5. 母集団の誤り（`measurement.md` の罠 26 へ）

**同じ条件を 2 通りの母集団で測ったら 66% 対 0%** になった:

| 母集団 | 偽の割合 |
|---|---|
| **同梱カード全部**（3,386 能力のうち `ON_PLAY` の条件付き 297） | **66.0%** |
| **実際に手札に在って候補になったカード** | **0%** |

**差の正体は `LEADER_NAME`／`LEADER_TRAIT`**——プール全部で見ると「他のリーダー用のカード」が
大半なので偽が出るが、**自分のデッキのカードでは必ず真**。
**プール全体の率をゲームの事実として読むと、効果の値を 2/3 に切ってしまう。**

> **一般化**: **率を測る母集団は、その値を使う母集団と同じでなければならない。**
> 罠 25（母数を出現から作るな）の裏側——**定義された集合で数えるべき量と、
> 使われる集合で数えるべき量がある。**

## 限界

- **カード単体の値付け（状態が無い）は依然として上限**——選択の利得の `W` はここを使う。
  **状態が無い所では条件を判定しない**と決めたので、**その上限性は設計どおり**である。
- **`FIELD_COUNT` の絞り込み付き 1,567 件は判定していない**（記録に枚数の内訳が無い）。
  **下限で回して動かないことは確かめた**が、個々の値は過大のままである。
- **`HAS_DON` は判定していない**——`ON_PLAY` では出したばかりの体に付与ドンは無いので
  **偽であるべき**だが、**「host が誰か」を記録から決められない**ので `None` に倒した。
  `PASSIVE`／`ON_ATTACK` では 221 件の最大勢力なので、**常在の値付けに進むときに要る**。
- **`threshold_or_raw_text` を写していない**（本文から数を拾う経路）＝int でない値は判定しない。
- **観察であって因果ではない**（§0.3 の限界はそのまま）。
