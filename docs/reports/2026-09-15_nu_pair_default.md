# `ν` の既定を `pair` にした——**ユーザ決定・式の水準が全帯で動く**

2026-09-15 実施。ユーザ決定「pair が既定でも良いかもね」（同日の `2026-09-15_shield_kop_pair.md`
§4 の推奨に対する判断）。本報告は特定時点のスナップショット（追記・改変しない）。

## 何を変えたか（3 行）

1. **`theory_order.NU_MODE` を `"base"` → `"pair"`**——`ν = (攻撃 + ブロック + 身代わり) × (1 − ko_p(パワー))`
   が既定。**`base`（身代わりなし・`ko_p` 定数 0.289）は旧い形として残す**。
2. **CLI は既定を別に持たない**——`theory_bridge --nu-mode`・`nu_measure --nu-mode` は**省略時に
   `theory_order.NU_MODE` を使う**（正本は 1 つ）。`nu_measure` は出力に `nu_mode_effective` を刻む。
3. **旧い式の主張を固定していたテスト 3 本を書き直した**（下記）。**新しい定数はゼロ**。

## 何が動くか——**過去の数字との比較に注意**

**2026-09-15 より前の全測定・全報告の `ν` は `base` で出ている。** 既定が動いたので、
**前後の数字を並べるときは `--nu-mode base` を明示する**。明示しないと、
**変えていない量まで動いて見える**（既定の変更を挟んだ比較の罠）。

既定で引いた `ν` の代表値（相手リーダー 5000・`R` = 4.128・非ブロッカー）:

| 帯 | 旧既定（`base`） | **新既定（`pair`）** | 実測 |
|---|---|---|---|
| リーダー未満（3000） | 0.0000 | **0.0431** | 0.0690 |
| リーダー〜飽和（6000） | 0.1617 | **0.2030** | 0.1503 |
| 飽和超え（9000） | 0.1860 | **0.2313** | 0.2112 |

**中盤帯の +0.053 超過はそのまま持ち越す**（当てはめて消さない・前報 §2）。

## 書き直したテスト（旧い主張 → 新しい主張）

| テスト | 旧 | **新** |
|---|---|---|
| `test_nu_calib::..._is_the_default` | 既定は `base` | **既定は `pair`**・明示せず呼んだ値が `pair` と一致（黙って戻ったら落ちる） |
| `test_nu_calib::test_nu_is_zero_block_for_a_non_blocker` | `base` でだけ検査 | **両形で回す**（差はブロック項ぶん・違うのは割り引く `ko_p` だけ） |
| `test_nu_measure::..._the_band_the_formula_zeroes` | 「リーダー未満は 0」 | **`base` は 0・既定は 0 を脱する**（`predict(mode=)` を素通し） |
| `test_nu_measure::..._every_below_leader_kind` | 「素性によらず 0」 | **`base` は 0・既定は素性によらず同じ正の値**（身代わりは素の体が持つ＝T21） |

**「リーダー未満は 0」はもともと T21 が実測で否定した主張**（素の体が 0.0753・CI が 0 を含まない）
なので、**テストが固定していたのは式の欠陥だった**。新しいテストは**両方の形を名指しで**固定する。

## 限界

- **既定の変更は測定を 1 つも増やしていない**——前報の橋（攻め側 +69%・中盤 `bridge_holds`・
  守り不動）と勘定（中盤 +0.053 超過）が判断材料の全部。
- **`ko_p` の帯（絶対パワー）と身代わりの帯（相手リーダーとの差）の境目は揃っていない**（前報の限界）。
- `nu_measure` の「式は両半分に同じ予測」等、**`ν` を使う下流の計器は全部値が動く**——
  次に回すとき、差が「既定の変更」か「その計器の変更」か分けるために `--nu-mode base` の対照を添える。
