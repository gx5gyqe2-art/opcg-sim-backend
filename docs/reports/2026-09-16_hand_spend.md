## 結論を 5 行で

1. **手札の中身は記録に既に在った**（枠 12〜21 の `card_idx`＝行の主の手札）。P8 の記録拡張を待たずに測れた。
2. **定義**: 札の価値 `v` = 使ったときの価値（μ を除く）= max(出す: `ν(P)` + 登場時効果 − コスト·δ, イベント: 効果 − コスト·δ, 0)。手札の価値 = Σv。
   守りで「払った額」= 実際に消えた札の `v` の和。μ はこの `v` の平均（中央値 0.0554 ≈ μ・独立に一致）。
3. **切る札は手札の中でやや安い札だが、最安ではない**: 順位の平均 0.45（0 = 最安・0.5 = 無作為）・最安 4 分位に 36〜41%（無作為なら 25%）・
   切った札の `v` は手札平均の 0.78／0.69 倍。**枚数 × μ との比は実 1.03・合成 0.62**（実デッキでは平均としては合っていた）。
4. **帳簿を「実際に消えた札の価値」で読むと、守り側の橋が返る**: `ΔG` の守り側 AUC **0.276 → 0.602（実）／0.429 → 0.574（合成）**・
   接戦帯 **0.328 → 0.641／0.467 → 0.566**・全体 0.879 → 0.908／0.874 → 0.880。攻め側・`ΔS` は定義上不変。
5. **`GUARD_COST_MODE=spent` を既定に**（帳簿の「払った額」を式の近似から記録の実額に戻しただけ・理論の定数は増えない）。
   価格の側（攻め手の見積もり `min(c(x)·μ, Θ·μ)`）は据え置き＝切る札の選び方は CPU の打ち筋（最安を選ばない）で、式に入れない。

## 3. 読み方

- **ユーザの指摘どおり**: 守りの窓で効いているのは枚数ではなく「どの札を切ったか」。式の近似（`c(x)·μ`・`Θ·μ`）を実額に替えただけで、
  T62/T63 で 3 形試しても動かなかった守り側が両記録で順向きに返った。**接戦帯が一番動いた**（0.33 → 0.64）＝守りの窓の差が勝敗を分ける帯。
- **切る札の選び方は最安ではない**（順位 0.45）。これは記録の CPU の打ち筋で、価格の側（攻め手の見積もり）には入れない（ユーザの原則）。
  実デッキでは Σv ≈ 枚数 × μ（1.03）なので、攻め手の見積もりとしての `c(x)·μ` は平均では正しい。合成デッキは 0.62（札が安い）。
- **μ の位置づけ**: μ は `v` の平均であって、1 枚ずつの価値は帯（0〜0.2）で散る。帳簿は実額で、価格は平均で持つ＝T58 の「決める価格と
  数える価格」の切り分けと同じ形。
