## 結論を 5 行で

1. **定義**: `H(手札, 状態) = max_計画 Σ_t s^t Σ_{t に出す札} v(札)`（今・次・その次のドン + 「それより後」の枠・各札 1 回・厳密 DP）、
   `ΔH(札) = H(手札 ∪ 札) − H(手札)`。**出せない札は 0・コストの穴を埋める札は満額**＝「必要な札」がそのまま数になる。
2. **引いた札の `ΔH` は 0.040／0.031**（μ 0.055 より低い＝計画は出す用途しか数えない・守る用途は別）。`ΔH` が 0 の引きは 27%／36%。
3. **探して手に入れた札の `ΔH` は 0.032／0.035 ＝ 引いた札と同じか低い**（差 **−0.008／+0.003**）。静的 `v` の差（T65: −0.005／+0.021）と同じ結論で、
   計画の穴で見てもサーチは引きに勝っていない。
4. **ただし札ごとの差は大きい**: プリン（4 枚見て「サンジ」かイベント）は `ΔH` 0.056（引き +0.015・0 は 1%）、**ウタ（5 枚見て赤髪海賊団）は
   `ΔH` 0.017（引き −0.024・0 が 55%）**——静的 `v` は 0.087 と高い（大きい体）のに計画には入らない＝**出せない大物を探している**。
   合成でも OP05-114 +0.068・OP03-110 +0.025 対 ST18-004 −0.021・EB02-028 −0.028。
5. **読み**: 「必要な札を集める」は `ΔH` で書ける（定数なし）。実測で利得が無いのは、記録の CPU（r3）が**計画に入らない札を選んでいる**ため
   ＝理論ではなく CPU の探し方の弱点（改善の手掛かり）。価格の側では「その探しで取れる札のうち `ΔH` 最大」（デッキから数える）を
   決める価格に、実際に取った札の `ΔH` を数える価格に置く形が筋（T58 の option／exercise と同じ切り分け・ユーザ判定待ち）。

## 3. 読み方

- **`ΔH` は「今この手札に必要か」を数える**: 同じ札でも、次のターンに出せる札が無い手札に来た低コストの札は満額、既に大物が並ぶ手札に
  来た大物は 0。静的 `v` では見えなかった「出せる札が在るか」がここに入っている。
- **サーチが引きに勝てていないのは、探し方の側**: ウタは特徴で 5 枚から選べるのに、計画に入らない大物（`v` は高い）を取る行が半分。
  価格が `v`（静的）で最良を選ぶ前提を置いているのと同じ誤りを CPU がしている可能性が高い。プリン型（イベントか小物）は計画を増やす。
- **理論への写し**: 探す能力の価格 = 「その探しで取れる札の集合（絞り込み・デッキから数える）のうち `ΔH` 最大」− `ΔH`(引き)。
  定数なし。実デッキで測れば、ウタ型は「取れる札に小物が在れば正、無ければ 0」に、プリン型は正になる見込み。

## 4. 次（ユーザ判定）

1. 探す能力の価格を **`E[max_{取れる札} ΔH] − E[ΔH(引き)]`** に置き換える（デッキの絞り込みに合う札から数える・`sel(k)` を捨てる）。
2. 帳簿（数える価格）は実際に取った札の `ΔH`（T58 の exercise と同じ）。
3. `PLAY_CARD`（手札から出す効果）の「出せる札が在るか」も `playable`（枠 12〜21・コスト ≤ ドン）で読める＝満額の価格を確率に。
