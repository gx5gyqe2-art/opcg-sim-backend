# 固定4デッキの対面バランス実測（v18・新規マーク採取の対面選定・2026-07-28）

ユーザ提供の実デッキリスト4種（ナミ/紫エネル/青緑ルフィ/シャンクス・
`tests/fixtures/decks/user_decks_20260728.json`）の全6対面を、**gen7 同士**の CRN ペア
（同 seed・席入替・24ペア=48局/対面）で計測した（`tests/scripts/matchup_balance_probe.py`）。
目的: コーチゲート後継のマーク採取を**互角の対面**で行うための事前選定
（v16/v17 の教訓＝一方的対面のマークは飽和局面に落ち教材にならない）。
スナップショット（追記・改変しない）。

## 読み

1. **注意: これは「デッキの強さ」でなく「gen7 が運用したときの強さ」**。マーク採取の対面選定には
   まさにこの量が正しい（マークが付くのは CPU の決定）が、デッキ固有の強弱とは分離できていない
2. **紫エネルの 0.02（対シャンクス）は異常に低く、gen7 の系統的な運用不全を強く示唆する**。
   紫エネルはドン経済（ドン!!-X コスト・ドンデッキ6枚・リーダー起動での再チャージ）という
   特殊資源管理のデッキで、この決定タイプは学習データにほぼ現れてこなかった。
   効果実装は検証済み（新エネル=検証済み5種）なので、エンジンバグより CPU の意思決定の問題が濃厚。
   **gen7 の「次の弱点」の具体的な候補**として記録する（トレース診断は別途）
3. ナミが自然デッキ相性以上に強く見える可能性もある（gen7 の学習履歴はナミ系の局面が最も厚い＝
   g3 レフェリー・マーク採取の中心だったため）

## マーク採取への推奨

- **主対面: ナミ vs シャンクス**（唯一の互角・付与系と防御窓系を両カバー）。CPU に両側を
  持たせた2局（CPU=ナミの局と CPU=シャンクスの局）でマークを付けるのが最効率
- 副対面: ユーザが弱い側デッキを持って腕で釣り合わせる形（例: ユーザ=青緑ルフィ vs CPU=ナミ）
- 紫エネル対面はマーク採取には不向き（飽和局面だらけになる）。代わりに**運用不全の診断対象**とする
