# 第 I 部 ゲームの形

## 1. 定義

ONE PIECE カードゲームは**有限・二人・零和・不完全情報・完全記憶の展開型ゲーム**である。

- **有限**: 盤面・手札・デッキは有限、手数に上限がある（実装も `max_steps` で切る）。
- **二人零和**: 終端利得は `z ∈ {+1, −1}`（引き分け 0）で、両者の利得の和は常に 0。
- **不完全情報**: 各手番で分からないものは**相手の手札の中身・伏せたライフの中身・両者の山の順**。
  観測できるのは公開情報（場・ライフ枚数・手札枚数・トラッシュ・ドン）と自分の私的情報。
- **完全記憶**: 各プレイヤーは自分の観測と行動をすべて覚えている（実装も状態に持つ）。
- **手番は交互**だが、**相手のターン中にも自分の決定点がある**（カウンター窓・ブロッカー宣言）。
  ＝同時手番ではない。すべての決定点は情報集合として一列に並ぶ。

**情報集合**: 自分が区別できない状態の集まり。カウンター窓での情報集合は
「相手の手札の中身と伏せライフの中身が違うだけの盤面」の束であり、**その大きさが打ち回しの難しさ**。

## 2. 零和から出てくること（前提として使っていい）

1. **ミニマックス値が存在し一意**（有限零和・完全記憶）。「正しい評価」という言葉に意味がある。
2. **`V` は反対称**: 同じ盤面を自席から見た値と相手席から見た値は `V_me(s) = −V_opp(s)`。
   **これは学習した V が満たすべき制約で、まだ一度も検査していない**（§25 の宿題 1）。
3. **相手は最善応手を打つと仮定してよい**（ユーザ指摘 2026-08-05）。零和では「相手が間違えてくれる」
   ことに期待する戦略は、正しく打つ相手に対して損。**窓の畳み込みはミニマックス**が正しく、
   訪問数による混合（PUCT の平均）は**保険ではない**——混合すると「相手が下手を打つ確率」を
   勝手に入れたことになる。実装は窓をミニマックスで畳んでいる（`docs/rust_engine_plan.md`）。
4. **自分の利得最大化 ＝ 相手の損失最大化**。攻め側の物差しを「相手に払わせた量」で書いてよい
   （第 III 部の `force`）。

## 3. 不完全情報から出てくること（ここが今の設計の弱点）

1. **最適戦略は一般に混合（確率的）**。純戦略（決定論）しか持たない打ち手は、
   **適応する相手に読まれる**。本エンジンは serve で決定論（同じ盤面・同じ seed なら同じ手）。
2. ただし**固定の相手に対しては純な最善応手で足りる**。つまり
   - **自己対戦アリーナ（両者が同じ固定方策）では、この弱点は原理的に観測できない**。
   - **人間（適応する相手）と打つときだけ損が出る**。
   ＝**アリーナの Elo は「読まれやすさ」を測っていない**（§21 の測定限界）。
   本シミュレータの用途は人間との対戦なので、**この穴は実害の側にある**。
3. 読まれやすさは量になる: 公開状態から自分の行動がどれだけ当てられるか
   ＝**条件付きエントロピー `H(行動 | 公開状態)`** と、単純な予測器の的中率。
   0 に近ければ完全に読める（§25 の宿題 2・計器 `policy_entropy.py`）。
4. **情報を与える／隠す行動がある**（カウンターを切る＝手札の中身を明かす・伏せライフの
   トリガーは公開される）。シグナリングの利得は本書では扱わない（未定式化）。

## 4. 公平性の規約（どこまで見てよいか・ユーザ決定 2026-09-04）

**相手の手札の中身は使わない**。**未見プール**（相手の手札∪山∪伏せライフの合計）は
「人間がデッキリストから知りうる範囲」なので入力に使う。相手の山の順・実際の手札は与えない。
＝エンジンは**情報集合の上で**打っており、determinization（§5）はその情報集合からの標本抽出である。

# 第 II 部 探索——PIMC の理論的位置

## 5. PIMC は不完全情報ゲームを解かない（構造的な誤り 2 つ）

本エンジンの探索は **PIMC（Perfect Information Monte Carlo）**: 情報集合から世界を `K` 本引き、
各世界を**完全情報ゲームとして**解いて、根の統計を束ねる。これは近似であって、
**2 つの誤りが原理的に残る**（Frank & Basin 以来の古典的な指摘）:

- **strategy fusion（戦略融合）**: 世界ごとに別の手を選べる前提で価値を作ってしまう。
  実際には**区別できない状態では同じ手しか打てない**。
  ＝「A の世界なら守る・B の世界なら受ける」で得た価値は達成不能。
- **non-locality（非局所性）**: 完全情報の解は「その世界の最善」を返すが、相手の戦略は
  情報集合全体に対して決まるので、ある世界での最善が全体の最適と一致しない。

**本エンジンでどう現れるか**: カウンター窓がまさにこれ。相手の手札が見えている世界では
「止められるかどうか」が確定するので、`K` 本の世界が**それぞれ違う結論**を出し、
束ねた訪問分布は「どの世界でも最善でない手」を選びうる。

**測れる**: `decide` の trace は `worlds>1` のとき **`per_world`（世界ごとの根の N/Q と最善手）** を返す。
- **世界間の最善手の一致率**が低ければ strategy fusion が実際に起きている。
- **束ねた選択がどの世界の最善とも違う**割合は、融合の直接の観測。
（§25 の宿題 3・計器 `pimc_diag.py`）

## 6. PIMC が「それでも上手く行く」条件

PIMC が実用で強い game（ブリッジ等）と弱い game を分けるのは、次の 3 つの性質だとされる
（Long ら 2010 の枠組み）:

| 性質 | 意味 | PIMC に有利な向き |
|---|---|---|
| **leaf correlation** | 末端で「どの世界でも同じ側が勝つ」度合い | 高いほど有利 |
| **bias** | game がどちらかの側に構造的に偏っているか | 偏りが強いほど有利 |
| **disambiguation factor** | 隠れ情報が**どれだけ速く公開情報になるか** | 大きいほど有利 |

**本 game の見立て**（仮説・要測定）:
- **disambiguation は高い**: 手札は打てば公開・ライフのトリガーは公開・カウンターは切れば公開。
  終盤へ向かうほど情報集合は小さくなる＝PIMC が効きやすい方向。
- **leaf correlation は中程度**: 「相手にカウンターが在るか」で勝敗が反転する局面が実在する
  （`c(x)` が手札に依存する＝世界で違う）。**終盤の窓ではここが低い**と予想。
- **bias**: 先手・後手の非対称はあるが小さい（実測は未整理）。

**含意**: PIMC を捨てる必要は無いが、**低 leaf correlation の帯（終盤の窓）でだけ**壊れる。
第 VI 部の F は「その帯を評価で補う」という形になる（探索を置き換えない）。

## 7. 世界数 `K` の検出確率

情報集合の中で「その線が通る世界」の割合を `p` とすると、`K` 本の標本で 1 度でも当たる確率は

```
1 − (1 − p)^K       K=1: p        K=4: p=0.2 → 59%       K=8: p=0.2 → 83%
```

**serve とアリーナは `K = 1`・生成だけ `K = 4`**（2026-09-13 に確認）。
＝**出荷エンジンは、教材を作った生成器より隠れ情報のサンプリングが粗い**。
「どちらにしろ負け濃厚なら最初から無茶をする」（ユーザ 2026-09-12）に要るのは
まさに「2 割の世界でしか通らない線」なので、`K=1` はそれを 8 割見落とす。
測定中（台帳 §6・帯 1031000〜1038000 の 2 腕）。

## 8. 木の混合は保険ではない（§2-3 の実装上の帰結）

PUCT の訪問分布は探索の副産物であって「相手の手のばらつき」ではない。
窓をミニマックスで畳むのは**零和の要求**。ここを平均にすると、
「相手が下手を打つ確率」を勝手に置いたことになる（ユーザ指摘 2026-08-05・実装済み）。

# 第 III 部 資源と価格（予算モデル）

## 9. 交換の恒等式

超過パワー `x` の攻撃に対し:

| | ライフ | 手札 | その他 |
|---|---|---|---|
| **受ける** | −1 | **+1**（ライフカードが手札へ） | トリガーの期待 `+τ` |
| **守る** | ±0 | **−c(x)** | — |

**受けるのは「ライフを失う」ではなく「ライフ 1 枚を手札 1 枚に変換する」**。
ここを落とすと「受ける＝損」という誤った前提が入る（実際に入っていた）。

## 10. 予算

`L` 今のライフ・`T` 決着までの自席ターン数・`A` 相手の 1 ターンの攻撃回数・
`N ≈ A·T` これから来る攻撃数・`B` ブロッカーで止める回数・`H` 手札・`D ≈ T` 引く枚数・
`K_atk` 攻めに要る枚数とすると

```
必ず守る回数   G = max(0, N − L − B)
余裕           S = H + (N − G) + D − K_atk − Σ_{安い G 本} c
```

## 11. **`c̄` はシャドー価格**（本書で初めて明示する読み）

受けた場合と守った場合の `S` を比べると `H` と `(N−G)` が打ち消えて

```
S(受ける) − S(守る) = c(x) − c̄
```

`c̄` は「後で必ず守る G 本」の平均単価。これは **LP の双対価格（shadow price）そのもの**である:
「`G` 回は守らねばならない」という制約に紐づく**手札 1 枚の機会費用**。したがって

- **今の攻撃の単価 `c(x)` が価格 `c̄` より安ければ守る・高ければ受ける**。
- `c̄` は**状態とデッキで決まる価格**であって、固定の定数ではない。
- **「ライフ 3 で守り始める」型の規則は、価格を 1 つの定数で近似したもの**＝原理的に誤り。

3 つの領域:

| 領域 | 条件 | 最適 |
|---|---|---|
| 1 | `G = 0`（全部受けても死なない） | **守るのは純粋な無駄**（`τ` も取りに行ける） |
| 2 | `G > 0` かつ `S ≥ 0` | **`c(x) < c̄` なら守り・`c(x) > c̄` なら受ける** |
| 3 | `S < 0` | どう守っても足りない＝**別の出口**（トリガー・相手の事故）を狙う |

領域 3 の「別の出口」は第 IV 部の risk-seeking（§16）に接続する。

### 11.1 `c̄` を 2 つの通貨の限界価値に分解する（§25 の宿題 7 の定式化・2026-09-13）

`§10` は `τ`・`K_atk`・`L/H` の再生を**記号のまま**置いていた（宿題 7＝未定式化）。
限界価値で書き直すと 3 つがまとめて片付く。**`λ` をライフ 1 枚の限界価値**、
**`μ` を手札 1 枚の限界価値**（どちらも勝率の単位）とすると、1 回の攻撃の窓は

```
ΔV(受ける) = −λ + (1 + τ_value)·μ         … ライフ 1 枚を失い、札 1 枚とトリガーの期待を得る
ΔV(守る)   = −c(x)·μ                      … 札を c(x) 枚失う
```

したがって

```
受ける ≽ 守る  ⟺  c(x) ≥ λ/μ − 1 − τ_value        すなわち   c̄ = λ/μ − 1 − τ_value
```

**§11 のシャドー価格 `c̄` は「ライフと札の交換レート `λ/μ` から、受けること自体の利得を引いた量」**である。
これで 3 つの loose な項が測れる形になる:

| 項 | 何だったか | 定式化した形 | 測り方 |
|---|---|---|---|
| **`τ`** | 【トリガー】の**密度**（枚数比・実測 0.17） | **`τ_value`＝期待値**＝`Σ_c p(c) · w(c, state)/μ`（`w` はその効果の勝率価値） | 反事実（同じ盤面でトリガーが出た／出なかった）。**密度は上限**＝「引いたら必ず役に立つ」を仮定している |
| **`K_atk`** | 攻めに要る枚数（定数のように書いていた） | **攻めの側のシャドー価格 `k̄`**＝同じ札を攻めに回したときの限界価値。守りと攻めは**同じ 1 つの予算**を食う | `k̄` は「札を 1 枚攻めに使ったときの `ΔV`」＝`order_option.py` と同じ反事実 |
| **`L/H` の再生** | 「ライフは戻らない・手札は引ける」 | `dH/dt = 1（ドロー）+ (受けた回数)`・`dL/dt = −(受けた回数)` ＝**受けるのは 1:1 の両替**で、価格は時計（§15）に依る | `λ` と `μ` を別々に測る（下記） |

**帰結（判断の規則が 1 つ変わる）**: 札は攻めにも守りにも使えるので、守る判断が比べるべき相手は
`c̄` **だけではなく `max(c̄, k̄)`** である。今日の測定は `k̄` が無視されている側を示している
——ドンを 2.32 個余らせ（§24）、安い攻撃を 47.9% 受けている。**`c̄` だけを教えると攻めの価格を
踏み潰す**可能性があるので、候補 F の設計は 2 つの価格を**同時に**渡す形にする。

**この分解は反証可能**: `μ` は**今日 +0.0433（勝率/枚）と実測**した（§24・`hand_value_slope`）。
`λ`（ライフ 1 枚の限界価値）を**同じ計器で測れば** `λ/μ` が出る。予測は

```
λ/μ − 1 − τ_value  ≈  c̄(実測 x 帯の平均) ≈ 2.2 枚（3000 の帯）
```

＝**`λ/μ ≈ 3.4 + τ_value`**（ライフ 1 枚は札 3 枚強に相当）。**外れたら予算モデルのどこかが誤り**
（`λ` が状態で大きく動く／`τ_value` が密度から遠い／`c̄` の測り方が攻めの価格を混ぜている、のいずれか）。
`λ` の測定は `hand_value_slope.py` の軸をライフに替えるだけ＝**次にやる測定**（宿題 7 を閉じる手）。

## 12. 整数性（lumpiness）——「7000 理論」の正体

`c(x)` は**整数**（カードは分割できない）で、カウンター値は 1000／2000 と離散。
したがって `c(x)` は `x` の階段関数であり、**段の位置に価値がある**。実測（§24）:

```
c̄(1000)=1.00  c̄(2000)=1.28  c̄(3000)=2.25  c̄(4000)=2.78  c̄(5000)=3.63   （合成 800 デッキ）
段の高さ:          +0.28        +0.97         +0.53        +0.85
```

平均すれば「+1000 ごとに +0.66 枚」だが、**`2000→3000` の段が +0.97 で最大**
——2000 カウンター 1 枚では 3000 を止められないため。
**ユーザの「7000 に積む」は、1 枚で足りない高さへ跨ぐ段を買う行為**であり、
1000 刻みの線形な足し算ではない。攻め側の `force` を線形に数えると**この段差を平らに潰す**。

## 13. しきい値は状態の関数

```
θ(deck, state) = A·T − B          （L < θ から守りが必須になり始める）
```

速いデッキ（`T` 小）→ θ 小＝守り始めが遅くて正しい。相手が横に並べる（`A` 大）→ θ 大。
ブロッカーが多い（`B` 大）→ θ 小。**実測で `c̄(3000)` はリーダー間で 2.09〜3.00**（§24）＝
同じ盤面・同じ `x` でも `c(x) − c̄` の符号が**リーダーで逆になる**。

## 14. 守りは**二重通貨**（札とドン）

`apply_counter` の裁定: **キャラ**は印字カウンターを足して捨てる＝**札 1 枚だけ**。
**【カウンター】イベント**は `pay_cost` でドンを払ってから解く＝**札 1 枚＋ドン `k` 個**。
符号化は両者を 1 列（`counter_value = max(印字, イベントの上げ幅)`）に畳んでいるので、
**予算の入力に使うと「払えないカウンター」を数に入れる**。正しい形は費用を 2 次元にする:

```
guard(x) = min { (枚数, ドン) : 合計の上げ幅 ≥ x }        払えるか = ドン ≤ D_相手ターン
```

`D_相手ターン` は**自分のターンの打ち回しで決まる**（使い切ればゼロ）＝
**「ドンを残す」が守りの予算に前借りで効く**。実デッキは【カウンター】イベントが合成の 1.7 倍（§24）
なので、この項は実デッキでより重い。

# 第 IV 部 時間

## 15. 時計とハザード

`V` は盤面に勝率 1 個を返すだけで「いつ」を持たない。分解すると

```
P(win | s) = Σ_t P(T = t | s) · P(win | s, T = t)
h(t) = P(T = t | T ≥ t)        （ハザード＝「今が勝負か」の形）
```

`E[T|s]` は盤面から読める（時間軸ヘッド・§24）。**分布 `P(T=t|s)` は測定中**。
`h(t)` が平らなら「決着はいつでも同じ確率で来る」＝盤面から時計を読む価値は薄い。
形が在るなら**ヘッドが学ぶべきは平均 1 個ではなく `h(t)`**。

## 16. 負けているときの危険選好は**零和では最適**

利得が勝率（確率）なので、**資源に対しては危険選好が正しい**:
`S < 0`（領域 3）では期待値を積む手より、**分散の大きい手**（トリガー・相手の事故・
2 割しか通らない線）の方が `P(win)` を上げる。ユーザの「どちらにしろ負け濃厚なら
最初から無茶をする」はこの帰結である。

**実装上の帰結**: その「2 割の線」を拾うには情報集合の標本が要る＝**`K` を上げる**（§7）。
`K=1` の serve は、理論上いちばん無茶が要る局面でいちばん無茶ができない。

# 第 V 部 測定の理論

## 17. 分解能

勝率 `w` と Elo は `w = 1/(1+10^(−Elo/400))`・`w≈0.5` での傾きは `ln10/1600 ≈ 0.00144`。
95% で `Δ` Elo を見分けるのに要る**局数**は

```
1.96 · 0.5 / √N = 0.00144 · Δ    ⇒    N ≈ (680 / Δ)²
```

現行ゲート（8 帯 × 24 ペア＝384 局）は **±35 Elo**。**実測された世代差は 5 Elo 級**（§24）
＝**原理的に見えない**。必要局数の比は `(35/5)² ≈ 48` 倍。

## 18. 観測された差は因果と選択の和

```
Δ_obs = Δ_causal + Δ_selection
```

「守った局は勝っている」は**守れる局が良い局**でも成り立つ。分けるには
**選べた行だけに絞る**（実測: 0.153 → 0.147 → 0.141 と残った・§24）か、反事実の教材を作る。

## 19. 交絡のカタログ（読むとき必ず添える）

1. **V が手札を負に学ぶ向き**（v5 までの符号化で実測された）。守るのは札を使う行為なので、
   `V_guard − V_take` は上振れしうる。**符号検査は測定中**。
2. **決定に汚染された軸**: 「決着までのターン数の真値」で守りを割ると、受けた結果が軸に入る
   ＝決める前の軸（予測）で割る。
3. **ターン単位と攻撃単位**: 旧 take/guard ラベルは相手ターン 1 つの単位＝
   「2 回殴られて 1 回守り 1 回受けた」が潰れる。予算の式は攻撃 1 回ごと。
4. **上限として読むべき量**: 「守れた 92.6%／足りた 71.0%」はドンを見ていない上限（§14）。
5. **f16 の丸め**: 符号化を戻すと 2000 が 2000.0002 になり、**ちょうど 1000 の倍数の閾値が
   1 段上がる**＝枚数が系統的に +1 される（計器は `PWR_EPS=10` で吸収）。

## 20. 何で選別するか（ゲートの検出力）

副条件「固定ミラーで退行なし（CI 下限 ≥ 0.45）」は 192 ペアでは**「観測勝率 ≥ 0.50」と同義**で、
真の勝率 0.47（≈ −21 Elo）を **88% 通す**。主条件も同じ分解能（±35 Elo）。
＝**ゲートの 2 条件はどちらも今作っている 5 Elo 級の差に無力**。
対して 3 波の holdout 行列は対応のある比較で **0.005〜0.01 の差を判別できる**。
**規約変更はユーザ決定**（`measurement.md` §11 に提案）。

## 21. **アリーナが測れないもの**（第 I 部 §3 の帰結・本書で明示）

自己対戦アリーナは**両者が同じ固定方策**なので、次を原理的に測れない:

1. **読まれやすさ（搾取可能性）**——適応する相手が居ないため。
2. **混合の価値**——決定論同士では混合の利得が出ない。
3. **人間の打ち筋に対する頑健さ**——人間は分布の外側を打つ。

**含意**: 「アリーナで差が出ない」は「強さが同じ」ではなく「**この物差しでは同じ**」。
人間相手の実用性は別の測定（読まれやすさ・実デッキでの挙動）で押さえる必要がある。

# 第 VI 部 候補 F の再設計（旧案は破棄）

## 22. 旧案の何が誤りだったか

旧 F は「**方針の価値で探索の事前分布をバイアスする**（効かせる範囲は決着 2 ターン以内の守り）」。
本書の観点で 3 つ誤っている:

1. **層を間違えている**。事前分布をいじるのは**方策**の手当てだが、観測された欠陥は
   **価格の誤り**（`c(x)` と `c̄` の比較）であり、これは**評価**の問題。
   零和では**評価が正しければ探索が拾う**（§2）。事前分布を歪めるのは
   「探索に嘘を教える」＝ミニマックスの畳み込み（§8）を壊す方向。
2. **しきい値で切っている**。「決着 2 ターン以内」も「ライフ 3」も、`θ` と `c̄` が
   状態とデッキの関数（§11・§13）である以上、**定数で切った時点で誤り**。
3. **根拠が未確定**。「守った方が勝ちやすい（+0.141）」は §19-1 の交絡（V が手札を負に学ぶ）で
   説明できる余地が残っており、符号検査の結果が出ていない。

> **2026-09-13 の実測で 1 と 3 の扱いが変わった**（`docs/reports/2026-09-13_readout_w32.md`・
> 台帳 §6 の該当行）。本書を書いた時点では未測定だった 2 本が出たため:
>
> - **3 は解消した（旧 F に有利な向き）**: 手札 1 枚の傾きは 3 ネット × 両席すべてで
>   実測と符号が一致（`slope_true` +0.043 対 `slope_V` +0.041〜0.045）＝**§19-1 の交絡は
>   NRel では起きていない**＝`V_guard − V_take` の +0.141 はそのまま根拠に使える。
> - **1 は誤りだった（新 F の前提が崩れた）**: 「零和では評価が正しければ探索が拾う」は
>   **事前分布が順序の情報を持っているときにだけ成り立つ**。実測の `order_acc(p,q)` は
>   接戦帯で **0.5016＝コイン**（全帯 0.50〜0.53）で、そこで失う Q 0.070 は**測った後悔の全量**。
>   PUCT は事前分布で枝を選ぶので、**順序情報が無い事前分布は探索の入口を塞ぐ**＝
>   評価だけ直しても探索は拾えない。**したがって「方策に触るのは層の間違い」は成立しない**。
> - 2（しきい値で切るのは誤り）は**そのまま残る**（`θ` は状態とデッキの関数であり、
>   実プレイで `L − θ` に対して守り率が平らだったことも定数で切る設計を支持しない）。
>
> **帰結**: §23 の「価格を**評価の入力**に入れる」は**必要だが十分ではない**——
> 同じ価格を**方策の順序の教師**にも入れる形へ組み直す。`c(x) − c̄` は
> 「どちらの手が良いか」の**符号を与える量**（§11）なので、順序の教師そのものになりうる。
> **具体の設計は書かない**（ユーザ指示 2026-09-13「F は最後」＝残りの未定量を片付けた後）。

## 23. 新しい F——**価格を評価の入力に入れる**（**方策側の追加が要る**・上の注を読むこと）

**設計方針（本書からの導出）**: 探索の形は変えない（§5-6 より PIMC は捨てない）。
**評価が持っていない量**を入力に足す。足すのは**すべて観測可能・対局前または盤面から決まる量**:

| 追加する列 | 何か | どこから来るか |
|---|---|---|
| `cbar_curve[5]` | `c̄(1000…5000)`＝**自デッキの守りの単価曲線** | デッキから**対局前に**計算（`deck_profile.py`） |

価格を渡せば、`c(x) − c̄` の符号という**最適の形そのもの**が線形に表現できる。
探索は今までどおりミニマックスで畳む＝零和の要求を壊さない。

**実装の段（append-only・過去に v13→v14 でやった手続きと同じ）**:

- **F-1**: `n_rel_feat.EXTRA_COLS` に上の列を**末尾へ追加**（v15）。Rust の `encode/scalars.rs` と

**やらないこと**: 事前分布のバイアス・ライフのしきい値・「決着 N ターン以内」の場合分け。
**どれも定数で切る形**なので本書の §11／§13 に反する。

## 24 の前に——**反証可能な予測**（F が誤りなら何が起きるか）

F-2 を入れて次のどれかが起きたら、**F は誤り**として捨てる:

1. **`order_errors`（領域 2 で価格を逆に使う割合）が減らない**
   → 価格は既に暗黙に学べていた＝足した列は情報を増やしていない。
2. `order_errors` は減るのに**アリーナが動かない**（2,800 ペアで CI が 0 を含む）

3. **`greedy_gap`（払い過ぎ）が増える**
   → 価格を渡したことで「守る」側へ寄り過ぎている＝`c̄` の推定が高すぎる。

1 か 2 が出たら、次の手当ては**探索（`K` を上げる・窓の情報集合を縮める）**であり、
入力でも方策でもない。**この分岐を先に決めておく**のが本書を書いた目的の 1 つ。
