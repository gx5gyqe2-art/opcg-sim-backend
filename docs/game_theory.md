# 第 I 部 このゲームは何であるか

## 1. 定義

ONE PIECE カードゲームは**有限・二人・零和・不完全情報・完全記憶の展開型ゲーム**である。

- **有限**: 盤面・手札・デッキは有限で、手数に上限がある。
- **二人零和**: 終局の利得は勝ち／負けの二値で、両者の利得の和は常に 0。
- **不完全情報**: 分からないのは**相手の手札の中身・伏せたライフの中身・両者の山の順**。
  見えるのは公開情報（場・ライフ枚数・手札枚数・トラッシュ・ドン）と自分の私的情報。
- **完全記憶**: 各プレイヤーは自分の観測と行動をすべて覚えている。
- **手番は交互**だが、**相手のターン中にも自分の決定点がある**（カウンター窓・ブロッカー宣言）。
  同時手番ではなく、すべての決定点は一列に並ぶ。

**情報集合**＝自分が区別できない状態の集まり。カウンター窓での情報集合は
「相手の手札と伏せライフの中身だけが違う盤面」の束であり、**その束の大きさが打ち回しの難しさ**。

### 1.3 まとめ——このゲームは「4 通貨 × 2 用途」の問題

| 通貨 | 記号 | 攻めの用途 | 守りの用途 |
|---|---|---|---|
| ライフ | `λ` | （受けて手札に替える＝資源に転換） | 被弾に耐える |
| 手札 | `μ` | 登場・イベント（＝`ν` を買う） | カウンター |
| ドン!! | `δ` | 付与（`c_opp(x)` を押し上げる）・コスト | 【カウンター】イベント |
| **場** | **`ν`** | 攻撃する（レストになる） | ブロックする・アクティブで残す |

**どの判断も「その資源を攻めに使う価値」と「守りに使う価値」の大小比較**に落ちる。
本書の残りは、この 4 つの価格を状態から計算する式である。

#### 攻撃と守りの費用（単位は**カードの枚数**）

| 記号 | 意味 | どこで決まるか |
|---|---|---|
| **`x`** | **超過パワー** ＝ `攻撃側のパワー − 攻撃対象のパワー`＝攻撃の「高さ」。**`x ≥ 0` なら「通る」**（パワーが対象以上なので当たる＝相手が上回らない限りライフが 1 減る）・**`x < 0` は届かない**＝価値 0。対象は**リーダーか相手のキャラ**で、**上限が違う**——リーダー狙いは相手が「受ける」を選べるので `Θ·μ` で飽和するが、**キャラ狙いに「受ける」は無い**ので上限は `ν(対象)`（§14.1） | 盤面 |
| **`R`** | **残りターン数**＝その体があと何回攻撃できるか（`r_turns`・実測 4.128）。**`R` を掛けてよいのはリーダー狙いだけ**——キャラ狙いの `ν(対象)` は**在庫**で、倒せるのは 1 体 1 回（§14.1） | 盤面 |
| **`c(x)`** | **費用曲線**＝`x` の攻撃を止めるのに要るカウンターの枚数 | **デッキ**（1.00／1.28／2.25／2.78／3.63 at x=1000…5000） |
| **`Θ`** | **無差別点**＝「攻撃がどれだけ高価なら、守らずに受けるか」の境目（枚数）。**`c(x) < Θ` なら守る・`c(x) > Θ` なら受ける**。**出し方が 2 通りある**（下の囲み）。**2026-09-16（T49）から出荷値は受ける費用の実測 `λ/μ − h ≈ 1.58`**（`h` = ライフの札が手に入る割合 0.89・T48）——旧 1.15 は相手が受け始める切替点＝費用ではない（罠 29） | **盤面**（実測 1.325・**ライフで 8 倍動く**）／**費用 1.58** |
| **`x*`** | **飽和点**＝`c(x) ≥ Θ` になる最小の `x`。**これを超えて積むのは無駄** | 盤面（平均 1406・**中央値 0**） |
| **`τ_value`** | **【トリガー】の期待値**＝ダメージを受けたときトリガーがもたらす得 | デッキ（実測 0.148） |
| `c̄` | `c(x)` の**平均**。`c_mean_blocked`（守る分）と `c_mean_all`（来る攻撃全部）を区別する | 観測量 |

> ### **`Θ` の出し方は 2 通りある**（同じ境目・材料が違う）
>
> どちらも「**攻撃がどれだけ高価なら、守らずに受けるか**」を枚数で表したものだが、
> **片方は価格から・片方は盤面から**出る。
>
> **A. 価格から（恒等式・§9）**——「1 回受けるといくら損するか」を数える。
> ライフを 1 枚失い（`λ`）、**その札は手札に入り**（`+μ`）、トリガーが乗るかもしれない（`+τ_value·μ`）。
> 差し引きを枚数に直すと:
>
> ```
> Θ = λ/μ − 1 − τ_value
> ```
>
> ＝**受ける損が何枚ぶんか**＝**それを防ぐために何枚まで払う気があるか**。**盤面を見ない。**
>
> **B. 盤面から（シャドー価格・§8）**——「死なないために何回守る必要があるか」を数える。
> 来る攻撃が `N` 本・ライフ `L`・ブロッカー `B` なら **必ず守る回数は `G = max(0, N − L − B)`**。
> 安い攻撃から順に守るので:
>
> ```
> Θ = 来る攻撃の c(x) を安い順に並べた G 番目
> ```
>
> ＝**守る中でいちばん高いものの費用**。**価格（`λ`・`μ`）を見ない。**
>
> **どちらか一方ではなく `max` が正しい**（ユーザ指摘 2026-09-14・`2026-09-14_theta_max.md`）——
> 守る理由は **経済**（受ける損より安い）と**生存**（守らないと死ぬ）の 2 つで、
> **どちらかが成り立てば守る**ので境目は大きい方になる:
>
> ```
> Θ(状態) = max( λ/μ − 1 − τ_value ,  来る攻撃の c(x) の G 番目 )
> ```
>
> **実測でも平均は一致する**（A・B ともに 1.325）が**帯ごとの形は違う**
> （ライフ 2 で A は 2.81・B は 0.85）。`max` が既定と違うのは全 main 行の 5.4% だけで、
> **A/B ではどのモードも区別できなかった**（`q_recovered` の標本誤差の方が大きい）＝
> **既定は定数 1.15 のまま**（第 V 部 8）。

#### 予算モデル（§7・「あと何回守らなければならないか」）

| 記号 | 意味 |
|---|---|
| **`L`** | 今の**ライフ**。0 になった次の被弾で負け＝**受けられるのは残り `L` 回** |
| **`N`** | **これから来る攻撃数**（`≈ A·T`） |
| `A` | 相手の**1 ターンあたりの攻撃回数** |
| `T` | **決着までのターン数**（`D ≈ T`＝これから引く枚数） |
| **`B`** | **ブロッカー**で止める回数（**手札を使わずに**止められる） |
| **`G`** | **必ず守る回数** ＝ `max(0, N − L − B)` |
| `H` | **手札**の枚数 ／ `K_atk` ＝ **攻めに要る**枚数 |
| `S` | **余裕**。`S < 0` ならどう守っても足りない（領域 3） |

**`Θ` と `G` の関係**: `Θ` は「来る攻撃の `c(x)` を安い順に並べた **`G` 番目**」
＝**順序統計量であって平均ではない**（平均で代用すると 30% 過小に出る・§8）。
`G` が増える（＝ライフが減る）ほど `Θ` が上がる。

#### 手札の 2 つの用途（§14）

| 記号 | 意味 |
|---|---|
| `c̄_use` | 手札を**守り**に使う価値 |
| `k̄_use` | 手札を**攻め**に使う価値。**`ν` と同じ量だと判明**（§1.2） |

`μ = max(c̄_use, k̄_use)`＝**札は高い方の用途で値が付く**。

## 2. 零和から出てくること（前提として使っていい）

1. **ミニマックス値が存在し一意**（有限零和・完全記憶）。だから「正しい評価」という言葉に意味がある。
2. **値は反対称**: 同じ盤面を自分から見た値と相手から見た値は `V_me(s) = −V_opp(s)`。
3. **相手は最善応手を打つと仮定してよい**。零和では「相手が間違えてくれる」ことに期待する戦略は、
   正しく打つ相手に対して損。**相手の選択は最善で畳む**のが正しく、
   「相手が下手を打つ確率」を混ぜるのは保険ではなく歪み。
4. **自分の利得最大化 ＝ 相手の損失最大化**。だから攻めの物差しを
   **「相手に払わせた量」**で書いてよい（第 II 部）。

## 3. 不完全情報から出てくること

1. **最適戦略は一般に混合（確率的）**。決定論的な打ち手は、**適応する相手に読まれる**。
2. ただし**固定の相手に対しては純戦略の最善応手で足りる**。
   ＝**同じ打ち方同士の対戦では、この弱点は原理的に現れない**。損が出るのは
   **打ち方を変えてくる相手（人間）と打つときだけ**。
3. **読まれやすさは量になる**: 公開状態から行動がどれだけ当てられるか
   ＝条件付きエントロピー `H(行動 | 公開状態)`。0 に近ければ完全に読める。
4. **しかし「読める」と「搾取できる」は別**。読まれても、相手の最善応手が
   自分の選択によって変わらないなら取り分は無い。搾取の上限は

```
G* = E_s[ max_a （私の手を知った上での相手の最善応手の値） − （知らないときの値） ]
```

   ＝**応手の感度**。`G*` が小さいゲームでは、決定論でもほとんど損をしない（§5 に続く）。
5. **情報を与える／隠す行動がある**（カウンターを切れば手札の中身が 1 枚分わかる・
   伏せライフのトリガーは公開される）。シグナリングの利得は**未定式化**（第 V 部）。

## 4. 何を見てよいか（公平性の規約）

**相手の手札の中身は使わない**。**未見プール**（相手の手札∪山∪伏せライフの合計）は
「人間がデッキリストから知りうる範囲」なので使う。相手の山の順・実際の手札は使わない。
＝打ち手は**情報集合の上で**打つ（ユーザ決定 2026-09-04）。

## 5. このゲームの情報構造（実測）

不完全情報ゲームは「隠れ情報がどう振る舞うか」で性質が大きく変わる。3 つの尺度で見る:

| 尺度 | 意味 | このゲームでの実測 |
|---|---|---|
| **disambiguation** | 隠れ情報がどれだけ速く公開情報になるか | **高い**——手札は打てば公開・トリガーは公開・カウンターは切れば公開。終盤へ向かうほど情報集合は小さくなる |
| **leaf correlation** | 「どの隠れ手札でも同じ側が勝つ」度合い | **高い**——ほとんどの局面ではどの世界でも勝敗が同じ。**低いのは接戦帯だけ**（実測§18） |
| **bias** | 構造的にどちらかに偏っているか | 先後の非対称はあるが小さい（**未整理**） |

**含意 1**: 隠れ情報の当て方（相手の手札を何通り想定するか）が効くのは**接戦帯だけ**。
`K` 通り想定して「その線が通る世界」が割合 `p` なら、1 度でも当たる確率は

```
1 − (1 − p)^K        K=1: p        K=4: p=0.2 → 59%        K=8: p=0.2 → 83%
```

**「2 割の世界でしか通らない線」は、1 通りしか読まなければ 8 割見落とす**。
そういう線が要るのは**負けが濃厚なとき**（§17）なので、**最も無茶が要る局面で最も読みが要る**。

**含意 2**: leaf correlation が高いことは、**§3-4 の `G*` が小さいこと**と同じ性質である
——自分の手が変わっても勝つ側が変わらないなら、読まれても相手の応手は変わらない。
つまり**このゲームでは決定論の罰が小さい**という説明が立つ（検査可能な含意・第 V 部）。

# 第 II 部 資源と価格——打ち回しの本体

## 6. 交換の恒等式（ここを間違えるとすべて狂う）

超過パワー `x`（攻撃側のパワー − 自リーダーのパワー）の攻撃に対して:

| | ライフ | 手札 | その他 |
|---|---|---|---|
| **受ける** | −1 | **+1**（ライフカードが手札に入る） | トリガーの期待 `+τ` |
| **守る** | ±0 | **−c(x)** | — |

**受けるのは「ライフを失う」のではなく「ライフ 1 枚を手札 1 枚に両替する」**。
ここを「受ける＝損」と置くと、以降の判断がすべて守り過ぎに寄る。

`c(x)` は**止めるのに要る枚数**＝手札のカウンター値の合計が `x` 以上になる最小の組。

## 7. 予算——「あと何回守らなければならないか」

- `L` 今のライフ（0 になった次の被弾で負け＝**受けられるのは残り `L` 回**）
- `T` 自分が決めるまでのターン数・`A` 相手の 1 ターンの攻撃回数・`N ≈ A·T` これから来る攻撃数
- `B` ブロッカーで止める回数・`H` 手札・`D ≈ T` これから引く枚数・`K_atk` 攻めに要る枚数

```
必ず守る回数   G = max(0, N − L − B)
余裕           S = H + (N − G) + D − K_atk − Σ_{安い G 本} c
```

`N − G` が足されるのは**受けた回数だけ手札が増える**から（§6）。

## 8. 価格——この窓の判断は 1 つの符号で決まる

受けた場合と守った場合の `S` を比べると `H` と `(N−G)` が打ち消えて

```
S(受ける) − S(守る) = c(x) − Θ
```

`Θ` は「**この先まだ守る、最も高い攻撃の費用**」＝経済学でいう**シャドー価格（双対価格）**。
「`G` 回は守らねばならない」という制約に紐づく**手札 1 枚の機会費用**である。したがって

> **安い攻撃を守り、高い攻撃を受ける**。境目は `c(x)` と `Θ` の大小だけ。

**記号を混同しないこと**（混同すると必ず誤る）:

| 記号 | 何か | 性質 |
|---|---|---|
| **`c(x)`** | **費用曲線**＝`x` を止める枚数 | **デッキで決まる**（中身を数えれば出る） |
| **`Θ`** | **無差別点＝価格** | **盤面で決まる**（`L`・`T`・`A`・`B` から） |
| `c̄_mean` | 実際に守った窓の平均費用 | 観測量。定義上 `c̄_mean < Θ`（安い側だけ守るので） |

3 つの領域に分かれる:

| 領域 | 条件 | 最適 |
|---|---|---|
| **1** | `G = 0`（全部受けても死なない） | **守るのは純粋な無駄**（トリガーも取りに行ける） |
| **2** | `G > 0` かつ `S ≥ 0` | **`c(x) < Θ` なら守り・`c(x) > Θ` なら受ける** |
| **3** | `S < 0` | どう守っても足りない＝**別の出口**（トリガー・相手の事故）を狙う（§17） |

## 9. 価格は限界価値から計算できる

`λ` をライフ 1 枚の価値、`μ` を手札 1 枚の価値（どちらも勝率の単位）とすると、§6 の表は

```
ΔV(受ける) = −λ + (1 + τ_value)·μ            ΔV(守る) = −c(x)·μ
⇒  受ける ≽ 守る  ⟺  c(x) ≥ λ/μ − 1 − τ_value
⇒  Θ = λ/μ − 1 − τ_value
```

**価格は「ライフと手札の交換レート」から、受けること自体の利得を引いた量**である。
`λ`・`μ`・`τ_value` はすべて測れる量（§18）。実測を入れると

```
λ/μ ≈ 2.5〜2.7  （ライフ 1 枚 ≈ 手札 2.5 枚）      Θ ≈ 0.8〜1.5 枚
```

`c(x)` 曲線（§18）に当てると**切れ目は x = 2000 と 3000 の間**＝

> **2000 までの攻撃は守り、3000 以上は受ける**のが平均的な最適。

`τ_value` の不確かさ（0〜0.67）の幅の中で、**この切れ目は動かない**。

## 10. 整数性（lumpiness）——「7000 に積む」の正体

`c(x)` は**整数**（カードは割れない）で、カウンター値は 1000／2000 と離散。
だから `c(x)` は**階段関数**であり、**段の位置に価値がある**。実測（§18）:

```
c(1000)=1.00  c(2000)=1.28  c(3000)=2.25  c(4000)=2.78  c(5000)=3.63
段の高さ:        +0.28        +0.97         +0.53        +0.85
```

平均すれば「+1000 ごとに +0.66 枚」だが、**`2000→3000` の段が +0.97 で最大**
——2000 カウンター 1 枚では 3000 を止められないため。

> **「リーダー 5000 に +2000 して 7000 を作る」は、1 枚で足りない高さへ跨ぐ段を買う行為**。
> 1000 刻みの線形な足し算ではない。**超過パワーを線形に数えると、この段差が平らに潰れる**。

> **この節は「段」の話だが、段を登り続ける意味はない**——どこで打ち止めるかは
> **§14.1 の飽和点 `x*`**（相手が「受ける」を選ぶ超過）で決まる。実測では 1000〜2000。

攻め側から見れば、ドン 1 本を付けて超過を 1000 上げる価値は

```
Δpressure(1000) = c_opp(x + 1000) − c_opp(x)        （段の上なら ≈ 1 枚・段でなければ 0）
```

**過剰盛り**（既に段を越えているのに足す）は `Δpressure = 0` ＝ 純粋な無駄。

## 11. しきい値は状態の関数（「ライフ 3 で守り始める」は誤り）

```
θ(deck, state) = A·T − B        （L < θ から守りが必須になり始める）
```

- 速いデッキ（`T` 小）→ θ 小＝**守り始めが遅くて正しい**
- 相手が横に並べる（`A` 大）→ θ 大＝**早くから守るのが正しい**
- ブロッカーが多い（`B` 大）→ θ 小

さらに `Θ` は `λ/μ` を通じて盤面に依り、`c(x)` はデッキに依る。実測で
**同じ `x` でも `c(x) − Θ` の符号がリーダーによって逆になる**（`c(3000)` が 2.09〜3.00・§18）。

> **固定のライフしきい値は「平均だから」ではなく「価格が状態とデッキの関数だから」誤り**。

> ### **`Θ` を盤面から直接測った——定数ではなく、ライフで 8 倍動く**

>
> **`Θ` の定義はシャドー価格**（§8「この先まだ守る、最も高い攻撃の費用」）なので、
> **`λ`・`μ`・`τ_value` を通らずに盤面から計算できる**:

> ```
> G = max(0, N − L − B)                 必ず守る回数（N＝来る攻撃数・B＝ブロッカー）

> 本書は §8 と §9 で**この 2 つを同じ `Θ` として扱っている**が、
> **それが成り立つのは最適手を打っているときだけ**かもしれない。**未解決**（第 V 部へ）。

> **同日午前の「`Θ` は 0.67 かもしれない」は誤りだった**（撤回・`2026-09-14_theta_price.md` §2）。
> 恒等式（§18）が `λ_opp` の水準を 32% 落とすので `λ/μ` も落ちると論じたが、
> **`Θ` が依るのは比 `λ/μ`** で、**`λ_opp` と `μ_opp` は同じ相手ターンの行から測っている**
> ＝**逆因果は両方に同じ向きに乗る**ので**比は動かない**。
> **水準だけ直して比を直さなかったのが誤り**。恒等式が縛るのは `λ` の水準だけで、
> **`Θ` には波及しない**（T19 の所見自体はそのまま有効）。

## 12. 守りは二重通貨（手札とドン）

- **キャラのカウンター**＝手札を 1 枚捨てるだけ＝**手札だけ**
- **【カウンター】イベント**＝**手札 1 枚 ＋ ドン `m` 個**（コストを払わないと打てない）

だから守りの費用は 1 次元では書けない:

```
guard(x) = min { (枚数, ドン) : 合計の上げ幅 ≥ x }       払えるか＝ドン ≤ （相手ターン中のドン）
```

**相手ターン中に使えるドンは、自分のターンの打ち回しで決まる**（使い切ればゼロ）。
＝**「ドンを残す」が守りの予算に前借りで効く**。

## 13. ドンは 2 段の決定である（窓では埋没費用）

ドンは自分の開始時に**全部アクティブに戻る**。したがって

> **相手ターンに使い残したドンは、次の自分のターンには何の損にもならない**
> ＝**窓の時点でドンは埋没費用（価格 0）**。価格が付くのは**1 ターン前**である。

### 段 1（自分のターン）——残すか、攻めに使うか

```
攻めに使う価値 = Δpressure(1000) · μ        （相手に払わせた枚数＝零和なので自分の利得）
残す価値       = p_need · μ · E[Θ − c_paid]  （p_need＝相手ターンにイベントでしか止まらない窓が来る確率）

残すべき  ⟺  p_need · E[Θ − c_paid] ≥ Δpressure(1000)
```

**実測値を入れると成立しない**: 右辺は平均 0.66 枚、左辺は `Θ ≤ 1.5`・`c_paid ≥ 1` なので
`p_need ≤ 1` でも 0.5 以下。したがって

> **平均的な局面では、【カウンター】イベントのためにドンを残すのは損**。攻めに使う方が良い。
> **例外はライフが薄い帯**——リーサル圏では「そのライフ 1 枚＝敗着」なので `λ` が跳ね、
> `Θ` が 2 枚を超えると成立しうる。**ドンを残すのは、自分が殺されかけている時だけ正しい。**

### 段 2（相手のターン・窓ごと）——使うか、後の窓に取っておくか

```
守る ⟺ c_free(x) ≤ Θ                                          （手札だけで止まる）
     または c_paid(x) ≤ Θ かつ m(x) ≤ d_res かつ m(x)·δ̄ ≤ Θ − c_paid(x)
```

`d_res` は残したドン、`δ̄` は**同じターンの後の窓のための機会費用**（最後の攻撃では 0）。
`Θ` と同じ型の価格が、ターンの内側にもう一段ある。

## 14. 手札は攻めにも使える——価格は 1 つでは足りない

同じ 1 枚を守りにも攻めにも使える。**窓の判断には価格 1 つで足りる**——`μ` を
実測の限界価値として使うなら、`μ` は「**最良の用途に使ったときの**価値」を既に含むので、
`Θ = λ/μ − 1 − τ_value` は攻めの用途を折り込んだ無差別点である。

**2 つ要るのは別の決定**＝**自分のターンに、この札を出すか残すか**:

```
守りの用途 c̄_use = E[ μ·(Θ − c(x_next)) ]        … 次に来る窓で節約できる量
攻めの用途 k̄_use = Δpressure·μ + P(通る)·λ_opp    … 相手に払わせる量＋ライフを取る量
札を攻めに出す ⟺ k̄_use ≥ c̄_use                   μ = max(c̄_use, k̄_use)
```

**`μ` を測っても内訳は出ない**（データは用途を区別しない）。どちらが支配的かは
**未測定**だが、**`k̄_use` は次の §14.1 で導ける**——攻めに札を使うとは**キャラを買うこと**なので、
`k̄_use` は「場のキャラの価格 `ν`」に等しい。

### 14.1 第 4 の通貨——**場のキャラの価格 `ν`**

§1.1 の点検で最大の穴だった量。**登場は「手札 1 枚＋ドン」を「場のキャラ 1 体」に両替する行動**で、
そのレートを書いていなかった。キャラが生むものは 3 つある:

```
ν(P, R) = Σ_{残り R ターン} （攻撃の価値）  ＋  （ブロックの option value）  −  P(KO される)·ν
登場する ⟺ ν ≥ μ + cost·δ                      （札 1 枚とドンを払う）
```

#### 攻撃 1 回の価値は**相手が選ぶので min になる**

攻撃を受けた相手は「守る（`c(x)` 枚）」か「受ける（`λ − (1+τ)μ = μ·Θ`）」の**安い方**を選ぶ。
零和なので相手の損＝自分の得。したがって

```
攻撃 1 回の価値 = μ_opp · min( c_opp(x), Θ_opp )          x = 自分のパワー − 相手リーダーのパワー
```

**ドン 1 枚の価値は、この式の増分として厳密に書ける**:

```
付与 k 枚の価値 = ( min(c_opp(x+1000k), Θ_opp) − min(c_opp(x), Θ_opp) ) · μ_opp
```

**段が平らな区間では 0 になる**——実測の曲線は `c(0) = c(1000) = 1.00`（どちらも 1 枚で止まる）なので、
**超過 0 の攻撃に 1 枚付与しても相手の費用は 1 も増えない**。
「とりあえず 1 枚付ける」は**この帯では完全な無駄**であり、意味が出るのは
**`1000 → 2000` を跨ぐとき**（+0.28 枚）と **`2000 → 3000`**（+0.97 枚＝最大）である。

**ここから「超過パワーの上限」が出る**（§10 の 7000 理論の精密版）:

> **`c_opp(x) ≥ Θ_opp` になった時点で価値は飽和し、それ以上パワーを足しても 1 も増えない**
> ——相手はもう「受ける」を選ぶので、超過を上げても払う量は変わらない。

実測を当てる（相手ターンの値 `λ/μ = 2.473`・`Θ ∈ [0.8, 1.47]`・`c` 曲線 1.00/1.28/2.25/…）と

```
飽和点 x* = min{ x : c(x) ≥ Θ } ≈ 1000〜2000        （リーダー 5000 に対して 6000〜7000）
```

**＝「7000 を作る」が正しい理由はここにある**。ただし**理由は「カウンター 2 枚を強要するから」ではない**
——実測の `c(2000)` は **1.31 枚**で 2 枚ではない。正しい理由は
**「守る費用を、受ける費用より高くするから」**。同じ 7000 を指すが、**予測が違う**:

- 「2 枚強要」説 → 必要な超過は相手のカウンターの構成だけで決まる（固定）。
- **本書の説** → `Θ_opp` は相手のライフで動くので、**相手のライフが薄いほど飽和点は上がる**
  （`λ` が跳ねて `Θ` が大きくなる＝相手はもっと高い攻撃でも守る）。
  **リーサル圏では超過を積む価値が残り、盤面が楽なときは 2000 で打ち止め**。

`x ≤ 0`（自分のパワーが相手リーダー以下）では攻撃は通らない＝**価値 0**。
実測で**打った攻撃の 38.5% が `x ≤ 0`**（`cpu_theory_gap.md` §5.3）＝この 0 の帯に落ちている。

#### **対象はリーダーだけではない**——パワーの価値の残り半分（2026-09-14・ユーザ指摘）

> 「パワーが大きいほど**相手の大きなキャラクターに対して攻撃する選択肢が残る**はず。それも式に合体できる？」

できる。**毎ターン一番おいしい対象を選ぶ**と書けばよい:

```
lead  = min( c(P − L_opp)·μ, Θ·μ )        リーダー狙い——**毎ターン繰り返せる**
v_T   = min( c(P − P_T)·μ,  ν(T) )        キャラ T 狙い——**1 体につき 1 回だけ**
atk   = Σ_{i < R}  max( v_(i), lead )     （v は高い順に 1 ターン 1 体ずつ充てる）
```

**上限が `Θ·μ` から `ν(T)` へ変わるのが要点**——リーダー狙いは「相手が受ける」を選べるので
`Θ·μ` で飽和するが、**キャラ狙いに「受ける」は無い**（倒されるだけ）。だから
**飽和点 `x*` を超えたパワーにも値段が残る**＝`c(P − P_T)` が伸び続ける。

> **`R` を掛けるのは `lead` だけ**。`ν(T)` は**在庫**（その体が持つ残り価値の総額）であって
> **毎ターンの流量ではない**ので、`R · max(lead, v_T)` と書くと「同じ 1 体を R ターン倒し続ける」
> ことになり単位が合わない（実装の初版がこれで 12000 の体を実測の 5 倍に値付けした）。
> **倒せるのは 1 体 1 回**なので、**高い順に 1 ターン 1 体ずつ充てて足す**。

**内側の `ν(T)` は深さ 1 で止める**（相手のキャラの価値を測るのにこちらの盤面を要求すると
相互再帰になる）。**この打ち切りの代償はリーダー未満の帯に出る**——相手の小さなキャラは
内側の式で `ν = 0` になるので、**「小さい体同士が取り合う」価値は依然として 0 のまま**である
（実測 0.0690・§18 の表）。そこは対象の選択肢ではなく**身代わり・常在効果**の項
（§14.1.1 の #7・#13）で埋める話であり、本項では閉じない。

#### ブロックの価値

ブロックは**攻撃をキャラで受け止める**＝「ライフ or 手札」を「キャラ」に振り替える:

```
ブロックする ⟺ ν_blocker · P(KO される) < μ · min( c(x), Θ )
```

パワーが攻撃側以上のブロッカーは KO されない＝**費用 0 で攻撃 1 回を消す**（純粋な得）。
**ブロッカーはアクティブでなければ使えない**（§1.1-b）ので、これはテンポの問題に接続する（§14.2）。

#### `k̄_use` は `ν` である

```
k̄_use = ν − cost·δ            （手札 1 枚を「場のキャラ」に替えたときの取り分）
```

したがって §14 の「どちらが支配的か」は**反事実で測る前に、上の式で予測できる**。
`ν` の項はすべて測定済みの量（`μ`・`λ`・`Θ`・`c(x)` 曲線・`R`）で書けている。

#### **`ν` の外に項が 1 つ在る**（ユーザ指摘 2026-09-14・**構造の訂正**）

> **実測の `ν` は観察された勝率の傾き**なので、**その体が場に居る間にすることは全部入っている**
> （常在効果もアタック時効果も）。だから `ν` に項を足して埋めるのは筋が違う。

> ＝**「体が場に居る価値」には原理的に入らない**。

play_value = ν ＋ 【登場時の一回性の利得】 − μ − cost·δ
                  ↑ ここが丸ごと欠けていた
```

価格は `μ`（平均的な 1 枚）ではなく `μ_search > μ` である。

### 14.1.2 **`ν` の勘定を組み直す——退場は損ではなく仕事の完了**（ユーザ決定 2026-09-14）

> 「**倒されるから出さないという考えではなく、ライフを守れているから出すという考えのはず**」

**現在の式は符号が逆である。**

```
旧:  ν = (攻撃 + ブロック) × (1 − ko_p)        ← 倒されるぶん割り引く
```

`(1 − ko_p)` は「体が消えると価値が消える」と言っているが、**このゲームでは違う**——
**体が殴られて消えたということは、その攻撃がリーダーに通らなかった**ということで、
**ライフ（またはカウンター札）を守っている**。**引くべきではなく足すべきものを引いていた。**

**これが `ν − 費用·δ` が 98.5% の行で負になった理由である**（T26・`2026-09-14_mu_branch.md`）。
**→ 2026-09-15 に解消した**（T38・`2026-09-15_t26_pair_remeasure.md`）——**3 段で解けた**: T30（動作 62 種の値付け）で 1.5% → 22.6%・T33（登場時効果）で → 40.2%（イベント込み）・**`pair` で体だけ 25.8% → 41.4%**、`μ_develop` の平均は ≈ 0 → **`μ` に並ぶ**（0.047〜0.057 対 0.055）。**§14.1.2 の組み直し（退場は仕事の完了）は式に入れていない**——**それ無しで矛盾が消えた**ので、②④の接続の優先度は下がった。

#### 組み直した勘定（ユーザの 5 項目）

**体は必ずいつか退場する。退場の仕方ごとに値が付く**というのが正しい形で、
**「退場する確率」を掛けて割り引く**のは勘定として誤りである。

| # | 項 | 誰の何が動くか | 符号 | いまの状態 |
|---|---|---|---|---|
| ① | **手札から出す** | 自分の手札 −1 | **−`μ`** | ★（`play_value`） |
| ② | **殴られたときに守る／守らずに退場する** | 守る＝自分の手札 −`c` 枚／守らない＝**退場するがライフは減らない** | **＋** | **測った・式に投入済・既定**（T21 の身代わり 0.0597／2026-09-15 の `pair`・同日ユーザ決定で既定） |
| ③ | **殴る** | 相手の手札 −`c` 枚 **または** ライフ −1（相手が安い方を選ぶ） | **＋** | ★（`attack_stream`） |
| ④ | **除去を要求する** | **相手がカード／効果を 1 つ払う** | **＋** | **無**（項が存在しない） |
| ⑤ | **登場時効果・常在効果** | 自分または相手の何かが増減 | **＋** | 無（§14.1.1 の 3・9〜11） |

**②が要点**——体が殴られたとき、自分には 2 つの道がある:

```
守る    → 手札を c 枚払って体を残す          （手札 −c・体は残る）
守らない → 体が退場する                      （体 −1・**ライフは減っていない**）
```

**どちらを選んでも、リーダーへの攻撃 1 回ぶんを消している。**
「守らない」を選んだときの退場は**損失ではなく、体が果たした仕事**である。

**④は新しい項**——相手が除去を撃ったなら、**相手はカードを 1 枚使った**。
零和なので**相手の手札 −1 は自分の +`μ_opp`**。体は消えるが、**消えるために相手が払っている**。

#### 書き直した形

```
ν = Σ_t P(t ターン生存) × （攻撃の価値）          ③ 殴っているあいだの稼ぎ
  + P(攻撃で退場) × （身代わりの価値）             ② **足す**（旧: 割り引いていた）
  + P(除去で退場) × （相手が払った費用）           ④ **新しい項**
  + （ブロックの option value）                    6（自発的な迎撃・②とは別物）
  + （効果）                                       ⑤
```

**`ko_p` は「割引率」ではなく「退場の仕方の分布」になる**——
`P(攻撃で退場) + P(除去で退場) + P(自分の都合で退場) + P(生存)` に分解して、
**それぞれに符号付きの値を掛ける**。

> **②とブロック（項 6）を混ぜないこと**——ブロックは**自分が選んで割り込む**行動、
> ②は**相手が体を殴ることを選んだ**結果である。決める側が違うので別の項。

> **真の損失は ① と ドンだけ**である（`play_value = ν − μ − cost·δ`）。
> 体そのものの退場は、上の 4 通りのどれかで**値が付いている**。

#### これが説明すること

| 現象 | 旧の式 | 組み直した式 |
|---|---|---|
| `ν − 費用·δ` がほぼ常に負（T26） | 説明できない（矛盾） | **退場の価値を引いていたから**——足せば符号が変わる。**2026-09-15 の再測定（T38）で解消**——`pair`（身代わり＋`ko_p` の形）で**体になった札の価値 `μ_develop` の平均が `μ` に並んだ**（0.047〜0.057 対 0.055）・「出すのは得」の行は 1.5% → 41%（`2026-09-15_t26_pair_remeasure.md`） |
| 弱い体に価値がある（T21） | 説明できない（攻撃項が小さい） | **②が主**（殴る value ではなく吸う value） |
| 消える率が中サイズで最大（T22） | 「高パワーほど死ににくい」と仮定して外れた | **狩られる＝相手が費用を払っている**＝④が厚い帯 |

**T22 の山形も、この枠では「損の分布」ではなく「仕事の分布」**として読める
——中サイズが一番死ぬのは、**中サイズが一番よく仕事をしている**可能性がある。

#### ②と④の形（ユーザ指摘 2026-09-14・実測付き）

**②は一律ではない——吸ったパワーで値が変わる。ただし `Θ·μ` で頭打ち。**

```
身代わり 1 本の価値 = min( c(x), Θ ) · μ        x = 攻撃側の実効パワー − 自リーダー
                     x < 0 なら 0               （リーダーに通らない攻撃は守っていない）
```

**実測（`2026-09-14_absorbed_power.md`）**: 超過 2000 を超えると全帯が **0.0634＝`Θ·μ`** で
同じ値になる＝**「2000 を吸うのか 10000 を吸うのか」は 2000 までしか効かない**
（守る側は高すぎる攻撃には**守らず受ける**を選ぶので、肩代わりする額がそこで止まる）。
**実デッキでは吸った攻撃の 38.7% が `x < 0`**（合成 17.2%）＝**身代わりが 26% 安い**。

**④は効果による除去だけではない——「パワー下げ＋攻撃」も除去である。**

この形は記録上**攻撃 1 つ**にしか見えないが、**相手はカードを 1 枚余分に払っている**ので
④に数える。実測で**攻撃のあった巡の 28.2%（実デッキ）に効果の解決が同居**する（合成 16.6%）。

> **そしてこの形は測定も歪める**——**パワーを下げられて生き残った体**は
> 「消えた」と誤って数えられる。**退場率の真値は挟み込みでしか言えない**
> （合成 [0.135, 0.273]・実デッキ [0.108, 0.274]）＝**`ko_p = 0.289` は上端に近い**。
> **体の同一性が要る**（T27-b）。

#### **身代わりと `ko_p` を対で式に入れた**（2026-09-15・T37・**切替として実装・既定は未変更**）

**T21 が「対でなければ入れられない」と言っていた 2 つを同時に入れた**（`theory_order.nu_of`）:

```
ν = ( 攻撃の流量 + ブロックの option + 身代わり ) × ( 1 − ko_p(パワー) )
```

| 項 | 出どころ | 値 |
|---|---|---|
| **身代わり**（P5） | T21 の**帯ごとの実測**（率 × 1 本の価値 × `R`） | 0.0597（リーダー未満）／0.0409（〜飽和）／0.0271（飽和超え） |
| **`ko_p`**（P4） | T22 の実測の**山形**（絶対パワー 4000〜6000 が峰） | 0.2417／0.2782／**0.3297**／0.2436／0.1987 |

**新しい定数はゼロ**（どちらも既に測ってあった値をそのまま置いた）。

> **身代わりは攻撃・ブロックと同じ括弧の中に置く**——T21 の実測は既に `R`（残りターン）を
> 掛けた「流量」なので、**生存の割引は 1 度だけ**掛かるのが正しい。
> 外に出して二重に割り引くと、**`ν` 最大の穴（弱い帯）が埋まらない**。

**勘定は閉じない**（実測 `ν` との突き合わせ・`2026-09-15_shield_kop_pair.md` §2）:

| パワー帯 | 旧（`base`） | **対（`pair`）** | **実測 `ν`** |
|---|---|---|---|
| **リーダー未満** | 0.0000 | **0.0431** | **0.0690** |
| リーダー〜飽和 | 0.1617 | **0.2030** | 0.1503 |
| 飽和超え | 0.1860 | **0.2313** | 0.2112 |

**弱い帯の穴は 63% 埋まるが、中盤帯が +0.053 超過する**（`base` の +0.011 から 4.6 倍）。
**理屈は追える**——`ko_p` の峰（絶対 4000〜6000）が中盤帯にちょうど重なって割引は最大なのに
足りない＝**中盤帯の攻撃項がもともと過大**で、そこに身代わりが乗る。
**残差に合わせて身代わりを下げない**（§0.1 の条件 3＝当てはめになる）。

### 14.1.3 **効果はコストと実行内容で整理する**（ユーザ決定 2026-09-14）

> 「イベント、起動メイン等の効果については**コストと実行内容で整理する**のが良い」

**採用する。** そしてこの整理の一番の値打ちは、**新しい自由度を作らないこと**にある——
**実行内容が既にある通貨に写れば、係数を選ぶ余地が無い**。

```
効果の価値 = Σ（実行内容が動かした通貨の価格） − （コスト）
コスト     = μ（札 1 枚） + cost·δ（ドン） + 差し出した自分の体（ν） + 払ったライフ（λ）
```

**T16 が「勘定は複数の互換でない仕方で閉じられる」と言って項を足す作業を止めたのは、
係数を選べたから**である（§7.4）。**この整理では選べない。**

#### **条件は足す項ではなく掛かる側**（2026-09-14・ユーザ確認）

> 「**効果は条件＋コスト＋アクションの要素で考えるという認識で良い？**」——**その通り**
> （`effect_types.py::Ability = trigger + condition + cost + effect`）。**ただし足し算に入るのは
> コストと実行内容だけ**で、**条件と契機は掛かる側**である:

```
能力の価値 = P(条件が成り立つ) × ( Σ実行内容 − Σコスト )
```

**そして `P` は「どこでこの値を使うか」で変わる**——ここを一律に扱うと片側が壊れる:

| 値の使いどころ | `P` | 根拠 |
|---|---|---|
| **起動メインの候補** | **1.0** | エンジンが `has_activatable_main` で**条件・回数・コスト・空振り**を確かめてから候補に出す（`rules/legal.rs`）＝**候補に在る時点で成立している**。割り引くと実測 36.6% を潰す |
| **体なしカードの登場** | **状態から判定**（述語） | `PLAY` の合法性は**コストだけ**・`ON_PLAY` の条件は解決時に判定される |
| **キャラの登場** | — | **効果を別項で足さない**（下記） |
| **カード単体**（手札の中） | **1.0＝上限** | 将来の盤面が判らない。**推定値を置かない** |

> **条件は確率ではなく述語として解く**（`condition_value.py`・判定はエンジンの
> `effects/cond.rs` を写す）——記録は判断点の状態を持っているので、成立率を推定する必要が無い。
> **実測（実デッキ 300 局）: 配線した経路で偽は 0 件**（真 4,951・判定できず 1,681）。
> **真の 4,729 件は `LEADER_NAME`**＝**そのリーダーのデッキに入っているカードだから構造的に成立**。
> **判定できなかった分を全部偽と置いても橋は動かない**（4.475 → 4.388）
> ＝この穴は結論を動かさない（`2026-09-14_condition_gate.md`）。

#### **キャラの登場時効果は `ν` の外に在る**（2026-09-15・**前日の記述を訂正**）

> **ユーザ指摘**「**`ν` は登場時の効果処理を差し引いた値にするのが正しいんじゃない？**」
> ——**原則としてはその通り**（二重計上は避ける）。**そこで測った。**

**前日ここには「`ν` に既に入っているので足すと二重計上」と書いたが、それは推定式から
確かめていない主張だった**。`ν` の推定は

```
z ~ Σ_c β_c ·（種類 c の自場の体数）      帯 =（自ライフ, 相手ライフ, ターン帯, 手札）
```

なので、**帯に在る通貨に現れる効果は条件付けられている**＝**`ν` に入らない**:

| 効果が現れる先 | 帯に在るか | `ν` に入るか | 足してよいか |
|---|---|---|---|
| **自分の手札**（ドロー・サーチ） | **在る** | **入らない** | **足してよい** |
| **ライフ** | **在る** | **入らない** | **足してよい** |
| 相手の場（登場時除去） | 無い | 入りうる | 量は **0.0016**＝`ν` の 1.5%（`entry_gain`） |
| **自分の場**（追加の体） | **説明変数そのもの** | 体数として数える | **2 体目として数えるのが正しい** |

**直接測った**（`nu_measure --scheme onplay_power`＝**自場の枠を「そのカードが登場時能力を
持つか」で割る**・`card_idx` から引く）——**式は登場時能力で `ν` を変えないので、
差が出ればそれが「`ν` に入っている効果」**である:

| パワー帯 | 効果持ち − 素の体（w39 / w42） |
|---|---|
| **リーダー未満** | **−0.042 / −0.036**（2 本とも**負**） |
| リーダー〜飽和 | +0.017 / −0.046（符号が反転） |
| 飽和超え | +0.019 / +0.008 |

**`ν` が効果を含むなら効果持ちが 0.05 級（値付けの中央値）高く出るはずだが、出ていない**
——最大の正が +0.019、2 本で一致する符号は**負**だけ。**よって `ν` からは引かない**
（引けば測定が否定する向きに定数を動かす）。**キャラの登場に効果を足すのは正しい。**
詳細は `docs/reports/2026-09-15_nu_onplay_split.md`。

#### **キャラの登場の式**（2026-09-15 に効果を足した）

```
キャラの登場 = ν(パワー・ブロッカー・相手の場) + 登場時効果(条件で判定) − μ − 費用·δ
```

**足すのは `ON_PLAY` だけ**——`ON_PLAY_TRIGGERS` は**体なしカード用に `ACTIVATE_MAIN` まで
含む**ので（イベントの本文がそこに入る）、キャラに使うと**場に出しただけで起動メインが
発動した**ことになる。**`CHAR_ON_PLAY_TRIGGERS = ("ON_PLAY",)` を別に持つ。**

> **「能力が無い」と「読めない」を分ける**——その契機の能力を持たないキャラは **0**、
> **効果 JSON に無いカードは `None`**。前者を `None` にすると**素のキャラが全部無言**になる
> （同梱の 1,863 枚）。**「0 と None を混ぜない」の両側**である。

#### **効果の値は盤面で変わる**（2026-09-15・ユーザ指摘）

> 「**登場時効果は `ν` ではなくて効果に紐づく価値を変動させるべきか**」——**その整理が正しい**。
> **`ν`（体の価格）は定数のまま**で、**盤面で変わるのは効果の側の値**である。

```
登場時 KO の価値 = Σ（取れる対象のうち価格が高い n 体の ν）      n は個数（在る数まで）
対象が 1 体も居なければ 0                                        （空振り）
```

**対象の `ν` の定義は攻撃側と同じものを使う**——`attack_stream` の中の
`nu_of(対象のパワー, 自リーダーのパワー, R, is_blocker=…)`。**違うと「攻撃で倒す価値」と
「効果で倒す価値」が食い違う。**

| 直した点 | 前 | 後 |
|---|---|---|
| 相手の場が空のときの除去 | 0.1087 | **0**（実測 406 件） |
| 「コスト 4 以下を KO」 | 0.1087 | **その範囲で一番高い体** |
| 2 体 KO | 2 × 0.1087 | **上位 2 体の和**（在る数まで） |
| 特徴・名前・色で絞る除去 | 0.1087 | **その素性を持つ体の一番高い `ν`**（2026-09-15 に `card_idx` から素性を引いた） |

**実測: 効いたのは候補の 4.4%**（1,883/43,263）**で、そこでの変化は中央値 −0.053＝札 1 枚ぶん**
（向きは**下**＝平均は除去を過大に見積もっていた）。**橋は動かない**（+4.274 → +4.325・
CI が重なる）＝**効かない直しではなく、効く範囲が狭い直し**である。
**橋が黙っていてもカードの本文と食い違う値付けは直す**——空振りに値段が付いていたのは
分解能とは無関係の誤りだった（`2026-09-15_effect_target_value.md`）。

> **判定の可否は「読めない名前の一覧」ではなく渡されたデータで決める**（2026-09-15）——
> **体の側にその素性が無ければ判定しない**。呼び出し側が素性を足せば自動で読めるようになり、
> 足さなければ黙って誤判定しない（静的な一覧は**更新し忘れ**という罠 25 の形を残す）。
>
> **効果の値付けの精緻化はここで打ち切った**——動いた候補は
> **キャラに効果を足す（全キャラ・橋が動いた）→ 盤面の対象（4.4%・動かない）→
> 枠の素性（0.4%・動かない）**と**1 桁ずつ枯れた**（`2026-09-15_target_identity.md`）。
> **残る大物は P8（記録の穴＝守り側）**で、そこは 6 段続けて価格では動いていない。

**実測（橋・§0.5 の受け入れ基準）**: **中盤の判定が `no_link` → `bridge_holds`**
（+0.940 → **+1.659**）・**接戦帯の攻め半分が +0.478 → +0.865**（+81%）・
**守りは不動**（候補リストを使わないので影響を受けないのが正しい＝差の由来の検算）。
**独立の突き合わせは桁が合う**（足した額 0.029〜0.081 対 記録の登場時利得 0.024〜0.053）が
**帯ごとの対応は取れない**——`entry_gain` は同ターンの他の行動を拾っており
（登場時能力を持たないキャラでも 0.024〜0.064 が出る）**帯の一致を要求できる精度が無い**
（`2026-09-15_char_onplay_wired.md`）。

> **コストの側は思ったより軽い**——**3,386 の能力のうちコストを持つのは 900（27%）**。
> 残り 73% は「登場時に無料で発動」であり、**コスト側の値付けは `μ`（札 1 枚）と
> `cost·δ` でほぼ足りる**。

#### **配線の形**（2026-09-14・`effect_value.py` → `theory_order.score_candidate`）

| 手 | 値 | 理由 |
|---|---|---|
| **起動メイン** | **効果の値そのまま** | カードは既に場に在る＝札 1 枚は既に払ってある。**コストは能力の中に在る** |
| **イベント・ステージ** | **効果の値 − `μ` − 費用·δ** | **体を持たない札**（T16）＝札 1 枚とドンを払って**効果だけを買う** |
| キャラの登場 | `ν − μ − 費用·δ` | 従来どおり（**体が増える**） |

**読めない効果は `None`**——0 にすると「効果が無い」と混ざる。
**この配線で理論の順序が勝敗の向きに揃った**（`2026-09-14_p2_wired.md`・1 手あたりの傾き
**−6.98 → +4.27**）＝**イベント・起動メインに値段が無かったことが、
橋の反転の正体の半分だった**。

#### 旧「6 つの型」の表（除去の側だけ・`deck_roles.FORMS`）

| 実行内容 | 何が動くか | 価格 | 新しい定数 |
|---|---|---|---|
| **KO** | 相手の場のキャラが消える | **`ν`（相手の体）** | **不要** |
| **bounce** | 相手の体が手札に戻る | `ν`（体）− `μ_opp`（相手の手札 +1） | **不要** |
| **trash** | 相手の手札が落ちる | **`μ_opp`** | **不要** |
| **deck** | 引く・見る・積む | **`μ`**（自分の手札） | **不要** |
| **reduce** | パワーが下がる | **`c(x)` を通して間接的**（下記） | **不要** |
| **lock** | レスト・攻撃できなくする | **テンポ** | **要る**（唯一） |

**5 つは既にある価格で書ける。** **`lock` だけが未測定**で、これは
**既に backlog #34「テンポの価格（lock: rest / freeze）」として挙がっている**項目である。

> **`reduce` に独自の係数を与えてはいけない**——パワーを下げると
> **(a) `c(x)` が下がって守備費用が減る**・**(b) KO の射程に入る**・
> **(c) 身代わりの価値が下がる**（`min(c(x), Θ)` が小さくなる）という**既存の式の入力が動く**だけ。
> **係数ではなく `x` の付け替えで書く**。ここを独立の項にすると自由度が 1 つ増える。

#### したがって P2 の作業は 2 段に割れる

| | 中身 | 新しい測定 |
|---|---|---|
| **P2-1** | **パーサのコストと `FORMS` を読んで、上の表で値を付ける** | **不要**（配線） |
| **P2-2** | **`lock`（テンポ）の価格を測る** | **要る**（backlog #34） |

**P2-1 だけで、無言の行の大半が値付けできる**見込み——打たれた無言の手の内訳は
**起動メイン 45%・イベント 36%・効果の対象選択 19%**（2026-09-14 実測・実デッキ 120 局）で、
**どれも「コスト＋実行内容」の同じ仕組みで書ける**（行動の種別が違うだけ）。

#### 残る注意

- **個数と対象数**（「2 体まで KO」「1 枚引く」）を読む必要がある——`Σ` の項数が変わる。
- **条件付き**（「自分のキャラが 3 体以上なら」）は §14.1.1 の項 10 で、**別の穴**。
- **上限つき**（「〜まで」）は**選択肢の max** であって固定の個数ではない（#39 と同じ形）。

### 14.2 テンポ——アクティブとレストは第 3 の軸

§1.1 の穴 2。ルールから出てくる非対称:

- **攻撃するとレストになる**（攻撃元）。**ブロックするとレストになる**。
- **攻撃の対象になるのはレストのキャラとリーダーだけ**——アクティブのキャラは通常狙えない。
- **自分のリフレッシュで全部アクティブに戻る**。

したがって**キャラは毎ターン 2 つの用途から 1 つを選ぶ**:

| 選択 | 得るもの | 失うもの |
|---|---|---|
| **攻撃する** | `μ_opp · min(c_opp(x), Θ_opp)` | レストになる＝**次の相手ターンにブロックできず、狙われる的になる** |
| **アクティブで残す** | ブロックの option value＋**狙われない** | 攻撃 1 回ぶんの圧力 |

```
攻撃する ⟺ μ_opp·min(c_opp(x), Θ_opp) ≥ ν·P(レストで KO される) + ブロックの option value
```

**これは §14 の「札を攻めに使うか守りに残すか」と同じ形**である。つまり

> **このゲームの打ち回しは「4 つの通貨（ライフ・手札・ドン・場）が、それぞれ攻めと守りの
> 2 つの用途を持ち、毎回そのどちらが高いかを比べる」問題に尽きる。**

`x ≤ 0` の攻撃（通らない攻撃）を打つのは、**得るものが 0 でレストという費用だけを払う**＝
テンポの純損失。実測の 38.5% はここに当たる。

> **`lock`（レスト・フリーズ）には値付けが 1 つも無い**（2026-09-14 に判明）。
> 打たれたイベント 337 件のうち 18 件がこれで、**4 通貨 + `ν` + パワーの軸のどこにも入らない**
> ＝イベントの純価値が負に出た残差の一部を説明しうる。**テンポの価格を測るのが宿題**
> （`2026-09-14_bodyless_and_power.md` §限界）。

## 15. ターンの中は逐次決定——攻撃順序に価値がある

リーサルの試行は**攻撃 1 本ごとの逐次決定**。1 本ごとに (a) 相手がカウンターを吐いたか＝
相手の予算の情報が更新され、(b) 自分の残り攻撃回数が減る。したがって

- **打ち切れるかの再計算**: 残りの攻撃で相手の予算を割れなければ、そこで「ゲームを伸ばす」へ移る。
  **ターンの最初は①（押し切る）でも、途中から②（伸ばす）に移る**のが正しい。
- **順序に option value がある**: 安い攻撃を先に通して相手の予算を測り、重い攻撃を後に残す
  （逆も戦術としてある）。量は `V(最良の順序) − V(最悪の順序)`。
  **記録を眺めても出ない**——打たなかった順序は棋譜に無いので、
  同じ盤面を別の順序で打ち直す反事実でしか測れない。

## 16. 中盤の 3 方針は「相手の時計のどの項を攻めるか」

自分が決めるまでのターン数 `T_me` と相手の `T_opp` の競争で、勝ち筋は `T_me < T_opp`。

| 方針 | 買うもの | 式の項 |
|---|---|---|
| 純粋な殴り合い | 相手のライフ | `T_me` の分子を削る |
| シーソー（キャラ攻撃を混ぜる） | **相手の手札**（カウンターを吐かせる）・相手のキャラ | 相手の予算 `S_opp` を削る・`A_opp` を減らす |
| 手札切れ待ち | 相手の手札 → 0（そこから `c` が払えない＝全部通る） | `S_opp < 0` を作る |

**キャラへの攻撃は「手札を使わない除去」**＝自分の手札コスト 0 で、相手に
「カウンターを吐く」か「キャラを失う」の二択を強いる。選択の基準は**交換レートの最大化**。
§14.1 の式で言えば、キャラを狙う攻撃の価値は `min(c_opp(x), ν_opp)`——
**相手はカウンターで守るか、キャラを失うかの安い方を選ぶ**（リーダーを狙うときの `Θ` が `ν` に替わる）。

## 16.1 **カードの効果は「通貨の束」である**（穴 7・8 の閉じ方）

§1.1 の点検で「効果の語彙 35 種のうち理論が触れているのは KO とカウンターとドン付与だけ」と出た。
しかし**新しい種類の価値を足す必要はない**——**どの効果も 4 通貨（と情報）の増減の束**として書ける:

```
効果の価値 = Δ(ライフ)·λ + Δ(手札)·μ + Δ(ドン)·δ + Δ(場)·ν + （情報の項）
```

| 効果 | 通貨の束 |
|---|---|
| KO・トラッシュへ | `−ν_opp` |
| 手札に戻す（バウンス） | `−ν_opp + μ_opp`（相手は札を取り戻すので差は `ν−μ`） |
| レスト・フリーズ | `−（そのキャラのテンポ）`＝§14.2 の攻撃側の選択肢を奪う（ターン数ぶん） |
| ドロー | `+μ × 枚数` |
| 捨てる | `−μ_opp × 枚数`（相手の予算 `S_opp` を直接削る） |
| 山を削る | `−（デッキの残り）`＝§16.2 の第 2 の時計を進める |
| ライフ回復 | `+λ` ＝**`G` を 1 回減らす**（守る回数が減る） |
| パワー増減 | `x` を動かす＝`c_opp(x)` を通じて間接的に（§14.1 の飽和点まで） |
| コスト増減 | `±δ`（払うドンが変わる） |
| ドン追加（ramp）・返却 | `±δ × 個数` |
| 能力の無効化 | 相手の効果の束を 0 にする＝**その効果の価値ぶん** |
| 見る・公開・並べ替え | 情報の項（**本書では未定式化**・§3-5） |

**帰結**: カードの個性は「新しい種類の価値」ではなく**どの束を買うか**に宿る。
したがって**4 つの価格（`λ`・`μ`・`δ`・`ν`）を測れば、原理的にすべての効果が値付けできる**。
残る本当の穴は**情報の項だけ**である。

## 16.2 デッキは**第 2 の時計**（穴 4 の閉じ方）

**山 0 枚でドローすると敗北**する。ドローは毎ターン 1 枚（効果で増減）なので、

```
残りターン数の上限 T_max = デッキの残り枚数        （効果で削られれば縮む）
```

＝**デッキは「戦闘とは無関係に毎ターン 1 ずつ減るライフ」**である。したがって

- 勝敗条件は 2 本（ライフ 0 で被弾 ／ 山 0 でドロー）で、**どちらも「0 に達した側が負ける計数器」**。
  `λ` と同じ形の価格が山札にも在り、**残りが大きい間は 0 に近く、境界で跳ねる**。
- **「手札切れ待ち」（§16）は、相手の `S_opp < 0` を作る戦法だが、自分の第 2 の時計も進む**
  ＝**長期戦は両者の山を削る**ので、伸ばす戦略には**山の残りという上限が付く**。
- 山を削る効果は「相手の第 2 の時計を進める」＝**ライフを削るのと同じ通貨の別チャネル**。

## 16.3 【トリガー】は任意発動——`τ` は `max(0, ·)` の期待値（穴 7 の閉じ方）

ライフが手札に入るとき、**トリガーを使うかは選べる**（使わない選択が常に在る）。したがって

```
τ_value = E[ max(0, その効果の価値) ] ≥ E[ その効果の価値 ]
```

**「常に使う」と仮定すると τ を過小に見る**（悪い効果でも使わされる勘定になるから）。
正しくは**下限が 0 に切り上げられた期待値**で、これは `Θ = λ/μ − 1 − τ_value` を通じて
**受ける側を有利にする**方向に効く。

## 16.4 マリガン（穴 6 の閉じ方）

初手 5 枚を**全部返して 5 枚引き直す**（1 回限り・部分交換は無い）。全交換なので判断は単純:

```
キープ ⟺ E[V | この手札] ≥ E[V | 引き直し]
```

引き直し後の分布は**デッキだけで決まる定数**なので、**キープの基準は「デッキ固有のしきい値」**に落ちる。
`ν` の言葉で言えば「序盤に場のキャラを買えるか」＝**低コストのカードが何枚在るか**が主項。

## 16.5 キーワードは倍率として入る（穴 8 の一部）

| キーワード | 式のどこに効くか |
|---|---|
| 【ブロッカー】 | `B` を +1・§14.1 のブロックの option value を生む（**アクティブが条件**） |
| 【速攻】 | 登場ターンから攻撃できる＝`ν` の `R`（残りターン数）が +1 |
| 【ダブルアタック】 | 通ったときのライフが 2 枚＝**`λ` の項が 2 倍**（`Θ` も上がる＝相手はもっと守る） |
| 【バニッシュ】 | 通ったライフが**手札にならない**＝受ける側の利得 `+(1+τ)μ` が消える＝**`Θ` が `λ/μ` まで上がる**（守る価値が最大化） |
| 【アンブロッカブル】 | `B` を無効化＝§7 の予算から `B` が落ちる |
| 【カウンター】（イベント） | §12 の二重通貨（札＋ドン） |

**バニッシュの効果が式で見える**のは収穫で、`Θ` が 0.8〜1.5 から **2.47（=λ/μ）** へ跳ねる
＝**バニッシュ攻撃は「ほぼ何枚払っても守るべき攻撃」**になる。

# 第 III 部 時間

## 17. 時計とハザード

勝率は「いつ決着するか」を潰した量である。潰さない形は

```
P(win | s) = Σ_t P(T = t | s) · P(win | s, T = t)
h(t) = P(T = t | T ≥ t)        （ハザード＝「今が勝負か」の形）
```

**実測: `h(t)` には形が在る**（盤面の帯ごとに振れ幅 0.26〜0.63・§18）。さらに
**同じ帯の中で `P(win|T=t)` が大きく動く**（決着が遅い方が勝ちやすい帯がある）＝
**上の分解は実際に働いており、「平均何ターンで決まるか」1 個では足りない**。

### 17.1 **通貨 → 時計 → 勝率**（転換・2026-09-14 にユーザ指摘で書き下した）

> 「大事なのは、価格をゲームの勝利にどう活かすかの転換」

**ここが本書で一番育っていなかった場所である。** §6〜§14 は**価格**を、§17 は**時計**を
書いているが、**両者をつなぐ式が無かった**。無いままだと次の齟齬が残る:

- **価格は線形**（通貨を足し引きして勝率に換算する）
- **勝利は閾値**（ライフを 0 にした方が勝つ）

**つなぐのは「2 本の時計」である。**

#### 17.1.0 **価格の定義は 1 つ——他はその近似**（2026-09-16・ユーザ指摘「正解は 1 つになりそう」で書き下した）

```
手 a の価値 = W(a を打った後の局面) − W(打つ前の局面)        W = その局面からの勝率
```

これが定義で、他に定義は無い。`λ`・`μ`・`δ`・`ν`・`w`・`Θ` は**この差を計算する道具**であり、`W` が直接は判らないので
近似が要るだけである。**形がいくつも出てくるのは「別の答え」ではなく「同じ答えの解像度」の違い**:

| 形 | 正体 |
|---|---|
| 定数の価格（`λ = 0.136` など） | `W` の傾きを記録に出た全局面で**平均**した値。局面ごとの違いを捨てている |
| `w(状態) × 時計の差分`（★） | 同じ傾きを**時計を経由して**書いたもの（合成関数の微分）。局面ごとの違いを残せる |
| `w = 0.5/R` | 傾きの値ではなく「経路に沿って足すと 0.5」という**制約**（割線）。局面の値は決めない |

`G(t) = W(s_t) − 0.5` を時間の関数と見ると、**手の価値 = 傾き `dG/dt` × その手で動いた時計の量**——`w` は
「傾き」であって「点の値」ではない。定数の価格は資源を静止した点の値段として扱っていた（**静止点と時間軸の混同**）。
**どの形が正解に近いかは定義そのものが判定する**: 本当の `W` なら 1 局の価値の変化を全部足すと必ず `z − 0.5` になる
（途中が打ち消し合う）ので、**橋の `ΔG` の「傾き 1」は望ましい性質ではなく定義が要求する等式**であり、傾きの不足は
近似の距離そのものである。**本当に選択が要る場所は 1 つ**——`W` は「両者がこの先どう打つか」を決めないと定まらない。
式の `min` は最善で打ち合う `W`、実現は記録の CPU の打ち方の `W`。両者の差（T48 の「相手が `min` を選ばない」）は
原則どおり追わず、傾きが 1 に届き切らない残差として受け入れる。
**ユーザ決定（同日）: 価格は 2 つ目の形で持つ**（`w(状態) × 時計の差分`）。3 つ目は 2 つ目の積分条件＝検算と土台。

#### 17.1.1 2 本の時計

```
T_me   = 自分が相手を倒しきるまでの手数
T_opp  = 相手が自分を倒しきるまでの手数
W = P(T_me < T_opp)            （手番の先後でタイブレーク）
```

**どの通貨も、2 本の時計のどちらかを動かすことでしか勝率に効かない。** したがって

```
price(X) = ∂W/∂X = (∂T_opp/∂X)·∂W/∂T_opp + (∂T_me/∂X)·∂W/∂T_me
```

零和かつ競走なので `∂W/∂T_opp = −∂W/∂T_me ≡ w`。**`w` は「テンポ 1 ターンの価値」**で、

```
price(X) = w · [ ∂T_opp/∂X − ∂T_me/∂X ]        ★ 転換の式
```

**＝すべての価格は「`w` × 時計の差分」である。** 価格は**基本量ではなく、時計の従属量**。

#### 17.1.2 4 通貨を時計に翻訳する

`A_opp` を**相手が 1 手番に通すリーダー攻撃の数**とする（実測 **1.060**）。

| 通貨 | 時計への効き方 | 価格 |
|---|---|---|
| **`λ`** ライフ | 被弾を 1 回多く受けられる＝**相手の時計 +1/A_opp** | `λ = w / A_opp` |
| **`μ`** 手札（守り） | `c̄` 枚で 1 撃止める＝ライフ 1 枚ぶん | `μ_guard = λ / c̄` |
| **`μ`** 手札（攻め） | 体になって**自分の時計を縮める** | `μ = max(μ_guard, μ_develop)` |
| **`δ`** ドン | パワーを上げ、相手の守備費用を `Δc` 枚増やす | `δ = Δc · μ`（実測 0.66·μ） |
| **`ν`** 体 | 攻撃で自分の時計を縮め、**身代わりで相手の時計を伸ばす** | 両方の和（§14.1） |

#### 17.1.3 **この枠から `Θ` が再導出される**（整合の確認）

§9 の `Θ = λ/μ − 1 − τ_value` は、**守り用途が縛っているとき** `μ = λ/c̄` なので

```
Θ = c̄ − 1 − τ_value
```

＝**`Θ` は `w` に依らない**（比だから）。**だから `Θ` はデッキと盤面だけで決まる量**であり、
§8 の盤面経路（`c(x)` の `G` 番目）と同じものを測っている——**平均か、限界かの違い**。
**ユーザ指摘の `max`（§1.4）は、この 2 つのうち縛っている方を採る操作**である。

**攻め用途が縛るとき（`μ_develop > λ/c̄`）は `μ` が上がり `Θ` が下がる**＝
**守らずに殴る**。これは「押している側はブロックしない」という打ち回しの原則そのもので、
**式から出てくる**。**ドンと盤面が厚いほど `μ_develop` が高い**＝
**「残りドン＝リーサル圧を高められる余裕」が `Θ` を下げる経路がここ**（ユーザ指摘 2026-09-14）。

#### 17.1.4 **数値の突き合わせ**（2026-09-14・300 局）

`w` を**独立な 3 経路**で出すと:

| 経路 | 式 | `w` |
|---|---|---|
| 恒等式から | `Σλ(ℓ)=0.5` をライフ 5 で割り `×A_opp` | **0.1060** |
| ゲームの長さから | `0.5 / R`（残りターン 4.128） | **0.1211** |
| 相手ターンの `λ` から | `λ · A_opp` | 0.1443 |

**前 2 つは 14% 以内で一致する。** 3 つ目が 36% 高いのは
**相手ターンの `λ` が逆因果で 32% 上振れている**（T19・`2026-09-14_life_price.md`）と整合＝
**別経路から同じ欠陥を指している**。

**自己整合の検査**: `w · R = 0.437` 対 **ゲーム 1 つ = 0.5**（13% 差）。
＝**「残りターンぶんのテンポ ≈ ゲーム 1 つ」**が成り立っている。

#### 17.1.5 **`Θ` が総合判断であるべき理由**（ユーザ指摘 2026-09-14）

> 「`Θ` は本来、フィールド、手札、残りドン、ライフを総合的に判断して計算するはず」

転換の式に照らすと、**4 つとも別の経路で `Θ` に入る**:

| 入力 | どこから入るか | 現状 |
|---|---|---|
| **フィールド** | `N`（来る攻撃）・`B`（ブロッカー）・**身代わり** | **N と B のみ**。身代わりは**未実装**（実測で攻撃の 20.7% はリーダーに来ない＝`N` を 2 割過大に数えている） |
| **ライフ** | `L`＝受けられる回数、かつ `λ(ℓ)` の水準 | `L` は入っている。**`λ(ℓ)` は未実装**（経済側は定数 1.15） |
| **手札** | **払える上限**＝`G` 本を実際に払えるか | **未実装**（払える前提で回っている） |
| **残りドン** | `μ_develop` を上げる＝**`Θ` を下げる** | **未実装**（相手の付与の推定にしか使っていない） |

**＝現状の `Θ` は 4 入力のうち 2 つ半しか使っていない。**

#### 17.1.5b **系——価格を縛るのは「デッキ」ではなく「進行」**（ユーザ指摘 2026-09-14）

> 「価格の考え方はデッキの中身でなくて進行により決まる。デッキの進行方法がデッキにより
> 特徴付けられているだけで、デッキ相性＝デッキの中身に特徴付けられる進行という意味では
> ないのかな。デッキの中身はリーダー効果や色によって縛られているので、それが出てくる」

★の式は `w(状態)` と時計の差分しか持たない＝**デッキの中身はどこにも入らない**。
**デッキは「取りやすい進行」を通じてしか価格に触れない**（リーダー効果と色が進行を縛る）。
したがって:

> **価格を測るときの帯は「進行の変数」で切るべきで、「デッキのラベル」で切るのは代理でしかない。**
> ラベルで縛ると**未見のデッキに一般化しない**。

**実測で確かめた**（`2026-09-14_progress_band.md`）——進行の粗い型
（相手の場・自分のドン・自リーダーのパワー）で切ると、**デッキラベルの効果の大半が再現し**
（実デッキの上 2 帯で 0.1112／0.1270 対ラベルの 0.1143／0.1193）、**落ちる行は半分以下**。
**そして合成の `ν` は進行で縛っても動かない**（飽和超え 0.2112 → 0.2045）＝
**ラベルのときだけ動いたのは標本の脱落だった**。

**残差**: 弱い体の帯だけ進行で取り切れない（−0.0227 対 ラベル +0.0178）＝
**今の 3 変数は時計の代理であって時計そのものではない**。次は `T_me`／`T_opp` の推定値で作る。

#### 17.1.5c **「進行」の定義**（2026-09-14・ユーザ指示「そこは固めましょう」）

17.1.5b は「帯は進行で切る」と言ったが、**進行を定義していなかった**（最初の実装は
「相手の場の体数・自分のドン・自リーダーのパワー」という**手近な代理を 3 つ選んだだけ**）。
★の式から導き直す。

> **進行 ≡ 2 本の時計の状態 `(T_me, T_opp)`。**

```
T_opp = （自分が耐えられる被弾回数）/（相手が 1 手番に通す攻撃数）
      = ( L_me + 守れる回数(H_me) + B_me + 吸収 ) / A_opp

T_me  = ( L_opp + 守れる回数(H_opp) + B_opp + 吸収 ) / A_me
```

**価格を測るときは、この入力のうち「説明変数でないもの」を帯に入れる。**
`ν`（体 1 つの価格）を測る場合、**説明変数は自分の場の体**なので:

| 入力 | どちらの時計 | 帯に入るか | 観測 |
|---|---|---|---|
| `L_me`・`L_opp` | 両方の分子 | **入る** | ライフ |
| `H_me`（自分の手札） | `T_opp` の分子 | **入る** | 手札枚数 |
| **`A_opp`**（相手の通る攻撃数） | **`T_opp` の分母** | **入る** | `incoming_x` の `x ≥ 0` を数える |
| **`H_opp`**（相手の手札） | **`T_me` の分子** | **入る** | scalars 列 7 |
| 自分のドン | `T_me` の分母（体以外） | **入る** | scalars 列 2 |
| **`A_me`・`B_me`（自分の場）** | **`T_me` の分母** | **入らない** | **これが説明変数** |

> **`T_me` を丸ごと帯に入れることはできない**——**自分の場が説明変数だから**。
> これは器の欠陥ではなく**推定量の定義からの帰結**である。
> 帯に入るのは**「相手の時計の全部」＋「自分の時計のうち体でない入力」**。

**自リーダーのパワーは別の変数として入れない**——**`A_opp` の中に入っている**
（相手の攻撃が越えるべき閾値そのもの）。最初の実装はこれを二重に持っていた。

**デッキの中身は 1 つも参照しない**＝**未見のデッキにも同じ値付けが効く**（17.1.5b の要件）。

**実測で代理版より良かった**（`2026-09-14_progress_band.md`）——
**合成では値を動かさず**（交絡が無いので動かないのが正しい: 0.0690/0.1503/0.2112 →
0.0633/0.1474/0.2089）、**実デッキでは負を消す**（−0.0346 → −0.0139・CI が 0 を含む）。
**理屈から導いた統制が、勘で選んだ 3 変数より効いた。**

**足りなかったもの 2 つ**（ユーザ指摘 2026-09-14「キャラクターのパワーやブロッカーなども
必要な情報な気がしています」——**どちらも正しかった**）:

1. **パワーは分母ではなく分子に効く**。`A_opp`（通る攻撃の**本数**）では
   **10000 の攻撃と 5100 の攻撃が同じ 1** になるが、止める費用は `c(5000)=3.63` 枚と
   `c(0)=1.00` 枚で全く違う＝**「守れる回数」を決めているのはパワーの大小**である。
   だから **`Σ c(x)`（来る攻撃を全部止める費用）**で持つ。
2. **ブロッカーが実装に無かった**。上の表には `B_me`・`B_opp` が在るのに落としていた
   （定義と実装のずれ）。**相手のブロッカーは帯に入れられる**（`T_me` の分子）。

**入れられないものは変わらない**——`B_me`（自分のブロッカー）・吸収・`A_me` は
**自分の場＝説明変数**なので帯に入らない。
**＝帯が描けるのは「自分の体が働く環境」までで、自分の体そのものは描けない。**

**実測——進行の記述を良くするほど、単調にデッキラベルの答えへ近づく**
（実デッキ・リーダー未満の帯・`2026-09-14_progress_band.md`）:

| 帯の切り方 | 値 | 95% CI |
|---|---|---|
| 状態のみ | **−0.0346** | [−0.063, **−0.006**] |
| 進行 v1（勘で選んだ 3 変数） | −0.0227 | [−0.052, 0.007] |
| 進行 v2（時計から導出・本数） | −0.0139 | [−0.043, 0.015] |
| **進行 v3（＋パワー＋相手ブロッカー）** | **−0.0078** | [−0.038, 0.023] |
| （デッキラベル） | +0.0178 | [−0.010, 0.045] |

**これが「デッキは進行の代理にすぎない」の一番強い証拠**である——
**進行を丁寧に書くほど、ラベルが持っていた情報が進行の側に移る**。
合成デッキでは（交絡が無いので）どの版でも値が動かない＝**歪めていない**ことも確かめた。

**残る限界**: `Σ c(x)` も `A_opp` も**今の盤面から見た 1 手番ぶん**で、
**残り全ターンの率ではない**（時計は本来は先を見る量）。相手のトリガー・除去・
次のターンに出てくる体は入っていない。**＝今のところ「進行の型」は時計の 1 次近似**である。

**全変数を機械的に洗って、この限界を裏から確かめた**（`2026-09-14_band_screen.md`・
ユーザ指示「今あるエンジンの変数から効きそうなものを洗えたりする？」）——
`scalars` 127 列を `bias ≈ (z を予測する強さ)×(説明変数と相関する強さ)` で採点すると、
**実デッキで残る上位はほぼ全部「これから来るもの」**（`leader_pair`・`deck_big`・
`my_deck_agg`・`deck_draw`・`my_deck_apex_*`・`opp_pool_max_power`）で、
**合成では同じ列が 4〜8 分の 1**（全員の未来が同じだから）。

> **ただし帯に入れても改善しなかった**——行が 4 割落ちて合成の値が動く（標本の脱落）。
> **帯は交絡を取り除くことしかできない。未来側は取り除く対象ではなく、価格そのものの入力**である
> ——`ν` は「残り `R` ターンぶんの攻撃の価値」なのだから、**`R` と `A` を先を見た値にする**のが筋で、
> **帯を細かくする話ではなかった**。**帯は進行 v3 が止めどころ**。

#### 17.1.6 **検定できる予測**——**実施済み・支持された**（2026-09-14・T24）

★の式が正しければ:

> **4 つの価格は 1 つの `w` を共有する。**
> ＝**競走の接近度で帯を切ると、価格の「水準」は揃って動き、「比」は動かない。**

`λ/μ`（＝`c̄`）・`δ/μ`（＝`Δc`）・`ν/μ` は**デッキと盤面の量**なので帯で動かないはずで、
`λ`・`μ`・`δ`・`ν` の**水準だけ**が `w(state)` と一緒に動くはずである。
**比が動けば、この枠は誤り。**

**実測（合成 900 局・`tests/scripts/price_scaling.py`・`docs/reports/2026-09-14_price_scaling.md`）**:

- 接近度は **`A_opp`（相手の通る攻撃数＝`T_opp` の分母）**で切る。
  **`|v0|` で切ってはいけない**（4 つの説明変数すべての下流・罠 21）。
- **判定 `supports_one_w`**——比の 95% CI は帯をまたいで**全組で重なり**、
  **CI は情報を持つ幅**（相対幅 ≤2.0）だった。
- **交絡の帯を旧帯から進行（§17.1.5c）へ替えても判定は同じ**。
  **水準は動く**（`δ` は +52%・`ν` は −11%）が、**比の平坦性という結論は共通**。
  ——★は**水準を予言していない。比が動かないことだけを予言している**。
- **水準は `μ`・`δ`・`ν` が `A_opp` とともに上がり、`λ` だけ平ら**。
  **これは★の含みと一致する**——`λ = w/A_opp` は**4 つのうち唯一 `A_opp` を分母に持つ**ので、
  `w` の上昇と `1/A_opp` の低下が打ち消し合う。（事前登録ではなく**事後の整合**。）

> **残る問い（T26）**: `μ = max(λ/c̄, μ_develop)` の**どちらの枝にいるか**。
> 守る枝なら `λ/μ` は完全に平ら、作る枝なら `A_opp` とともに下がる。
> **点推定は両方の帯で下がっている**（4.36→2.90／3.35→2.75）＝**作る枝**の読みと整合するが、
> CI は重なる。**`μ_develop` と `λ/c̄` を行ごとに比べれば直接数えられる。**

**`Θ` への含み**: `Θ = λ/μ − 1 − τ` より **1.88（旧帯）／1.66（進行の帯）**
——**出荷既定の 1.15 より高い**。900 局で再現した（既定の変更は未実施＝ユーザ決定）。

#### 17.1.7 **目的の一致——手の良し悪しの説明と恒等式**（ユーザ決定 2026-09-15・`2026-09-15_goal_alignment.md`）

**完成の定義**: `v(手)`＝「その手で勝率がどれだけ動くか」が正しいなら、ゲーム通しで足すと恒等式になる:

```
z − 0.5  ≈  ΔG  =  (B_自分 − B_相手)  +  (S_自分 − S_相手)
G = Σ v(打った手)   B = Σ v(その行の最善)   S = G − B ≤ 0
```

- **`B`＝局面が差し出す上限**（デッキ相性・引き・相手の手・自分の過去の手で決まる）。
- **`S`＝上限からの取りこぼし**（最善を打てば 0）。「選択肢の中で最も良い手を打つのが最善」＝`S = 0`。
- **対面の勝率**＝両者が最善を打ったときの `B_自分 − B_相手`。

**判定**: `ΔG` が勝敗を**傾き 1** で説明し、**記録を替えても符号が変わらない**こと。**`ΔS` は副次**
（局面の上限を消しているので、通っても `v` の水準が正しい証拠にならない）。

**現状（T40）**: 合成 900 局で傾き **0.30**（向きは合うが価格が総体で 3 倍ほど大きい）・実デッキ 300 局で
**−0.27**（符号が逆・型で割ると攻撃 0.87／効果 0.16）＝**攻撃と効果・登場の価格の比が現実と合っていない**。
攻撃は `Θ·μ`（札 1.15 枚）で頭打ち、KO 効果は対象の `ν`（最大で札 4 枚相当）。

**成り立つための条件**: (1) 「行で最善＝ゲームで最善」は **`v` が将来まで含んだ現在価値**のときだけ
——`ν` は流量・テンポは在庫÷R・サーチは選択の利得としてそう作ってあるが、P7（`ν` の先読み）と P1
（`w(状態)`）が穴。(2) **`B` は固定ではない**（相手の手・自分の過去の手で動く）＝(1) と同じ場所に帰着。

**次**: 型ごとに「価格」と「実現した価値」を別々に測って並べ（T41・回帰しない）、比が合わない型を
測定値で写し替え、`ΔG` を回し直す。

**T41 の結果（同日・`2026-09-15_price_vs_realised.md`）**: **攻撃の価格は正しい**（実現との比 0.91／0.84）。

勝敗を AUC 0.84 で説明するが傾きは 0.48**＝恒等式の半分（減衰込み）＝実測の価格の水準も総体で最大 2 倍（P1 の場所）。

## 18 の前に——負けているときの危険選好は零和では最適

利得が勝率（確率）なので、**資源に対しては危険選好が正しい**:
領域 3（`S < 0`）では期待値を積む手より**分散の大きい手**（トリガー・相手の事故・
2 割しか通らない線）の方が勝率を上げる。

> **「どちらにしろ負け濃厚なら、最初から無茶をする」は正しい**。
> そしてその線を見つけるには**隠れ情報を何通りも読む**必要がある（§5 の `1−(1−p)^K`）
> ——理論上いちばん無茶が要る局面が、いちばん読みを要求する。

### リーダー未満の帯の正体——**身代わり**（2026-09-14 に実測・`2026-09-14_shield_term.md`）

**効果ではなく体そのものだった**。効果を 1 つも持たない**素の体**（帯の 65%）が
**0.0753** [0.030, 0.121]（CI が 0 を含まない）を持ち、効果持ちは 0.0584 で**上回らない**。

正体は **§14.1.1 #7 の身代わり**——**キャラが殴られると、その攻撃はリーダーに通らない**:

```
身代わり項（粗） = Σ（吸った攻撃 1 本ごとの価値） / 露出 × R
1 本の価値      = min( c(x_lead)·μ , Θ·μ )      x_lead = 攻撃側のパワー − 自リーダー
```

**1 本を一律 `Θ·μ` と置いてはいけない**（ユーザ指摘 2026-09-14・
`2026-09-14_shield_value.md`）——「2000 のパワーを吸うのか、10000 を吸うのかで価値は変わる」。
**`Θ·μ` は上限**にすぎず、**`x_lead < 0` なら価値は 0**（相手の 3000 の体は 5000 の
リーダーに通らないので、それが自分の 2000 を殴っても**リーダーは何も守られていない**）。
**実測で吸った攻撃の 17.6% がこれ**（弱い体では 23.9%）。

**攻撃の 20.7% がキャラ狙い**（6,426 本）。**率と 1 本の価値は逆を向く**:
