## 4. 未測定の宿題（優先順・コーディネータの意見）

1. **`∂V̂/∂手札` の符号検査**——「守った方が良い」という結論そのものの前提（`measurement.md` §12）
   ＝**測定中**（`tests/scripts/hand_value_slope.py`・台帳 §6・2026-09-13 発注）
2. **`guard_enough` の DON 補正**——今日の会計の再計算（`life_budget.md` §5）
   ＝**測定中**（`tests/scripts/guard_afford.py`・同）。**書いている途中で予算式の穴が 1 つ出た**:
   守りの費用は札とドンの 2 成分で、`c(x)` は 1 通貨で書けていなかった（`life_budget.md` §18）
3. **行動空間の被覆** ＝ **閉じた**（2026-09-13・40 局 2,606 判断点で `coverage` 1.000・
   `missing_any` 0.000・`best_not_in_a` 0.000・`exhausted_a_any` 0.000）。
   **枝予算は候補を 1 つも落としていない**＝2026-08-12 の 36% は当時の Python の列挙の話。
   **残るのは「人間の配分が列挙の設計に入っているか」**（無制限の列挙を正とみなす以上
   この方法では測れない）。`2026-09-13_search_limits.md`
4. **`worlds` を上げた効果** ＝ **効果の証拠なし・ただし分解能不足**（2026-09-13・
   腕 4 が +12.6 Elo [−20.1, +45.6]／腕 8 が +3.0 [−31.4, +37.6]・**用量反応は逆向き**）。
   250 ペア前後では **+20 Elo 級を棄却できていない**（事前想定は 1,200 ペア）。
   **前提の誤りも直した**: serve／アリーナの既定は `worlds = 1` で、4 は生成だけ。
   `2026-09-13_search_limits.md`
5. 接戦帯の **`order_acc`**（較正ではなく順序）
   ＝**測定中**（`tests/scripts/order_acc.py`・同）
6. デッキ別の **`c̄(t)`**・攻撃順序の価値・貪欲と入口コミットの差・τ
   ＝**τ と `c̄` は実測済み**（`deck_profile.py`・`2026-09-13_deck_profile.md`・`life_budget.md` §19）。
   **貪欲と入口コミットの差**は `budget_audit.py` の `greedy_gap`（測定中）。
   **攻撃順序の価値だけが残る**＝記録では測れない（同じ盤面を別の順序で打ち直す反事実が要る）＝
   被覆と同じ「エンジンに 2 通りやらせる」型の計器が必要
7. **零和の反対称が破れている**（2026-09-13 実測・`sum_mean −0.138` CI [−0.187, −0.092]）
   ＝**片側あたり約 3.5 ポイント悲観**。切り分け（価値が全体に悲観か・手番でない席の評価が分布外か）は
   手番側の較正で付く。**未着手**。`game_theory.md` §2-2
8. **PIMC の融合は接戦帯に限局**（2026-09-13 実測・close で割れ 44%・融合 2.0%・Q の幅 0.361）
   ＝探索は今のところ上限を作っていない。融合の**損の大きさ**は反事実が要る。`game_theory.md` §5
9. **読まれやすさ `H(行動｜公開状態)`**＝計器完成・波 32 で測定中（アリーナでは原理的に測れない量）
10. **候補 F**（予算を打ち回しに入れる・**ゲーム理論から再設計**＝`game_theory.md` 第 VI 部）
