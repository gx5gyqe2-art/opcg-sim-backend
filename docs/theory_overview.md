この文書は、理論フェーズで「何を作り、何ができて、何が既知の限界か」を 1 か所にまとめたもの。
正本は台帳 `docs/cpu_theory_gap.md`（§0.6 が現在地の地図、§0.7 が改善の流れ）。数字は各報告（`docs/reports/`）から写した。
数字は「実戦の記録（300 局）／合成デッキの記録（900 局）」の順。

---

## 1. この理論は何か

- **目的**: CPU を変える前に「手の良し悪しを説明する理論」を組み上げる。理論が損と言う手を禁じて勝率が上がるか（出口 T18）で役立つかを確かめる。
- **前提**: **完全情報**で組む。両席の手札とデッキの中身が見えている前提で式を書き、まず勝敗の説明をつける。相手の手札が見えないことの扱いは後の層。
- **守る約束（4 つ）**: 当てはめた局で測らない／項は測る前に決める／各項は独立の量を言い当てる／**新しい定数を足さない**（規則・デッキ・既存の実測値だけで書く）。

## 2. 理論の部品

| 部品 | 何をするか |
|---|---|
| 通貨 | ドン 1 枚・手札 1 枚・ライフ 1 枚などを同じ単位に換算する（実測で固定・検算済み） |
| 攻めと守りの値段 | 攻撃を受ける費用・止める費用・ブロッカーの値打ち |
| 効果の値段 | 登場時・起動・付与・除去・条件つきの効果。コストを払えるかはエンジンと同じ規則で判定する |
| 手札の価値 | 手札の 1 枚ごとに「出す・カウンターに使う・持っておく」の最適な割り当てで測る |
| 守る側の計算 | 守り手が先読みの範囲（平均 4〜5 ターン）で最善に守ると置いて、毎ターンどれだけ削られるかを解く |
| **交点の橋**（時計） | 両席について「相手を倒し切るまで何ターンかかるか」を出し、どちらが先に届くかで勝ち負けを言う |
| 線形の橋 | 打った手の値打ちの累積で勝敗を並べる |
| 局面の傾き | 2 本の時計の差から「その局面で 1 単位の得が勝率をどれだけ動かすか」を出す |
| 決着の定義 | 「相手が最善で守っても通る本数 ≥ 相手の残りライフ ＋ 1」なら、そのターンで決着（規則だけ） |
| 表（`tests/fixtures/harm_profile.json`） | 損害の輪郭・時計のばらつき・平均の傾きの実測値。`make theory-table` で作り直し、出所を点検する |

計算は全部 Rust（`rust/opcg_engine/src/theory/`）。Python は入口・記録の読み込み・集計だけ。正しさは cargo の記録の再生と golden で守る。

## 5. 既知の限界

1. **手札の厚い守り手の生存を言い過ぎる時計の群れ**（時計の 10％／13％）。その群れの勝った側の時計は約 1.4／1.9 ターン遅い。
   原因は先読みの範囲の外の読み方にあると見られる。ただし範囲の内側の直し（3 回）ではどれも動かなかった。
   直しても予測は良くならないことが確かめられている（§3）。
2. **合成の記録の打ち切り**（30 ターンで時計が届かない 70 本）と、それによる**合成のばらつきの大きさ**（実戦の約 1.4 倍の 7 割はこの 21 本）。
3. **実際の守り手（CPU）は理論より 1 ターンに約 0.5 枚多く札を切る**。理論の最善と「目先だけの最善」のちょうど間にいる。打ち筋の課題として訓練の側の材料になる。
4. 線形の橋の行ごとの判定は、実戦で「逆向き」と出る（全体の並べる力は保たれている）。
5. 決着の定義は「1 ターンで詰む」まで。複数ターンの必勝は決着前の層に任せている。
